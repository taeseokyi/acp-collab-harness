# .githooks

이 저장소의 버전 관리되는 git 훅 모음입니다. `.git/hooks/` 는 clone 시 복사되지 않으므로,
훅을 저장소에 넣고 `core.hooksPath` 로 이 폴더를 가리키게 하는 방식을 씁니다.

## 활성화 방법

```sh
git config core.hooksPath .githooks
```

**세션 로컬 설정입니다.** 이 저장소를 새로 clone 하거나, 다른 머신/워크스페이스에서
작업하는 세션은 각자 한 번씩 실행해야 합니다. 전역으로 걸고 싶다면
`git config --global core.hooksPath .githooks` 를 쓸 수도 있지만, 그러면 이 값이
**다른 모든 저장소**에도 적용되어 그 저장소들의 로컬 훅을 무시하게 되므로 권장하지 않습니다.

적용됐는지 확인:

```sh
git config core.hooksPath   # ".githooks" 가 출력되어야 함
```

## `pre-commit` 이 하는 일

스테이징된 파일만 보고 필요한 검사만 돌립니다(무관한 커밋에서는 아무것도 실행하지 않음).

- **`AIMEM.md` 가 스테이징에 포함되면** `python3 tools/aimem_lint.py AIMEM.md` 를 돌립니다.
  구조 불변식(REV 유일성, 세션 명부 슬롯/토큰 중복, 작업 보드 상태값·소유 슬롯 존재,
  파일 소유권 유효성 등)을 위반하면 위반 목록을 그대로 보여주고 커밋을 거부(exit 1)합니다.
- **`tests/` 또는 `tools/` 아래 파일이 스테이징에 포함되면**
  `python3 -m unittest discover -s tests` 를 돌립니다. 실패하면 커밋을 거부합니다.
- `python3` 이 PATH 에 없으면 (검사가 필요한 커밋에 한해) 명확한 오류와 함께 커밋을 거부합니다.
  검사 자체를 건너뛰고 통과시키지 않습니다 - 조용히 넘어가면 훅의 목적이 사라지기 때문입니다.

## 우회 방법 (`--no-verify`)이 정당한 경우

```sh
git commit --no-verify
```

훅은 실수로 깨진 `AIMEM.md` 를 커밋하는 것을 막기 위한 안전망이지, 관리자의 판단을
대신하지 않습니다. 다음과 같은 경우에는 `--no-verify` 로 우회하는 것이 합리적입니다.

- **관리자(AIMEM.md 단독 쓰기 권한자)가 의도적으로 과도기 상태를 커밋해야 할 때** -
  예: 여러 슬롯의 갱신을 순차적으로 합치는 중간 단계라 일시적으로 표가 불일치하지만,
  다음 커밋에서 곧바로 고칠 게 확실한 경우.
- **`tools/aimem_lint.py` 자체를 고치는 커밋인데, 아직 반영 전인 구버전 린터가
  새 정책과 충돌해서 오탐을 내는 경우** - 다만 이 경우는 가능하면 린터부터 먼저 고쳐
  통과시키는 편이 낫습니다.
- **`tests/` 실행 환경이 일시적으로 망가져 있어(예: 의존성 문제) 관련 없는 커밋까지
  막힐 때** - 임시 우회이며, 환경 문제는 별도로 고쳐야 합니다.

우회하지 말아야 할 경우: 단순히 "지금 린트 통과가 귀찮아서", 혹은 위반의 원인을
파악하지 않은 채 넘어가려는 경우. `aimem_lint.py` 가 잡아내는 위반은 대부분
다른 세션의 작업을 깨뜨리는 종류(예: 태스크 ID 중복, 존재하지 않는 슬롯 참조)이므로,
원인을 고치는 것이 우회보다 항상 우선입니다.

## 훅이 느려지면

이 훅은 스테이징된 파일 목록만 보고 조건에 안 걸리면 즉시 종료합니다(`AIMEM.md`,
`tests/`, `tools/` 와 무관한 커밋은 `git diff --cached --name-only` 한 번 외에
아무것도 실행하지 않습니다). 검사가 실행될 만큼 느려졌다면 `tools/aimem_lint.py` 나
테스트 스위트 자체의 속도를 봐야지, 이 훅의 조건 분기를 의심할 필요는 없습니다.
