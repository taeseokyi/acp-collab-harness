# T-251 `serve()` 의 SIGTERM 처리기 설치 자리 (재검수 R19-P6)

쓸 파일은 **하나**입니다: `tools/aimem_monitor/server.py`. `tests/**` 와 다른 `tools/**` 는
읽기만 하고 **절대 고치지 마십시오**. 계획을 세우지 말고 바로 고치십시오.

## 무엇이 잘못됐나

`serve()` (`:3199` 근처) 는 지금 이 차례입니다:

1. `httpd` 를 만든다
2. `signal.signal(signal.SIGTERM, _sigterm_interrupt)` 로 처리기를 건다 (`sigterm_installed = True`)
3. `log_line(...)` 을 **여러 줄** 찍는다 (주소·엔드포인트·인증 안내·토큰 파일·새 토큰·경고)
4. `try: httpd.handle_request()/serve_forever() ... finally: ... flush_denied_audit(root); httpd.server_close()`

2 와 4 사이(3 번 구간)에 SIGTERM 이 오면 `_sigterm_interrupt` 가 `KeyboardInterrupt` 를 던지는데,
아직 `try:` 안이 아니라 **`finally` 가 돌지 않습니다**. 그러면 `flush_denied_audit` 도,
`httpd.server_close()` 도, 처리기 되돌리기도 건너뛴 채 예외가 `serve()` 밖으로 터져 나갑니다.

## 고칠 것

**처리기 설치 블록을 `try:` 바로 앞으로 옮기십시오.** 즉 차례를 이렇게:

1. `httpd` 만들기
2. `log_line(...)` 들 (지금 그대로, 글자도 차례도 바꾸지 마십시오)
3. `sigterm_installed = False` + `try: old_sigterm = signal.signal(...)` 블록  ← **여기로 옮김**
4. 바로 이어서 `try: httpd.handle_request() if once else httpd.serve_forever()` …

- `_sigterm_interrupt` 함수 자체, `finally` 안의 되돌리기·`flush_denied_audit(root)`·`server_close()`
  는 **그대로 두십시오**
- 주석 한 줄로 까닭을 적으십시오 (`재검수 R19-P6: 처리기와 try 사이에 틈이 없어야 한다`)
- `signal.signal` 이 주 스레드가 아니면 `ValueError`/`OSError` 를 내는 것을 조용히 넘기는
  지금 동작(`except (ValueError, OSError): pass`)은 그대로 유지하십시오. 시험은 스레드에서 서버를 띄웁니다

## 하지 말 것

- `serve()` 의 반환값·인자·동작을 바꾸지 마십시오
- `log_line` 문구를 바꾸거나 지우지 마십시오
- 다른 함수를 건드리지 마십시오
