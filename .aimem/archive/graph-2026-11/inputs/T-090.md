## 목표 - 재검수 (읽기 전용)

네가 직전에 `tools/fleet_graph.py` 에서 결함 6건을 찾았다. S1 이 그중 5건을 고쳤다고 한다.
**고쳤다는 말을 믿지 말고 같은 시나리오를 다시 돌려라.** 그리고 **고치면서 새로 생긴 결함**을
찾아라 - 수정은 거의 항상 새 구멍을 낸다.

## 쓰기 없음

**파일을 하나도 만들거나 고치지 마라.** `fleet_graph.GRAPHS` 와 `fleet.RUNS` 를
`tempfile` 디렉터리로 바꿔 놓고 메모리 안에서만 재현하라.

## S1 이 고쳤다고 주장하는 것

1. **(결함 1, 높음)** `_kill_run` 이 `os.kill` 대신 **`os.killpg(pgid, …)`** 를 쓴다.
   보내기 전 안전 검사: `int` 이고 `bool` 아니고 `pid > 1`,
   `os.getpgid(pid) == pid`, `pgid != os.getpgid(0)`, `pgid != 0`.
2. **(결함 2, 중간)** 죽이기 전에 `/proc/<pid>/cmdline` 에 run id 또는 brief 경로 또는
   `fleet` 이 있는지 본다. 아무것도 없으면 **죽이지 않고** `.lost` 만 남기고 로그를 쓴다.
   `/proc` 이 없으면 이 검사를 건너뛴다.
3. **(결함 3, 중간)** `report_block_reason` 에 `(?![A-Za-z0-9_-])` 단어 경계,
   `NEEDS-` 뒤 최소 한 글자, `IGNORECASE` 는 `상태:`/`Status:` 접두가 있을 때만.
   벗겨 내는 접두에 `>`, `-`, `*`, `` ` ``, `[`, `]`, `숫자.` 추가.
4. **(결함 4·5, 낮음)** `_node_timeout` 이 `math.isfinite(x) and x > 0` 아니면 다음 후보로
   (`bool` 거부). `_check_timeout` 이 파싱과 뺄셈을 한 `try` 로 묶고 tz 를 naive 로 떨군다.
   `progress()` 도 같은 파서를 쓴다.
5. **(결함 6, 낮음)** 스폰 전 검증은 **`todo` 노드에만** 슬롯·소유권을 적용.
   `validate_graph(g)` 를 인자 없이 부르면 **예전 동작 그대로**.

## 반드시 다시 돌려라 (회귀 확인)

- **결함 1 재현을 그대로:** `bash -c "<자식>; echo $? > rc"` 꼴 래퍼를
  `start_new_session=True` 로 띄우고 `_kill_run` 뒤 **자식이 죽었는지** `pgrep -g <pgid>` 로.
- **안전 검사 8개 입력**(`None`/`0`/`-1`/`1`/`"123"`/`True`/`3.5`/`os.getpid()`)에
  아무도 죽지 않는지.
- **거짓 양성 6개 + 거짓 음성 6개 + 깨면 안 되는 7개**의 `report_block_reason` 결과 전부.
- `timeout_sec` = `nan`/`0`/`-1`/`True` 에 갓 띄운 작업자가 사는지.
- `started` = `'garbage'`/`None`/`''`/tz 붙은 값에 `step()` 과 `progress()` 가 둘 다 사는지.
- `done` + 명부 밖 슬롯 그래프에서 `cmd_step` 이 rc 2 가 **아닌지**,
  그리고 `cmd_validate` 는 **여전히 rc 2 인지**.
- 잠금 배타성·예외 중 해제·unlink 없음·`.lost` 덮어쓰지 않음·빈 그래프 무한 루프 없음·
  `_busy_slots`·고아 스폰 방지·원자적 저장·`_ready()` 의 모르는 dep 차단.

## 새 구멍을 노려라 (수정이 만들 수 있는 것)

- **`os.killpg` 가 관리자 자신을 죽일 수 있나.** 관리자 셸과 작업자가 **같은 pgid** 가 되는
  경우는? `os.getpgid(0)` 비교를 **어느 시점에** 하나? 경쟁 상태로 빠져나갈 길은?
- **`os.getpgid(pid) == pid` 검사가 정상 작업자를 거르나.** `fleet.py` 가 실제로
  `start_new_session=True` 로 띄우는지 **코드로** 확인하라. 아니면 이 검사가 타임아웃을
  통째로 무력화한다 - 그러면 고친 것이 아니라 **끈 것**이다.
- **`/proc/<pid>/cmdline` 검사의 거짓 음성.** `fleet.py` 가 브리프를 **argv 에 넣지 않고
  stdin/파일로** 넘긴다(`8.0-5`). 그러면 cmdline 에 run id 도 brief 경로도 **없을 수 있다.**
  `fleet` 문자열은 들어 있나? 실제 작업자 argv 를 `_worker_argv()` 로 만들어 확인하라.
  **없으면 타임아웃이 영영 아무도 못 죽인다.**
- **`cmdline` 이 읽기 권한 없음/빈 파일/널바이트 투성이일 때** 터지나.
- **단어 경계 정규식이 멀쩡한 상태를 흘리나.** `'BLOCKED: 이유'`(콜론), `'BLOCKED.'`,
  `'BLOCKED,'`, `'NEEDS-LOCK:'`, `'상태:BLOCKED'`(공백 없음), 전각 콜론 `'상태：BLOCKED'`.
- **`IGNORECASE` 를 좁히면서 잃은 것.** `'blocked'`(접두 없이 소문자)가 이제 `None` 인데
  그게 맞나? 실제 작업자(특히 kistillm)가 소문자로 쓸 가능성은?
- **`progress()` 가 같은 파서를 쓰면서** 예전에 잘 되던 정상 입력이 느려지거나 달라졌나.
- **`spawnable_only` 필터가 `running` 노드를 빼면서** 돌고 있는 작업자의 소유권 위반을
  영영 못 잡게 되지 않았나(그게 의도인가, 사고인가).
- **빈 그래프·노드 0개·`attempts` 빈 리스트**에서 새 코드가 `IndexError` 를 내나.

## 보고 형식

첫 줄 `상태: DONE`(검수 완료) 또는 `상태: BLOCKED`.
이어서 **두 묶음**으로 적어라.

**(1) 지난 결함 6건의 현재 상태** - 각각 `고쳐짐` / `부분` / **`안 고쳐짐`** / `끈 것`
(= 고친 게 아니라 기능이 안 돌게 된 것) 중 하나 + **재현 출력**.

**(2) 새 결함** - 아래 꼴로, 심각도 높은 것부터:

```
### 결함 N - <한 줄 제목>  [높음|중간|낮음]
- 어디: tools/fleet_graph.py <함수/행>
- 무엇이 틀렸나: (한 문단)
- 재현: (실제로 돌린 명령과 출력 그대로. "~할 것이다" 는 결함이 아니다)
- 고치는 방향: (한두 줄. 네가 고치지는 마라)
```

새 결함이 없으면 없다고 적고, 네가 돌린 적대적 시나리오를 명령과 출력으로 보여라.
