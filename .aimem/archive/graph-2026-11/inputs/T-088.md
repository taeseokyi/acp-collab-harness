## 목표

`tools/fleet_graph.py` 에 이번 라운드에 들어간 세 가지(**단일 실행자 잠금 · 노드 타임아웃 ·
보고 첫 줄 BLOCKED 판정**)를 **계약 테스트로 못박는다.** 지금 이 도구에는 테스트가 하나도 없고,
S4 적대적 검수가 결함 6건을 잡았는데 **스위트 217건이 전부 통과하는 중이었다.**

## 쓰기 경로

`tests/test_fleet_graph.py` **하나뿐이다.** 새 파일이다. 다른 파일은 읽기만 하라.
**`tools/fleet_graph.py` 를 고쳐서 테스트를 통과시키지 마라** - 어긋나면 보고 첫 줄을
`BLOCKED` 로 하고 무엇이 어긋나는지 적어라.

## (A) `graph_lock(gid)` - 단일 실행자 잠금

1. **배타성:** `graph_lock("G-900")` 을 잡은 채 **자식 프로세스**에서 같은 잠금을 잡으려 하면
   그 자식이 **rc 2** 로 끝나고 stderr 에 `다른 실행자가 잡고 있습니다` 와 **holder 의 pid** 가
   찍힌다. (`subprocess.run([sys.executable, "-c", ...])` 로 만들어라. 같은 프로세스 안에서
   두 번 잡는 것으로 대신해도 되지만, **자식 쪽이 진짜 계약**이다.)
2. **해제 뒤 재획득:** 바깥 `with` 를 빠져나온 뒤에는 자식이 **rc 0** 으로 잡는다.
3. **예외가 터져도 풀린다:** `with graph_lock(...)` 안에서 `RuntimeError` 를 던지고 밖에서
   잡은 뒤, 다시 잡을 수 있다. `SystemExit` 으로도 같은지 보라.
4. **잠금 파일을 지우지 않는다:** `with` 가 끝난 뒤에도 `<GRAPHS>/G-900.lock` 이 **존재한다.**
   (지우면 다음 실행자가 다른 inode 를 잡아 잠금이 무력해진다 - 이게 계약이다.)
5. **파일 내용:** 잡은 쪽이 `{"pid": <int>, "started": <ISO 문자열>, "cmd": <문자열>}` 을 쓴다.
   `pid` 는 `os.getpid()` 와 같다. 옛 내용이 길어도(예: `"x"*500` 을 미리 써 둠)
   **잔재가 남지 않는다**(= 읽은 JSON 이 깨지지 않는다).
6. **경로 구분자 거부:** `gid` 가 `"a/b"`·`".."`·`""` 면 잠금을 잡지 않고 터진다
   (`ValueError` 또는 `SystemExit`. **무엇이든 `<GRAPHS>` 밖에 파일이 생기면 안 된다**).

## (B) `report_block_reason(report)` - 보고 첫 줄 판정

표 하나(`list[tuple[입력, 기대]]`)로 돌리고 `subTest` 를 써라.

**`None` 이어야 하는 것 (거짓 양성 금지 - blocked 는 재시도가 없어 복구가 사람 손이다):**
```
''                               None            (빈 문자열)
None                             None
'   \n\n  '                      None            (공백만)
'상태: DONE'                      None
'PARTIAL'                        None
'상태: DONE - BLOCKED 되었던 것을 풀었다'   None
'DONE (이전 시도는 NEEDS-LOCK)'    None
'상태: DONE\nBLOCKED'             None            (둘째 줄은 안 본다)
'## 보고\n상태: BLOCKED'           None            (첫 줄만 본다 - 의도된 동작)
'Rejected 된 항목 없음, 모두 통과'  None            (단어 경계)
'REJECTED_FIX 적용 완료'          None
'Blocked 링크 3개를 풀었다'        None
'BLOCKED-FREE 빌드 성공'          None
'NEEDS-'                         None            (뒤에 글자가 있어야 한다)
```

**잡아야 하는 것:**
```
'BLOCKED'                        'BLOCKED'
'상태: BLOCKED - 이유'            'BLOCKED'
'**NEEDS-LOCK** 경로'             'NEEDS-LOCK'
'\n\n# NEEDS-APPROVAL x'         'NEEDS-APPROVAL'
'REJECT - y'                     'REJECT'
'> BLOCKED'                      'BLOCKED'
'1. BLOCKED'                     'BLOCKED'
'- BLOCKED'                      'BLOCKED'
'`BLOCKED`'                      'BLOCKED'
'[BLOCKED]'                      'BLOCKED'
'상태: `BLOCKED`'                 'BLOCKED'
'Status: BLOCKED'                'BLOCKED'
'상태: blocked - 소문자'           'BLOCKED'       (`상태:` 접두가 있으면 대소문자 무시)
```

**매우 긴 첫 줄**(`'BLOCKED' + 'x'*100000`)에도 터지지 않고 `'BLOCKED'` 를 준다.

> 위 표가 **현재 구현과 어긋나면 테스트를 현재 동작에 맞추지 말고 `BLOCKED` 로 보고하라.**
> 이 표가 계약이다.

## (C) `step()` 의 완료 판정 - rc 0 이어도 BLOCKED 면 `done` 이 아니다

가짜 run 기록으로 만든다. `fleet._run_state` 와 `fleet.run_report` 를 patch 하는 쪽이 쉽다.

1. `rc == 0` + 보고 첫 줄이 `상태: BLOCKED - 이유` → 노드가 **`blocked`**, 시도 횟수가
   **1 에서 늘지 않는다**(재시도 없음), attempt 에 `report_status` 가 남는다.
2. `rc == 0` + 보고 첫 줄이 `상태: DONE` + `verify` 없음 → 노드가 **`done`**.
3. BLOCKED 판정이 **검증보다 세다:** `verify` 를 `"false"`(항상 rc 1)로 두어도
   보고가 BLOCKED 면 결과는 `blocked` 다(`failed` 가 아니다).
4. 의존 노드 연쇄: `blocked` 노드에 의존하는 `todo` 노드는 다음 틱에 **`blocked`** 가 된다.

## (D) 노드 타임아웃

**실제 프로세스를 죽이는 테스트는 만들지 마라.** `_kill_run`(또는 같은 일을 하는 함수)을
patch 해 "죽이라고 불렸는지"만 보라.

1. **한도 선택 순서:** `n["timeout_sec"]` → `g["node_timeout_sec"]` → **1800**.
   세 경우를 각각 확인하라(함수가 `_node_timeout` 이면 그것을 직접 불러도 된다).
2. **불량값은 버린다:** `timeout_sec` 이 `float("nan")`·`0`·`-1`·`True`·`"abc"` 면
   그 후보를 **버리고 다음 후보**로 간다. 결과적으로 **갓 띄운 작업자(시작 1초 전)가
   죽지 않는다.**
3. **넘으면 처리한다:** `started` 가 한참 전이고 한도가 짧으면 - attempt 에
   `rc == 124`, `state == "timeout"`, `timeout is True` 가 붙고, `.lost` 마커가 생기며,
   `max_attempts` 안이면 노드가 **`todo`**(재시도), 넘으면 **`failed`**.
4. **`.lost` 를 덮어쓰지 않는다:** 이미 `{"ended": "2026-11-10T01:02:03"}` 인 마커가 있으면
   타임아웃 처리 뒤에도 **그 값 그대로**다.
5. **`started` 가 깨져도 죽지 않는다:** `'garbage'`·`None`·`''`·
   `'2026-11-10T09:00:00+09:00'`(tz 붙음) 네 경우에 `step()` 과 `fleet_graph.progress()` 가
   **둘 다 예외를 던지지 않는다.** 그리고 작업자를 **죽이지 않는다**(patch 한 kill 이 안 불린다).

## (E) 시작 전 모양 검증

1. `cmd_step` / `cmd_run` 이 **DAG 모양이 깨진 그래프**(사이클, 모르는 dep)에서
   **rc 2** 로 끝나고 **스폰이 한 번도 일어나지 않는다**(`fleet.cmd_spawn` patch 가 안 불린다).
2. **끝난 그래프는 막히지 않는다:** 노드가 `status="done"` 이고 `slot="S9"`(명부에 없음)
   하나뿐인 그래프에서 `cmd_step` 이 **rc 2 가 아니다.**
3. `validate_graph(g)` 를 **인자 없이** 부르면 예전 동작 그대로다 - `done` 노드의
   명부 밖 슬롯도 문제로 **잡는다**(`cmd_validate`/`cmd_new` 가 이것을 쓴다).
