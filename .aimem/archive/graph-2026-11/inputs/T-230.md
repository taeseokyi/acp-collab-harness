# T-230 '프로젝트 칸의 볼드 기준' 검사도 **임시 저장소**에서 돌게 고치십시오

고칠 파일은 **`tests/browser_monitor_ui.py` 하나**입니다. 제품 코드(`tools/aimem_monitor/**`)는
**읽기만 하고 절대 고치지 마십시오.**

## 무엇이 문제인가 (관리자가 실측함)

`프로젝트 칸의 볼드 기준` 검사(264행 근처)가 **진짜 저장소의 작업자 실행 기록**을 봅니다.

```python
page.click("#tab-fleet")
page.wait_for_selector("#runs-table-wrap", state="visible", timeout=15000)
project_names = page.query_selector_all("#runs-table-wrap .proj-tag:not(.none) .proj-name")
none_names    = page.query_selector_all("#runs-table-wrap .proj-tag.none .proj-name")
rounds        = page.query_selector_all("#runs-table-wrap .proj-round")
...
bool(project_names) and bool(none_names) and bool(rounds) and ...
```

실행 표는 **최근 20건**만 보입니다. 지금은 그 20건이 전부 함대 자체의 일(`project` 가 빈 값)이라
`.proj-tag:not(.none)` 이 **0개**가 되어 검사가 빨갛습니다.

```
[FAIL] 프로젝트 칸의 볼드 기준 - 프로젝트 이름 [], 프로젝트 없음 [400 × 20], 라운드 꼬리표 [400 × 20]
```

제품은 멀쩡합니다. 검사가 **그때그때의 실행 기록**에 기대고 있는 것이 문제입니다. 프로젝트 일을 한
라운드가 지나가면 초록이 됐다가 함대 일만 한 라운드가 지나가면 빨개집니다.

## 고칠 내용

바로 앞 라운드에서 `graph_title_expand_scenario` 를 고친 것과 **같은 방식**입니다 - 임시 저장소를
만들고 `monitor_server(root=temp_root)` 로 띄웁니다. 이미 `write_fixed_requests` 와
`write_fixed_graph` 두 도우미가 그 본을 보여 줍니다(327행·344행 근처). `main()` 아래쪽의
`tempfile.TemporaryDirectory()` 블록도 보십시오.

1. **고정 실행 기록을 쓰는 도우미를 더하십시오.**

   ```python
   def write_fixed_runs(root):
       """프로젝트가 붙은 실행과 안 붙은 실행을 임시 저장소에 하나씩 씁니다."""
   ```

   - 쓸 곳은 `root / ".aimem" / "runs"` 입니다. 실행 하나는 `<id>.json` 과 `<id>.rc` 두 파일입니다
     (`.rc` 가 없으면 아직 도는 것으로 봅니다 - `0\n` 을 쓰십시오)
   - `<id>.json` 의 꼴은 진짜 저장소의 `.aimem/runs/*.json` 과 같습니다. 필요한 칸:

     ```json
     {"id": "T-901-S3-a1-000001", "slot": "S3", "harness": "opencode", "task": "T-901",
      "attempt": 1, "date": "2026-11-01", "label": "임시 실행 (프로젝트 있음)", "rev": 159,
      "write": [], "started": "2026-11-01T00:00:01", "project": "데모프로젝트", "round": 9}
     ```

   - **둘을 쓰십시오.** 하나는 `"project": "데모프로젝트"`, 다른 하나는 `"project": ""`
     (둘 다 `"round": 9`). 그래야 `.proj-tag`·`.proj-tag.none`·`.proj-round` 셋이 다 생깁니다
   - `"pid"` 는 **넣지 마십시오**(살아 있는 프로세스를 찾으려 합니다)

2. **그 검사만 떼어 새 시나리오로 옮기십시오.**

   ```python
   def run_project_tag_scenario(browser, base, checks):
       """임시 저장소의 고정 실행 기록으로 프로젝트 칸의 볼드 기준을 잽니다."""
   ```

   지금 264~273행에 있는 `checks.ok("프로젝트 칸의 볼드 기준", …)` 와 그 바로 위의
   `page.click("#tab-fleet")` ~ `round_weights = …` 까지(252~263행)를 **그대로** 이 함수로 옮깁니다.
   판정 식과 글귀는 **한 글자도 바꾸지 마십시오.** 원래 있던 시나리오에서는 그 토막을 지웁니다
   (그 시나리오의 **다른 검사들은 그대로 두십시오** - 뒤에 이어지는 `page.set_viewport_size(...)`
   부터는 손대지 않습니다. 옮기면서 그 뒤 코드가 기대하던 뷰포트·탭 상태가 달라지지 않는지
   **돌려 보고 확인하십시오**).

3. `main()` 의 임시 저장소 블록에서 `write_fixed_runs(temp_root)` 를 부르고
   `run_project_tag_scenario(browser, temp_base, checks)` 를 부르십시오
   (`write_fixed_graph` 와 같은 블록을 써도 되고 따로 두어도 됩니다).

## 하지 말 것

- 검사를 느슨하게 만들지 마십시오. `bool(project_names) and bool(none_names) and bool(rounds)` 와
  볼드 기준(`>= 700` / `<= 500`)을 그대로 두십시오
- 진짜 `.aimem/runs/` 에 파일을 쓰지 마십시오 - **임시 폴더에만** 씁니다
- 다른 시나리오를 고치지 마십시오. 검사 수는 **줄지 않아야** 합니다
