## 지금 동작 (적대적 검수가 찾은 결함 셋)

`_audit_denied` 는 거절 한 건을 `.aimem/access.log` 에 한 줄 남깁니다. 같은 키가 60초 안에 또 오면 삼키고
(`_REVOKED_AUDIT_MIN_SEC`), 분당 전체 60줄이 넘으면 더 안 씁니다(`_DENIED_AUDIT_MAX_PER_MIN`).

- **N1 (중간, 제일 급함).** 키를 고를 때 `has_subject = bool(subject) and subject != "-"` 면 경로를 키에
  넣습니다: `key = (event, subject, safe_path, safe_method)`. 그런데 `app-ticket-bad` 를 남길 때 넘어오는
  `subject` 는 **URL 에 든 티켓에서 푼 값**이지 요청자를 인증한 결과가 아닙니다. 그래서 쿠키 없는 공격자가
  티켓 하나(만료된 것도 됨)를 들고 경로만 바꿔 가며 300번 보내면 키가 300개 생겨 **분당 60줄 상한을 혼자
  채웁니다.** 그동안 허용 목록에서 지워진 계정의 진짜 시도는 **한 줄도 안 남습니다**(실측: 30분·150회 시도 →
  0줄). 줄에는 티켓 주인의 `gh:kim` 이 찍혀 주인이 공격자로 보입니다.
- **N1-b.** 상한에 걸려 **쓰지 않은** 경우에도 그 앞에서 이미 `_revoked_last[key] = (now, 0, first_path)` 로
  "방금 기록함" 표시를 해 둡니다. 그래서 그 키는 이후 60초 동안 키 억제까지 받아, 매 분 상한이 차 있으면
  영원히 안 남습니다.
- **N2 (낮음).** `생략 N건` 숫자가 **그 키의 것이 아니라 전역 합계**(`_denied_key_skipped + _denied_cap_skipped`)
  입니다. kim 의 억제 10건이 엉뚱한 `token-bad` 줄에 `생략 10건` 으로 실립니다. 키별로 세어 둔
  `rec[1]` 은 늘리기만 하고 읽지 않는 죽은 값입니다. 홍수가 끝나고 남은 숫자는 어디에도 안 남습니다.
- **N3 (낮음).** `first_path = rec[2] if rec is not None else safe_path` 가 **1분 창이 지난 뒤에도** 옛
  레코드의 경로를 이어받습니다. 그래서 그 키의 줄은 서버가 떠 있는 내내 **맨 처음 본 경로**를 적습니다.
  공격자가 무해한 경로를 한 번 먼저 보내 두면 진짜 표적 경로는 감사에 한 번도 안 나옵니다.

## 고칠 내용 (이대로 하십시오)

### 1) `_audit_denied` 에 `authenticated=False` 인자를 더합니다

```python
def _audit_denied(root, event, ip, subject, path, method="GET", reason="", authenticated=False):
```

`authenticated=True` 는 **서버가 요청자를 인증해서 얻은 주체**일 때만 줍니다. 호출하는 자리는 딱 둘입니다.

- `_audit_revoked(...)` 안의 `_audit_denied(root, "github-revoked", ...)` → `authenticated=True`
- `"주체 불일치"` 를 남기는 자리 (넘기는 주체가 `credential_subject = self._subject()` 인 곳) → `authenticated=True`

나머지 호출 자리(`app-ticket-bad` 의 `형식`·`주체 못 찾음(회수 또는 위조)`·`서명·만료`·`무주체`,
`token-bad`, `session-bad`)는 **건드리지 마십시오**(기본값 `False`).

### 2) 키 고르는 규칙

```python
has_subject = bool(subject) and subject != "-"
if has_subject and authenticated:
    key = (event, subject, safe_path, safe_method)   # 인증된 주체만 경로를 키에 넣는다
elif has_subject:
    key = (event, subject, safe_method)              # URL 이 주장한 주체 - 경로를 빼서 키를 못 늘리게 (N1)
else:
    key = (event, "-", safe_method)
```

### 3) 레코드를 2칸으로 줄이고, 기록한 경우에만 갱신합니다

`_revoked_last[key]` 를 `(마지막으로 기록한 시각, 그 뒤 삼킨 건수)` **2칸 튜플**로 바꿉니다
(`first_path` 세 번째 칸은 없앱니다 - N3). 잠금 안의 흐름을 아래 순서로 바꾸십시오.

```python
    dropped = 0
    with _revoked_lock:
        if not _revoked_last:
            _denied_window_start = now
            _denied_window_written = 0
            _denied_cap_skipped = 0
        rec = _revoked_last.get(key)
        if rec is not None and now - rec[0] < _REVOKED_AUDIT_MIN_SEC:
            _revoked_last[key] = (rec[0], rec[1] + 1)      # 그 키의 건수로 센다 (N2)
            _revoked_last.move_to_end(key)
            return
        if now - _denied_window_start >= 60:
            _denied_window_start = now
            _denied_window_written = 0
            dropped = _denied_cap_skipped                   # 창이 바뀌며 버린 건수를 털어 낸다 (N2)
            _denied_cap_skipped = 0
        if _denied_window_written >= _DENIED_AUDIT_MAX_PER_MIN:
            _denied_cap_skipped += 1
            return                                          # 안 썼으므로 rec 을 갱신하지 않는다 (N1-b)
        _denied_window_written += 1
        skipped = rec[1] if rec is not None else 0
        _revoked_last[key] = (now, 0)
        _revoked_last.move_to_end(key)
        while len(_revoked_last) > _REVOKED_AUDIT_MAX:
            _revoked_last.popitem(last=False)
    detail = f"{safe_method} {safe_path}"                    # 지금 요청의 경로를 쓴다 (N3)
    if skipped:
        detail += f" 생략 {skipped}건"
    if reason:
        detail += f" {reason}"
    if dropped:
        audit(root, "audit-dropped", "-", None, f"상한 생략 {dropped}건")
    audit(root, event, ip, subject, detail)
```

`global` 줄에서 `_denied_key_skipped` 를 빼고, 649행 근처의 모듈 전역 `_denied_key_skipped = 0` 도 지우십시오
(이제 쓰는 데가 없습니다). `_denied_cap_skipped` 는 남깁니다.
창이 막 열린 직후에는 `_denied_window_written == 0` 이므로 `dropped > 0` 인 경우에 상한에 걸릴 수는 없습니다 -
`dropped` 를 잃지 않습니다.

### 4) 함수 docstring 을 바뀐 규칙에 맞게 두세 줄로 고치십시오
