# T-226 적대적 검수가 찾은 **시험 구멍**을 메우십시오 (N9 중간 · M10)

고칠 파일은 **`tests/test_monitor_ticket_regress.py` 하나**입니다. 제품 코드
(`tools/aimem_monitor/server.py`)는 **읽기만 하고 절대 고치지 마십시오.**

## 무엇이 문제인가 (검수가 실측한 것)

이번 라운드가 `_audit_denied` 의 **가장 무거운 결함(N1)** 을 고쳤습니다. 핵심은 **URL 이 주장한 티켓
주체를 인증된 주체로 치지 않는 것**(키에서 경로를 뺌)입니다. 그런데 **그 수정을 되돌려도 시험이 전부
초록**입니다.

- **M1**: `_audit_denied` 의 `authenticated` 를 늘 `True` 로 → 시험 **0건 빨강**
- **M2**: `elif has_subject:` 가지의 키에 `safe_path` 를 다시 넣음 → 시험 **0건 빨강**
- **M11**: `주체 불일치` 자리의 `authenticated=True` 를 지움 → 시험 **0건 빨강**

세 변이 중 아무거나 넣고 가상 30분을 돌리면, 회수된 계정의 시도는 다시 **0줄**이 됩니다(수정 전과 같음).

**왜 못 잡나.** 지금 있는 `test_ticket_subject_cannot_grow_the_audit_keys` 가 태그 자리를
`'a' * 12` 로 채운 **가짜 티켓**을 씁니다. 그러면 `app_ticket_resolve` 가 주체를 못 찾아 주체가 `None` 이
되고, `(event, "-", method)` 쪽 키를 탑니다 - **고친 갈래를 아예 안 지납니다.**

그리고 **M10**(창이 바뀌어도 상한 생략 수를 0 으로 안 돌림 = 같은 수를 두 번 싣기)도 못 잡습니다.

AIMEM.md 와 검수 문서는 읽지 마십시오.

## 더할 시험 (넷)

`mint_ticket("kim")` 은 `/app/~<만료>.<태그>.<mac>/알파/` 꼴의 **진짜** 티켓 경로를 돌려줍니다.
그 티켓 칸을 그대로 쓰되 **앱 이름을 `베타`(없는 이름)로 바꿔** 보내면, 주체는 `gh:kim` 으로 풀리고
mac 만 안 맞아 `app-ticket-bad … 서명·만료` 가 됩니다 - **이것이 고친 갈래**입니다.

1. `test_real_ticket_subject_cannot_grow_the_audit_keys` (M1 · M2 를 빨갛게)
   `mint_ticket("kim")` 으로 받은 티켓 칸을 꺼내, 쿠키 없이 `/app/~<티켓>/베타/z{i}` 를
   **i=0..199** 로 보냅니다(모두 403). 늘어난 감사 줄이 **5줄 이하**여야 합니다.
   덧붙여, 그 줄 가운데 적어도 하나에 `gh:kim` 이 주체 칸으로 들어 있는지도 확인하십시오
   (주체는 살아 있고 **경로만** 키에서 빠졌다는 뜻).

2. `test_a_revoked_account_is_still_audited_during_a_ticket_flood` (M1 · M2 를 빨갛게)
   1번과 같은 홍수를 200번 보낸 **뒤**, `revoke_all()` 로 허용 목록을 비우고
   `self.get("/api/state", self.github_headers("lee"))` 를 한 번 보냅니다.
   `audit_event_lines("github-revoked")` 가 **한 줄 이상 늘어야** 합니다.
   (고치기 전에는 0줄이었습니다. `revoke_all` 뒤에는 `mint_ticket` 이 안 되니 **순서를 지키십시오**.)

3. `test_credential_subject_mismatch_keeps_the_path_in_the_key` (M11 을 빨갛게)
   `mint_ticket("kim")` 으로 kim 의 티켓을 받은 뒤, **lee 의 세션 쿠키**(`github_headers("lee")`)를 달고
   그 티켓 경로로 서로 다른 경로 **다섯 개**(`.../알파/a`, `.../알파/b`, …)를 보냅니다 → `주체 불일치`.
   이 갈래는 **인증된 주체**라 키에 경로가 들어 있으므로, 늘어난 감사 줄이 **3줄 이상**이어야 합니다
   (경로마다 따로 남는다는 뜻). `M11` 처럼 `authenticated=True` 가 빠지면 1줄로 줄어 빨개집니다.

4. `test_cap_skipped_count_is_reported_only_once` (M10 을 빨갛게)
   `server._audit_denied` 를 **직접** 불러 상한을 채웁니다(주체를 `gh:user{i}` 로 바꿔 가며
   `_DENIED_AUDIT_MAX_PER_MIN + 20` 번, `authenticated=True`). 그 뒤
   `server._denied_window_start` 를 `time.time() - 61` 로 밀고 새 주체로 한 번 부릅니다 →
   `audit-dropped` 줄이 하나 생깁니다. **다시** 창을 61초 밀고 또 새 주체로 한 번 부릅니다 →
   이번에는 `audit-dropped` 줄이 **더 생기지 않아야** 합니다(또는 생기더라도 수가 0 이어야 합니다).
   `audit-dropped` 줄의 숫자 합이 **상한으로 버린 실제 건수와 같은지**도 확인하십시오.

## 지킬 것

- 이미 있는 시험을 지우거나 고치지 마십시오. **더하기만** 하십시오
  (약한 `test_ticket_subject_cannot_grow_the_audit_keys` 도 그대로 둡니다)
- 실제 시각을 기다리지 마십시오. `server._denied_window_start` 를 직접 밀거나
  `mock.patch.object(server, "_REVOKED_AUDIT_MIN_SEC", 0.1)` 를 쓰십시오.
  더하는 넷이 **합쳐서 10초 안에** 끝나야 합니다
- 시험이 제품의 결함을 찾으면 제품도 시험도 고치지 말고, 보고 첫 줄을
  `NEEDS-FIX: <무엇이 어디서>` 로 쓰고 멈추십시오
