## 목표

`tools/fleet_graph.py` 에 남은 결함 3건(`AIMEM.md` `4.5` 대기 큐 7·8·9번)을 고친다.
S4 적대적 검수가 **두 라운드째** 지적한 항목이다.

## 쓰기 경로

`tools/fleet_graph.py` **하나뿐이다.** 다른 파일은 읽기만 하라 - 테스트 파일도 만들지 마라
(테스트는 다른 슬롯 소유다).

## 지금 코드에서 알아야 할 것

- `step(g, concurrency)` 가 스케줄러 한 틱이다: (1) `running` 노드를 거두어 `_verify()` 하고
  `rc==0 && verify_rc==0` 이면 `done`, 아니면 `max_attempts` 까지 재시도, (2) 의존이 실패한
  노드를 `blocked`, (3) `_ready()` 중 슬롯이 안 바쁜 것을 `_spawn_node()` 로 띄운다.
- `cmd_run(a)` 은 `step()` 을 `--poll` 초 간격으로 타임아웃까지 반복한다.
- 실행 상태는 `fleet._run_state(run_id) -> (state, rc)`, 메타는 `fleet._run_meta(run_id)`
  (딕셔너리에 `pid`, `slot`, `harness`, `started` 가 들어 있다), 보고 본문은 `fleet.run_report(run_id)`.
- `_save(g)` 는 이미 원자적이다(tmp + `os.replace`). 그 구조를 깨지 마라.
- `TERMINAL = ("done", "failed", "blocked")` 이고 `cmd_run` 의 종료 조건이 이것을 본다.

## (A) 큐 7번 - 단일 실행자 잠금

**지금 무엇이 틀렸나.** `run` 이 도는 중에 다른 터미널에서 `step` 이나 `run` 을 또 치면
**같은 노드를 두 번 띄운다.** 실측에서 한 노드에 run 3개가 붙었다
(`[('A','S1','fake-1'), ('A','S1','fake-2'), ('A','S1','fake-3')]`).

**고칠 모양.**

- `contextlib.contextmanager` 로 `graph_lock(gid)` 를 만든다. 이름을 정확히 이렇게 써라 -
  검수와 다음 라운드가 이 이름을 부른다.
- 잠금 파일은 `.aimem/graph/<gid>.lock` 이고 `fcntl.flock(fd, LOCK_EX | LOCK_NB)` 를 쓴다.
- **못 잡으면 스폰하지 말고** stderr 에
  `그래프 <gid> 를 다른 실행자가 잡고 있습니다 (pid <n>, 시작 <시각>, cmd <run|step>)`
  를 찍고 **rc 2 로** 끝낸다. pid·시작·cmd 는 잠금 파일 내용에서 읽는다(못 읽으면 `?`).
- 잡은 **뒤에** 파일 내용을 `{"pid": …, "started": "<ISO>", "cmd": "run"|"step"}` JSON 으로 쓴다
  (`os.ftruncate` 로 비우고 쓰고 `flush`).
- **죽은 pid 는 저절로 회수된다** - `flock` 은 프로세스가 죽으면 커널이 푼다. 그러니
  pid 생존 검사를 따로 만들지 마라. 그리고 **잠금 파일을 `unlink` 하지 마라** - 지우면
  다음 실행자가 다른 inode 를 잡아 잠금이 무력해진다. 빠져나올 때는 `flock(LOCK_UN)` 과 `close` 만.
- 거는 범위는 `cmd_run` 과 `cmd_step` 의 **전체**다. `validate`/`status`/`list` 는 읽기 전용이니 걸지 않는다.

## (B) 큐 8번 - 모양 검증 재사용 + 노드별 타임아웃

**B-1 (모양 검증 재사용).** `step()` 은 `validate_graph()` 를 다시 돌리지 않는다. 손으로 고친
그래프의 오타(없는 dep, 명부 밖 슬롯, 소유가 아닌 쓰기 경로)가 `step` 에서야 드러난다.

- `cmd_step` 과 `cmd_run` 이 **스케줄을 시작하기 전에 한 번** `validate_graph(g)` 를 돌린다.
  문제가 있으면 한 줄씩 찍고 **rc 2** 로 끝낸다(스폰 없음).
- `step()` **안에서** 매 틱 돌리지는 마라 - 수십 분 도는 루프다.

**B-2 (노드별 타임아웃).** 지금은 작업자가 영영 안 끝나면 `run` 이 `--timeout` 전체를 쓴다.

- 노드별 한도는 `n["timeout_sec"]` → 없으면 `g.get("node_timeout_sec")` → 없으면 **1800** 이다.
- `step()` 의 **거두기 단계**에서, 아직 `running` 인 노드의 `attempts[-1]["started"]`
  (ISO 문자열)로부터 경과가 한도를 넘으면:
  1. `fleet._run_meta(run_id)` 에서 `pid` 를 읽어 `os.kill(pid, signal.SIGTERM)`.
     5초 기다려도 살아 있으면(`os.kill(pid, 0)` 이 안 터지면) `SIGKILL`.
     **pid 가 없거나 이미 죽었으면(`OSError`) 그냥 넘어간다.**
     **`pkill -f` 를 절대 쓰지 마라** - `AIMEM.md` `8.0-5` 주의: 그 명령으로 작업자가
     자기 자신을 죽인 사례가 있다. pid 로만 지목한다.
  2. `.aimem/runs/<run_id>.lost` 가 없으면 `{"ended": "<ISO 현재>"}` 로 만든다
     (`fleet.py` 가 lost 판정과 경과 고정에 쓰는 마커다. `fleet.RUNS` 를 쓰라).
  3. 그 attempt 에 `"ended"`, `"rc": 124`, `"state": "timeout"`, `"timeout": true` 를 적는다.
  4. 재시도 한도(`max_attempts`) 규칙은 **기존 실패와 똑같이** 탄다
     (한도 안이면 `todo`, 넘으면 `failed`).
  5. 로그 한 줄: `timeout <node> after <n>s (run <id>, pid <p>)`.
- 경과 계산에 쓸 시각이 깨져 있으면(`fromisoformat` 실패) 타임아웃 판정을 **건너뛴다** -
  멀쩡한 작업자를 죽이는 쪽이 더 나쁘다.

## (C) 큐 9번 - rc 0 이어도 보고가 BLOCKED 면 `done` 이 아니다

**지금 무엇이 틀렸나.** 완료 판정이 `rc==0 && verify_rc==0` 뿐이다. 작업자가
`상태: BLOCKED - 소유가 아닌 경로가 필요하다` 라고 보고하고 **깨끗이 종료하면 `done` 이 된다.**
`AIMEM.md` `0.3` 상 보고의 **첫 줄**이 상태다.

- `report_block_reason(report) -> str | None` 를 **모듈 최상위 함수로** 따로 만든다.
  이름을 정확히 이렇게 써라(검수가 이것을 부른다).
  - 보고의 **첫 비어 있지 않은 줄**만 본다.
  - 그 줄 앞의 `상태:` / `**` / `#` / 공백은 벗겨 낸다. 대소문자는 무시한다.
  - 벗긴 뒤 `BLOCKED`, `NEEDS-LOCK`, `NEEDS-APPROVAL`, `NEEDS-` 로 시작하는 다른 말,
    `REJECT` 중 하나로 **시작하면** 그 말(대문자)을 돌려준다. 아니면 `None`.
  - `DONE` / `PARTIAL` / 그 밖의 첫 줄은 `None` 이다(지금 동작 그대로).
- `step()` 의 거두기에서 `rc == 0` 일 때 `fleet.run_report(run_id)` 를 이 함수에 통과시킨다.
  (이미 `att["report"]` 에 받아 두고 있으니 그 값을 쓰면 된다.)
  - `None` 이 아니면 **`done` 으로 만들지 않는다.** 노드 상태를 `blocked` 로 두고
    **재시도하지 않는다** - 사람이 풀어야 할 일이다(`AIMEM.md` `8.0-4-3`).
  - attempt 에 `"report_status": "<잡은 말>"` 을 남기고 로그에
    `BLOCKED <node> - <첫 줄 60자>` 를 쓴다.
  - 검증(`_verify`)은 이 경우 돌리지 않아도 된다(돌려도 무방하나 판정은 `blocked` 가 이긴다).

## 재현해서 보고에 붙일 것

**실제 `.aimem/graph/` 를 건드리지 말고** 임시 디렉터리로 `fleet_graph.GRAPHS` 를 바꿔
잠금을 재현하라. 예:

```
python3 -c "
import sys, pathlib, tempfile, subprocess, textwrap
sys.path.insert(0,'tools'); import fleet_graph as fg
d = pathlib.Path(tempfile.mkdtemp()); fg.GRAPHS = d
child = textwrap.dedent('''
    import sys, pathlib
    sys.path.insert(0,'tools'); import fleet_graph as fg
    fg.GRAPHS = pathlib.Path(sys.argv[1])
    with fg.graph_lock('G-900'):
        print('child got the lock - WRONG')
''')
with fg.graph_lock('G-900'):
    r = subprocess.run([sys.executable,'-c',child,str(d)], capture_output=True, text=True)
    print('child rc =', r.returncode)
    print('child stderr =', r.stderr.strip())
"
```

`child rc = 2` 와 "다른 실행자가 잡고 있습니다" 메시지가 나와야 한다.
`report_block_reason` 도 한 줄로 재현하라:
`BLOCKED`, `상태: BLOCKED - 이유`, `**NEEDS-LOCK** 경로`, `상태: DONE` 네 입력의 결과를 찍어라.

## 보고

첫 줄은 `상태: DONE` / `PARTIAL` / `BLOCKED` 중 하나. 이어서
(1) A·B-1·B-2·C 각각 무엇을 어떻게 고쳤는지 한 문단씩,
(2) 위 완료 판정 명령들과 재현 두 가지의 **출력을 그대로** 붙여라(요약 금지),
(3) 못 한 것이 있으면 어느 항목인지 번호로 적어라.
