# T-148 웹워들 하드 모드 검사를 엄하게 만드십시오

**고칠 파일은 `projects/웹워들/web/js/game.js` 하나뿐입니다.** 고칠 함수도 하나 - `hardModeViolation`
(74행 근처) 입니다. 다른 함수·다른 파일은 건드리지 마십시오.

## 지금 코드 (74~93행)

```js
export function hardModeViolation(guess, rows) {
  const g = String(guess).toLowerCase();
  for (const row of rows || []) {
    const prev = String(row.guess).toLowerCase();
    for (let i = 0; i < prev.length; i++) {
      if (row.scores[i] === CORRECT && g[i] !== prev[i]) {
        return `${i + 1}번째 글자는 ${prev[i].toUpperCase()} 이어야 합니다`;
      }
    }
  }
  for (const row of rows || []) {
    const prev = String(row.guess).toLowerCase();
    for (let i = 0; i < prev.length; i++) {
      if (row.scores[i] === PRESENT && !g.includes(prev[i])) {
        return `${prev[i].toUpperCase()} 가 들어가야 합니다`;
      }
    }
  }
  return null;
}
```

`CORRECT`·`PRESENT` 는 이 파일 위쪽에 이미 있는 상수입니다(문자열). `row.scores` 는 다섯
칸짜리 배열이고 값은 `CORRECT`/`PRESENT`/`ABSENT` 중 하나입니다.

## 못 보고 있는 것 셋

1. **노랑이 몇 개 드러났는지를 안 봅니다.** `aroma` 를 쳐서 두 `a` 가 모두 노랑이면 답에
   `a` 가 둘 이상인데, 다음 추측에 `a` 가 하나만 있어도 지금은 통과합니다
2. **같은 자리에 다시 놓는 것을 안 봅니다.** 3번째 자리의 `r` 이 노랑이면 답의 `r` 은
   3번째 자리가 **아니라는** 뜻인데, 다음 추측에서 또 3번째에 `r` 을 놓아도 통과합니다
3. 안내 문구가 두루뭉술합니다

## 바꿔 넣을 코드

`hardModeViolation` 전체를 아래로 **바꿔 넣으십시오**(함수 이름·`export`·인자는 그대로).
그 위의 `// NYT 와 같이 ...` 주석 줄도 아래 주석으로 바꿉니다.

```js
// 초록 자리 -> 노랑 개수 -> 노랑 자리 되놓기 순으로 봅니다 - 안내가 더 구체적인 쪽이 먼저 나오게.
export function hardModeViolation(guess, rows) {
  const g = String(guess).toLowerCase();
  const prevRows = (rows || []).map((row) => ({
    word: String(row.guess).toLowerCase(),
    scores: row.scores,
  }));

  // 1. 초록 자리는 그대로 두어야 합니다.
  for (const { word, scores } of prevRows) {
    for (let i = 0; i < word.length; i++) {
      if (scores[i] === CORRECT && g[i] !== word[i]) {
        return `${i + 1}번째 글자는 ${word[i].toUpperCase()} 이어야 합니다`;
      }
    }
  }

  // 2. 글자마다 "최소 몇 개" 가 드러났는지 - 한 줄에서 초록+노랑을 세고 줄 사이에서는 큰 쪽을 남깁니다.
  const need = {};
  for (const { word, scores } of prevRows) {
    const seen = {};
    for (let i = 0; i < word.length; i++) {
      if (scores[i] === CORRECT || scores[i] === PRESENT) {
        seen[word[i]] = (seen[word[i]] || 0) + 1;
      }
    }
    for (const ch of Object.keys(seen)) {
      if (!need[ch] || seen[ch] > need[ch]) need[ch] = seen[ch];
    }
  }
  for (const ch of Object.keys(need)) {
    let have = 0;
    for (const c of g) if (c === ch) have++;
    if (have < need[ch]) {
      const n = need[ch];
      return n === 1
        ? `${ch.toUpperCase()} 가 들어가야 합니다`
        : `${ch.toUpperCase()} 가 ${n}개 들어가야 합니다 (지금 ${have}개)`;
    }
  }

  // 3. 노랑이었던 자리에 같은 글자를 다시 놓을 수 없습니다 - 그 자리가 아니라는 것을 이미 알았습니다.
  for (const { word, scores } of prevRows) {
    for (let i = 0; i < word.length; i++) {
      if (scores[i] === PRESENT && g[i] === word[i]) {
        return `${word[i].toUpperCase()} 는 ${i + 1}번째 자리가 아닙니다`;
      }
    }
  }

  return null;
}
```

## 지켜야 할 것

- **`checkAnswer`·`submit`·`shareText` 등 다른 함수는 한 줄도 바꾸지 마십시오**
- 이미 있던 안내 문구 두 개(`N번째 글자는 X 이어야 합니다`, `X 가 들어가야 합니다`)는
  **글자 그대로 남아 있어야 합니다** - 기존 검사가 그 문구를 봅니다
- 바꾼 뒤 `node --check projects/웹워들/web/js/game.js` 가 조용하고,
  `node --test projects/웹워들/tests/*.mjs` 가 **fail 0** 이어야 합니다.
  빨개지면 제품도 검사도 더 고치지 말고 첫 줄을 `NEEDS-FIX: <무엇이 어디서>` 로 보고하십시오

보고 첫 줄은 `DONE` 또는 `NEEDS-FIX: ...` 또는 `BLOCKED - <이유>` 입니다.
