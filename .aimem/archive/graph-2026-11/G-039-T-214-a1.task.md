## 더할 것 - 시험 6건 이상 (합계 17건 이상)

`_audit_denied` 를 직접 부르는 시험은 **`server._revoked_last` 를 비우고 시작**하십시오
(`with server._revoked_lock: server._revoked_last.clear()`). 전역이라 시험끼리 샙니다.

1. `test_denied_audit_key_ignores_the_client_ip` (M10) - 주체가 있는 거절을 **서로 다른 ip** 로
   두 번 → **1줄**. 같은 ip·**다른 경로**로 한 번 더 → **2줄**
2. `test_bad_bearer_is_audited` (M12) - 진짜 소켓으로 `Authorization: Bearer <틀린 값>` →
   `token-bad` 줄이 **늘고**, 그 줄에 **토큰 값이 들어 있지 않다**
3. `test_bad_session_cookie_is_audited` (M13) - 진짜 소켓으로 **세션 쿠키** 이름에 틀린 값 →
   `session-bad` 줄이 늘고, 줄에 쿠키 값이 **없다**
4. `test_session_bad_needs_the_session_cookie` (D2) - `Cookie: theme=dark` 만 보내면
   `session-bad` 가 **안 는다**
5. `test_suppression_table_stays_under_the_cap` (M15) - `_REVOKED_AUDIT_MAX + 10` 개의 서로 다른 키로
   `_audit_denied` 를 부른 뒤 `len(server._revoked_last) <= server._REVOKED_AUDIT_MAX`
6. `test_suppressed_count_is_reported` (M17) - 같은 키로 여러 번 부르고
   `server._REVOKED_AUDIT_MIN_SEC` 를 잠깐 0.01 로 바꿔(`unittest.mock.patch.object` 나
   `try/finally` 로 **반드시 되돌리기**) 다음 줄에 **`생략`** 과 삼킨 수가 들어 있는지
7. `test_unauthenticated_flood_is_bounded` (D1 회귀) - 진짜 소켓, 자격 없이
   **경로를 200개 다르게** 가짜 티켓 요청 → 감사 줄 증가가 **10줄 이하**이고 **1줄 이상**
