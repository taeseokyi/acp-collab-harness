# T-116 `browser_ui.py` - 통계 목표의 검사 구멍 메우기

## 고칠 파일 (이 하나뿐입니다)

`projects/웹워들/tests/browser_ui.py` (541줄). **검사를 더하기만** 합니다.
이미 있는 59개 검사의 문구·조건·순서를 **바꾸지 마십시오.** 앱(`web/` 아래)과 다른 테스트 파일은
남의 것입니다.

## 왜 - 지금 통계 검사는 참·거짓을 못 가립니다

`scenario_stats` 는 빈 통계에서 한 판만 이기고 네 값이 `["1", "100", "1", "1"]` 인지 봅니다.
**판수·승률·연승·최대 연승이 모두 1 이나 100 이라서, 네 칸이 서로 자리가 바뀌어 그려져도
그대로 통과합니다.** 그리고 **진 판 뒤의 통계**와 **끝난 판을 새로 고친 뒤의 통계**는 아무도 안 봅니다.

## 알아야 할 것 (확인된 사실이니 그대로 쓰십시오)

- 통계는 `localStorage` 의 `webwordle.stats` 키에 JSON 으로 들어 있습니다:
  `{played, wins, streak, maxStreak, dist: [6개], lastDay: "YYYY-MM-DD"}`
- `lastDay` 가 **오늘도 어제도 아니면 연승이 0 으로 끊깁니다.** 연승을 이어 가려면
  **브라우저 지역 시간 기준 어제 날짜**를 넣으십시오
- 통계 창의 네 칸은 `#stat-row .stat b` 이고 **판수 · 승률(%) · 연승 · 최대 연승** 순서입니다.
  승률은 `Math.round(wins / played * 100)` 이라 **정수 문자열**입니다
- 분포는 `#dist .dist-row` 여섯 줄, 각 줄의 숫자는 `.bar` 의 글자입니다
- 도움말 창을 안 띄우려면 `webwordle.seenHelp` 에 `true` 를 심거나 기존 `dismiss_help(page)` 를 쓰십시오
- `run_scenario` 가 시나리오마다 새 context 를 주므로 `localStorage` 는 늘 비어서 시작합니다

통계를 미리 심는 코드 (그대로 써도 됩니다. 심은 **뒤 `page.reload()`** 하고
`page.wait_for_selector("#board .tile", timeout=10000)` 로 기다리십시오):

```python
SEED_JS = (
    "(s) => {"
    "  const d = new Date(); d.setDate(d.getDate() - 1);"
    "  const p = (n) => String(n).padStart(2, '0');"
    "  s.lastDay = d.getFullYear() + '-' + p(d.getMonth() + 1) + '-' + p(d.getDate());"
    "  localStorage.setItem('webwordle.stats', JSON.stringify(s));"
    "  localStorage.setItem('webwordle.seenHelp', 'true');"
    "  return s.lastDay;"
    "}"
)
page.evaluate(SEED_JS, {"played": 7, "wins": 5, "streak": 2, "maxStreak": 4,
                        "dist": [0, 1, 2, 1, 1, 0], "lastDay": ""})
```

이미 파일 안에 있는 도우미를 쓰십시오 - `answer_for_page`, `wrong_words`, `type_guess`,
`wait_submit_settled`, `board_signature`, `keyboard_snapshot`, `open_settings`, `close_modal`,
`dismiss_help`, `toast_text`, `shot`. 새로 만들지 마십시오.

## 더할 시나리오 셋 (`main()` 의 `run_scenario` 목록에도 등록하십시오. 목표 이름은 `"통계"`)

### A. 네 값이 서로 다른 통계 - 자리가 바뀌면 드러나게

1. 위 코드로 `played 7 · wins 5 · streak 2 · maxStreak 4 · dist [0,1,2,1,1,0] · lastDay 어제` 를 심고
   새로 고칩니다
2. `#btn-stats` 를 눌러 통계 창을 열고 네 값이 **`["7", "71", "2", "4"]`** 인지 봅니다
   (`round(5/7*100) = 71`). **네 값이 모두 다르므로 자리가 바뀌면 여기서 걸립니다**
3. 분포 여섯 줄의 숫자가 **`["0", "1", "2", "1", "1", "0"]`** 인지 봅니다
4. 창을 닫고 오늘의 정답을 한 줄에 맞혀 이깁니다
   (`answer = answer_for_page(page)` → `type_guess` → `wait_submit_settled(page, 0, answer)`)
5. 저절로 열리는 통계 창에서 네 값이 **`["8", "75", "3", "4"]`** 인지 봅니다
   - 판수 8 · 승률 75 · 연승 3 · 최대 연승 4. **넷이 모두 다른 값입니다.**
   - 특히 **연승(3)과 최대 연승(4)이 서로 다른 것**이 이 시나리오의 핵심입니다
6. 분포가 **`["1", "1", "2", "1", "1", "0"]`** 인지 봅니다 (한 줄에 맞혔으니 첫 칸이 0→1)
7. `shot(page, "stats-mixed")`

### B. 진 판 뒤의 통계 - 연승은 끊기고 최대 연승은 남는다

1. 같은 값을 심고 새로 고칩니다
2. `wrong = wrong_words(page, answer_for_page(page), 6)` 으로 틀린 단어 여섯 개를 받아
   여섯 줄을 모두 틀립니다 (줄마다 `type_guess` → `wait_submit_settled(page, row, guess)`).
   여섯 개가 안 나오거나 그중에 정답이 섞여 있으면 그것부터 실패로 적으십시오
3. `정답: XXXXX` 토스트가 뜨고 통계 창이 저절로 열릴 때까지 기다립니다
   (`page.wait_for_selector("#modal-stats:not([hidden])", timeout=15000)`)
4. 네 값이 **`["8", "63", "0", "4"]`** 인지 봅니다 (`round(5/8*100) = 63`)
   - **연승 0 · 최대 연승 4** - 진 판이 연승만 끊고 최대 연승은 안 건드리는 것이 핵심입니다
5. 분포는 **심은 그대로 `["0", "1", "2", "1", "1", "0"]`** 이어야 합니다 (진 판은 분포에 안 들어감)
6. `shot(page, "stats-after-loss")`

### C. 끝난 판을 새로 고친 뒤 - 두 번 세지 않는다

1. A 와 같은 값을 심고 새로 고친 뒤 한 줄에 맞혀 이깁니다
2. 통계 창을 닫고 `board_signature(page)` 와 네 값을 적어 둡니다
3. `page.reload()` + `page.wait_for_selector("#board .tile", timeout=10000)`
4. 다음을 봅니다
   - **판수가 또 늘지 않음** - 통계 창을 열어 네 값이 새로 고치기 전과 **똑같은지**
     (`["8", "75", "3", "4"]`). 여기서 9 가 나오면 끝난 판을 다시 세는 결함입니다
   - 보드가 그대로 - `board_signature(page)` 가 새로 고치기 전과 같은지
   - 키보드 색이 그대로 - `keyboard_snapshot(page)` 가 같은지
   - **공유 단추가 보임** - `page.locator("#btn-share").is_visible()` 이 `True`
     (속성이 아니라 **보이는지**로 보십시오)
   - 끝난 판이므로 글자를 쳐도 보드가 안 바뀜 - `page.keyboard.type("abcde")` 뒤
     `board_signature(page)` 가 그대로
5. `shot(page, "stats-reload-finished")`

## 하지 말 것

- 검사를 조건부로 만들거나(`if ... else pass`) `try/except` 로 삼키지 마십시오
- `sleep` 을 쓰지 마십시오. 기다림은 모두 `page.wait_for_function` / `wait_for_selector` 로
- 기대값을 "실제로 나온 값" 으로 맞춰 쓰지 마십시오. **위에 적힌 숫자가 기대값입니다**
