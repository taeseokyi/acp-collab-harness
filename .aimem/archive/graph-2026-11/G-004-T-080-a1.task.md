## 목표

`tools/fleet.py` 의 **"운영 상태 DB 우선 · 마크다운 폴백"** 경로에 회귀 테스트를 새로 만든다.
이 경로에는 지금 테스트가 **하나도 없다.** `fleet.py` 는 작업자를 띄우는 함대의 생명선이고,
R5 적대적 검수가 여기서 결함 2건(실패 영구 캐시 / `sys.path` 누락)을 잡았다.

## 쓰기 경로

`tests/test_fleet.py` **하나뿐이다.** 새 파일이다. 다른 파일은 읽기만 하고 절대 고치지 마라.
특히 `tools/fleet.py` 와 `.aimem/aimem.db` 는 **읽기만** 한다.

## 전제

- 표준 라이브러리만 쓴다. **`pytest` 는 이 환경에 없다.** `unittest` + `tempfile` + `unittest.mock`.
- import 는 이렇게 한다(저장소에 `tools/` 패키지가 없다):

```python
import pathlib
import sys
sys.path.insert(0, str(pathlib.Path(__file__).resolve().parent.parent / "tools"))
import fleet
```

- `fleet.db_state()` 는 **모듈 전역 캐시** `fleet._DB_CACHE = {"at": float, "state": dict|None}` 를 쓴다.
  **모든 테스트의 `setUp` 에서 `fleet._DB_CACHE.update(at=0.0, state=None)` 로 비워라.**
  안 비우면 테스트끼리 상태가 샌다.
- 대부분의 테스트는 `unittest.mock.patch.object(fleet, "db_state", return_value=...)` 로 만든다.
  폴백을 보는 테스트는 `db_state` 가 `None` 을 주도록 patch 하고 `fleet.AIMEM` 을 임시 파일 경로로
  patch 한다(`patch.object(fleet, "AIMEM", tmp_path)`).

### `db_state()` 가 돌려주는 모양 (테스트에서 만들 가짜 값)

```python
{"rev": 114,
 "slots": [{"slot": "S1", "token": "a41f0c", "harness": "claude", "model": "opus",
            "role": "...", "note": "..."}],
 "tasks": [{"id": "T-001", "title": "제목", "slot": "S1", "status": "TODO", "artifacts": ""}],
 "ownership": [{"path_pattern": "tests/x.py", "owner": "S2", "note": ""}]}
```

## 덮을 것 - 10가지를 각각 독립 테스트 메서드로

1. **`roster()` - DB 경로.** `db_state()` 가 slots 를 주면 `{slot: (token, harness, "")}` 로 돌려준다.
   세 번째 칸(세션키)은 **항상 빈 문자열**이다. 슬롯 이름이 `S\d+` 꼴이 아닌 행(예: `"관리자"`,
   `""`, `None`)은 **걸러진다.**
2. **`roster()` - 폴백.** `db_state()` 가 `None` 이고 `fleet.AIMEM` 이 아래 표를 가진 임시 파일이면
   그 표를 파싱해 돌려준다:
   `| S9 | \`abc123\` | claude | opus | 역할 | 세션키자리 |`
   같은 테스트에서 **표가 없는 파일**(지금의 `AIMEM.md` 상태)이면 **빈 dict** 라는 것도 확인하라.
3. **`read_rev()` - DB 경로.** `db_state()["rev"]` 를 `int` 로 돌려준다(문자열 `"114"` 여도 `114`).
4. **`read_rev()` - 폴백.** `db_state()` 가 `None` 이고 `fleet.AIMEM` 이 `- **REV: 77**` 줄을
   가진 임시 파일이면 `77`.
5. **`read_rev()` - 둘 다 없으면 `SystemExit`.** `assertRaises(SystemExit)`.
6. **`owned_paths("S2")`.** ownership 행 중 `owner == "S2"` 인 `path_pattern` 만 들어오고,
   `owner == "해당 슬롯"` 인 행은 패턴 안의 `<슬롯>` 이 `"S2"` 로 **치환되어** 들어온다.
   다른 슬롯 소유 행은 들어오지 않는다.
7. **`board_rows()`.** `db_state()["tasks"]` 를 `(id, title, slot, status)` 튜플 리스트로 준다.
   `title` 이 `None` 이면 `""`, `slot` 이 `None` 이면 `"-"`.
8. **`path_allowed()` 경계.** 세 가지를 한 테스트 안에서:
   - `path_allowed("tests/test_aimem_lint.py.bak", ["tests/test_aimem_lint.py"])` 는 **`None`**
     (정확한 파일 패턴은 정확히만 맞는다 - R5 검수 7번의 회귀)
   - `path_allowed("tests/test_aimem_lint.py", ["tests/test_aimem_lint.py"])` 는 그 패턴 문자열
   - `path_allowed(".aimem/archive/x.md", [".aimem/archive/**"])` 는 그 패턴 (디렉터리 패턴은 하위 허용)
9. **`db_state()` 캐시 TTL.** `fleet._DB_CACHE` 에 `{"at": <지금>, "state": <가짜 dict>}` 를 넣고
   `fleet.time.monotonic` 을 patch 해서,
   - 경과 < `fleet.DB_CACHE_TTL_SEC` 이면 **캐시된 그 객체를 그대로** 돌려준다(다시 읽지 않는다)
   - 경과 > TTL 이면 **다시 읽는다** (돌려주는 값이 캐시에 넣어 둔 가짜 객체가 아니다)
10. **`db_state()` 가 실패를 캐시하지 않는다.** `state` 가 `None` 인 캐시는 TTL 과 **무관하게**
    매번 다시 시도한다. (R5 에서 `fleet_graph run` 한 실행 내내 명부가 `{}` 가 되어 **모든 노드가
    "명부에 없음" 으로 실패**했던 결함의 회귀 테스트다.)
    - `_DB_CACHE` 를 `{"at": <지금>, "state": None}` 으로 두고 `db_state()` 를 부르면 실제로
      다시 읽어 **DB 값(또는 patch 한 값)이 나온다**는 것으로 확인하라.
    - 같이 확인: 읽기가 예외를 던지면 **stderr 에** `[fleet] .aimem/aimem.db 를 읽지 못했습니다`
      가 찍히고(조용히 삼키지 않는다) 돌려주는 값은 `None` 이다.
      (`contextlib.redirect_stderr` 로 받아라.)

## 하지 말 것

- 실제 `.aimem/aimem.db` 를 **쓰거나 고치지 마라.** 읽기만 하는 테스트도 되도록 피하고
  전부 mock 으로 만들어라 - 이 테스트는 DB 내용이 바뀌어도 깨지면 안 된다.
- 작업자를 실제로 띄우는 코드(`cmd_spawn`, `_worker_argv`)는 **이번 태스크 범위가 아니다.**
  건드리지 마라.
- `tools/fleet.py` 를 고쳐서 테스트를 통과시키지 마라. 테스트가 현재 동작과 어긋나면
  **보고 첫 줄을 `BLOCKED` 로** 하고 무엇이 어긋나는지 적어라.

## 완료 판정

두 명령이 모두 rc 0 이어야 한다.

```
python3 -m unittest tests.test_fleet -q
python3 -m unittest discover -s tests -q
```

두 번째는 **기준선이 195건 OK** 다. 이보다 줄거나 실패가 생기면 네가 깬 것이다.

## 보고

첫 줄은 `상태: DONE` / `PARTIAL` / `BLOCKED` 중 하나. 이어서
(1) 새로 만든 테스트 메서드 이름 목록, (2) 위 두 명령의 출력 **꼬리 5줄을 그대로** 붙여라
(요약하지 말고 복사해라), (3) 현재 동작과 어긋나 못 덮은 항목이 있으면 번호로 적어라.
