### 고칠 함수: `tools/aimem_monitor/server.py` 의 `_audit_denied()` (711행 근처)

지금은 창(60초)마다 `_DENIED_AUDIT_MAX_PER_MIN = 60` 줄까지만 쓰고 나머지는 세기만 합니다.
R17 적대적 검수가 찾은 네 가지를 닫습니다.

**(가) 창마다 처음 보는 `(event, subject)` 는 상한과 무관하게 한 줄 (검수 N5·N6·N8)**
- 모듈 수준에 `_denied_window_seen = set()` 과 `_DENIED_AUDIT_FIRST_MAX = 256` 을 둡니다
- 창이 바뀔 때(`now - _denied_window_start >= 60`) `_denied_window_seen` 도 **비웁니다**
- `bucket = (event, subject or "-")`. 이번 창에서 `bucket` 이 **처음**이고
  `len(_denied_window_seen) < _DENIED_AUDIT_FIRST_MAX` 이면, `_denied_window_written` 이 이미 상한이어도
  **기록합니다**(그리고 `_denied_window_written` 을 그대로 1 올립니다 - 상한을 넘겨 셉니다).
  처음이 아니면 지금처럼 상한을 봅니다
- 이것이 닫는 것: 회수된 계정 하나가 경로를 바꿔 가며 상한을 독식해도 **다른 주체는 창마다 최소 한 줄**을
  받습니다. 쿠키 없는 요청자가 티켓을 26개 넘게 모아도 같습니다

**(나) 억제 표에서 밀려난 키의 생략 수를 잃지 않기 (검수 N6)**
- `while len(_revoked_last) > _REVOKED_AUDIT_MAX:` 에서 `popitem(last=False)` 로 **밀려난 기록의 생략
  수**(`rec[1]`)가 0 보다 크면 모듈 수준 `_denied_evicted_skipped` 에 더합니다
- 다음 창 전환 때 `dropped` 와 **함께** 내보냅니다

**(다) 조용해져도 남은 수를 잃지 않기 (검수 N7)**
- 모듈 수준 함수 `flush_denied_audit(root)` 를 만듭니다. `_denied_cap_skipped + _denied_evicted_skipped`
  가 0 보다 크면 `audit(root, "audit-dropped", "-", None, f"상한 생략 {n}건")` 한 줄을 쓰고 둘 다 0 으로
  되돌립니다. 0 이면 **아무것도 쓰지 않고** 돌아옵니다. `_revoked_lock` 안에서 수를 읽고 비운 뒤
  **락 밖에서** `audit()` 를 부르십시오
- `serve()` 의 `finally:` (3094행 근처, `httpd.server_close()` 바로 앞)에서 `flush_denied_audit(root)` 를
  부릅니다

**(라) `app-ticket-bad` 의 서로 다른 사유가 한 키를 공유하는 것 (검수 N10)**
- 지금 키는 `(event, subject, path, method)` / `(event, subject, method)` / `(event, "-", method)` 입니다.
  **세 꼴 모두 꼬리에 `str(reason)[:24]` 를 더합니다**
- `reason` 은 서버가 쓰는 고정 문자열입니다(`"형식"`, `"주체 못 찾음(회수 또는 위조)"`, `"서명·만료"`,
  `"무주체"`, `"주체 불일치"`, `"허용 목록 밖"`). 요청자가 넣는 값이 아니므로 키가 폭발하지 않습니다
- 이것이 닫는 것: 꼴 깨진 요청을 한 번 보내 두면 60초 동안 **위조 시도가 숫자로만 남던 것**

**건드리지 말 것**: `authenticated` 인자로 키에서 경로를 빼는 R17 의 동작(`github-revoked` 와 인증된
주체만 경로를 가짐)은 **그대로 둡니다**. `_DENIED_AUDIT_MAX_PER_MIN` 의 값 60 도 바꾸지 마십시오.
