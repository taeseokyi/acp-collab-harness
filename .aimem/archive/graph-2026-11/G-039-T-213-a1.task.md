# T-213 무인증 요청으로 감사 로그를 불릴 수 있는 것을 막으십시오 (검수 D1 중간 · D2 낮음)

고칠 파일은 **`tools/aimem_monitor/server.py`** 하나입니다. **이번 라운드가 스스로 연 공격면입니다.**

## 무엇이 잘못됐나 (관리자가 실측했습니다)

앞 태스크 T-206 이 거절마다 감사를 남기게 하면서 억제 키에 **경로**를 넣었습니다.
그런데 `app-ticket-bad` · `token-bad` · `session-bad` 는 **인증 전**에 찍히고,
무인증 요청의 주체는 늘 `-` 이며 **경로는 공격자가 마음대로 정합니다.**

```
무인증 가짜 티켓 300번(경로 끝만 바꿈) -> 감사 300줄
틀린 Bearer 300번(경로만 바꿈)        -> 감사 300줄
요청 651번에 access.log 62 KB
```

검수 실측으로는 클라이언트 하나가 **하루 약 15 GB** 를 쓸 수 있고, `.aimem/access.log` 는
순환도 상한도 없으며 관리 도구(`admin.py` 의 `audit_tail`)가 파일을 통째로 읽습니다.

**D2:** `session-bad` 조건이 "쿠키 헤더가 있으면" 이라, `theme=dark` 같은 **남의 쿠키**만 있어도
"서명·만료" 로 찍힙니다. 사실과 다르고 위 홍수도 이 길을 탑니다.

## 고칠 것

### 1. 무인증 거절은 경로로 쪼개지 마십시오 (D1)

`_audit_denied` 의 억제 키를 **주체 유무로 갈라** 쓰십시오.

- 주체가 있으면(`subject` 가 참이고 `-` 가 아니면) 지금 그대로 `(event, subject, path, method)` -
  이미 인증된 적 있는 쪽이라 경로별로 보는 것이 쓸모 있습니다
- **주체가 없으면**(`None` 또는 `-`) 키에서 **경로를 빼고** `(event, "-", method)` 를 쓰십시오.
  공격자가 키를 마음대로 늘리지 못하게 하는 것이 요점입니다.
  이때 detail 의 경로는 **그 창에서 처음 본 경로 하나**만 보기로 싣고 뒤에 `생략 N건` 을 붙입니다

### 2. 감사 쓰기에 전역 상한을 두십시오 (D1 둘째 겹)

키가 아무리 늘어도 쓰기가 폭주하지 않게, `_audit_denied` **전체**에 프로세스 전역 상한을 두십시오.

```python
_DENIED_AUDIT_MAX_PER_MIN = 60      # 분당 줄 수 상한 (전역)
```

- 1분 창 안에서 이미 60줄을 썼으면 더 쓰지 말고 **세기만** 하십시오
- 창이 바뀌어 처음 쓸 때 그 줄 detail 에 `생략 N건` 으로 그동안 삼킨 수를 실으십시오
  (**숫자를 잃지 마십시오** - 조용히 사라지면 홍수를 못 봅니다)
- `_revoked_last` 의 상한 `_REVOKED_AUDIT_MAX`(256) 는 그대로 두십시오

### 3. `session-bad` 는 **세션 쿠키가 있을 때만** (D2)

`self.headers.get("Cookie")` 가 아니라 **`self._cookie(SESSION_COOKIE) is not None`** 일 때만
`session-bad` 를 남기십시오.

### 4. 잃으면 안 되는 것

- 거절 종류별 이벤트 이름(`app-ticket-bad` · `token-bad` · `session-bad` · `github-revoked`)과
  사유 문구는 **그대로**입니다
- **거절이 아예 안 남으면 안 됩니다** - 억제는 묶는 것이지 지우는 것이 아닙니다
- 자격이 아예 없는 평범한 요청(쿠키·Bearer 없음)은 지금처럼 **안 남깁니다**
- 티켓 가리기(`_TICKET_LOG_RE`)와 경로·메서드 표기는 그대로입니다
