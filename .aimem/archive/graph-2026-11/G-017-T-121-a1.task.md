# T-121 "보드" 목표 - 타일이 **정말 도는지** 보는 검사로 바꾸기

## 고칠 파일 (이 하나뿐입니다)

`projects/웹워들/tests/browser_core.py` (지금 `통과 64 / 전체 64`)

**앱(`web/` 아래)은 건드리지 마십시오.** 지금 64개가 전부 초록입니다. 그중 **세 개가 거짓 초록**이라
적대적 검수(S1)가 잡았습니다. 그 셋만 고치고 나머지 61개는 건드리지 마십시오.

## 결함 1 (가장 중요) - `animationName` 은 애니메이션이 **없어도** `flip` 으로 나옵니다

`scenario_board` 의 `"보드 - 애니메이션이 실제로 걸림"` 검사는 `.flip` 이 붙는 순간의 계산된
`animationName === "flip"` 과 `animationDuration === "0.5s"` 만 봅니다.

**S1 이 크로미움에서 직접 확인한 사실:** `@keyframes flip` 블록을 지워도
계산된 `animationName` 은 그대로 `flip`, `animationDuration` 은 그대로 `0.5s` 로 나옵니다
(`getAnimations()` 만 0개가 됩니다). 즉 **지금 검사는 키프레임이 통째로 사라져도 초록입니다.**

→ **애니메이션이 실제로 시작됐다는 증거**로 바꾸십시오. `animationstart` 이벤트가 가장 확실합니다 -
   이 이벤트는 애니메이션이 **정말 돌 때만** 발생합니다.

`.flip` 을 보던 `MutationObserver` 는 **그대로 두고**(칸 순서·시각 판정에 쓰입니다),
Enter 를 누르기 **전에** 같은 다섯 칸에 `animationstart` 듣기를 더하십시오. 예를 들어

```python
WATCH_ANIM_JS = (
    "() => {"
    "  window.__anims = [];"
    "  document.querySelectorAll('#board .row:nth-child(1) .tile').forEach((t, i) => {"
    "    t.addEventListener('animationstart', (e) => {"
    "      window.__anims.push({i: i, name: e.animationName, at: performance.now(),"
    "                           running: t.getAnimations().map(a => a.animationName)});"
    "    });"
    "  });"
    "}"
)
```

줄 판정이 끝난 뒤 `page.evaluate("() => window.__anims")` 로 읽어 **세 가지**를 봅니다
(각각 따로 `checks.ok`, 목표 이름은 `"보드"`):

- **다섯 칸 모두에서 `flip` 애니메이션이 시작됐다** - `name == "flip"` 인 기록의 칸 번호 모음이
  정확히 `{0, 1, 2, 3, 4}`
- **시작한 순간 그 칸에 도는 애니메이션이 잡힌다** - 기록마다 `running` 안에 `"flip"` 이 들어 있음
- **기록이 하나도 없으면 실패** - 아래 결함 2 와 같은 이유입니다

`animationstart` 가 안 잡히는 일이 있으면 대신 `t.getAnimations()` 를 뒤집기 도중에 읽어
`flip` 이름의 애니메이션이 `running` 상태인지 봐도 됩니다. **어느 쪽이든 "키프레임을 지우면
빨개지는" 검사여야 합니다.**

## 결함 2 - `all(...)` 이 빈 목록이면 참입니다

`"보드 - 애니메이션이 실제로 걸림"` 의 `all(...)` 은 기록이 하나도 없으면 **조용히 통과합니다.**
바로 앞 "다섯 칸 모두" 검사가 우연히 막아 주고 있을 뿐입니다.

→ 이 검사와 위에서 새로 만드는 검사 모두 **"기록이 정확히 다섯 칸 분"** 을 조건에 **함께** 넣으십시오.
   `all(...)` 만 쓰지 말고 `len(...) == 5 and all(...)` 꼴로 쓰십시오.
   같은 꼴의 위험이 `scenario_board` 안에 더 있으면 같이 고치십시오.

## 결함 3 - `"0.5s"` 를 박아 둬서 **동작 줄이기** 기계에서 거꾸로 깨집니다

`style.css:298` 에 `@media (prefers-reduced-motion: reduce) { … animation-duration: .01s; }` 가 있습니다.
그런 설정을 쓰는 기계에서는 `animationDuration` 이 `"0.01s"` 라 **지금 검사가 거짓으로 실패합니다.**

→ `== "0.5s"` 를 버리고 **`0보다 큰 시간인지**로 바꾸십시오
   (`"none"`·`"0s"` 이면 실패). 실제 값은 `detail` 에 그대로 찍으십시오.
   `style.css` 의 숫자를 테스트에 베껴 오지 마십시오.

## 공통으로 지킬 것

- **도구 호출 모양의 글자(`<tool_call>`, `<function=…>`, `<parameter=…>`)를 본문에 쓰지 마십시오.**
  파일을 고칠 때는 실제 편집 도구를 쓰고, 본문에는 사람이 읽을 말만 쓰십시오.
  이번 라운드에 그 글자를 찍고 끝나 아무것도 안 바뀐 시도가 네 번 있었습니다
- 계획을 적는 단계를 건너뛰고 **바로 파일을 열어 고치십시오**
- `sleep` 금지. 기다림은 `wait_for_function` / `wait_for_selector`
- 검사를 조건부로 만들거나 `try/except` 로 삼키지 마십시오
- 기대값을 "실제로 나온 값" 에 맞춰 적어 두지 마십시오
- **검사가 제품(`web/` 아래)의 진짜 결함 때문에 빨개지면 제품도 검사도 고치지 말고**
  첫 줄을 `NEEDS-FIX: <무엇이 어디서>` 로 보고하고 멈추십시오
- 당신의 샌드박스에서는 크로미움이 안 뜹니다(`sandbox_host_linux.cc FATAL`). **그래도 멈추지 말고**
  코드를 정확하게 써 놓고 `python3 -m py_compile` 까지 한 뒤 `PARTIAL` 로 보고하십시오 -
  검증은 엔진이 샌드박스 밖에서 돌립니다. 재시도를 받으면 브리프에 붙은 **검증 출력 꼬리**를 보고 고치십시오
