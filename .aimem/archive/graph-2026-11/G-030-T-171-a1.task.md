## 결함 3 (먼저 고치십시오 - 지금 단위 시험이 빨갛습니다)

`remove()` 가 부모에게 `{op:'remove', key, value:null}` 을 보냅니다. **규약은 `op:'put'` 에
`value:null`** 입니다(설계 2절). 모니터는 `op:'remove'` 를 아예 안 보므로 지우기가 한 번도
반영되지 않았습니다 - 지난 `daily.*` 정리도 안 돼 61일째부터 키 상한에 걸립니다.

→ `remove()` 가 보내는 메시지의 `op` 를 `'put'` 으로 바꾸십시오. 보내기 전 검사가 `value` 의
길이를 재고 있다면 **`null` 은 통과**시켜야 합니다(길이 검사는 문자열일 때만).

지금 `node --test projects/웹워들/tests/*.mjs` 를 돌리면 `지우기는 value 가 null 이다` 가 빨갛습니다.
고친 뒤 초록이 되어야 합니다.

## 결함 2

`init()` 에서 스냅숏이 500ms 안에 **안 와도** `parentMode = true` 가 켜집니다. 그러면 그 뒤 첫
`write()` 가 **빈 메모리에서 계산한 값**을 `put` 으로 보내 모니터 칸에 저장돼 있던 통계·설정을
덮어씁니다 (`played:50` → `played:1`). 설계 3.2 는 이 경우를 **"메모리 모드"** 라고 못박았습니다.

→ **스냅숏을 실제로 받았을 때만** `parentMode = true` 로 하십시오. 시간 초과면 `parentMode` 를
켜지 말고(= `put` 을 보내지 않고) 지금처럼 메모리로만 돕니다. 판은 그대로 돌아가야 합니다.

지난 `daily.*` 정리(`init` 안)도 **스냅숏을 받았을 때만** 하십시오 - 받지 못했으면 지울 대상이
무엇인지 모르는 상태이고, 지우기를 보내면 남의 기록을 지우게 됩니다.
