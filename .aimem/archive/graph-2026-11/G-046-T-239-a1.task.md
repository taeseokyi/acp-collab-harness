# T-239 `tests/browser_monitor_usage.py` 의 입력 자료를 **진짜 파일 꼴**로 고치십시오

쓸 파일은 **하나**입니다: `tests/browser_monitor_usage.py`. **`tools/**` 와 다른 검사 파일은
읽기만 하고 절대 고치지 마십시오.** 계획을 세우지 말고 바로 고치십시오.

## 무엇이 틀렸나

이 검사의 `usage_root()` 가 `.aimem/claude-usage.json` 에 써 넣는 `rate_limits` 가 **list** 이고,
원소가 `{"key": ..., "percent": ..., "resets_at_iso": ...}` 입니다. 그런데 그 모양은 **서버가
내놓는 결과** 이지 **파일에 들어 있는 모양이 아닙니다.** 파일은 Claude Code 상태줄이 그대로 옮겨
적은 것이고(`tools/claude_usage_statusline.py`), `rate_limits` 는 **창 이름을 키로 하는 dict** 이며
각 값이 `{"used_percentage": <숫자>, "resets_at": <ISO 문자열>}` 입니다.
`tools/aimem_monitor/server.py` 의 `claude_usage()` 도 dict 만 받고 아니면 `None` 을 돌려줍니다.
그래서 지금 화면에 행이 **0개**로 나와 13건 중 10건이 빨갛습니다. **제품이 맞고 검사가 틀렸습니다**
(관리자가 Claude Code 2.1.80 변경 기록으로 확인했습니다: "`rate_limits` ... 5-hour and 7-day windows
with `used_percentage` and `resets_at`").

## 할 일

`base_rows()`(그리고 그것을 쓰는 자리들)를 아래 꼴로 바꾸십시오. **기대값은 그대로 둡니다** -
`KEYS`·`LABELS`·`PCTS`·`CLASSES`·`RATIOS` 와 `초기화 HH:MM` 기대는 손대지 마십시오.

```python
def base_rows():
    t = dt.datetime.now().replace(hour=18, minute=0, second=0, microsecond=0)
    return {
        "five_hour": {"used_percentage": 40.0, "resets_at": t.isoformat()},
        "seven_day": {"used_percentage": 85.0, "resets_at": t.replace(hour=20, minute=30).isoformat()},
        "seven_day_opus": {"used_percentage": 97.0, "resets_at": t.replace(hour=21, minute=10).isoformat()},
        "seven_day_sonnet": {"used_percentage": 12.0},
    }
```

- `seven_day_sonnet` 에는 `resets_at` 을 **넣지 않습니다**(그래야 `.usage-reset` 요소가 없다는 기대가 삽니다)
- `usage_root(rows, at=...)` 는 받은 것을 그대로 `{"at": at, "rate_limits": rows}` 로 씁니다 - 그대로 두십시오
- 다른 시나리오(`stale_scenario`·`empty_scenario`·`narrow_scenario`·`scroll_scenario`)가 자료를 따로
  만들고 있으면 **같은 dict 꼴로** 고치십시오. 빈 상태 시나리오는 파일을 아예 쓰지 않거나
  `rate_limits` 를 `{}` 로 두면 됩니다
- 검사 건수(13)를 줄이지 마십시오. 기대를 느슨하게 바꾸지 마십시오

## 검증

```bash
python3 tests/browser_monitor_usage.py
```

마지막 줄이 `통과 13 / 전체 13` 이어야 합니다. 빨간 것이 남으면 **화면 쪽 결함일 수 있습니다** -
그때는 `tools/**` 를 고치지 말고 보고 첫 줄을 `NEEDS-FIX: <무엇이 어디서>` 로 쓰십시오.
