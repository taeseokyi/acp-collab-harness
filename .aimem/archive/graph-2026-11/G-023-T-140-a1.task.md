## `tests/test_aimem_monitor_app.py` - 다섯 개

이 파일의 `ProjectAppTests` 에는 이미 `self.app()` (임시 프로젝트 `알파` 를 만듦)과
`self.route(path, auth=False)` (핸들러를 직접 불러 `(status, headers, body)` 를 돌려줌)가 있습니다.
**그 둘을 그대로 쓰십시오.** `route` 는 지금 `Host: localhost:18799`·`tls=False` 로 고정돼 있으니,
**맨 먼저 `route` 에 인자 둘을 더하십시오**(기존 호출은 그대로 동작해야 합니다):

```python
    def route(self, path, auth=False, host="localhost:18799", tls=False):
        h = server.Handler.__new__(server.Handler)
        h.path = path
        h.command = "GET"
        h.tls = tls
        h.require_auth = auth
        h.root = self.root
        h.access_token = None
        h.headers = email.message.Message()
        h.headers["Host"] = host
        ...   # 나머지는 지금 그대로
```

그리고 검사 다섯 개를 클래스 **맨 끝**(`test_malformed_tickets_never_raise` 다음)에 더합니다.

1. `test_csp_origin_is_https_under_tls` - `self.app()` 뒤 `tls=True, host="192.168.0.5:18800"` 로
   티켓 302 를 받고(`self.route("/app/알파/", tls=True, host="192.168.0.5:18800")` 의 `Location`),
   그 경로를 같은 인자로 다시 불러 CSP 에 `https://192.168.0.5:18800` 이 **있고** `http://` 가
   **없음**을 확인합니다. (구멍: TLS 인데 출처가 `http://` 가 되어도 지금은 아무 검사도 안 빨개집니다.)
2. `test_csp_origin_rejects_unknown_host_name` - `host="evil.com"` 으로 같은 두 번(302 → 티켓 경로)을
   돌려 CSP 에 `evil.com` 이 **없고** `default-src 'self';` 처럼 `'self'` 만 남는지 확인합니다.
   (R11 검수 B 결함 1 의 회귀 시험입니다.)
3. `test_csp_origin_keeps_ip_and_localhost` - `host="127.0.0.1:18799"` 면 CSP 에
   `http://127.0.0.1:18799` 가 들어가고, `host="[::1]:18799"` 면 `http://[::1]:18799` 가 들어가는지.
   (운영이 IP 로 들어오므로 **막히면 안 되는 쪽**의 검사입니다.)
4. `test_issued_ticket_expires_within_ttl` - 302 `Location` 에서 티켓을 떼어
   `exp = int(ticket.split(".")[0])` 이 `time.time()` 보다 크고
   `time.time() + server.PROJECT_APP_TICKET_TTL_SEC + 2` 보다 작은지 확인합니다.
   (구멍: 수명을 10년으로 바꿔도 지금은 아무 검사도 안 빨개집니다.)
5. `test_service_worker_skips_app_paths` - `tools/aimem_monitor/static/sw.js` 를 **텍스트로 읽어**
   `"/app/"` 로 시작하는 요청을 `return` 으로 지나치는 줄이 있고(`startswith('/app/')` 를 쓰는 줄),
   `VERSION`(또는 캐시 이름) 문자열이 들어 있는지 확인합니다. 경로는
   `pathlib.Path(__file__).resolve().parents[1] / "tools/aimem_monitor/static/sw.js"` 입니다.
   (구멍: 서비스 워커가 `/app/` 을 캐시하기 시작해도 지금은 아무 검사도 안 빨개집니다.)

티켓 가리기(`/app/~***`)는 로그 쪽이라 여기서 시험하지 않습니다.

## `tests/test_aimem_monitor_auth.py` - 한 개

이 파일에는 이미 임시 루트 위에 서버를 띄우는 `_Srv(root, require_auth=True, token=TOKEN, tls=False)`
와 `_h(headers, name)` 가 있습니다. **`_Srv(..., tls=True)` 는 평문 소켓에 핸들러만 TLS 모드로
띄웁니다** - 그래서 인증서 없이도 TLS 쪽 동작을 잽니다. `AuthHttpTests` 를 본떠 검사 하나를 더하십시오.

`test_login_cookie_is_secure_under_tls`:
- `tls=True` 서버에 `POST /api/login` 으로 토큰을 보내 `Set-Cookie` 에
  `Secure`·`HttpOnly`·`SameSite=Strict` 가 **모두** 있는지
- `tls=False` 서버에서는 `Secure` 가 **없고** `HttpOnly` 는 있는지(로컬 http 검증이 깨지지 않게)

로그인 본문·헤더 꼴은 같은 파일의 기존 로그인 검사를 그대로 본뜨십시오(`Content-Type: application/json`,
본문 `{{"token": TOKEN}}`). 서버는 `addCleanup(srv.close)` 로 꼭 닫습니다.
