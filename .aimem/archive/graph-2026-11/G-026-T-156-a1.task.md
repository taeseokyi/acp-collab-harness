## 무엇이 잘못됐나

GitHub 허용 목록(`github_allowed_logins`, 481행)은 **로그인하는 순간에만** 봅니다
(2931행, 2963행). 그 뒤로는 서명된 세션 쿠키 하나로 끝입니다:

```python
    def _subject(self):
        """인증된 주체 문자열 또는 None. Bearer 토큰 -> 쿠키 순으로 봅니다."""
        ...
        sess = verify_session(tok, self._cookie(SESSION_COOKIE))
        return sess["subject"] if sess else None
```

`verify_session` 은 서명과 만료만 봅니다. 그래서 **허용 목록에서 계정을 지워도 그 사람의
쿠키는 `SESSION_TTL_SEC` 가 다 갈 때까지 그대로 듣습니다** - `/app/` 실행 티켓도,
`/api/` 도 전부. 회수 수단이 "접근 토큰을 갈아 끼워 모두를 내보내기" 밖에 없습니다.

## 고치는 법

`_subject()` 의 마지막 두 줄을 아래로 바꾸십시오:

```python
        sess = verify_session(tok, self._cookie(SESSION_COOKIE))
        if not sess:
            return None
        subject = sess["subject"]
        # **GitHub 주체는 요청마다 허용 목록을 다시 봅니다.** 목록은 로그인 때만 보던 것이라,
        # 계정을 지워도 서명된 쿠키가 TTL 동안 그대로 들었습니다 (R12 T-155 가 찾음).
        # 파일은 작고 캐시하지 않습니다 - 지운 즉시 끊기는 것이 이 검사의 값어치입니다.
        if subject.startswith(SESSION_SUBJECT_GITHUB_PREFIX):
            login = subject[len(SESSION_SUBJECT_GITHUB_PREFIX):].lower()
            if login not in github_allowed_logins(self.root):
                return None
        return subject
```

`SESSION_SUBJECT_GITHUB_PREFIX` 와 `github_allowed_logins` 는 이 파일에 이미 있습니다
(69행 근처 import, 481행 정의). **새로 import 할 것은 없습니다** -
`grep -n "SESSION_SUBJECT_GITHUB_PREFIX" tools/aimem_monitor/server.py` 로 확인하십시오.

**`_subject()` 말고 다른 함수는 한 줄도 바꾸지 마십시오.**

## 시험 더하기 (`tests/test_aimem_monitor_app_gate.py`)

이미 있는 일곱 개는 그대로 두고, 아래 셋을 더하십시오. T-155 가 만든
`gh:` 쿠키 도우미(88행 근처)와 임시 루트 짜임새를 그대로 쓰십시오.

1. **목록에서 빠진 계정은 `/api/` 도 못 본다** - 같은 쿠키로 `GET /api/state`
   (또는 이 파일이 이미 부르는 아무 `/api/` 경로)가 **200 이 아니다**
2. **허용 목록 파일 자체가 없어지면** 그 쿠키는 더는 듣지 않는다
   (`github_allowed_logins` 는 파일이 없으면 빈 집합입니다)
3. **대소문자** - 허용 목록에 `TaeSeok` 이라 적혀 있고 주체가 `gh:taeseok` 이면
   **들어가진다** (목록은 소문자로 읽고 주체도 소문자로 맞춰 비교하므로)

그리고 **토큰 로그인 세션(`SESSION_SUBJECT_TOKEN`)은 이 검사에 걸리지 않아야 합니다** -
이미 있는 `test_the_normal_flow_still_works` 가 그것을 지킵니다. 빨개지면 고친 코드가
틀린 것입니다.
