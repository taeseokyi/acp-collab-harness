# T-134 미리보기가 **실제로 뜨게** 고칩니다 (검수 결함 1~4)

## 지금 무엇이 틀렸는가 (관리자가 직접 확인했습니다)

모니터 프로젝트 칸의 `실행` 을 누르면 iframe 은 뜨는데 **안이 비어 있습니다.**
`python3 tests/browser_monitor_ui.py` 가 지금 **`통과 4 / 전체 6`** 입니다.

```
[FAIL] 안쪽 보드가 진짜로 그려졌다 - 대기 오류=TimeoutError
[FAIL] 패널 밖으로 잘리지 않는다 - iframe y=157.19 h=702 / detail-body y=71.80 h=753.20
```

브라우저 콘솔:

```
Access to script at '.../app/%EC%9B%B9%EC%9B%8C%EB%93%A4/js/ui.js' from origin 'null'
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present
```

**원인 (S1 검수가 끝까지 확인했습니다):**

1. `sandbox` iframe 의 출처는 `null`(불투명)입니다. `<script type="module">` 은 **언제나 CORS 로**
   받으므로 `Access-Control-Allow-Origin` 이 없으면 막힙니다 → 게임 코드가 아예 안 뜹니다
2. 거기에 더해, **인증을 켜면**(운영은 켭니다) 불투명 출처가 보내는 하위 요청에는
   `SameSite=Strict` 세션 쿠키가 실리지 않습니다 → `css/style.css` 까지 `302 /login` 으로 튕깁니다.
   **CORS 헤더만 더해서는 운영에서 안 고쳐집니다**
3. 같은 이유로 `새 탭에서 열기` 는 **같은 출처**라 잘 돌지만, 그 대가로 결과물 JS 가
   **로그인한 사람의 세션으로 `/api/*` 를 전부 부를 수 있습니다**(검수 실측: `GET /api/state` 200,
   `POST /api/requests` 가 처리기까지 도달). 작업자 AI 가 쓴 코드에 사람의 권한이 넘어갑니다

- `tools/aimem_monitor/static/app.js` · `tools/aimem_monitor/static/style.css`

## 고치는 방법 - **쿠키 대신 경로 티켓**

`/app/` 아래만은 세션 쿠키가 아니라 **경로에 박힌 짧은 HMAC 티켓**으로 인가합니다.
티켓이 경로 **앞쪽**에 있어야 `css/style.css` 같은 상대 경로가 티켓을 그대로 물고 갑니다.

```
/app/웹워들/            ← 사람이 누르는 주소 (세션 쿠키로 인증) → 302
/app/~<티켓>/웹워들/     ← 실제로 열리는 주소 (쿠키 없이 티켓으로 인가)
/app/~<티켓>/웹워들/css/style.css      (상대 경로가 알아서 이 꼴이 됩니다)
```

### 1. `__init__.py` - 계약

```python
#: `/app/` 경로 티켓. 불투명 출처(sandbox) 안에서는 SameSite=Strict 쿠키가 실리지 않아
#: 세션으로는 하위 요청을 인가할 수 없습니다. 그래서 **경로 앞에 박는 짧은 HMAC 티켓**을 씁니다.
#: 티켓 하나는 프로젝트 하나의 정적 파일만, TTL 동안만 열어 줍니다.
PROJECT_APP_TICKET_PREFIX = "~"
PROJECT_APP_TICKET_TTL_SEC = 12 * 3600
```

`SERVER_KEYS` 는 바꾸지 마십시오(응답 모양이 그대로입니다).

### 2. `server.py` - 티켓

```python
def app_ticket(name, exp, key):
    """`<만료 epoch>.<hmac 32자>`. key 는 bytes."""

def app_ticket_ok(ticket, name, key, now=None):
    """티켓이 그 프로젝트에 대해 아직 유효한가. 참/거짓만 돌려주고 예외를 던지지 않습니다."""
```

- mac = `hmac.new(key, f"app.v1.{exp}.{name}".encode(), hashlib.sha256).hexdigest()[:32]`
- 비교는 반드시 **`hmac.compare_digest`**
- 만료(`exp < now`), 꼴이 틀림, 숫자가 아님, 이름이 다름 → 거짓
- 키: `self.access_token.encode()` 가 있으면 그것, 없으면(인증 끈 로컬) **모듈 수준에서 한 번 만든
  `_APP_TICKET_FALLBACK_KEY = secrets.token_bytes(32)`**. 키 고르기는 `_app_ticket_key(self)` 한 함수에 모으십시오.
  **접근 토큰을 갈아 끼우면 티켓도 전부 무효가 됩니다** - 그것이 회수 수단입니다 (주석으로 적으십시오)

### 3. `server.py` - 라우팅

`_APP_RE` 를 티켓을 받도록 고치십시오:

```python
_APP_RE = re.compile(r"\A/app/(?:~(?P<ticket>[^/]{1,80})/)?(?P<name>[^/]{1,400})(?P<slash>/(?P<rel>.*))?\Z", re.S)
```

- **티켓이 없을 때**: 지금처럼 인증을 거친 뒤(아래 4번), `/app/~<새 티켓>/<이름>/<rel>` 로 **302**.
  끝 슬래시가 없으면 거기서도 슬래시를 붙여 보냅니다. 새 티켓의 `exp` 는 `int(time.time()) + TTL`
- **티켓이 있을 때**: `app_ticket_ok()` 로 검사 →
  - 거짓이면 **403** JSON: `{"ok": False, "error": "실행 티켓이 만료됐습니다. 모니터에서 '실행' 을 다시 누르십시오."}`
  - 참이면 `project_app_file()` 로 그대로 내려 줍니다 (**세션을 다시 보지 않습니다**)

### 4. `server.py` - 인증 통과구

`_auth_gate()` 에서 **`/app/~` 로 시작하는 경로는 막지 말고 통과**시키십시오(티켓 검사가 라우팅에서 일어납니다).
`/app/` 으로 시작하되 티켓이 없는 경로는 **지금처럼** `/login` 으로 보냅니다.
`AUTH_EXEMPT_PATHS` 는 건드리지 마십시오 - 거기는 완전 일치 목록입니다.

### 5. `server.py` - 응답 헤더 (결함 1·2 의 나머지 절반)

`/app/` 200 응답에 **둘 다** 붙이십시오.

- `Access-Control-Allow-Origin: null` 과 `Vary: Origin`
  (**`Access-Control-Allow-Credentials` 는 붙이지 마십시오.** 쿠키 없이 보는 것이 요점입니다)
- `app_csp()` 가 만드는 CSP **맨 앞**에 지시어 하나를 더하십시오:
  `sandbox allow-scripts allow-popups allow-modals; ` …(나머지는 지금 그대로)

  이 `sandbox` 지시어가 **새 탭으로 열었을 때도** 문서를 불투명 출처로 만듭니다 → 결함 2 가 닫힙니다.
  (티켓이 있으니 쿠키 없이도 파일은 내려옵니다.)

`app_csp()` 의 서명은 그대로 두고 문자열만 바꾸십시오. 기존 단위 시험이 그 모양을 봅니다 - **고쳐야 하면 고치십시오.**

### 6. `static/app.js` - 안내 문구만

iframe 의 `src` 와 `sandbox` 는 **그대로 두십시오**(서버가 302 로 티켓 주소로 보냅니다).
`새 탭에서 열기` 링크의 `title` 만 고치십시오:

- 지금: `새 탭에서는 기록이 저장됩니다`
- 고친 뒤: `더 큰 화면으로 봅니다. 여기서도 격리되어 기록은 저장되지 않습니다`

맨 위 안내 줄의 `격리된 칸에서 돌아갑니다 - 기록(통계·설정)은 저장되지 않습니다` 는 그대로 두십시오.

### 7. `static/style.css` - 결함 3·4

**결함 3 (미리보기가 패널 밖으로 34px 잘림).** 지금 `.proj-app-frame` 은 `height: min(78vh, 900px)`
인데 패널(`.detail-panel { max-height: 90vh }`) 안에 머리줄·안내 줄·링크가 함께 들어갑니다.
`.detail-body` 를 `display:flex; flex-direction:column` 으로 두고 `.proj-app-frame` 에 `flex: 1 1 auto`
+ `min-height: 320px` 를 주어 **남은 높이에 맞게** 들어가도록 하십시오. 실측 기준:
`#detail-body` 가 `y=71.8 h=753.2` 일 때 iframe 의 아래 끝이 그 안에 들어와야 합니다.
`.detail-body` 의 기존 `overflow-y: auto` 를 지우지 마십시오 - 다른 상세 화면(파일 본문)이 그것을 씁니다.
flex 를 주었을 때 다른 상세 화면이 깨지지 않도록, **`.proj-app-frame` 이 들어 있을 때만** 적용되게
하십시오 (`.detail-body:has(.proj-app-frame)` 를 쓰거나, `openProjectApp` 이 `body.classList.add('detail-app')`
를 붙이고 `.detail-body.detail-app { ... }` 로 받으십시오 - 후자가 확실합니다. 그러면 `app.js` 도 한 줄 바뀝니다).

**결함 4 (좁은 화면 규칙이 죽어 있음).** `@media (max-width: 720px)` 안의 `.proj-app-frame` 규칙이
같은 선택자의 기본 규칙보다 **앞에** 있어 언제나 덮입니다. 미디어 쿼리 규칙을 기본 규칙 **뒤로** 옮기십시오.

### 8. `tests/test_aimem_monitor_app.py` - 시험을 늘립니다

지금 있는 것을 **지우지 말고** 다음을 더하십시오 (6개 이상):

- `app_ticket()` 으로 만든 티켓이 `app_ticket_ok()` 를 통과한다
- 만료된 티켓(`exp` 가 과거)은 거짓
- 글자 하나를 바꾼 티켓은 거짓, **다른 프로젝트 이름**으로는 거짓
- 꼴이 깨진 티켓(`"x"`, `"1.2.3"`, 빈 문자열, 아주 긴 것)에도 **예외가 나지 않고** 거짓
- `app_csp()` 결과가 `sandbox allow-scripts` 로 시작하고 `allow-same-origin` 을 담지 않는다
- 기존 CSP 시험이 깨지면 새 모양에 맞게 고치십시오

**검증 출력 꼬리**를 보고 고치십시오 - 거기에 어느 검사가 왜 빨간지 그대로 찍힙니다.
