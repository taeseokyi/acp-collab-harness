# T-259 `test_fleet_ctl.py`: 한도 로그 정규식의 **부정 사례** (R18-C2)

쓸 파일은 **하나**입니다: `tests/test_fleet_ctl.py` (지금 **38건**).
**`tools/**` 와 다른 `tests/**` 는 읽기만 하고 절대 고치지 마십시오.** 바로 보태십시오.

## 구멍

`tools/fleet_ctl.py` 의 `_round_hit_limit(round)` 은 그 라운드 그래프의 `.log` 줄에서
**`limit` 으로 시작하는 줄**(시각 뒤 첫 낱말)을 찾아 "그 라운드가 사용 한도에 부딪혔다" 고 봅니다.
지금 시험(`test_round_hit_limit_only_when_graph_log_has_limit_line`, `:361` 근처)은
긍정 사례 하나와 `retry-queued` 부정 사례 하나뿐입니다. 그래서 정규식의 **앵커를 풀어도**
(`^...limit` → `.*limit`) 초록입니다 - 줄 **가운데** `limit` 이 든 부정 사례가 없기 때문입니다.

## 보탤 것 (기존 시험 안에 덧붙여도 되고 새 시험으로 떼어내도 됩니다)

로그 줄을 아래로 두고 `_round_hit_limit` 이 **`False`** 인지 `assert` 하십시오.

- `"2026-11-10T22:40:25 retry-queued T-1 - rate limit 문구\n"` ← 줄 가운데 `limit`
- `"2026-11-10T22:40:25 done T-2 - 한도 표시 카드를 만들었다 (limit card)\n"`
- `"2026-11-10T22:40:25 blocked T-3 - NEEDS-FIX: usage limit reached 라는 글이 화면에 보인다\n"`
  ← 보고 글자를 그대로 적은 평범한 로그 줄

그리고 **긍정 사례가 여전히 `True`** 인지도 같이 확인하십시오
(`"2026-11-10T22:40:25 limit T-1 (R-1) - 사용 한도로 끊김\n"`).
`_log` 가 찍는 진짜 꼴은 `fleet_graph.py` 의 `_log(g, f"limit {n['id']} ...")` 입니다 -
`fleet_graph.py` 는 **읽기만** 하십시오.

기존 시험이 임시 저장소에 `.aimem/graph/G-920.json` 과 `G-920.log` 를 꾸미는 방식을
**그대로 쓰십시오.**
