## 고칠 파일 (이 하나뿐입니다)

`tests/browser_monitor_auth.py` (190줄쯤, 지금 검사 6개). **읽을 파일도 이것 하나입니다.**

## 왜

6번 검사 `check_sandbox_isolation` 은 **iframe 안**의 `window.origin == "null"` 을 봅니다. 그런데
그건 iframe 의 `sandbox` 속성만으로도 `null` 이라, 서버 CSP 에서 `sandbox` 지시어를 빼 버려도
이 검사는 초록입니다(적대적 검수가 실제로 빼 보고 확인했습니다). **새 탭(최상위 창)의 격리를
지키는 브라우저 검사가 하나도 없습니다.** 결과물 JS 가 사람의 세션으로 모니터 API 를 부르는 길이
다시 열려도 아무도 모릅니다.

## 무엇을 더하는가

기존 함수 여섯은 **건드리지 말고**, 새 함수 하나를 더해 `run_checks` 의 맨 끝에서 부르십시오.
이 파일에는 이미 `_step(checks, 목표, fn)`(예외를 FAIL 로 적어 주는 감싸개)과 로그인된 컨텍스트
`ctx` 가 있습니다.

```python
def check_top_level_is_opaque(ctx, base, checks):
    """티켓 URL 을 **최상위 창**으로 열어도 격리되는가 (CSP sandbox 지시어).

    iframe 의 sandbox 속성이 아니라 **서버가 보낸 CSP** 가 지키는 몫입니다.
    """
    page = ctx.new_page()
    try:
        page.goto(base + "/app/웹워들/", wait_until="load")     # 서버가 티켓 경로로 302
        url_ok = "/app/~" in page.url
        origin = page.evaluate("() => window.origin")
        cookie = page.evaluate("() => document.cookie")
        reached = page.evaluate(
            "async () => { try { const r = await fetch('/api/state'); return 'status ' + r.status; }"
            " catch (e) { return 'blocked ' + e.name; } }")
        ...
    finally:
        page.close()
```

`checks.ok(목표, 조건, 자세히)` 로 **셋**을 적습니다.

1. `"새 탭(최상위)도 불투명 출처다"` - `url_ok` 이고 `origin == "null"`
2. `"새 탭에서 사람의 세션 쿠키가 보이지 않는다"` - `cookie == ""`
3. `"새 탭의 결과물 코드가 /api/* 를 부르지 못한다"` - `reached` 가 `"blocked "` 로 시작하거나
   상태가 200 이 **아님**. 잰 값을 `자세히` 에 그대로 적으십시오

`run_checks` 끝에 다음 한 줄을 더합니다.

```python
        _step(checks, "새 탭(최상위)도 불투명 출처다",
              lambda: check_top_level_is_opaque(ctx, base, checks))
```
