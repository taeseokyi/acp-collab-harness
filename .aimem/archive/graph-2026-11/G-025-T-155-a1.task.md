# T-155 `gh:` 세션으로 실행 티켓이 나오는지 시험을 쓰십시오

**고칠 파일은 `tests/test_aimem_monitor_app_gate.py` 하나뿐입니다.**
`tools/` 아래는 **읽기만 하고 한 줄도 고치지 마십시오.**

## 왜

태석님이 실제로 쓰는 로그인은 **GitHub 로그인**입니다. 세션 주체가 `gh:<계정>` 꼴이 됩니다.
R11 의 적대적 검수는 **토큰 로그인 세션만** 시험했고 `gh:` 쪽은 아무도 안 봤습니다.
`/app/<이름>/` 이 `gh:` 세션에서도 302(티켓 발급) -> 200 으로 이어지는지,
**허용 목록에서 빠진 계정의 옛 세션 쿠키로는 안 되는지**를 봅니다.

## 먼저 읽을 것 (이 범위만)

- `tests/test_aimem_monitor_app_gate.py` 전체 - 서버를 어떻게 띄우고, 쿠키를 어떻게 넣고,
  302 의 `Location` 을 어떻게 따라가는지. **이 파일의 짜임새를 그대로 따라 하십시오**
- `tools/aimem_monitor/server.py` 에서 `grep -n` 으로 찾아 그 함수들만:
  `sign_session`, `verify_session`, `_subject`, `_auth_gate`,
  `SESSION_COOKIE`, `SESSION_TTL_SEC`, 그리고 **GitHub 허용 목록**을 보는 곳
  (`grep -n "gh:\|allow\|GITHUB" tools/aimem_monitor/server.py`)

**읽지 마십시오:** `AIMEM.md`, `tests/` 의 다른 파일, `projects/` 아래 전부.

## 실제 GitHub 를 부르지 마십시오

네트워크를 쓰지 않습니다. **세션 쿠키를 직접 만듭니다** -
`sign_session(token, "gh:<계정>", exp)` 로 서명한 값을 `SESSION_COOKIE` 에 넣으면
서버는 GitHub 로그인을 끝낸 사람과 똑같이 봅니다. 허용 목록은 서버를 띄울 때 주는
환경변수/설정으로 정합니다 - `grep` 으로 그 이름을 찾아 쓰십시오.

## 쓸 시험 (다섯 개 안팎)

1. **허용된 `gh:` 세션 -> 티켓 발급** - `GET /app/웹워들/` 이 **302** 이고
   `Location` 이 `/app/~<exp>.<mac>/웹워들/` 꼴이다
2. **그 `Location` 을 같은 쿠키로 따라가면 200** 이고 본문이 HTML 이다
3. **허용 목록에 없는 `gh:` 계정의, 서명은 올바른 세션** -> 티켓이 나오지 않는다
   (302 로 `/login` 이거나 401/403. 어느 쪽이든 **`/app/~` 로는 안 간다**)
4. **서명이 틀린 `gh:` 쿠키** -> 티켓이 나오지 않는다
5. **만료된 `gh:` 쿠키**(`exp` 가 지난 값) -> 티켓이 나오지 않는다

3~5 는 모두 **`Location` 에 `/app/~` 가 없다**를 `assertNotIn` 으로 단언하십시오
(상태 코드만 보면 구현이 바뀌었을 때 거짓 초록이 납니다).

## 지켜야 할 것

- 이미 있는 시험은 지우지 말고 더하기만
- 시험이 **제품의 결함을 찾으면**(예: 허용 목록에서 빠진 계정에 티켓이 나온다)
  제품도 시험도 고치지 말고 첫 줄을 `NEEDS-FIX: <무엇이 어디서>` 로 보고하십시오.
  **이것은 중요한 결과입니다 - 숨기지 마십시오**
- 시험은 임시 루트(`tempfile`)에서 돌려 운영 `.aimem/access.log` 를 더럽히지 마십시오
  (이 파일에 이미 그렇게 하는 길이 있습니다)
- **운영 서버(18799)는 재시작하지 마십시오**

## 확인

```
python3 -m unittest discover -s tests -q 2>&1 | tail -3
```

`OK` 이고 시험 수가 T-154 가 끝난 뒤보다 늘어야 합니다.

보고 첫 줄은 `DONE` 또는 `NEEDS-FIX: ...` 또는 `BLOCKED - <이유>` 입니다.
보고 본문에 **허용 목록을 정하는 환경변수/설정 이름**을 적으십시오.
