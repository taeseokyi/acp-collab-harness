## 목표 - 적대적 검수 (읽기 전용)

S1 이 방금 고친 `tools/fleet_graph.py` 를 **깨러** 들어가라. 자기 채점은 자기 사각지대를
영원히 못 본다(`AIMEM.md` `8.0-1`). 네 일은 "괜찮아 보인다" 가 아니라 **재현 가능한 결함**을
가져오는 것이다.

## 쓰기 없음

**파일을 하나도 만들거나 고치지 마라.** 재현은 `python3 -c` / `python3 - <<` 로 메모리와
`tempfile` 안에서만 하라. 특히 `.aimem/graph/` 와 `.aimem/runs/` 의 **실제 파일을 건드리지 마라** -
`fleet_graph.GRAPHS` 와 `fleet.RUNS` 를 임시 디렉터리로 바꿔 놓고 재현하라.

## S1 이 고쳤다고 주장하는 것 (`4.5` 큐 7·8·9번)

1. **단일 실행자 잠금.** `graph_lock(gid)` 컨텍스트 매니저. `.aimem/graph/<gid>.lock` 에
   `fcntl.flock(LOCK_EX|LOCK_NB)`. 못 잡으면 stderr 메시지 + **rc 2**. 잠금 파일은
   `{"pid","started","cmd"}` JSON. **unlink 하지 않는다.** `cmd_run`·`cmd_step` 전체에 건다.
2. **모양 검증 재사용 + 노드 타임아웃.** `cmd_step`/`cmd_run` 이 시작 전에 `validate_graph()`
   한 번, 문제가 있으면 rc 2 로 스폰 없이 종료. 노드 한도는
   `n["timeout_sec"]` → `g["node_timeout_sec"]` → `1800`. 넘으면 `_run_meta(run_id)["pid"]`
   로 SIGTERM → 5초 뒤 SIGKILL, `.lost` 마커 생성, attempt 에 `rc=124`/`state="timeout"`,
   재시도 규칙은 기존 실패와 동일.
3. **보고 첫 줄 BLOCKED 판정.** `report_block_reason(report) -> str|None`.
   첫 비어 있지 않은 줄에서 `상태:`/`**`/`#`/공백을 벗긴 뒤 `BLOCKED`/`NEEDS-LOCK`/
   `NEEDS-APPROVAL`/`NEEDS-*`/`REJECT` 로 시작하면 그 말, 아니면 `None`.
   `step()` 이 `rc==0` 이어도 이것이 `None` 이 아니면 **`done` 금지, `blocked`, 재시도 없음.**

## 특히 노려라 (과거에 여기서 결함이 나왔다)

- **잠금이 실제로 배타적인가.** 같은 프로세스 안에서 두 번 잡으면? (flock 은 같은 fd 가
  아니면 같은 프로세스여도 fd 가 다르면 어떻게 되나 - 실제로 돌려 보라.) 예외가 터져도
  풀리나(`finally`)? `cmd_run` 이 중간에 `SystemExit` 으로 죽으면?
- **잠금 파일을 지우는 길이 남아 있나.** 지우면 다음 실행자가 다른 inode 를 잡아
  **잠금이 무력해진다.** `_save`/`cmd_*` 어디에도 그 길이 없는지 보라.
- **타임아웃이 엉뚱한 프로세스를 죽이나.** `pid` 가 재사용됐을 때는? `pid` 가 `None`/0/
  음수/문자열일 때는? `_run_meta` 가 `None` 을 줄 때는? **`os.kill(0, …)` 은 프로세스
  그룹 전체를 죽인다** - 그 길이 열려 있는지 반드시 확인하라.
- **타임아웃이 관리자 자신을 죽이나.** `pkill -f` 가 다시 들어왔는지 `grep` 하라
  (`AIMEM.md` `8.0-5` 주의 - 실제로 작업자가 자기를 죽인 사례가 있다).
- **`started` 가 깨져 있을 때.** `fromisoformat` 이 터지면 `step()` 전체가 죽나?
  멀쩡한 작업자를 타임아웃으로 오인해 죽이나?
- **`.lost` 마커를 덮어쓰나.** 이미 있는 마커를 덮으면 `reader` 의 경과 고정(T-058)이 깨진다.
- **`report_block_reason` 의 거짓 양성.** 보고 첫 줄이
  `상태: DONE - BLOCKED 되었던 것을 풀었다` 이면? `DONE (이전 시도는 NEEDS-LOCK)` 이면?
  빈 보고(`""`)·`None`·공백만 있는 보고는? 첫 줄이 아주 긴 줄이면?
  **거짓 양성은 멀쩡한 노드를 영원히 `blocked` 로 만든다** - 재시도가 없으므로 복구가 사람 손이다.
- **`report_block_reason` 의 거짓 음성.** `blocked:` (소문자, 콜론)? `> BLOCKED`? `1. BLOCKED`?
  앞에 빈 줄 여러 개?
- **기존 동작 회귀.** 슬롯 바쁨 검사(`_busy_slots`), 고아 스폰 방지(노드마다 `_save`),
  원자적 저장(tmp + `os.replace`), `_ready()` 의 모르는 dep 차단이 **그대로 살아 있나.**
  `validate` 를 앞에 끼우면서 `cmd_step` 의 반환값(rc)이 바뀌어 `fleet_graph.py run` 의
  종료 조건이 달라지지 않았나.
- **빈 그래프·노드 0개**에서 `cmd_run` 이 무한 루프를 도나.

## 검증 명령 (직접 돌려서 출력을 붙여라)

```
python3 -m py_compile tools/fleet_graph.py
python3 -m unittest discover -s tests -q
grep -n "pkill" tools/fleet_graph.py
grep -n "unlink" tools/fleet_graph.py
```

전체 스위트 **기준선은 195건 OK** 다(T-080 이 새 테스트를 더했으면 그보다 많을 수 있다).

## 보고 형식

첫 줄은 `상태: DONE`(검수 완료) 또는 `상태: BLOCKED`(검수를 못 했다).
이어서 **결함 목록**을 아래 꼴로, 심각도 높은 것부터:

```
### 결함 N - <한 줄 제목>  [높음|중간|낮음]
- 어디: tools/fleet_graph.py <함수/행>
- 무엇이 틀렸나: (한 문단)
- 재현: (실제로 돌린 명령과 출력을 그대로. "돌려 보면 ~할 것이다" 는 결함이 아니다)
- 고치는 방향: (한두 줄. 네가 고치지는 마라)
```

결함이 없으면 **없다고 적고, 대신 네가 실제로 돌려 본 적대적 시나리오 목록**을 명령과
출력으로 보여라. "검토했다" 만 적은 보고는 검수가 아니다.
