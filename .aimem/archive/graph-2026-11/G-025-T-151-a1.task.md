**고칠 파일은 `projects/웹워들/tests/test_game.mjs` 하나뿐입니다.** 제품 코드
(`web/js/game.js`)는 **읽기만 하고 고치지 마십시오.**

## 먼저 읽을 것 (이것만)

- `projects/웹워들/tests/test_game.mjs` 전체 - `node:test` 를 어떻게 쓰는지, `hardModeViolation` 을
  이미 어떻게 부르는지
- `projects/웹워들/web/js/game.js` 의 **`hardModeViolation` 함수만** (74행 근처부터 그 함수 끝까지)

**읽지 말 것:** `AIMEM.md`, `ui.js`, `words.js`, `tests/` 의 다른 파일.

## 하드 모드 규칙 (지금 `game.js` 에 들어 있는 것)

`hardModeViolation(guess, rows)` 는 어기면 **한국어 문자열**, 안 어기면 `null` 을 돌려줍니다.
`rows` 는 `[{guess: "crane", scores: [...]}]` 꼴이고 `scores` 값은
`"correct"`/`"present"`/`"absent"` 입니다 (`game.js` 위쪽 상수를 그대로 쓰십시오 - 이미
`test_game.mjs` 가 import 하고 있으면 그것을 쓰고, 아니면 문자열을 직접 적으십시오).

규칙은 셋이고 **이 순서로** 봅니다:

1. 초록 자리는 그대로 - `N번째 글자는 X 이어야 합니다`
2. 드러난 글자 **개수**까지 - 한 개면 `X 가 들어가야 합니다`,
   두 개 이상이면 `X 가 N개 들어가야 합니다 (지금 M개)`
3. 노랑이었던 **그 자리**에 같은 글자를 다시 놓을 수 없음 - `X 는 N번째 자리가 아닙니다`

## 더할 검사 (여섯 개 안팎)

지금 파일의 `test(...)` 짜임새를 그대로 따라 하십시오.

1. **초록 자리 어김** - 1번 규칙이 전처럼 잡히는지 (회귀)
2. **노랑 글자가 아예 빠짐** - `X 가 들어가야 합니다` 가 나오는지 (회귀)
3. **노랑이 둘 드러났는데 하나만 넣음** - 예: 이전 추측에서 같은 글자가 두 자리 모두
   노랑이었는데 다음 추측에 그 글자가 하나뿐이면 `2개 들어가야 합니다` 가 들어간 문자열
4. **노랑이 둘 드러났고 둘을 다 넣음** - `null`
5. **노랑이었던 자리에 같은 글자를 다시 놓음** - `자리가 아닙니다` 가 들어간 문자열
6. **규칙을 다 지킨 추측** - `null`
7. **`rows` 가 빈 배열이거나 `null`** - `null` (첫 줄에는 아무 제약이 없음)

각 검사는 **돌려받은 문자열에 기대하는 조각이 들어 있는지**(`assert.ok(msg.includes(...))`)
로 보십시오 - 문구 전체를 글자 그대로 비교하지 마십시오.
