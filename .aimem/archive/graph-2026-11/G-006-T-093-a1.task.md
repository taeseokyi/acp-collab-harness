## 목표

`tests/test_fleet_graph.py` 는 **21건 중 20건이 통과**한다. 실패하는 1건은 **관리자 브리프의
계약 표가 틀린 것**이다. 그 행을 고치고 두 행을 더한다.

네가 `BLOCKED` 로 보고한 것은 **옳은 판단이었다** - 도구를 고쳐 테스트를 통과시키지 않았다.
관리자가 계약을 고쳤으니 이어서 하라.

쓰기 경로: `tests/test_fleet_graph.py` **하나뿐이다.** `tools/` 아래는 고치지 마라.

---

## (1) 틀린 행을 고쳐라 (`tests/test_fleet_graph.py:197` 근처)

지금 표에 이렇게 들어 있다:

```
'BLOCKED' + 'x'*100000           ->  'BLOCKED'     # 틀림
```

**이것은 `BLOCKEDxxxxx…` 라는 한 낱말이다.** 단어 경계(`(?![A-Za-z0-9_-])`)가 생긴
뒤로는 `None` 이 맞다 - `BLOCKED-FREE 빌드 성공` 을 거르려고 일부러 넣은 경계이고,
`BLOCKEDxxx` 도 같은 이유로 상태가 아니다.

원래 의도는 **"첫 줄이 아주 길어도 터지지 않는다"** 였다. 그러니 **두 행으로 나눠라:**

```
'BLOCKED' + 'x'*100000           ->  None          # 한 낱말이다. 단어 경계가 막는다
'BLOCKED ' + 'x'*100000          ->  'BLOCKED'     # 낱말 뒤가 공백 - 아주 긴 줄에도 터지지 않는다
```

두 행 모두에 **왜 그런지 한 줄 주석**을 달아라. 다음 사람이 "이거 버그 아닌가" 하고
되돌리지 않게.

## (2) 표에 두 행을 더해라 (경계가 진짜로 일하는지)

```
'BLOCKED-FREE 빌드 성공'          ->  None
'BLOCKED: 소유가 아닌 경로'        ->  'BLOCKED'
```

> 둘째 행이 **현재 구현에서 `None` 이면** 고치지 말고 그대로 두고, 보고에 적어라.
> (콜론 뒤 처리는 다른 슬롯이 같은 시각에 손대고 있다.)

## 하지 말 것

- `tools/fleet_graph.py` 를 **절대 고치지 마라.**
- 통과하고 있는 **나머지 20건을 건드리지 마라.**
- 테스트를 "현재 동작에 맞추는" 방향으로 바꾸지 마라. (1) 은 계약이 틀렸던 것이고,
  그 밖에 어긋나는 것이 또 있으면 **고치지 말고 보고하라.**

## 알아 둘 것 - 네 환경의 한계

네 보고에 `discover` 가 `errors=22` 로 나왔다. 그것은 **네 샌드박스가 loopback 소켓을
막아서** `test_aimem_monitor*` 의 HTTP 테스트가 못 도는 것이고, **관리자 환경에서는 전부
통과한다**(실측 217건 OK). `tests.test_fleet_graph` 만 네 판단 근거로 삼아라.

## 완료 판정

```
python3 -m unittest tests.test_fleet_graph -q
```

**21건 이상, 실패 0건**이어야 한다. (`discover` 의 `errors=22` 는 위 사유로 무시하라.)
