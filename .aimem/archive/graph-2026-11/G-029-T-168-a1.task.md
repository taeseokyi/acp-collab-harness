# T-168 요청 트리의 **ETA·진행 상태**를 실제 상태에 맞게 고치십시오

태석님 요청 `Q-261111-0afe`: "요청트리, 요청별 분담트리에서 계획 중이든 완료든 상관없이
'관리자 분담 대기' 가 보입니다. ETA 및 진행상태 기능 점검하고 개선해."

고칠 파일은 셋뿐입니다. 다른 파일은 고치지 마십시오.

- `tools/aimem_monitor/reader.py`
- `tools/aimem_monitor/static/app.js`
- `tests/test_aimem_monitor.py`

## 1. `reader.py` - 진짜 버그 하나

`_estimate()` (327~398행)에서, 요청이 **아직 안 닫혔고 서브태스크가 하나도 없을 때**
`remaining` 이 비어 `eta_sec = 0` 이 됩니다. 그러면 `eta_at = 지금 시각` 이 되어 화면이
**"ETA 지금, 0초 남음"** 이라고 말합니다 - 아무도 시작하지 않은 요청인데 말입니다.

**376~378행**의

```python
    if not remaining:
        eta_sec = 0
        basis = "남은 서브태스크 없음" if subs else "서브태스크 없음 - 분담 후 추정됩니다"
```

를 이렇게 고치십시오.

```python
    if not subs:
        # 분담 전에는 추정할 표본 자체가 없다. 0 을 내면 화면이 "지금 도착" 이라고 말한다
        eta_sec = None
        basis = "분담 전 - 관리자가 서브태스크로 나눈 뒤 추정됩니다"
    elif not remaining:
        eta_sec = 0
        basis = "남은 서브태스크 없음"
```

`progress_pct` 는 지금처럼 `0.0` 으로 두십시오 (프로젝트 진행률 계산이 이 값을 씁니다).

## 2. `app.js` - 화면이 상태에 맞게 말하게

`renderRequests` 안의 **2606~2650행** 만 보면 됩니다.

### 2-1. 새 순수 함수 하나 (`renderRequests` 바로 위에 두십시오)

```js
// 서브태스크가 하나도 없을 때 그 자리에 뭐라고 적을지 - 상태마다 다릅니다 (요청 Q-261111-0afe)
function subtaskEmptyText(req) {
  switch (String(req && req.status || '').toUpperCase()) {
    case 'NEW': return '관리자 분담 대기';
    case 'PLANNED': return '분담 계획됨 - 아직 서브태스크가 없습니다';
    case 'IN-PROGRESS': return '진행 중 - 서브태스크 없이 관리자가 직접 하는 일입니다';
    case 'DONE': return '서브태스크 없이 끝난 요청입니다';
    case 'REJECTED': return '서브태스크 없이 거절된 요청입니다';
    default: return '서브태스크 없음';
  }
}
```

### 2-2. 접힌 줄 (2611행 근처)

지금:

```js
    line.textContent = (pct === null ? '' : fmtPct(pct) + ' · ') + '서브태스크 ' + subs + '건';
```

→ 서브태스크가 0건이면 건수 대신 상태 문구를 씁니다.

```js
    line.textContent = (pct === null ? '' : fmtPct(pct) + ' · ')
      + (subs ? '서브태스크 ' + subs + '건' : subtaskEmptyText(req));
```

### 2-3. ETA 칸 (2628~2631행 근처)

지금 `etaText(req)` 가 `'-'` 를 돌려주면 화면에 `ETA -` 가 뜹니다. `ETA 미정` 으로 바꿉니다.

```js
    const closed = REQ_CLOSED.has(String(req.status || '').toUpperCase());
    const eta = etaText(req);
    etaLabel.textContent = closed ? '종료' : (eta === '-' ? 'ETA 미정' : 'ETA ' + eta);
```

### 2-4. 펼친 본문의 빈 메시지 (2646행 근처)

```js
      body.appendChild(emptyP('관리자 분담 대기'));
```

→

```js
      body.appendChild(emptyP(subtaskEmptyText(req)));
```

**`app.js` 의 다른 곳은 건드리지 마십시오.**

## 3. `tests/test_aimem_monitor.py` 에 검사 두 개 더하기

`reader._estimate` 를 직접 부르는 검사입니다. 기존 검사 꼴을 보고 같은 클래스 아무 데나 더하십시오.

```python
    def test_eta_none_before_split(self):
        # 분담 전(서브태스크 0) 요청은 ETA 를 0 이 아니라 '없음' 으로 낸다
        import datetime
        eta = {"by_harness": {}, "overall": {"median_sec": 100, "samples": 3}}
        out = reader._estimate({"status": "NEW", "subtasks": []}, {}, {}, eta, datetime.datetime.now())
        self.assertIsNone(out["eta_sec"])
        self.assertIsNone(out["eta_at"])
        self.assertIn("분담 전", out["eta_basis"])

    def test_eta_zero_when_all_subtasks_done(self):
        # 서브태스크가 있고 전부 DONE 이면 ETA 0 이다
        import datetime
        eta = {"by_harness": {}, "overall": {"median_sec": 100, "samples": 3}}
        req = {"status": "IN-PROGRESS", "subtasks": [{"id": "T-1", "status": "DONE", "slot": "S2"}]}
        out = reader._estimate(req, {}, {}, eta, datetime.datetime.now())
        self.assertEqual(out["eta_sec"], 0)
```

그 파일이 `reader` 를 어떻게 import 하는지 확인하고 **그 이름을 그대로** 쓰십시오.
`import datetime` 이 파일 맨 위에 이미 있으면 함수 안의 `import` 는 지우십시오.
