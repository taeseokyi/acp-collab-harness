## 목표

태석님 요청 `Q-261110-549a`: **"AIMEM 함대 모니터 페이지가 너무 길어졌어. UI 구조 탭방식으로
변경해."** 지금 한 화면에 카드 6개가 세로로 길게 이어져 있다. **탭으로 묶는다.**

## 쓰기 경로

세 파일이다. 모두 `tools/aimem_monitor/static/` 아래다.

- `tools/aimem_monitor/static/index.html`
- `tools/aimem_monitor/static/app.js`
- `tools/aimem_monitor/static/style.css`

이 밖의 파일은 읽기만 하라. **서버·reader·테스트를 고치지 마라.**

## 태석님이 지정한 탭 그룹 (이대로 하라)

| 탭 | 들어가는 기존 섹션 |
| --- | --- |
| **함대** | `#fleet-section`(1. 함대 현황) + `#kisti-section`(KISTI LLM 서버) + `#runs-section`(2. 작업자 실행 상태) |
| **보드·큐** | `#board-section`(3. 보드와 큐 = 작업 보드 + 대기 큐) |
| **요청 트리** | `#requests-section`(5. 요청별 분담 트리 = 그래프 목록 + 요청 목록) |

**`#request-form-section`(4. 작업 요청)은 탭에 넣지 않는다.** 태석님 요구:
**"작업 요청은 어떤 탭에서든 항상 열려서 요청할 수 있게."** 탭 묶음 **바깥**에 두고
어느 탭에서도 보이게 하라(탭 목록 아래나 위, 어느 쪽이든 좋다).

## 구현 규칙

- **섹션의 내용·DOM id·클래스 이름을 바꾸지 마라.** `aimem-meta`, `slots-table-wrap`,
  `kisti-card`, `runs-table-wrap`, `board-table-wrap`, `queue-table-wrap`,
  `graphs-list`, `requests-list`, `request-form`, `detail-overlay` 등은 **그대로** 둔다.
  `app.js` 의 렌더 함수와 CSS 가 그 이름을 본다. 섹션을 **감싸기만** 하라.
- 탭 버튼은 `<button type="button" role="tab">` 이고 패널은 `role="tabpanel"` 이다.
  - 선택된 버튼에 `aria-selected="true"`, 나머지는 `"false"`.
  - 버튼의 `aria-controls` 가 패널 id 를, 패널의 `aria-labelledby` 가 버튼 id 를 가리킨다.
  - **안 보이는 패널은 `hidden` 속성**으로 감춘다(`display:none` 을 JS 로 직접 건드리지 마라).
  - 탭 목록은 `role="tablist"`.
- **키보드:** 탭 목록 안에서 `←`/`→` 로 탭을 옮기고 `Home`/`End` 로 처음·끝으로.
  선택되지 않은 탭 버튼은 `tabindex="-1"`, 선택된 것만 `tabindex="0"`
  (roving tabindex). 탭이 바뀌면 그 버튼에 `focus()`.
- **렌더는 탭과 무관하게 돈다.** `renderAll(data)` 는 지금처럼 **모든** 섹션을 그린다.
  숨은 패널도 그려 둬야 탭을 눌렀을 때 바로 보인다. **렌더 함수를 건드리지 마라.**
- **선택한 탭을 기억한다.** `location.hash`(예: `#tab=board`)에 적고, 로드할 때 읽어 복원한다.
  해시가 없거나 모르는 값이면 첫 탭(**함대**)이다.
  `?demo=1` 같은 기존 쿼리스트링을 **지우지 마라**(해시만 쓴다).
- **CSS:** 탭 버튼 줄, 선택 표시, 패널 여백만 더하라. 이미 있는 색 토큰(`--st-*` / `:root` 의
  변수)을 **그대로 쓰고 hex 를 새로 박지 마라.** 밝은 모드·어두운 모드 둘 다에서 읽혀야 한다.
  화면이 좁으면 탭 줄이 가로 스크롤되게 하라(버튼이 깨져 겹치면 안 된다).

## 하지 말 것

- 새 라이브러리·프레임워크·빌드 단계를 들이지 마라. **바닐라 JS + 정적 CSS 그대로**다.
- `app.js` 의 `resolveBoardRunId`, `rowRunIds`, `openDetail`, `closeDetail`,
  `detailReturnFocus`, KISTI `pending`/`stale` 뱃지를 **지우거나 고치지 마라.** 직전
  라운드에 들어간 것들이다.
- 상세 패널(`#detail-overlay`)은 탭 **바깥**에 있다. 그대로 둬라.

## 완료 판정

```
node --check tools/aimem_monitor/static/app.js
grep -c 'role="tab"' tools/aimem_monitor/static/index.html
grep -n 'role="tablist"' tools/aimem_monitor/static/index.html
grep -n 'request-form-section' tools/aimem_monitor/static/index.html
grep -n 'resolveBoardRunId\|detailReturnFocus' tools/aimem_monitor/static/app.js
grep -nE '#[0-9a-fA-F]{3,6}\b' tools/aimem_monitor/static/style.css | tail -5
```

- 첫 명령 rc 0.
- `role="tab"` 이 **3개**(세 탭).
- `role="tablist"` 가 1개.
- `request-form-section` 이 **탭 패널 바깥**에 있다는 것을 보고에서 구조로 설명하라.
- `resolveBoardRunId` 와 `detailReturnFocus` 가 **아직 있다**(직전 산출물을 안 지웠다는 확인).
- 마지막 명령은 **네가 새로 넣은 hex 가 없다**는 확인용이다. 기존 줄만 나와야 한다.

그리고 탭 전환 로직을 node 로 직접 돌려 보여라 - 전환 함수가 DOM 에 의존하면,
**`hidden` 을 켜고 끄는 순수 부분**을 작은 가짜 객체로 흉내 내서
`함대 → 보드·큐 → 요청 트리` 세 번 전환할 때 **보이는 패널이 항상 정확히 1개**임을 찍어라.
