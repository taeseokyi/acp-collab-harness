# T-184 웹워들 **미리보기 기록 저장**을 진짜 브라우저로 재십시오

새로 만들 파일은 **`tests/browser_monitor_preview.py` 하나**입니다. 다른 파일은 만들지도 고치지도 마십시오.

## 왜

웹워들의 마지막 목표 - *"모니터 안에서 실행해도 통계·설정이 남는다"* - 는 기능이 다 들어 있고
적대적 검수·재검수까지 끝났는데 **브라우저로 잰 증거가 0** 이라 아직 체크하지 못했습니다.
`app.js` 의 보관함 코드는 변이 10개 중 0개가 잡힙니다. 그 구멍을 메우는 것이 이 노드입니다.

## 읽을 것 (이것만)

- `tests/browser_monitor_app.py` 전부 - `monitor_server()` 틀, `openProjectApp` 을 여는 길,
  `Checks` 요약 꼴을 그대로 베낍니다. **그 파일은 고치지 마십시오**
- `tools/aimem_monitor/static/app.js` 의 `openProjectApp` 과 그 안의 `aimem.app.v1.` 보관함 처리 **만**
- `projects/웹워들/web/js/storage.js` 의 `init()` **만**

**읽지 마십시오:** `AIMEM.md`, `tools/aimem_monitor/*.py`, `projects/웹워들` 의 나머지

## 무엇을 재는가

모니터 페이지 `/` 를 열고 **'실행' 을 눌러 격리 칸(iframe) 안에서** 재야 합니다.
`/app/웹워들/` 을 최상위로 바로 열면 보관함 길이 **한 줄도 돌지 않습니다** - 그러면 가짜 초록입니다.

격리 칸은 `allow-scripts` 만 있고 `allow-same-origin` 이 없어 `localStorage` 가 막힙니다.
그래서 `storage.js` 가 부모(모니터 페이지)에게 `{aimem:'store.v1',op:'ready'}` 를 보내고
부모가 `aimem.app.v1.<프로젝트 이름>` 칸을 빌려 줍니다. 쓰기는 `op:'put'` 으로 부모에게 흐릅니다.

## 더할 검사

### 1. 한 판 두고 패널을 닫았다 다시 열어도 그 줄이 남는다 (검사 셋)

클로드 코드가 2026-11-11 21:58 에 운영 화면에서 손으로 확인한 길입니다. 이것을 검사로 굳힙니다.

- 모니터 `/` 를 열고 프로젝트 `웹워들` 의 '실행' 을 눌러 iframe 이 보일 때까지 기다립니다
- iframe 안에서 `CRANE` 을 **물리 키보드로** 칩니다(`frame.keyboard` 가 아니라 `page.keyboard` 로
  iframe 에 초점을 준 뒤 치거나, 화면 키보드 단추를 눌러도 됩니다) 그리고 `Enter`
- 첫 줄 다섯 칸이 **그려진 글자**로 `C R A N E` 인지 `inner_text()` 로 확인합니다 (검사 ①)
- 패널을 닫고(`openArchivePanel` 아님 - 미리보기 패널의 닫기), 다시 '실행' 을 눌러 엽니다
- 새 iframe 의 첫 줄이 다시 `C R A N E` 이다 (검사 ②)
- 통계 화면이나 `settings` 가 함께 남아 있다 - 어두운 테마를 켠 뒤 닫았다 열면 켜진 채다 (검사 ③)

### 2. 가짜 두 번째 프로젝트와 칸이 섞이지 않는다 (검사 둘)

- 임시 저장소를 만들어 `projects/웹워들/` 과 **이름만 다른 가짜 프로젝트**를 함께 두십시오
  (가짜 쪽은 `app.json` 과 `index.html` 한 장이면 됩니다. 그 `index.html` 이 부모에게
  `{aimem:'store.v1',op:'ready'}` 를 보내고 받은 스냅숏을 화면에 찍게 하십시오)
- 가짜 프로젝트를 열었을 때 받은 스냅숏에 **웹워들이 저장한 키가 하나도 없다** (검사 ④)
- 가짜 프로젝트에서 `put` 한 값이 웹워들 쪽 칸에 나타나지 않는다 (검사 ⑤)
- 임시 저장소를 쓸 때 **`.aimem/tls/` 는 복사하지 마십시오.** 다 쓰면 그 `/tmp` 폴더를 `rm -rf` 하십시오
  (자기가 만든 `/tmp` 폴더를 지우는 것은 금지 대상이 아닙니다)

## 주의

- 브라우저는 `chromium` 만 씁니다
- **운영 모니터(18799)를 부르지 마십시오.** 임시 포트에 띄운 서버만 씁니다
- `page.wait_for_timeout` 으로 때우지 말고 `wait_for_selector` / `expect` 로 기다리십시오.
  `storage.js` 는 스냅숏을 **최대 500ms** 기다리므로 첫 글자를 치기 전에 보드가 그려졌는지 확인하십시오
- 검사 하나가 막히면 **거기서 멈추지 말고** 나머지를 다 돌린 뒤 요약을 찍으십시오
  (`tests/browser_monitor_app.py` 의 `Checks` 가 그렇게 돼 있습니다)
- **제품을 고치지 마십시오.** 검사가 결함을 찾으면 고치지 말고 첫 줄을 `NEEDS-FIX: <무엇이 어디서>` 로
  보고하십시오 - 뒤의 노드가 고칩니다
- 파일은 **260줄 안쪽**. 다 못 하겠으면 **한 검사라도 진짜로 돌게** 하고 나머지는 `PARTIAL` 로 보고하십시오

## 검증

```bash
python3 tests/browser_monitor_preview.py
```

마지막 줄이 `통과 N / 전체 N` 이고 둘이 같아야 하며 `전체` 가 **5 이상**이어야 합니다.

## 보고

첫 줄은 `DONE` / `PARTIAL` / `BLOCKED` / `NEEDS-FIX: …` 중 하나만. 그 아래 네 줄 안쪽으로
검사가 무엇을 재는지와 마지막 `통과 N / 전체 N` 줄.
