# T-212 상한 넘는 티켓 칸이 **프로젝트 이름으로 넘어가는** 것을 막으십시오 (T-210 NEEDS-FIX 후속)

고칠 파일은 **`tools/aimem_monitor/server.py`** 하나입니다.

## 읽을 것 (이것만)

- `tools/aimem_monitor/server.py` 의 `_APP_RE`(2114행) · `_auth_gate()` 의 티켓 분기(2490~2505행) ·
  `/app/` 라우팅(2619행부터)
- `tools/aimem_monitor/__init__.py` 의 `PROJECT_NAME_RE`(167행) - **읽기만**
- `tests/test_monitor_ticket_regress.py` 의 `test_ticket_longer_than_160_is_not_routed` - **읽기만**

**읽지 마십시오:** `AIMEM.md` 본문, `tools/aimem_db.py`, `projects/**`, `rounds/**`.

## 무엇이 잘못됐나 (앞 태스크 T-210 이 찾아 `NEEDS-FIX` 로 보고)

```
_APP_RE.match("/app/~" + "a"*161 + "/알파/")
  -> ticket=None, name="~aaaa…"(161자)
```

티켓 칸의 상한 `{1,160}` 을 넘으면 선택적 티켓 그룹이 **통째로 건너뛰어지고**,
`~aaa…` 가 **프로젝트 이름 칸으로 넘어갑니다.** 지금 당장 새는 것은 없습니다 -
인증을 켠 길은 `_auth_gate` 가 `ticket is None` 이라 404 를 내고, 라우팅도 `_PROJECT_RE` 에서 404 입니다.
**하지만** 상한이 라우팅 수준에서 지켜진다는 전제가 깨져 있고, 한 경로가 두 가지로 읽히는 길이 남아 있습니다.

## 고칠 것 - 이름 칸이 `~` 로 시작하지 못하게

`PROJECT_NAME_RE` 는 이미 `\A[0-9A-Za-z가-힣]` 으로 시작합니다. 즉 **`~` 로 시작하는 프로젝트 이름은
존재할 수 없습니다.** `_APP_RE` 의 이름 칸에 그 사실을 적으십시오.

```python
_APP_RE = re.compile(
    r"\A/app/(?:~(?P<ticket>[^/]{1,160})/)?(?P<name>[^/~][^/]{0,399})(?P<slash>/(?P<rel>.*))?\Z", re.S)
```

- 길이는 그대로 **1~400자**입니다(`[^/~]` 한 자 + `[^/]{0,399}`)
- 이렇게 하면 `/app/~<161자>/알파/` 는 **`_APP_RE` 가 아예 None** 이 됩니다
- `_auth_gate` 와 라우팅 **둘 다** `am` 이 None 이 되는 길을 지납니다.
  `_auth_gate` 는 지금도 `am` 이 없으면 404 를 내므로 그대로 두면 됩니다.
  라우팅에서 `am` 이 None 이면 그 뒤의 처리로 떨어져 **404** 가 나와야 합니다 - 실제로 그런지 확인하고,
  500 이나 200 이 나오면 그 자리를 고치십시오

**이것 말고는 아무것도 바꾸지 마십시오.** 티켓 꼴·감사·회수는 앞 태스크들이 이미 고쳤습니다.
