# T-206 거절이 감사에 안 남는 것과 억제 키를 고치십시오 (큐 2 D5 · 큐 3 D3·D4)

고칠 파일은 **`tools/aimem_monitor/server.py`** 하나입니다. 시험 셋은 깨지면 고쳐도 됩니다.

## 읽을 것 (이것만)

- `tools/aimem_monitor/server.py` 의 `audit()` · `_audit_revoked()` (655~690행 근처) ·
  `_REVOKED_AUDIT_MIN_SEC` 둘레의 전역들(605~612행) · `_TICKET_LOG_RE`(134행) ·
  `Handler._audit()` · `_subject()`(2330~2360행) · `/app/` 티켓 처리(2556~2600행)
- 재현기 `.aimem/graph/verify/r16_audit.py` - **무엇을 요구하는지 여기 다 적혀 있습니다.** 읽으십시오.
  **고칠 수는 없습니다**(쓰기 범위 밖)

**읽지 마십시오:** `AIMEM.md` 본문, `tools/aimem_db.py`, `projects/**`, 다른 `rounds/**`.

## 무엇이 잘못됐나 (R15 적대적 검수 D3·D4·D5)

1. **D5** - 티켓 403 세 갈래(꼴이 틀림 · 서명·만료 틀림 · 남의 주체)와 **서명이 틀린 쿠키**,
   **틀린 Bearer** 가 감사 로그(`.aimem/access.log`)에 **한 줄도 안 남습니다.**
   남는 것은 `_audit_revoked` 하나뿐입니다
2. **D3** - 억제 키가 `(주체, ip)` 라 **출발 주소만 바꾸면 억제 없이 매번 기록**됩니다. 로그를 불릴 수 있습니다
3. **D4** - 거꾸로 프록시 뒤라 ip 가 같으면 **남의 첫 사용이 내 폴링 줄에 묻힙니다.**
   기록에 **경로도 메서드도 없어** 무엇이 거절됐는지 알 수 없습니다

## 고칠 것

### 1. `_audit_denied` 를 만들고 `_audit_revoked` 를 그 위에 얹으십시오

```python
def _audit_denied(root, event, ip, subject, path, method="GET"):
    """거절 한 건을 감사에 남긴다.

    억제 키는 `(event, subject, path, method)` - **ip 는 넣지 않는다**(D3).
    억제된 동안의 건수를 세어 다음에 남길 때 detail 에 `생략 N건` 으로 싣는다.
    """
```

- 억제 간격은 지금처럼 `_REVOKED_AUDIT_MIN_SEC`(60초), 표 상한도 `_REVOKED_AUDIT_MAX`(256) 를 그대로 쓰십시오
- `detail` 은 **`f"{method} {path}"`** 로 시작해야 합니다(억제 건수가 있으면 뒤에 ` 생략 N건`,
  회수 같은 사유가 있으면 그 뒤에 한마디). 재현기가 줄 안에 `GET` 과 `/app/` 이 있는지 봅니다
- **경로에서 티켓을 가리십시오:** `path = _TICKET_LOG_RE.sub("/app/~***", path)`.
  감사 줄에 티켓 문자열이 그대로 들어가면 안 됩니다 (재현기가 봅니다)
- `_audit_revoked(root, ip, subject)` 는 지우지 말고 **`_audit_denied(root, "github-revoked", ...)`
  를 부르는 얇은 껍데기**로 바꾸십시오. 부르는 자리에 경로·메서드를 넘기도록 인자를 늘려도 됩니다

### 2. 거절마다 한 줄씩 남기십시오 (D5)

이벤트 이름은 **이대로** 쓰십시오 (재현기와 뒤 라운드의 시험이 이 이름을 봅니다).

| 어디 | 이벤트 | detail 의 사유 |
| ---- | ------ | ------------- |
| 티켓 꼴이 틀림 (`_app_ticket_parts` 가 None) | `app-ticket-bad` | `형식` |
| 서명·만료가 틀림 (`app_ticket_ok` False) | `app-ticket-bad` | `서명·만료` |
| `require_auth` 인데 주체가 자리표 `-` | `app-ticket-bad` | `무주체` |
| 자격 주체 ≠ 티켓 주체 | `app-ticket-bad` | `주체 불일치` |
| 허용 목록 밖 gh 주체 | `github-revoked` (그대로) | `허용 목록 밖` |
| **쿠키가 실려 있는데** `verify_session` 이 None | `session-bad` | `서명·만료` |
| `Authorization: Bearer` 가 토큰과 다름 | `token-bad` | `토큰 불일치` |

**조심할 것 - 폴링으로 로그를 불리면 안 됩니다.**
쿠키도 Bearer 도 **아예 없는** 평범한 요청은 **절대 남기지 마십시오**(재현기가 이것도 봅니다).
`_subject()` 는 모든 요청에서 불립니다. 쿠키 헤더가 **있을 때만** `session-bad` 를 남기십시오.
