# T-189 **두 번 적히는 것·버려지는 칸·부분 문자열 확인·낡은 스냅샷**을 고치십시오

고칠 파일은 **`tools/aimem_db.py` 하나**입니다. 다른 파일은 고치지 마십시오.
앞 두 노드(T-187·T-188)가 같은 파일을 고쳤습니다. **그것을 지우지 말고 이어서 고치십시오.**

> **먼저 읽으십시오 - 이 노드는 한 번 실패했습니다.** 앞 시도가 결함 3·7·8·12 를 고쳤지만 두 가지가 남았습니다.
> (가) 이벤트 아카이브에 `rev` 가 **늘 `null`** 로 적힙니다 - `archive_plan` 이 `rev` 를 안 담기 때문입니다.
> (나) 정리 끝에 부르는 `render()` 가 **운영 저장소의 `AIMEM-state.md` 와 `.aimem/handoff.md` 를 덮어썼습니다.**
> 아래 「새로 드러난 결함」 두 항목이 그것이고, **이번 노드에서 반드시 함께 고쳐야 합니다.**
> 그리고 `tests/test_aimem_db_cli.py` 의 검사 하나가 옛 `events-<월>.md` 를 기대해 빨갛습니다 -
> **그 검사는 고치지 마십시오.** 다음 노드(다른 슬롯)가 고칩니다. 전체 시험에서 **그 파일만** 빨간 것은 괜찮습니다.

## 읽을 것 (이것만)

- `tools/aimem_db.py` 의 `archive_apply` 전체와 `_sync_handoff_files`(110~130행 근처)
- 같은 파일의 `cmd_render` / `render` 가 무엇을 쓰는지 **이름만**

**읽지 마십시오:** `AIMEM.md`, `tools/aimem_monitor/**`, `tests/**`, `projects/**`

## 결함 8 (중간, 실제 손실) - 핸드오프 확인이 부분 문자열이다

`line in text` 로 봅니다. 그래서 **이미 적힌 다른 줄의 앞부분인 줄**은 "들어 있다" 로 판정되어
**아카이브에 쓰지 않고 DB 에서 지웁니다.** 계획이 최신 먼저라 `…작업 12` 가 먼저 적히고
`…작업 1` 은 안 적힌 채 사라집니다(검수 S10: `'작업 1' 줄 그대로 있나: False`).

**고칠 것:** 확인을 **줄 단위 일치**로 바꾸십시오 - `line in text.splitlines()`.
같은 꼴이 `_sync_handoff_files` 의 122행 근처(`if line not in old`)에도 있으니 **거기도 함께** 고치십시오.

## 결함 3 (중간) - 중간에 죽은 뒤 다시 돌리면 두 번 적힌다

태스크(988~994행)·이벤트(1072~1079행)·로그(1129~1140행) 모두 "덧붙이고 → 들어갔나 확인 → 원본 지우기"
라서, 지우기 직전에 죽으면 다음 실행 때 **또** 덧붙습니다.

**고칠 것:** 덧붙이기 **전에** "이미 그 줄이 있나" 를 보고 있으면 건너뛰십시오(핸드오프와 같은 수준).
- 태스크: `f"| {r['id']} |"` 가 이미 있으면 안 씁니다
- 이벤트: 표식이 이미 있으면 안 씁니다
- 로그: 옮길 줄이 아카이브 파일에 **그대로 이어서** 들어 있으면 안 씁니다
  (줄 하나하나가 아니라 묶음 단위로 보십시오 - 같은 줄이 여러 번 찍히는 로그가 있습니다.
  묶음 전체 문자열이 끝부분과 같으면 건너뜁니다)

## 결함 7 (낮음~중간) - 이벤트 아카이브가 `rev` 칸을 버리고 줄바꿈을 편다

아카이브 줄로 원래 행을 되만들 수 없습니다. **"지우지 않고 옮긴다" 가 한 칸만큼 깨집니다.**

**고칠 것:** 이벤트 아카이브를 `.aimem/archive/events-<YYYY-MM>.jsonl` 로 쓰십시오 -
한 줄에 `json.dumps({"seq","at","actor","rev","kind","body"}, ensure_ascii=False)` 그대로,
**모든 칸을 원문 그대로**(줄바꿈도 JSON 안에 그대로 남습니다).
확인은 그 파일을 다시 읽어 각 줄을 `json.loads` 한 `seq` 집합으로 합니다
(결함 11 대비로 `at` 도 함께 봅니다 - `(seq, at)` 쌍이 맞아야 "들어갔다"입니다).
**사람이 읽을 `.md` 는 더 만들지 마십시오** - 하나면 됩니다. 이미 만들어진 `events-*.md` 가 있으면 그대로 두십시오.

## 결함 12 (낮음) - 정리 끝에 `render` 를 안 부른다

`AIMEM-state.md` 는 최근 이벤트 50개를 담으므로 이벤트를 내리면 바로 낡고 린터가 걸립니다.

**고칠 것:** `archive_apply` 가 무엇이든 옮겼으면 **맨 마지막에**(`VACUUM` 뒤) 스냅샷을 다시 쓰십시오.
같은 파일의 render 경로를 그대로 부르고, 실패해도 정리는 성공으로 두되(`try/except Exception`)
그 사실을 `out["render_error"]` 에 적으십시오.

## 새로 드러난 결함 가 - `plan["events"]` 가 `rev` 를 안 담는다

`archive_plan` 의 이벤트 묶음이 `SELECT seq, at, actor, kind, body` 라 **`rev` 가 없습니다.**
그래서 `.jsonl` 에 `"rev": null` 이 적히고, 결함 7 을 고쳤다고 해도 칸은 여전히 버려집니다.

**고칠 것:** `SELECT seq, at, actor, rev, kind, body` 로 바꾸고 `plan["events"]` 의 각 항목에 `rev` 를 담으십시오.

## 새로 드러난 결함 나 (높음) - `render()` 가 **운영 저장소**를 덮어쓴다

`STATE_MD = ROOT / "AIMEM-state.md"` 가 **207행, 모듈을 읽을 때** 굳습니다. 시험은
`mock.patch.object(aimem_db, "ROOT", 임시폴더)` 로 `ROOT` 만 바꾸므로 `STATE_MD` 는 그대로
**진짜 저장소**를 가리킵니다. 그래서 정리 끝에 `render()` 를 부르는 순간, 임시 DB 의 내용이
**운영 `AIMEM-state.md` 와 `.aimem/handoff.md` 를 덮어썼습니다.** (2026-11-12 00:57 에 실제로 벌어져
관리자가 `render` 로 되살렸습니다. 345줄이 40줄이 됐습니다.)

**고칠 것:**
- `render()` 안에서 쓸 경로를 **부를 때** `ROOT / "AIMEM-state.md"` 로 만드십시오.
  `STATE_MD` 상수는 지우지 말고 남겨 두되(다른 곳이 쓸 수 있습니다), **쓰기는 부를 때 만든 경로로** 합니다
- 같은 눈으로 `archive_apply` 와 `_sync_handoff_files` 가 쓰는 경로도 보십시오 -
  `.aimem/archive/`, `.aimem/handoff.md` 는 모두 **부를 때** `ROOT` 에서 만들어야 합니다
  (`HANDOFF` 도 모듈 상수입니다 - 그 함수 안에서 `ROOT / ".aimem" / "handoff.md"` 로 만드십시오)
- 다른 모듈 상수가 `ROOT` 에서 미리 만들어져 있으면 **이 세 길이 쓰는 것만** 고치십시오.
  관계없는 곳을 건드리지 마십시오
