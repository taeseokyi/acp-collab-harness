## 풀어야 할 문제

함대 모니터(`tools/aimem_monitor/`)는 프로젝트 결과물을 `/app/<이름>/` 으로 내려 주고,
화면에서는 **격리된 칸**(`sandbox` iframe + CSP `sandbox` 지시어)에 띄웁니다. 그래서
결과물의 출처가 **불투명(opaque)** 해지고 `localStorage` 가 막힙니다. 웹워들은
`web/js/storage.js` 가 막히면 메모리로 넘어가게 돼 있어 게임은 돌지만,
**통계·설정·진행 중인 판이 새로 고치면 사라지고 도움말이 매번 뜹니다.**

격리는 **일부러 고른 것**입니다. 같은 출처로 띄우면 결과물 JS 가 로그인한 사람의 세션으로
모니터 API(`/api/...`)와 쿠키에 닿습니다(R10 적대적 검수 결함 2, R11 검수 A 의 인증 우회).
**그 성질을 잃지 않으면서** 기록만 남게 하는 길을 설계하십시오.

## 문서에 반드시 있어야 할 것 (이 차례로, 각 절에 제목을 다십시오)

1. **지금 무엇이 막혀 있나** - 격리 칸에서 `localStorage` 가 어떤 예외를 내는지,
   `storage.js` 가 지금 어떻게 넘어가는지. 실제 코드 줄을 인용
2. **주고받을 것** - 메시지 두 종류면 충분한지, 꼴은 무엇인지. 구체적인 JSON 예를 적으십시오.
   키 이름·값의 자료형·크기 상한을 못박습니다
3. **모니터가 받을 때 보는 것** - `event.origin` 과 `event.source` 를 어떻게 보는지
   (불투명 출처는 `origin` 이 `"null"` 입니다 - 그 사실을 똑바로 다루십시오),
   메시지 크기 상한, 키 이름 허용 목록, 자료형 검사. **왜 그 검사만으로 충분한지**
4. **프로젝트끼리 섞이지 않게** - 저장소를 프로젝트 이름으로 어떻게 나누는지.
   `../` 나 이상한 이름이 들어와도 다른 프로젝트 칸에 닿지 못하는 근거
5. **어디에 남기나** - 모니터의 `localStorage`(브라우저별) 인지 서버인지. 서버라면
   인증·용량·누가 쓰나를 적고, **서버는 고르지 않기를 권합니다**(모니터 API 가 늘어납니다)
6. **새 길이 생기지 않는다는 근거** - 이 설계가 끝난 뒤에도 결과물 JS 가
   (a) 모니터 API 를 부를 수 없고 (b) 세션 쿠키를 읽을 수 없고 (c) 실행 티켓을 얻을 수 없고
   (d) 다른 프로젝트의 기록을 읽거나 쓸 수 없다는 것을, **무엇이 그것을 막는지** 하나씩
7. **무엇이 바뀌나** - 파일별로 몇 줄쯤, 무슨 검사가 필요한지 (목록만)
8. **고르지 않은 길과 그 이유** - 적어도 둘 (예: 같은 출처로 띄우기, 서버 저장)
9. **남은 물음** - 설계만으로는 못 정한 것
