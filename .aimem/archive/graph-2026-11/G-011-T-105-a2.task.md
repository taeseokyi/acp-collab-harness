# T-105 웹워들 브라우저 검증 1 - 공용 하네스 + 핵심 한 판

## 배경

`projects/웹워들/` 에 워들 한 벌이 다 있고 로직 테스트도 초록인데, **아직 아무도 브라우저로 화면을
본 적이 없습니다.** 이번 라운드의 할 일은 실제 크로미움으로 한 판을 두어 보고 화면이 정말 되는지
증거를 남기는 것입니다. 당신은 그 첫 번째이자 뒤따르는 두 스크립트가 쓸 **공용 하네스**를 만듭니다.

## 만들 파일 (이 둘만 - 다른 파일은 모두 남의 것입니다)

1. `projects/웹워들/tests/browser_harness.py`
2. `projects/웹워들/tests/browser_core.py`

`web/` 아래, `tests/` 의 다른 파일, `serve.py` 는 **고치지 마십시오.** 앱에서 결함을 찾으면 고치지 말고
보고에 적으십시오 (고치는 것은 다음 태스크입니다).

## 화면 계약 (관리자가 실제 브라우저로 확인한 사실입니다 - 믿고 쓰십시오)

서버를 띄우고 `index.html` 을 열면: `#board .row` 6개, 각 줄에 `.tile` 5개(모두 30개),
`#keyboard .key` 28개, 콘솔 오류 0건. **첫 방문이면 도움말 창이 저절로 열립니다.**

- **타일** `#board .row:nth(r) .tile:nth(c)` - `data-state` 가 `empty|filled|correct|present|absent`,
  `textContent` 는 대문자 한 글자, `aria-label` 은 "`1번째 줄 2번째 칸, C, 맞음`" 꼴
- **키** `#keyboard .key[data-key="a"]` ... `[data-key="z"]`, `[data-key="enter"]`, `[data-key="back"]`.
  제출한 뒤에만 `data-state` 가 붙습니다(안 눌린 글자에는 **속성이 아예 없습니다**)
- **없는 단어** → 그 줄에 `.shake` 클래스가 600ms 동안 붙고 `#toasts .toast` 가 생깁니다
- **이김** → 맞은 줄 타일에 `.bounce`, 칭찬 토스트, **2000ms 뒤 통계 창이 저절로 열립니다**
- **짐** → `정답: XXXXX` 토스트(사라지지 않음), **1500ms 뒤 통계 창**
- **창** `#modal-help` · `#modal-stats` · `#modal-settings` - 열리면 `hidden` 속성이 빠지고
  `#app` 에 `inert` 가 붙습니다. `.modal-close` 클릭 또는 `Escape` 로 닫힙니다.
  **창이 열려 있는 동안 보드 입력은 전부 무시됩니다**
- **통계** `#stat-row .stat b` 4개 = 판수·승률%·연승·최대연승 (이 순서).
  `#dist .dist-row .bar` 6개. `#btn-share` 는 판이 끝나야 `hidden` 이 빠집니다
- **설정** `#set-hard` · `#set-dark` · `#set-cb` (체크박스).
  켜면 `<html>` 의 `data-theme="dark"` · `data-colorblind="on"` 이 바뀝니다
- **저장** `localStorage` 키 `webwordle.daily.<YYYY-MM-DD>` · `webwordle.stats` ·
  `webwordle.settings` · `webwordle.seenHelp`
- **애니메이션** 칸 하나가 500ms, 칸 사이 100ms → 제출 뒤 보드가 멎기까지 약 950ms.
  `time.sleep` 말고 `page.wait_for_function` 으로 `data-state` 가 바뀌기를 기다리십시오

**오늘의 정답과 허용 단어는 쪽 안에서 물어봅니다** (하드코딩 금지 - 날마다 바뀝니다):

```python
answer = page.evaluate("async () => { const g = await import('/js/game.js');"
                       " const w = await import('/js/words.js');"
                       " return g.answerForDate(new Date(), w.ANSWERS); }")
puzzle = page.evaluate("async () => (await import('/js/game.js')).dailyIndex(new Date())")
wrong  = page.evaluate("async (a) => { const w = await import('/js/words.js');"
                       " return w.ALLOWED.filter(x => x !== a).slice(0, 6); }", answer)
```

## 1) `browser_harness.py` 가 줄 것

```python
ROOT = Path(__file__).resolve().parent.parent      # projects/웹워들
sys.path.insert(0, str(ROOT))
from serve import Handler                           # 서버는 이미 있는 것을 씁니다
```

- `server()` - `@contextmanager`. `socketserver.TCPServer(("127.0.0.1", 0), functools.partial(Handler,
  directory=str(ROOT / "web")))` 를 데몬 스레드로 띄우고 `http://127.0.0.1:<포트>` 를 내줍니다.
  나갈 때 `shutdown()` + `server_close()`. **포트를 숫자로 박지 마십시오** (0 = 빈 포트)
- `new_page(browser, base, viewport=None, clipboard=False)` - `viewport` 기본값
  `{"width": 420, "height": 900}`. `clipboard=True` 면 컨텍스트에
  `permissions=["clipboard-read", "clipboard-write"]`. 새 컨텍스트라 `localStorage` 가 비어 있습니다.
  `page.on("pageerror", ...)` 와 `page.on("console", ...)`(type == "error" 만) 로 오류를 모으고,
  `context.close()` 를 감싼 함수나 `page._errors` 리스트로 꺼내 볼 수 있게 하십시오.
  `page.goto(base + "/index.html")` 뒤 `page.wait_for_selector("#board .tile", timeout=10000)`
- `shot(page, name)` - `ROOT / "tests" / "screenshots" / GROUP / f"{name}.png"`.
  `GROUP` 은 모듈 전역(`set_group("core")` 로 바꿀 수 있게). 폴더는 `mkdir(parents=True, exist_ok=True)`
- `Checks` - `ok(goal, cond, detail="")` 로 쌓고, `finish()` 가 `[OK] 목표 - 설명` / `[FAIL] ...` 를
  한 줄씩 찍고 마지막에 `통과 n / 전체 m` 을 찍은 뒤 실패 수(0 이면 0)를 돌려줍니다

하네스에는 **검사 내용을 넣지 마십시오** - 다음 두 스크립트가 그대로 가져다 씁니다.

## 2) `browser_core.py` 가 증명할 목표 네 개

`set_group("core")` 로 시작하고, 시나리오마다 **새 컨텍스트**(저장소가 비어 있어야 합니다)를 씁니다.
첫 방문이면 도움말 창이 뜨니 **`#modal-help .modal-close` 를 눌러 닫고 나서** 입력하십시오.

### 목표 "보드" - 6×5 타일, 입력 중 글자 보임, 제출 시 뒤집기
- 타일 30개, 줄 6개. 시작할 때 모두 `data-state="empty"` 이고 글자가 없음
- `page.keyboard.type(wrong[0])` → 첫 줄 다섯 칸이 `filled` 이고 글자가 대문자로 보임
- 한 칸 지웠다가(`Backspace`) 다시 쳐도 맞게 되돌아옴
- `Enter` 제출 → 첫 줄 다섯 칸의 `data-state` 가 `correct|present|absent` 중 하나로 바뀜.
  **뒤집기가 왼쪽부터 차례로 일어나는 것**을 확인하십시오: 제출 직후 약 250ms 에
  첫 칸은 이미 판정 색인데 마지막 칸은 아직 아닌 순간이 있어야 합니다
  (`page.wait_for_function` 으로 첫 칸이 바뀌기를 기다린 뒤 마지막 칸 상태를 바로 읽습니다).
  동시에 바뀐다면 애니메이션이 없는 것이니 `[FAIL]` 입니다
- 판정 색이 실제 정답과 맞는지도 보십시오: `answer` 와 `wrong[0]` 으로 직접 계산한 기대값과 대조

### 목표 "키보드" - 화면 키보드 + 물리 키보드, 글자마다 색 누적
- 물리 키보드로 친 글자가 들어감(위에서 이미 확인) + **화면 키를 눌러서도** 들어감:
  `page.click('#keyboard .key[data-key="q"]')` → 그 칸에 Q
- 제출한 뒤 `#keyboard .key[data-key="<친 글자>"]` 에 `data-state` 가 붙고 그 값이 타일 판정과 같음
- 안 친 글자의 키에는 `data-state` 속성이 **없음**
- 색 누적: 어떤 글자가 한 줄에서 `present`, 다음 줄에서 `correct` 가 되면 키는 `correct` 로 올라가고
  **다시 내려가지 않음**. 정답 글자 하나를 골라 틀린 자리 → 맞는 자리 순서로 두 줄을 두어 확인하십시오

### 목표 "없는 단어 거절" - 흔들림 + 안내
- `zzzzz` 를 쳐서 제출 → 그 줄에 `.shake` 가 붙고(600ms 안에 봐야 합니다) `#toasts .toast` 가 생기며
  그 글이 비어 있지 않음. 줄은 **지워지지 않고 글자가 그대로** 남아 있어야 함
- 다섯 글자가 안 된 채로 `Enter` 를 눌러도 같은 식으로 거절되는지 확인
- `shot(page, "invalid-word")`

### 목표 "판 끝" - 승리/패배 표시와 정답 공개
- **이기는 판:** 새 컨텍스트에서 `answer` 를 바로 쳐서 제출 → 다섯 칸이 모두 `correct`,
  그 줄 타일에 `.bounce`, 칭찬 토스트, **2초쯤 뒤 `#modal-stats` 가 저절로 열림**.
  `shot(page, "win")` (통계 창이 열리기 전에 보드가 보이는 것으로 한 장, 창이 열린 뒤로 한 장)
- **지는 판:** 새 컨텍스트에서 `wrong` 여섯 개를 차례로 제출(정답이 섞이지 않게 확인) →
  여섯 줄이 다 차고 `정답: <ANSWER>` 토스트가 뜨며 그 글에 **정답이 대문자로 들어 있음**.
  1.5초쯤 뒤 `#modal-stats` 가 열림. `shot(page, "lose")`
- 판이 끝난 뒤에는 글자를 더 쳐도 보드가 바뀌지 않아야 함

## 브라우저가 샌드박스에서 안 뜨면

`python3 -c "from playwright.sync_api import sync_playwright"` 가 되고 이 기계에는 chromium 145 가
깔려 있습니다(관리자가 확인). 그래도 **당신의 샌드박스에서 브라우저가 못 뜨면** 거기서 멈추지 말고,
스크립트를 끝까지 **정확하게 써 놓고** 보고 첫 줄을 `PARTIAL` 로, 둘째 줄에 정확한 오류 메시지를
적으십시오. 검증은 관리자 환경에서 다시 돌립니다. 브라우저가 안 뜬다고 `assert` 를 지우거나
조건을 느슨하게 만들지 마십시오 - **통과시키려고 검사를 무르게 하는 것이 이 태스크의 유일한 실패입니다.**
