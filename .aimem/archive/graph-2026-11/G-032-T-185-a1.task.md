# T-185 미리보기 보관함이 **엉뚱한 쪽의 쓰기를 무시하는지** 재십시오

새로 만들 파일은 **`tests/browser_monitor_preview_guard.py` 하나**입니다.
다른 파일은 만들지도 고치지도 마십시오. 특히 `tests/browser_monitor_preview.py` 는 **다른 슬롯이 쓰고 있습니다** -
건드리지 마십시오.

## 읽을 것 (이것만)

- `tests/browser_monitor_app.py` 전부 - `monitor_server()` 틀과 `Checks` 요약 꼴을 그대로 베낍니다.
  **그 파일은 고치지 마십시오**
- `tools/aimem_monitor/static/app.js` 의 `openProjectApp` 안 `aimem.app.v1.` 보관함 처리 **만**

**읽지 마십시오:** `AIMEM.md`, `tools/aimem_monitor/*.py`, `projects/**`, `tests/browser_monitor_preview.py`

## 무엇을 재는가

모니터 페이지가 격리 칸(iframe)에 `aimem.app.v1.<프로젝트>` 칸을 빌려 줄 때,
신원을 `ev.source === fr.contentWindow` 객체 동일성으로 확인합니다. 그 방어가 진짜로 도는지를
**브라우저에서** 잽니다. 지금 이 길은 자동 검사가 0개입니다.

## 더할 검사 (다섯)

모니터 `/` 를 열고 프로젝트 '실행' 으로 iframe 을 띄운 상태에서 잽니다.

1. **중첩 iframe 의 `put` 이 무시된다** - 열린 iframe 안에 또 iframe 을 만들어 거기서
   `parent.parent.postMessage({aimem:'store.v1',op:'put',key:'stats',value:'1'},'*')` 를 보냅니다.
   패널을 닫았다 다시 열었을 때 그 값이 **들어 있지 않다**
2. **팝업(`window.open`)의 `put` 이 무시된다** - 같은 식으로 새 창에서 `opener.postMessage` 를 보냅니다.
   (팝업이 열리지 않으면 그 사실을 `detail` 에 적고 검사를 `False` 가 아니라 **건너뛴 것으로** 표시하지 말고,
   `window.open` 이 막혔음을 적은 채 `True` 로 두십시오 - 막힌 것도 방어입니다)
3. **모니터 페이지 자신이 보낸 `put` 이 무시된다** - 부모 창에서 `window.postMessage(...)` 를 자기에게
   보내도 칸이 바뀌지 않는다
4. **키 꼴이 아닌 것은 거절된다** - 진짜 iframe 에서 `key: '../other'` 와 `key: 'a'.repeat(300)` 을
   `put` 해도 칸에 들어가지 않는다
5. **값 상한** - 8,192자를 넘는 값은 저장되지 않는다

확인은 **화면으로** 하십시오: 패널을 닫았다 다시 열어 `storage.js` 가 받은 스냅숏이 화면에 어떻게
그려지는지, 또는 부모 쪽 `sessionStorage`/`localStorage` 의 `aimem.app.v1.` 칸을
`page.evaluate` 로 읽어 비교하십시오(이쪽이 간단합니다).

## 주의

- 브라우저는 `chromium` 만 씁니다. **운영 모니터(18799)를 부르지 마십시오** - 임시 포트의 서버만 씁니다
- `page.wait_for_timeout` 으로 때우지 말고 기다릴 조건을 쓰십시오. `postMessage` 는 비동기라
  보낸 뒤 **한 번은** 짧게 기다려야 합니다(`page.wait_for_timeout(200)` 정도는 괜찮습니다)
- 검사 하나가 막혀도 나머지를 다 돌린 뒤 요약을 찍으십시오
- **제품을 고치지 마십시오.** 결함을 찾으면 고치지 말고 첫 줄을 `NEEDS-FIX: <무엇이 어디서>` 로 보고하십시오
- 파일은 **220줄 안쪽**

검사가 무엇을 재는지와 마지막 `통과 N / 전체 N` 줄.
