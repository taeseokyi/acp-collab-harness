# T-178 정리에 **핸드오프·전달 기록·로그 줄**을 더하고 `VACUUM` 으로 닫으십시오

고칠 파일은 **`tools/aimem_db.py` 하나**입니다. 다른 파일은 고치지 마십시오.
바로 앞 노드(T-177)가 같은 파일에 `plan["runs"]` · `plan["events"]` 와 그 옮기기를 넣었습니다.
**그것을 지우거나 고치지 말고 이어서 더하십시오.**

## 읽을 것 (이것만)

- `tools/aimem_db.py` 의 `archive_plan` · `archive_apply` · `cmd_archive` (T-177 이 고친 뒤 모습)
- 같은 파일 26~130행의 핸드오프 묶음 - `HANDOFF_MAX`(12) · `_handoff_rows` · `_handoff_line` · `_sync_handoff_files`

**읽지 마십시오:** `AIMEM.md`, `tools/aimem_monitor/**`, `tests/**`, `projects/**`

## 더할 것 1 - `plan` 에 세 묶음

```python
plan["handoff"] = [{"seq": 3, "at": "...", "line": "- `2026-09-01 10:00` 관리자: ..."}, ...]
plan["relay"]   = [{"round": 7, "files": ["r7.json", "r7.log", "r7-instruction.md"]}, ...]
plan["logs"]    = [{"file": "fleet-mode.log", "lines": 120}, {"file": "monitor.log", "lines": 0}]
```

`plan["total_records"]` 에 이 셋도 더하십시오(핸드오프 건수 + 전달 라운드 수 + 로그 줄 수).
기존 키의 뜻은 그대로 둡니다.

### 핸드오프 - **최신 12건은 무엇이 있어도 남깁니다**

- 후보는 `_handoff_rows(con)[HANDOFF_MAX:]` 뿐입니다. 앞의 12건은 절대 건드리지 마십시오 -
  `.aimem/handoff.md` 가 그것으로 만들어지고 다음 관리자가 그것으로 이어받습니다
- 그중 `at` 이 `plan["cutoff"]` **이하**인 것만 고릅니다
- `line` 은 `_handoff_line(row)` 로 만든 줄입니다

### 전달 기록 `.aimem/relay/r<N>.*`

- 요청의 규칙: **그 라운드의 그래프가 모두 정리되면 함께 갑니다**
- 판정: `.aimem/graph/*.json` 가운데 **이번 정리로 옮겨지지 않고 남는** 그래프
  (`plan["graphs"]` 에 없는 것) 중 `g.get("round") == N` 인 것이 하나도 없으면 라운드 N 은 정리 대상입니다
- 그리고 `.aimem/relay/r<N>.json` 의 `at` 이 `plan["cutoff"]` 이하여야 합니다
- `files` 는 `.aimem/relay/` 에서 `r<N>.` 또는 `r<N>-` 로 시작하는 파일 전부입니다
  (`r1` 과 `r13` 을 헷갈리지 마십시오 - `r13.json` 은 `r1` 의 파일이 아닙니다)

### 로그 줄

- 대상은 **`.aimem/monitor.log` 와 `.aimem/fleet-mode.log` 둘뿐**입니다
- **`.aimem/access.log` 는 건드리지 마십시오** - 접속 기록은 감사 기록이라 옮기지도 지우지도 않습니다
- 옮길 줄의 조건: 줄이 `YYYY-MM-DDTHH:MM:SS` 또는 `YYYY-MM-DD HH:MM:SS` 로 **시작**하고
  그 시각이 `plan["cutoff"]` 이하일 때. **그 밖의 줄은 모두 그대로 둡니다**
  (`monitor.log` 는 지금 줄에 시각이 없어 거의 0줄이 나올 것입니다 - 그것이 정상이고,
  시각을 찍는 일은 다른 요청입니다. 억지로 다른 기준을 만들지 마십시오)
- `lines` 는 옮길 줄 수입니다

## 더할 것 2 - `archive_apply` 가 옮기기

- **핸드오프**: 그 줄이 `.aimem/archive/handoff-<YYYY-MM>.md`(`<YYYY-MM>` 은 줄의 날짜)에 들어 있는지
  확인하고, 없으면 **먼저 덧붙여 쓴 뒤 다시 읽어 확인**합니다. 확인된 것만
  `DELETE FROM events WHERE seq IN (…)` 합니다. 확인 못 한 것은 지우지 말고 건너뜁니다.
  지운 뒤 `_sync_handoff_files(con)` 와 같은 식으로 `.aimem/handoff.md` 를 다시 쓰십시오
  (최신 12건이 그대로 보여야 합니다). `handoff_archived` 표는 그대로 두십시오
- **전달 기록**: `.aimem/relay/<파일>` → `.aimem/archive/relay-<YYYY-MM>/<파일>`
  (`<YYYY-MM>` 은 그 라운드 `at` 의 앞 7자, 없으면 `plan["cutoff"][:7]`)
- **로그**: 옮길 줄을 `.aimem/archive/logs-<YYYY-MM>/<원래 이름>` 에 **덧붙여 쓰고**,
  다시 읽어 줄 수가 늘었는지 확인한 **뒤에만** 원본을 남은 줄로 다시 씁니다.
  원본 쓰기는 같은 폴더의 임시 파일에 쓰고 `replace` 로 갈아 끼우십시오(쓰다 죽어도 반쪽이 남지 않게)
- `out["handoff"]`, `out["relay"]`, `out["log_lines"]` 를 돌려주고 `out["files"]` 를 맞게 더하십시오

## 더할 것 3 - `VACUUM` 과 건수

- 옮긴 것이 하나라도 있으면 **맨 마지막에**(`events(kind='archive')` 줄을 넣은 뒤) `VACUUM` 을 한 번 돌립니다.
  `VACUUM` 은 트랜잭션 안에서 돌지 않습니다 - `con.isolation_level = None` 인 새 연결에서 `con.execute("VACUUM")` 하십시오.
  실패해도 정리 자체는 성공으로 두고(`try/except sqlite3.Error`) 그 사실만 출력에 적으십시오
- `events(kind='archive')` 본문에 `, 핸드오프 N건, 전달 N개, 로그 N줄` 을 덧붙이십시오
- `cmd_archive` 끝 줄에도 같은 종류·건수를 모두 적고, `--dry-run` 에서도 종류별 건수를 찍으십시오

## 절대 하지 말 것

- **최신 핸드오프 12건**, `.aimem/tls/`, `projects/`, `rounds/`, `AIMEM.md`, `.aimem/access.log` 는 건드리지 않습니다
- `meta` 의 `rev` 를 건드리지 마십시오. `handoff add --bump --expect-rev` 와 린터가 쓰는 길이 그대로여야 합니다
- T-177 이 넣은 `runs`·`events` 처리를 고치지 마십시오
- **기존 시험을 고치지 마십시오.** 빨간 것이 나오면 그 시험이 옳습니다
