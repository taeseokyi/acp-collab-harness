# T-166 모니터에서 **KISTI LLM 서버 상태 감시**와 **`aimem.goal`** 을 걷어내십시오

태석님 요청 둘입니다. "함대에서 kistillm 모니터링 제거 - 필요할 때 서빙 사이트 내가 직접 접속해 보면 됨"
(`Q-261111-2665`), "현재 목표는 항상 고정으로 제공하는 정보가 없습니다 - 개선 또는 삭제"(`Q-261111-e099`).
화면 쪽은 다른 태스크가 합니다. **당신은 서버·파서·테스트만** 고칩니다.

고칠 파일은 이 다섯뿐입니다.

- `tools/aimem_monitor/server.py`
- `tools/aimem_monitor/__init__.py`
- `tools/aimem_monitor/reader.py`
- `tests/test_aimem_monitor.py`
- `tests/test_aimem_monitor_detail.py`

`static/**`, `tools/fleet*.py`, 다른 `tests/*.py` 는 고치지 마십시오.

## 1. `server.py` - KISTI 감시 들어내기

### 1-1. 통째로 지울 두 덩이

- **941행 `# -- KISTI LLM 서버 상태 ---...` 배너부터 962행 `KISTI_MAX_LIVE_REFRESH = 2` 까지**
  (배너 주석 · `_kisti_lock` · `_kisti_cache` · `KISTI_REFRESH_STUCK_SEC` · `KISTI_MAX_LIVE_REFRESH`)
- **979행 `#: 상류 호스트(...)` 주석부터 `def kisti_status(...)` 의 끝(1095행)까지**
  (`_UPSTREAM_HOST` · `_scrub_upstream` · `_scrub` · `_typed_fields` · `_fetch_kisti` ·
  `_refresh_kisti` · `kisti_status`)

**그 사이의 `def _no_redirect_opener():` (965~976행)는 남겨야 합니다.** 깃허브 로그인(465·477·3003행)이
씁니다. 남길 때 그 위에 짧은 배너 한 줄을 새로 다십시오:
`# -- 외부 HTTP (깃허브 OAuth) -----------------------------------------------`

### 1-2. 남은 자리 세 군데

- **75~76행 import** - `KISTI_API_KEY_ENV` 만 남기고 `KISTI_CACHE_SEC`·`KISTI_FIELDS`·
  `KISTI_FIELD_TYPES`·`KISTI_STATUS_URL`·`KISTI_TIMEOUT_SEC` 를 뺍니다
- **722행** `state.update({"kisti": kisti_status(), "graphs": ...})` → `"kisti"` 항목만 뺍니다.
  **881행** `state["kisti"] = kisti_status()` 줄은 통째로 지웁니다
- **856~861행** `kisti = state.get("kisti")` 로 시작하는 `if` 블록 전체를 지웁니다
  (`PUBLIC_FORBIDDEN["kisti"]` 와 `_scrub_upstream` 을 쓰던 곳)
- **1620~1623행** 준비 점검의 네 줄(`k = kisti_status(sync=True)` ~
  `extra.append(ctl._check("KISTI LLM 서버 (S2 kistillm)", ...))`)과 바로 위 두 줄짜리 주석을 지웁니다.
  바로 아래의 `try:` 로 시작하는 '슬롯 역할 미배정' 점검은 **남깁니다**

### 1-3. 남길 것 (지우지 마십시오)

- `KISTI_API_KEY_ENV` 상수와 `_ENV_KEYS`(563행)·`_load_env` 의 쓰임 - 키가 환경에 있으면
  응답에서 가려야 하기 때문입니다
- `_secrets()`(2536행)의 `os.environ.get(KISTI_API_KEY_ENV)` 줄
- 14행·535행·585행·592행의 **주석에 적힌 `KISTI_API_KEY`** (키 보관 이야기이지 감시가 아닙니다).
  14행의 `서버가 붙이는 kisti / graphs / managers` 만 `서버가 붙이는 graphs / managers` 로 고치십시오

## 2. `__init__.py` - 상수 지우기

- `KISTI_STATUS_URL` · `KISTI_CACHE_SEC` · `KISTI_TIMEOUT_SEC` · `KISTI_FIELDS` ·
  `KISTI_FIELD_TYPES` 와 그 위의 `#:` 주석 묶음을 지웁니다 (125~146행 근처)
- **`KISTI_API_KEY_ENV` 는 남깁니다**
- `PUBLIC_FORBIDDEN` 을 `{"top": ("root", "paths"), "slot": ("token",)}` 로 고치고,
  바로 위 주석에서 `kisti` 줄과 `_scrub_upstream` 언급을 지웁니다

## 3. `reader.py` - `aimem.goal` 지우기

- `_parse_aimem`(80~108행)에서 `goal_text`·`goal_status` 를 만들던 `while` 루프와 그 변수들을
  통째로 지우고, 돌려주는 사전에서 `"goal"` 키를 뺍니다
  (`{"rev": rev, "lines": len(lines), "updated": updated}` 만 남습니다)
- `_section(lines, r"1\.")` 를 goal 때문에만 부르고 있었다면 그 호출도 지웁니다
- **510행** 의 기본값에서 `"goal": {...}` 를 뺍니다

## 4. 테스트 고치기

두 파일에서 **없어진 것을 보는 검사만** 지웁니다. 고쳐 쓰려 하지 말고 지우십시오.

- `tests/test_aimem_monitor.py`
  - 262~264행의 `goal` 단언 세 줄, 917행 단언에서 `goal` 부분
  - 563행 클래스 독스트링의 `kisti.url` 언급, 602~606행 `test_kisti_has_no_url_key`,
    608~632행에서 `kisti` 를 보는 단언들(`out["kisti"]`·`branch["kisti"]`),
    610행과 901행의 샘플 상태에서 `"kisti": {...}` 항목
  - 같은 검사 안에서 `kisti` 말고 다른 것도 보고 있으면 **그 다른 단언은 남깁니다**
- `tests/test_aimem_monitor_detail.py`
  - 302~321행의 `_kisti_cache` 를 만지는 `setUp`/`tearDown` 짝,
    433~450행 `test_kisti_weird_field_types_no_500`,
    470행 `fake_kisti` 와 그것을 `mock.patch.object(server, "kisti_status", ...)` 로 쓰는 검사들

  - `kisti_status` 를 패치하던 검사 중 **다른 것을 재던 검사**는 패치만 걷어내고 본문은 남기십시오
  - 4행 독스트링의 KISTI 언급을 지웁니다

`tests/test_aimem_monitor_access.py` · `tests/test_aimem_monitor_slots.py` 는 **고치지 마십시오**
(거기 있는 `KISTI_API_KEY` / `model_provider=kisti` 는 남는 것입니다).
