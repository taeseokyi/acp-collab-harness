# T-245 `tests/test_monitor_claude_usage.py`: 악성 사용 한도 파일 회귀 시험

쓸 파일은 **하나**입니다: `tests/test_monitor_claude_usage.py`. **`tools/**` 는 읽기만 하고 절대
고치지 마십시오.** 계획을 세우지 말고 바로 고치십시오. 지금 18건이고 **23건 이상**이 돼야 합니다.

## 왜 (적대적 검수가 찾은 구멍)

앞 노드 T-244 가 고친 것을 **시험이 지키지 못합니다.** 검수가 제품에 결함을 일부러 넣었는데
시험이 초록이었습니다: 64 KiB 상한을 지워도, `_empty_state`/`collect_state` 에서 `claude_usage`
키를 빼도 초록이었습니다. 악성 입력 시험은 아예 없었습니다.

## 더할 시험 (적어도 다섯)

1. **깊은 중첩** - `{"at": <정상 ISO>, "rate_limits": {"five_hour": {"used_percentage": 40}},
   "pad": "[" * 1500 + "]" * 1500}` 을 임시 저장소의 `.aimem/claude-usage.json` 에 쓰고
   `server.claude_usage(root)` 가 **예외 없이** 돌아오는 것(값은 `None` 이어도 됩니다)
2. **범위 밖 `at`** - `at="0001-01-01T00:00:00+05:00"` 과 `"9999-12-31T23:59:59-05:00"` 둘 다
   예외 없이 돌아오고 `rows` 는 정상으로 만들어지는 것
3. **`/api/state` 가 그래도 200** - 1번 파일을 둔 임시 저장소로 서버를 띄워
   `/api/state` 가 200 이고 본문이 JSON 이며 `claude_usage` 키가 있는 것.
   서버 띄우는 꼴은 `tests/test_aimem_monitor_access.py` 나 `tests/browser_monitor_usage.py` 의
   `monitor_server()` 를 베끼십시오(`http.server.ThreadingHTTPServer` + 0번 포트 + 데몬 스레드,
   `require_auth=False`). **운영 서버(10443)를 부르지 마십시오.**
4. **64 KiB 상한** - `rate_limits` 는 **정상**인데 파일 전체가 64 KiB 를 넘도록 군더더기를 채운
   파일에서 `claude_usage()` 가 `None` 인 것 (상한을 지우면 빨개져야 합니다 - 지금 시험 파일에는
   `rate_limits` 가 없어서 상한을 지워도 초록이었습니다)
5. **두 갈래 모두 키가 있다** - `server.collect_state(root)` 와, `reader.collect` 가 예외를 던지게
   `mock.patch` 한 실패 갈래 **둘 다** 결과에 `claude_usage` 키가 있는 것
   (`tests/test_aimem_monitor_detail.py:489` 의 꼴을 참고하되 **그 파일은 고치지 마십시오**)

이미 있는 18건은 그대로 두십시오. 임시 저장소는 `tempfile.mkdtemp` 로 만들고 `tearDown` 에서
`shutil.rmtree` 로 치우십시오(자기가 만든 `/tmp` 폴더 삭제는 금지 대상이 아닙니다).
