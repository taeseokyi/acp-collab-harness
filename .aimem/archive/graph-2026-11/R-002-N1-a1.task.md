**실측 결함.** `_estimate()` 안의 이 줄이 원인이다 (현재 271행 근처):

```python
        if run and run.get("state") == "running" and run.get("elapsed_sec") is not None:
            med = max(0, med - run["elapsed_sec"])
```

실행이 하네스 중앙값을 넘기면 `max(0, ...)` 가 0 으로 바닥을 쳐서 ETA 가 "지금" 또는 과거를 가리킨다. 11-09 실측: S2·S3 가 중앙값 68s/55s 대비 760s 를 돌고 있는데 화면은 `ETA 55초 뒤` 였다.

## 기대 동작 (이대로 구현한다)

1. **초과를 0 으로 바닥치지 않는다.** 실행 중인 서브태스크의 `elapsed_sec` 가 중앙값 `med` 를 넘으면:
   - 그 서브태스크의 남은 시간 추정을 0 이 아니라 **초과분에 비례한 값**으로 둔다. 공식은 이걸 쓴다:
     `over = elapsed_sec - med` (양수) 일 때 `남은 추정 = max(1, int(med * 0.5))` 로 두고,
     동시에 그 서브태스크를 **초과 목록**에 `{"slot": ..., "run_id": ..., "over_sec": over, "median_sec": med}` 로 기록한다.
     ("이미 중앙값을 넘겼으니 최소한 반주기는 더 걸린다" 라는 보수적 가정이다. 더 정교한 모형을 발명하지 말 것.)
   - 넘기지 않았으면 지금처럼 `med - elapsed_sec` 를 쓴다.
2. **`eta_basis` 문자열에 초과를 적는다.** 초과 목록이 비어 있지 않으면 기존 근거 문자열 끝에 다음을 덧붙인다:
   `" · 초과 중: <slot>(run <run_id>) 중앙값 <median_sec>s 를 <over_sec>초 초과"` - 여러 건이면 `, ` 로 잇는다.
3. **딕셔너리에 기계가 읽을 필드를 추가한다.** `_estimate()` 가 돌려주는 딕셔너리에 키 하나를 더한다:
   `"eta_over": [ {slot, run_id, over_sec, median_sec}, ... ]` (초과가 없으면 빈 리스트 `[]`).
   **기존 키 `progress_pct` / `eta_sec` / `eta_at` / `eta_basis` 의 이름과 뜻은 바꾸지 않는다.** 프런트와 테스트가 그 이름을 읽는다.
4. **표본에 가중.** `median_durations()` 는 그대로 둔다(성공 실행만 표본). 대신 `_estimate()` 안에서
   초과 중인 실행이 있으면 그 하네스의 `med` 를 **그 실행의 `elapsed_sec` 와 비교해 큰 쪽**을 다음 서브태스크 추정의 바닥값으로 쓴다.
   즉 같은 요청 안에서 아직 시작하지 않은 서브태스크의 추정 `med` 를 `max(med, elapsed_sec)` 로 올린다.
   (지금 760초째 돌고 있는데 다음 것을 55초로 보는 것이 틀렸기 때문이다.)

## 하지 말 것

- `collect()` 의 최상위 키 집합을 바꾸지 말 것 (`generated, root, aimem, slots, board, queue, log, runs, eta, requests, errors`). `eta_over` 는 **요청 딕셔너리 안**에만 추가한다.
- 다른 파일을 수정하지 말 것. `server.py`·`static/**`·`tests/**` 는 네 소유가 아니다.
- 네트워크를 타지 말 것. `reader.py` 는 파일만 읽는다.
