## 결함 2 - `접근성 - 시나리오 실행 - TimeoutError` (793~794줄 근처)

```
[OK]   접근성 - 화면 키만으로 한 줄 제출
[FAIL] 접근성 - 시나리오 실행 - TimeoutError: Page.wait_for_function: Timeout 5000ms exceeded.
```

**원인 (관리자가 `ui.js` 에서 확인했습니다):**

- `ui.js:193` - `handleKey()` 는 **`busy` 인 동안 입력을 통째로 무시합니다**
- 제출하면 마지막 칸의 판정이 `4 × 100 + 250 = 650ms` 에 찍히는데,
  `busy` 는 `4 × 100 + 500 + 50 = 950ms` 에야 풀립니다 - **300ms 의 빈틈**이 있습니다
- `wait_submit_settled(page, row, guess)` 는 ① 그 줄이 다 판정됐는지와 ② `guess` 의 글자 키에
  `data-state` 가 붙었는지를 봅니다. 그런데 이번에 고른 단어가 **`ababa`** 라
  글자가 `a`·`b` 둘뿐이고 **둘 다 앞 줄(`abaci`)에서 이미 색이 칠해져 있었습니다.**
  그래서 ②가 처음부터 참이라 이 함수가 **`busy` 가 풀리기 전에 돌아왔습니다**
- 돌아오자마자 `type_guess(page, answer)` 가 글자를 치는데 `busy` 라서 **다섯 글자가 모두 버려지고**,
  이어진 Enter 는 빈 줄을 제출해 "글자가 모자랍니다" 로 튕깁니다.
  그래서 다음 줄이 영영 판정되지 않아 `wait_submit_settled` 가 시간 초과로 죽습니다

**고치는 법:** 화면 키로 한 줄을 제출한 **뒤**, 다음 추측을 치기 전에 **`busy` 가 풀릴 때까지**
기다리십시오. `busy` 는 바깥에서 볼 수 없으니 **눈에 보이는 것**으로 기다려야 합니다. 예를 들어

```python
def wait_input_ready(page, row, timeout=5000):
    """busy 가 풀려 입력이 다시 먹을 때까지 기다린다 (ui.js: busy 동안 handleKey 가 무시된다)."""
    page.wait_for_function(
        "() => document.querySelectorAll('#board .tile.flip').length === 0",
        timeout=timeout,
    )
    page.wait_for_function(
        "(r) => {"
        "  const t = document.querySelector('#board .row:nth-child(' + r + ') .tile');"
        "  return t && t.dataset.state === 'empty';"
        "}",
        arg=row + 1,
        timeout=timeout,
    )
```

위 코드를 그대로 써도 되고 더 나은 방법을 써도 됩니다. **반드시 지킬 것:**

- `sleep` 을 쓰지 마십시오 (느린 기계에서 깨지고, 이 파일의 규칙이기도 합니다)
- 글자가 정말 들어갔는지 **확인한 뒤** Enter 를 치는 방식이면 더 좋습니다
  (예: 첫 글자를 치고 그 칸이 `filled` 가 될 때까지 기다린 뒤 나머지를 친다)
- **`ababa` 같은 단어를 피하는 식으로 때우지 마십시오.** 단어를 바꾸면 이번만 초록이 되고
  빈틈은 그대로 남습니다. **기다림을 고치십시오**
- 이 빈틈은 `scenario_accessibility` 말고 **다른 곳에도 같은 모양으로 있을 수 있습니다.**
  `wait_submit_settled(...)` 바로 뒤에 `type_guess(...)` 가 오는 자리를 모두 찾아
  같은 기다림을 넣으십시오
