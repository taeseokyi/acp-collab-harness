## 목표

모니터 웹 UI 의 **상세 패널 진입점**을 늘린다. 지금은 "작업자 실행 상태" 표의 행만
클릭할 수 있다. S1 교차검수(T-054)가 지적한 것 중 3건을 고친다.

## 쓰기 경로

`tools/aimem_monitor/static/app.js` **하나뿐이다.** `index.html` 도 `style.css` 도
고치지 마라(필요하면 `app.js` 안에서 클래스를 붙여 쓰고, 이미 있는 클래스만 쓴다).

## 지금 코드에서 알아야 할 것 (읽어 두어라)

- `newTable(headers, rows, rowClasses, opts)` 가 표를 만든다. `opts.rowRunIds` 가 배열로
  들어오면 **행마다** `makeRowOpenable(tr, runId)` 가 걸려 클릭·Enter·Space 로
  `openDetail(runId)` 가 열린다. `renderRuns()` 가 이미 이렇게 쓰고 있다
  (`rowRunIds: runs.map((r) => r.id)`).
- `openDetail(runId)` 는 `GET /api/runs/<id>` 를 부르고 결과를 `renderDetail()` 로 그린다.
- 서버 상태(`/api/state`)에는 `data.runs[]`(각 `{id, slot, harness, model, label, state,
  rc, elapsed_sec, started, …}`), `data.board[]`(각 `{id, task, slot, status, handoff,
  artifact}`), `data.requests[]`(각 `{…, subtasks: [{id, title, slot, harness, status,
  run_id}]}`) 가 들어 있다.
- `renderBoard(data)` 는 `board[]` 로 표를 만들지만 `rowRunIds` 를 주지 않는다.
- `renderRequests(data)` 안의 서브태스크 표도 `rowRunIds` 를 주지 않는다
  (`st.run_id` 를 "연결된 실행" 칸에 글자로만 쓴다).

## (1) 큐 18번 - 보드 행과 요청 서브태스크를 클릭하면 상세 패널이 열린다

**관리자가 정한 데이터 계약 (이대로 구현하라. 서버·reader 는 고치지 않는다):**

> `board[]` 에 run id 를 **싣지 않는다.** 보드 행 → 실행 매핑은 **프런트가** 이미 받은
> `requests[].subtasks[]` 와 `runs[]` 만으로 푼다. 이유: 이 매핑은 화면에만 필요하고,
> `STATE_KEYS` 계약을 건드리면 서버·테스트 세 곳을 같이 고쳐야 한다.

- **서브태스크 행:** `st.run_id` 가 있으면 그 값으로 바로 열 수 있게 한다
  (`rowRunIds: subtasks.map((st) => st.run_id || null)`). `null` 이면 그 행은 클릭 대상이 아니다.
- **보드 행:** `resolveBoardRunId(taskId, data)` 를 새로 만들어 다음 순서로 푼다.
  1. `data.requests[]` 의 모든 `subtasks[]` 를 훑어 `st.id === taskId` 이고 `st.run_id` 가
     있으면 그 `run_id`.
  2. 없으면 `data.runs[]` 중 **id 가 `taskId + '-'` 로 시작하는 것**들(새 실행 id 체계가
     `T-050-S1-a2-174829` 꼴이다) 가운데 `started` 가 **가장 늦은** 것의 `id`.
  3. 둘 다 없으면 `null`.
- 열 수 없는 행은 클릭 가능하게 만들지 말고, 그 행의 `title` 속성에
  `연결된 실행 기록 없음` 을 넣어 **왜 안 열리는지** 보이게 하라.
- `makeRowOpenable` 과 `opts.rowRunIds` 를 **그대로 재사용**하라. 클릭 처리를 새로 쓰지 마라.

## (2) 큐 19번 - 404·400 의 **이유를 화면에 쓴다**

지금 `openDetail()` 은 404 면 `'404 - 실행 기록을 찾을 수 없습니다: ' + runId`,
400 이면 `'400 - 잘못된 실행 id 입니다: ' + runId` 라는 **고정 문구**만 쓴다.
서버는 본문에 이유를 실어 보낸다: `{"ok": false, "error": "그런 실행 기록이 없습니다: <id>"}`.

- 404·400·그 밖의 `!res.ok` **세 분기 모두** 본문을 `await res.json()` 으로 읽어
  `body.error` 가 문자열이면 그 문장을 화면에 쓴다.
- 본문이 JSON 이 아니거나 `error` 가 없으면 **지금의 고정 문구로 되돌아간다**
  (`try/catch` 로 감싸라 - 본문 파싱 실패로 패널이 빈 채 남으면 안 된다).
- 화면 문구는 `HTTP <상태> - <서버가 준 이유>` 꼴로 한다.
- **`innerHTML` 을 쓰지 마라.** 지금처럼 `textContent` 로만 넣어라(서버 문자열이 그대로 들어간다).
- `state.detailSeq` 로 늦게 도착한 응답을 버리는 기존 가드(`if (seq !== state.detailSeq) return;`)
  를 **모든 분기에서 유지**하라.

## (3) 큐 21번 - `DEMO_STATE` 에서 두 줄 제거

`app.js` 위쪽 `DEMO_STATE` 에 아직 공개면에 나가지 않는 값이 남아 있다. **두 줄을 지워라.**

- 최상위 `root: '/home/tsyi/work/ai-fleet',` (30행 근처)
- `kisti:` 안의 `url: 'https://aida.kisti.re.kr:10430/status',` (77행 근처)

서버는 REV 114 에서 이 두 키를 **키도 값도** 빼고 내보낸다. 데모 상태가 그보다 많은 것을
보여 주면 "공개면에 이게 나간다" 고 읽힌다. 지운 뒤 **데모 모드에서 화면이 깨지지 않는지**
확인하라 - 어느 코드도 `data.root` / `data.kisti.url` 을 읽으면 안 된다
(`grep -n "\.root\b" tools/aimem_monitor/static/app.js` 로 확인하라).

## 하지 말 것

- `index.html`·`style.css`·서버·reader 를 고치지 마라.
- 새 라이브러리·프레임워크·`fetch` 래퍼를 들이지 마라. 바닐라 JS 그대로다.
- 기존 DOM id 와 클래스 이름을 바꾸지 마라(테스트와 CSS 가 그 이름을 본다).

## 완료 판정

```
node --check tools/aimem_monitor/static/app.js
grep -n "rowRunIds" tools/aimem_monitor/static/app.js
grep -n "resolveBoardRunId" tools/aimem_monitor/static/app.js
grep -c "aida.kisti.re.kr" tools/aimem_monitor/static/app.js
```

- 첫 명령이 rc 0 (문법 오류 없음).
- `rowRunIds` 가 **세 군데 이상**(실행 표 · 보드 표 · 서브태스크 표)에서 쓰인다.
- `resolveBoardRunId` 가 정의·호출 두 군데 이상 나온다.
- 마지막은 **0** 이어야 한다.

그리고 `resolveBoardRunId` 의 순수 로직을 node 로 직접 돌려 보여라 - 예를 들어
함수 본문을 복사해 `runs` 3개(`T-050-S1-a1-120000`, `T-050-S1-a2-130000`, `T-099-S2-a1-140000`)와
`requests` 하나를 넣고 `T-050` 이 `…a2-130000` 으로, `T-099` 가 `…140000` 으로,
`T-001` 이 `null` 로 풀리는지 찍어라.

## 보고

(2) 위 완료 판정 명령 4개의 **출력을 그대로** 붙여라,
(3) `resolveBoardRunId` 재현 출력.
