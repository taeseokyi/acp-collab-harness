## (1) 요청 본문의 줄바꿈을 그대로 보여 준다

**태석님 말:** *"웹에서 요청한 내용의 줄바꿈이 사라져 한 줄로 이어져 보인다.
요청분담트리 등 요청 본문이 보이는 모든 곳에서 입력한 텍스트 형태(줄바꿈 유지) 그대로
보이게 한다."*

**왜 사라지나.** 요청 본문을 `textContent` 로 넣는데 HTML 의 기본 `white-space` 가
줄바꿈을 공백 하나로 뭉갠다. 글자는 다 들어 있고 **보이기만** 한 줄이다.

**고칠 모양.**

- 요청 본문(`req.detail`)을 그리는 요소에 **CSS 클래스 하나**를 붙이고
  `style.css` 에 `white-space: pre-wrap; overflow-wrap: anywhere;` 를 준다.
  (`pre` 가 아니라 **`pre-wrap`** 이다 - 긴 줄이 가로로 넘치면 안 된다.)
- **`innerHTML` 을 절대 쓰지 마라.** `textContent` 그대로 두고 CSS 로만 푼다.
  요청 본문은 사용자가 보낸 문자열이다.
- 요청 본문이 보이는 **모든 자리**에 적용하라. `grep -n "detail" tools/aimem_monitor/static/app.js`
  로 찾아 빠짐없이 하라(요청 카드 본문, 상세 보기, 그 밖에 `req.detail` 을 쓰는 곳).
- 상세 패널의 `보고 본문`/`지시 본문`/`stderr 꼴리` 처럼 **이미 `<pre>` 로 그리는 자리는
  건드리지 마라.**

## (2) 긴 요청 본문을 클릭하면 전체를 볼 수 있다

**태석님 말:** *"요청분담트리에서 요청 본문이 길면 뒷부분이 생략되는데, 클릭하면 전체
상세 내용(줄바꿈 유지)을 볼 수 있게 한다."*

**알아야 할 계약 (서버가 이미 이렇게 보낸다 - 바꾸지 마라).**
`/api/state` 의 `requests[]` 각 항목에 이 세 키가 있다:

| 키 | 뜻 |
| --- | --- |
| `detail` | 본문. **600자가 넘으면 잘려 있고 끝에 `…` 가 붙어 있다** |
| `detail_truncated` | 잘렸으면 `true` |
| `detail_len` | **원본** 글자 수 |

**고칠 모양.**

- `detail_truncated === true` 인 요청의 본문 아래(또는 옆)에
  **`전체 보기 (N자)`** 버튼을 둔다. `N` 은 `detail_len` 이다.
  (`<button type="button">` 이다. `<a href="#">` 를 쓰지 마라 - 탭 해시를 깨뜨린다.)
- 누르면 **이미 있는 상세 다이얼로그**(`#detail-overlay` / `#detail-body`)를 열어
  제목을 요청 제목으로, 본문을 **지금 가진 `detail` 문자열 그대로**(줄바꿈 유지,
  `white-space: pre-wrap`) 보여 준다.
  - **새 다이얼로그를 만들지 마라.** `ensureDetailPanel()` / `bindDetailControls()` /
    `closeDetail()` 를 재사용하라. T-083 이 넣은 **포커스 저장·가둠·복귀**가 그대로 걸려야 한다.
  - `openDetail(runId)` 는 실행 기록용이라 그대로 두고, **`openRequestDetail(req)` 를 따로**
    만들어 같은 다이얼로그를 쓰라. 열기 전에 `state.detailSeq += 1` 을 해서
    늦게 도착한 `/api/runs/...` 응답이 이 내용을 덮지 못하게 하라.
- **지금 화면에 있는 600자가 전부다.** 서버에 전문을 다시 묻는 길은 **없다**(그런 엔드포인트가
  없다). 그러니 다이얼로그 끝에 한 줄을 적어라:
  `원본 N자 중 앞 600자입니다. 전문은 .aimem/requests/<id>.json 에 있습니다.`
  **이 문장을 임의로 바꾸거나 빼지 마라** - 없으면 보는 사람이 전문을 봤다고 믿는다.
- `detail_truncated` 가 `false` 면 버튼을 만들지 마라(이미 전문이다).
- `detail_truncated`/`detail_len` 키가 **없는** 응답(옛 서버)에서도 터지지 않아야 한다 -
  없으면 버튼 없음으로 간다.

## 하지 말 것

- `index.html`·서버·reader·테스트를 고치지 마라.
- `innerHTML`·`document.write`·새 라이브러리 금지.
- 기존 DOM id 와 클래스 이름을 바꾸지 마라.
- T-094 의 탭 코드, `resolveBoardRunId`, `detailReturnFocus`, KISTI `pending`/`stale`
  뱃지를 지우지 마라.

- `pre-wrap` 이 `style.css` 에 있다.

- `grep -c innerHTML` 는 **0** 이어야 한다.
