# T-204 **실제 브라우저**로 D1 이 닫혔는지 재십시오

고칠 파일은 **`tests/browser_monitor_auth.py` 하나**입니다. 제품은 고치지 마십시오.

## 읽을 것 (이것만)

- `tests/browser_monitor_auth.py` 전체 (이미 인증을 켠 서버를 띄웁니다 - 그 뼈대를 그대로 씁니다)
- `rounds/R15/REVIEW-ticket.md` 의 **D1 줄만**

**읽지 마십시오:** `AIMEM.md`, `tools/**`, `projects/**`.

## 배경

인증을 켜면 iframe 안의 앱이 **js·css 403** 으로 깨져 있었습니다(검수 D1). 관리자가 이 파일을
그대로 돌려 `안쪽이 진짜로 그려졌다`·`CSS 가 실제로 입혀졌다` 두 검사가 **실패**하는 것을 봤습니다
(`통과 7 / 전체 9`). 다른 슬롯이 방금 고쳤습니다. **이 파일은 이미 그 둘을 재고 있으므로,
지금 돌리면 통과해야 합니다.** 당신이 할 일은 거기에 **회수 검사**를 더하는 것입니다.

## 더할 검사 (지금 9개 -> 12개 이상)

1. **하위 자원이 실제로 200 이다**: iframe 안에서 `performance.getEntriesByType('resource')` 또는
   playwright 의 `page.on("response")` 로 `.js`·`.css` 응답 **코드**를 모아 **403 이 하나도 없음**을
   단언하십시오 (지금 두 검사는 "그려졌다" 로 간접 확인만 합니다 - 코드를 직접 보는 검사를 더합니다)
2. **회수가 듣는다**: 미리보기가 뜬 **뒤에**, 서버의 허용 목록 파일에서 그 계정을 지우고
   같은 티켓 주소의 하위 자원 하나를 다시 부르면 **403** 이어야 합니다
   (`page.evaluate` 의 `fetch(url).then(r => r.status)` 로 충분합니다)
3. **지운 뒤 새로 고치면 못 들어간다**: 같은 상태에서 iframe 을 다시 띄우면 앱이 안 보여야 합니다

## 규칙 (화면 검사)

- 그려진 것을 재십시오: 보임은 `is_visible()`, 색은 `getComputedStyle`, 자리·겹침·잘림은 `bounding_box()`
- **요소끼리 겹치지 않는다**·**입력한 뒤에도 화면 밖으로 안 나간다** 는 이 파일의 기존 검사를 따르십시오
- 브라우저는 chromium 하나만 깔려 있습니다
