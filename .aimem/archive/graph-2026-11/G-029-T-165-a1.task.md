# T-165 적대적 검수 - 미리보기 보관함 (postMessage 길)

당신은 **만든 사람을 믿지 않는** 사람입니다. 코드를 고치지 마십시오 -
**`rounds/R13/REVIEW-preview.md` 하나만** 씁니다. 찾은 결함은 고치지 말고 그 파일과 보고에 적습니다
(고치는 것은 뒤따르는 무료 슬롯 몫입니다).

## 무엇이 새로 생겼나

격리된(`sandbox`, `allow-same-origin` 없음) 미리보기 iframe 안의 결과물이, 부모(모니터) 페이지에
`postMessage` 로 **자기 프로젝트 몫 문자열 보관함**을 읽고 쓰게 됐습니다. 보관함은 모니터
`localStorage` 의 `aimem.app.v1.<encodeURIComponent(이름)>` 한 칸입니다.

`app.js` 전체(3,200줄)와 `server.py` 전체는 읽지 마십시오.

## 따질 것 - 설계 6절 (a)~(d) 를 하나씩 깨 보십시오

1. **(a) 모니터 API 를 대신 불러 주지 않는가** - 메시지 핸들러에서 `fetch`·`XMLHttpRequest`·
   `location`·`import()`·`eval`·`new Function` 으로 가는 길이 하나라도 있는가
2. **(b)(c) 스냅숏에 그 칸 말고 다른 것이 섞이지 않는가** - 모니터의 다른 `localStorage` 키,
   쿠키, 티켓, URL 이 메시지에 실리는가
3. **(d) 칸 가르기** - `ev.source === fr.contentWindow` 가 **진짜 신원 검사**로 쓰이는가.
   닫은 패널의 리스너가 남아 `null === null` 로 통과하는 길(`!src` 검사), 떼어 낸 iframe
   (`isConnected`), 중첩 iframe·팝업·다른 패널의 창을 각각 따져 보십시오
4. **키가 `localStorage` 키로 승격되는 길이 없는가** - `part` 가 메시지에서 올 수 있는가,
   `key` 가 사전 밖으로 나가는가. `__proto__`·`constructor`·`hasOwnProperty`·`../x` 를 직접 넣어 보십시오
5. **상한이 진짜인가** - 직렬화 기준 65,536자·키 64개·`put` 20/초·`ready` 2회가 **되돌리기까지
   포함해** 지켜지는가. `"` 로만 된 8,192자 값을 여러 번 넣어 상한을 넘겨 보십시오
6. **정리가 진짜 되는가** - 패널을 닫고 다른 패널을 열었을 때 리스너가 남는가, 밀린 쓰기가 나가는가,
   `setItem` 이 던질 때 정리가 중간에 끊기는가
7. **검사의 진위** - `tests/browser_monitor_app.py` 에 이번에 더해진 검사가 **늘 참인 조건**은 아닌가.
   **변이 시험**으로 확인하십시오: 저장소를 `/tmp` 에 복사하되 **`.aimem/tls/` 는 빼고**
   (`cp -r` 뒤 `rm -rf <복사본>/.aimem/tls`), 거기서 `app.js` 의 검사 한 줄씩을 일부러 망가뜨려
   (예: `src !== fr.contentWindow` 를 지우기, 상한 숫자 늘리기) 검사가 **빨개지는지** 보십시오.
   브라우저 검사가 없으므로 변이 시험 대상은 `projects/웹워들/tests/test_storage.mjs` 와
   `tests/browser_monitor_app.py` 의 **기존 8개**입니다 - 기존 검사가 이 새 길을 전혀 못 본다면
   그 사실 자체가 결함입니다.
   안 빨개지면 그 검사는 빈 검사입니다. 끝나면 **당신이 만든 그 `/tmp` 폴더를 `rm -rf` 하십시오**
   (당신이 만든 `/tmp` 폴더를 지우는 것은 금지 대상이 아닙니다)
