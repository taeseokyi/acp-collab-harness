# T-157 T-156 의 수정을 **적대적으로** 다시 때리십시오

**쓸 파일은 `rounds/R12/REVIEW-auth.md` 하나뿐입니다.**
제품 코드도 시험도 **한 줄도 고치지 마십시오.** 찾은 것을 적기만 합니다.

## 무엇을 검수하나

공개 운영 중인 모니터(HTTPS + 인증, 18799)의 **GitHub 로그인 세션 회수**입니다.

- T-155 가 찾은 것: 허용 목록(`.aimem/tls/allowed-github-logins`)에서 계정을 지워도
  그 사람의 서명된 세션 쿠키가 `SESSION_TTL_SEC` 동안 그대로 들었습니다
  (`_subject()` 가 서명·만료만 보고 목록을 다시 안 봤습니다)
- T-156 이 고쳤습니다: `_subject()` 가 `gh:` 주체면 `github_allowed_logins(self.root)` 를
  요청마다 다시 봅니다

## 읽을 것

- `git diff tools/aimem_monitor/server.py` 와 `git diff tests/test_aimem_monitor_app_gate.py`
  (**`finish_request`·`_client_ip` 쪽 변경은 다른 사람 것입니다 - 검수 대상이 아닙니다**)
- `tools/aimem_monitor/server.py` 에서 `grep -n` 으로 찾아 그 함수들만:
  `_subject`, `verify_session`, `sign_session`, `github_allowed_logins`,
  `_auth_gate`, `_issue_session`, `app_ticket`, `app_ticket_ok`, `audit`
- `tests/test_aimem_monitor_app_gate.py` 전체

**읽지 마십시오:** `AIMEM.md` 전체, `projects/` 아래 전부.

## 따져 볼 것 (하나씩, 깰 수 있다/못 깬다 + 근거)

1. **지나가는 길이 남았나** - `_subject()` 를 **거치지 않고** 인증을 통과하는 경로가 있나.
   `_auth_gate` 가 `_subject` 를 쓰나, 따로 쿠키를 보나. `grep -n "verify_session"` 으로
   **`_subject` 밖에서 쿠키를 푸는 데가 있는지** 세십시오
2. **Bearer 토큰 갈래** - 토큰 로그인은 이 검사를 건너뜁니다. 그래도 되나(토큰 자체가
   회수 수단인가)
3. **이미 발급된 실행 티켓** - 계정을 지우기 **전에** 받아 둔 12시간짜리 티켓은
   `/app/<이름>/~<티켓>/` 로 여전히 듣습니다. `app_ticket_ok` 는 주체를 안 봅니다.
   **이것이 남은 구멍인지, 받아들일 만한지** 판단하고 적으십시오
4. **주체 문자열을 거꾸로 푸는 법** - `gh:` 를 떼고 소문자로 만들어 목록과 맞추는데,
   로그인 때 `re.sub(r"[^A-Za-z0-9_-]", "", login)[:60]` 로 **글자를 버리고** 60자로
   자릅니다. 목록의 이름과 **어긋나는 계정 이름**이 있나(점·60자 넘는 이름).
   어긋나면 **정당한 사람이 쫓겨납니다** - 가용성 결함입니다
5. **목록 파일이 읽히지 않을 때** - 권한 오류·깨진 인코딩이면 `github_allowed_logins` 가
   빈 집합을 돌려줍니다. 그러면 **모두가 쫓겨납니다.** 받아들일 만한가
6. **요청마다 파일 읽기** - 초당 수백 요청에서 비용이 문제가 되나. 캐시가 필요한가
7. **감사 로그** - 끊긴 요청이 `audit`/`monitor.log` 에 남나. 남지 않으면
   "왜 못 들어오지" 를 아무도 못 봅니다
8. **`None` 을 돌려주는 자리가 바꾼 뜻** - `_subject()` 가 `None` 이면 호출하는 쪽이
   어떻게 하나. 302 `/login` 인가 401 인가, **무한 리디렉션**이 생기나

## 변이 시험 (반드시 하십시오)

저장소를 `/tmp` 에 복사해 **`.aimem/tls/` 를 빼고** 임시 토큰으로 돌리십시오.
끝나면 그 `/tmp` 폴더를 `rm -rf` 하십시오(자기가 만든 `/tmp` 폴더는 지워도 됩니다).

복사본에서 T-156 의 수정을 **되돌려 놓고**
`python3 -m unittest tests.test_aimem_monitor_app_gate -v` 를 돌리십시오.
**빨개지는 시험이 몇 개인지** 적으십시오 - 0 개면 새 시험이 아무것도 지키지 않는 것입니다.

그리고 수정을 **반만 되돌린** 변이도 둘 해 보십시오(예: `.lower()` 빼기,
`startswith` 를 `in` 으로). 각각 몇 개가 빨개지는지.
