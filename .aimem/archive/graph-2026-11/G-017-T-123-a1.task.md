## 당신이 지난번에 짚은 것 (이번에 고쳤다는 것들)

| 목표 | 당신이 짚은 결함 | 고쳤다는 내용 |
|---|---|---|
| 보드 | 계산된 `animationName`/`animationDuration` 은 `@keyframes flip` 이 **없어도** `flip`/`0.5s` 로 나와 거짓 초록 | `animationstart` 이벤트와 `getAnimations()` 로 **정말 돌았는지** 보게 바꿈 |
| 보드 | `all(...)` 이 빈 목록이면 참 | `len(...) == 5 and all(...)` 로 |
| 보드 | `"0.5s"` 를 박아 둬 `prefers-reduced-motion` 기계에서 거짓 실패 | "0보다 큰 시간" 으로 |
| 통계 | 분포를 **1번째 줄 승리만** 봄 | 4번째 줄에서 이겨 4번째 칸만 느는지 보는 시나리오 추가 |
| 통계 | 네 값의 **이름표**를 안 읽음 | 이름표 순서 검사 추가 |
| 보기 설정 | "주황" `r>g>b` 가 **노랑도 통과** | hue(0~40도 / 190~250도) 검사 추가 |
| 보기 설정 | 새로 고친 뒤 **칠해진 body 색**을 다시 안 잼 | 새로 고침 전후 계산 배경색 비교 추가 |

## 1) 돌려 보십시오

```bash
python3 projects/웹워들/tests/browser_core.py;   echo "core rc=$?"

```

세 줄의 `통과 n / 전체 m` 과 rc 를 보고에 그대로 옮기십시오.
(직전 상태: core 64/64 · layout 18/18 · ui 146/146)

## 2) 고쳤다는 것을 **거꾸로 찔러** 보십시오

말을 믿지 말고, **그 검사가 정말 빨개지는지** 확인하십시오. 가장 확실한 방법은
**잠깐 망가뜨려 보고 되돌리는 것**입니다. 다만 `web/` 아래는 **당신의 쓰기 범위가 아닙니다** -
파일을 고치지 말고, 쪽 안에서 바꿔 보거나(`page.evaluate` 로 스타일시트 규칙을 지워 보는 등)
적어도 **검사 코드를 읽어 논리로 따져** 결론을 내십시오. 무엇을 했는지 보고에 적으십시오.

- **보드**: `@keyframes flip` 이 없으면 그 검사가 정말 빨개집니까?
  `animationstart` 를 Enter 누르기 **전에** 걸었습니까(늦게 걸면 놓칩니다)?
  기록이 0개일 때 통과하는 길이 남아 있습니까?
- **통계**: 4번째 줄 승리 시나리오가 정말 4번째 줄에서 이깁니까(중간에 `busy` 로 글자가 버려지면
  줄 수가 달라집니다)? 기대값 네 개와 분포 여섯 칸이 **셈과 맞습니까**?
  `hl` 검사는 늘 참이 되지 않습니까?
- **보기 설정**: hue 범위가 실제 색(`#f5793a` ≈ 20도, `#85c0f9` ≈ 209도)과
  **노랑**(`#c9b458` ≈ 48도)을 정말 가릅니까? 새로 고침 전후 색 비교가
  "둘 다 같은 기본값" 이라 늘 참이 되지는 않습니까?

## 3) 빈 검사를 또 찾으십시오

늘 참인 단언, `try/except` 로 삼켜진 검사, 조용한 `return`, 실제로 나온 값에 맞춰 적은 기대값,
`sleep`, 날짜·정답·포트 박기. 새로 더해진 검사에 특히 눈을 두십시오.
