## 1. 뒤집기를 **실제 애니메이션**으로 확인 (목표: 보드)

### 지금 무엇이 잘못됐나

`scenario_board` 의 검사 `"보드 - 뒤집기가 왼쪽부터 차례로 진행"` 은 Enter 를 누른 뒤
**첫 칸이 바뀌고 마지막 칸이 바뀌기 전(약 400ms)** 안에 값을 읽어야 통과합니다.
느린 기계에서는 그 창을 놓쳐 **거짓 실패**가 납니다. 그리고 `.flip` class 와 키프레임이
정말 도는지는 아무도 안 봅니다.

### 어떻게 고치나 - 시간 창을 없애고 **관찰자**로 바꿉니다

Enter 를 **누르기 전에** 첫 줄 다섯 칸에 `MutationObserver` 를 걸어 `.flip` 이 붙는 순간을
기록해 두고, 줄 판정이 끝난 **뒤에** 기록을 읽습니다. 이러면 느리든 빠르든 놓치지 않습니다.

```python
WATCH_FLIP_JS = (
    "() => {"
    "  window.__flips = [];"
    "  document.querySelectorAll('#board .row:nth-child(1) .tile').forEach((t, i) => {"
    "    new MutationObserver(() => {"
    "      if (!t.classList.contains('flip')) return;"
    "      const s = getComputedStyle(t);"
    "      window.__flips.push({i: i, at: performance.now(),"
    "                           name: s.animationName, dur: s.animationDuration});"
    "    }).observe(t, {attributes: true, attributeFilter: ['class']});"
    "  });"
    "}"
)
page.evaluate(WATCH_FLIP_JS)
# ... 여기서 Enter 를 누르고 wait_row_done(page, 0) 로 기다린 뒤
flips = page.evaluate("() => window.__flips")
```

같은 칸이 두 번 기록될 수 있으니 **칸 번호(`i`)마다 가장 이른 것 하나만** 남겨 쓰십시오.

더할 검사 (각각 따로 `checks.ok`, 목표 이름은 `"보드"`):

- **다섯 칸이 모두 `.flip` 을 받았다** - 남은 칸 번호가 `{0,1,2,3,4}`
- **애니메이션이 실제로 걸려 있다** - 기록된 `name` 이 모두 `"flip"` 이고
  `dur` 이 `"0.5s"` (`none` 이거나 `0s` 이면 실패). `detail` 에 실제 값을 찍으십시오
- **왼쪽부터 차례로** - 칸 번호 순서대로 `at` 이 **커진다**(같거나 작아지면 실패).
  첫 칸과 마지막 칸의 시간차도 `detail` 에 적으십시오
- **끝나면 `.flip` 이 떨어진다** - `wait_row_done` 뒤
  `page.locator("#board .row:nth-child(1) .tile.flip").count()` 가 0 이 될 때까지
  `page.wait_for_function` 으로 기다리고(3초 제한) 0 인지 확인

그리고 기존 검사 `"보드 - 뒤집기가 왼쪽부터 차례로 진행"` (`last_state == "filled"` 를 보는 것,
약 400ms 창에 기대는 그 한 줄)은 **지우고 위 검사들로 대신하십시오.** 이 파일에서 **지워도 되는
검사는 이것 하나뿐입니다.**

## 2. 화면의 `ENTER` 와 `⌫` 를 실제로 눌러 보기 (목표: 키보드)

지금은 화면 글자 키(`q`)만 클릭해 보고, `ENTER` 와 `⌫` 는 **물리 키보드로만** 시험합니다.
`scenario_keyboard` 안(또는 새 시나리오)에 더하십시오. 목표 이름은 `"키보드"`.

- `page.click('#keyboard .key[data-key="back"]')` 로 **마지막 글자가 지워지는지**
  (한 칸이 `empty` 가 되고 앞 칸들은 그대로)
- 다섯 글자를 **화면 글자 키 클릭만으로** 채운 뒤
  `page.click('#keyboard .key[data-key="enter"]')` 로 **제출이 되는지**
  (`wait_submit_settled` 로 기다려 줄 판정이 `correct/present/absent` 로 끝나는지)
- 다섯 글자가 안 찼을 때 `enter` 키를 클릭하면 **제출되지 않고 안내 토스트가 뜨는지**
  (`toast_text(page)` 를 `detail` 에 찍으십시오)
- 두 키가 **눌리는 자리에 실제로 보이는지** - `is_visible()` 이 `True` 이고
  `bounding_box()` 의 너비·높이가 둘 다 **0보다 큰지**

## 3. 키 색이 `correct` 에서 **내려가지 않는지** (목표: 키보드)

지금은 `present → correct` 로 **올라가는 것**만 봅니다. 반대 방향을 봐야 합니다.

- 어떤 글자가 **첫 줄에서 `correct`** 가 되는 추측을 하나 제출합니다
  (`find_present_pair` 를 참고하되, 필요하면 쪽 안에서 `scoreGuess` 로 골라도 됩니다 -
  `answer_for_page` 와 `score_guess` 가 이미 있습니다)
- 그다음 줄에서 **같은 글자가 `present` 나 `absent` 로 판정되는** 추측을 제출합니다
  (같은 글자를 다른 자리에 놓으면 `present` 또는 `absent` 가 됩니다)
- 그 글자의 키가 **여전히 `correct`** 인지 봅니다. `present`/`absent` 로 내려가면 결함입니다
- 그런 추측 쌍을 못 찾으면 그것 자체를 실패로 적으십시오 (조용히 건너뛰지 마십시오)
