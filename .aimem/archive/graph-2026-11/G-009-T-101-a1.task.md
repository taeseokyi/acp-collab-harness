# T-101 웹워들 화면 결함 고치기 (검수 1·2·3·4·6·7·8번)

## 배경

같은 프로젝트를 적대적으로 검수한 결과 결함 여덟 개가 나왔습니다. 그 가운데 **당신이 소유한 세 파일**의
일곱 개를 고치십시오. 새 기능을 만들지 말고, 아래 번호에 적힌 것만 고치십시오.

고칠 파일 (이 셋만):

- `projects/웹워들/web/js/ui.js`
- `projects/웹워들/web/js/storage.js`
- `projects/웹워들/web/css/style.css`

`web/js/game.js` 와 `web/js/words.js` 는 **다른 슬롯 소유이니 고치지 마십시오.**
(5번 결함은 `game.js` 소유 슬롯이 같은 라운드에 따로 고치고 있습니다.)

## 고칠 것

### 1. 지난 판의 알림이 새 판에 남습니다 (`ui.js:243`, `ui.js:458`, `startToday` 412~431)

진 판의 `정답: …` 알림을 `ms=0`(사라지지 않음)으로 띄우는데, 날짜가 바뀌어 새 판을 시작할 때
알림 영역(`#toasts`)을 비우지 않습니다. 그래서 새 날의 판 위에 어제 정답이 계속 떠 있습니다.

→ 새 판을 시작할 때 알림 영역을 비우십시오.

### 2. 하루를 건너뛰어도 연승이 끊기지 않습니다 (`storage.js:73~86`)

`recordResult` 가 날짜를 모릅니다. 사흘 만에 들어와 이겨도 연승이 이어집니다.

→ 통계에 `lastDay`(`"YYYY-MM-DD"`) 를 더하고, 서명을 `recordResult(won, guessCount, dayKey)` 로 바꾸십시오.
   `lastDay` 가 **`dayKey` 의 바로 전날이 아니면** 연승을 다시 시작합니다 (이기면 1, 지면 0).
   바로 전날이면 지금처럼 이어 갑니다. 끝나면 `lastDay = dayKey`.
   **예전에 저장된 통계에 `lastDay` 가 없으면** 연승을 건드리지 말고 그날을 적어 두기만 하십시오.
   `ui.js` 의 부르는 쪽도 함께 고치십시오 (두 파일 다 당신 소유입니다).

### 3·4. 글자와 배경의 대비가 모자랍니다 (`style.css:9,23,26,116,164~166`)

지금은 모든 칸에 흰 글자를 써서 밝은 테마 초록이 2.78:1, 어두운 테마 노랑이 2.63:1, 화면 키보드는
3.81~4.21:1 입니다. 목표는 **4.5:1 이상**입니다.

**칸 색(배경)은 뉴욕 타임즈와 똑같이 두고, 글자색만 바꾸십시오.** 아래 표대로 하면 전부 통과합니다
(WCAG 상대 휘도로 미리 계산한 값입니다. 숫자를 바꾸지 마십시오).

| 쓰이는 곳 | 배경 | 글자 | 대비 |
| --------- | ---- | ---- | ---- |
| 밝은 테마 맞음 | `#6aaa64` (그대로) | `#121213` | 6.73 |
| 밝은 테마 자리 틀림 | `#c9b458` (그대로) | `#121213` | 9.05 |
| 밝은 테마 없음 | `#6b6f71` (`#787c7e` 에서 바꿈) | `#ffffff` | 5.08 |
| 어두운 테마 맞음 | `#538d4e` (그대로) | `#121213` | 4.71 |
| 어두운 테마 자리 틀림 | `#b59f3b` (그대로) | `#121213` | 7.12 |
| 어두운 테마 없음 | `#3a3a3c` (그대로) | `#ffffff` | 11.35 |
| 색약 맞음 | `#f5793a` (그대로) | `#121213` | 6.85 |
| 색약 자리 틀림 | `#85c0f9` (그대로) | `#121213` | 9.72 |
| 밝은 테마 안 누른 키 | `#d3d6da` (그대로) | `#121213` | 12.84 |
| 어두운 테마 안 누른 키 | `#565758` (`#818384` 에서 바꿈) | `#ffffff` | 7.4 |

→ 글자색도 배경색처럼 CSS 변수로 두고(예: `--on-correct`), 칸과 키보드가 같은 변수를 쓰게 하십시오.
   테마를 갈아끼울 때 글자색도 같이 바뀌어야 합니다.

### 6. 세로가 낮은 창에서 넘칩니다 (`style.css:90`)

`min(…, 100dvh - 260px, …)` 에서 (가) `dvh` 를 모르는 브라우저는 `min()` 전체를 버려 보드 폭 상한이
사라지고, (나) 빼는 값 260px 가 실제 머리글+키보드+여백(약 269px)보다 작아 약 10px 넘칩니다.

→ 같은 속성을 두 번 선언해 대비책을 두십시오 (앞 줄에 `vh` 를 쓴 값, 뒷 줄에 `dvh` 를 쓴 값 - 모르는
   브라우저는 뒷 줄을 버리고 앞 줄을 씁니다). 빼는 값은 `280px` 로 넉넉히 잡으십시오.

### 7. 화면 키를 누른 뒤 스페이스바가 그 키를 다시 누릅니다 (`ui.js:164`, `ui.js:249~267`)

마우스로 `ENTER` 를 누르면 포커스가 그 버튼에 남아, 그다음 스페이스바에 또 제출됩니다.

→ 마우스로 누른 경우에는 포커스가 버튼에 남지 않게 하십시오(`mousedown` 의 기본 동작을 막거나 누른 뒤
   `blur()`). **키보드로 `Tab` 해서 오는 포커스는 살려 두어야 합니다** - 키보드만으로 플레이할 수 있어야 하니
   포커스 테두리를 없애지 마십시오.

### 8. 이어하는 빈 판에 설정의 하드 모드가 반영되지 않습니다 (`ui.js:424~427`)

저장된 판을 이어받을 때 아직 한 줄도 두지 않았다면, 설정의 하드 모드 값을 따르게 하십시오.

