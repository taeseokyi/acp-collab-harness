# T-210 티켓을 지키는 회귀 시험을 새 파일에 쓰십시오 (큐 6 N1 · 큐 8 N2·N6·D6)

만들 파일은 **`tests/test_monitor_ticket_regress.py`** 하나입니다 (새 파일).
**제품도 다른 시험도 고치지 마십시오** - 쓰기 범위 밖입니다.

## 읽을 것 (이것만)

- `tools/aimem_monitor/server.py` 의 `_app_ticket_canon` · `app_ticket_tag` · `app_ticket` ·
  `_app_ticket_parts` · `app_ticket_ok` · `app_ticket_resolve` (226~300행 근처) ·
  `_APP_RE`(2060행) · `_audit_denied` · `/app/` 티켓 처리(2556~2610행)
- `tests/test_aimem_monitor_app_gate.py` 의 **1~60행** - 임시 뿌리와 진짜 소켓 서버를 띄우는 본보기입니다.
  그 `setUp`/`get` 을 본떠 쓰십시오 (복사해도 됩니다)

**읽지 마십시오:** `AIMEM.md` 본문, `tools/aimem_db.py`, `projects/**`, `rounds/**`.

## 무엇이 없나 (R15 재검수 N1·N2·N6·D6)

제품은 안전한데 **그것을 지키는 시험이 없습니다.** 제품 코드를 망가뜨리는 변이를 넣어도
기존 시험 88건이 전부 초록이었습니다. 아래 다섯 변이를 **빨갛게 만드는** 시험을 쓰십시오.

| 변이 | 무엇을 망가뜨리는가 | 시험이 잡아야 할 것 |
| ---- | ------------------ | ------------------ |
| **M5** | 발급·검증 payload 에서 **주체를 뺀다** | 티켓의 가운데 칸(주체 태그)만 바꾸고 mac 을 **그대로** 둔 요청이 403 |
| **M8** | `_APP_RE` 의 `{1,160}` 상한을 지운다 | 티켓 칸이 **161자 이상**이면 라우팅 수준에서 안 받는다 |
| **M9** | 티켓 경로의 회수 거절에서 감사를 뺀다 | 허용 목록에서 지운 뒤 옛 티켓을 쓰면 `.aimem/access.log` 에 줄이 는다 |
| **M10** | `_app_ticket_parts` 의 태그 꼴 검사를 지운다 | 가운데 칸이 16진 12자리가 아니면(`AAAA`, `gh:kim`, 빈 칸) 거절 |
| **M11** | `app_ticket_ok` 의 `_PROJECT_RE` 이름 검사를 지운다 | 이름이 프로젝트 꼴이 아니면 `app_ticket_ok` 가 False |

## 쓸 것 - 시험 11건 이상

`unittest.TestCase` 로 쓰십시오. 절반은 함수를 바로 부르고(빠름), 절반은 진짜 소켓으로 재십시오.

1. `test_tag_swap_with_same_mac_is_refused` - `app_ticket` 으로 `gh:kim` 티켓을 만들고
   가운데 칸을 다른 로그인의 태그(`app_ticket_tag("gh:lee", key)`)로 바꿔치기. mac 은 그대로.
   `app_ticket_ok(..., "gh:lee")` 가 **False** (M5)
2. `test_tag_swap_over_http_is_403` - 1번의 바꿔치기 티켓을 **진짜 소켓**으로 보내 **403** (M5)
3. `test_tag_is_not_the_login` - 발급한 티켓 문자열에 `kim` 도 `gh:` 도 들어 있지 않다
4. `test_ticket_longer_than_160_is_not_routed` - 티켓 칸을 161자로 만들어
   `_APP_RE.match("/app/~" + "a"*161 + "/알파/")` 가 **None** (M8)
5. `test_long_ticket_over_http_is_not_served` - 같은 것을 소켓으로 보내 200 이 **아니다** (M8)
6. `test_revoked_ticket_path_is_audited` - 허용 목록 계정으로 티켓을 받아 200 을 확인하고,
   목록을 비운 뒤 같은 티켓으로 다시 불러 **403** 이고 `.aimem/access.log` 줄 수가 **늘었다** (M9)
7. `test_audit_line_hides_the_ticket` - 6번의 감사 줄에 티켓 문자열이 **없다**
8. `test_bad_tag_shapes_are_refused` - 가운데 칸이 `AAAA`, `gh:kim`, ``(빈 칸), `0`*13 인 네 가지에
   `_app_ticket_parts` 가 **None** (M10) - `subTest` 로 묶으십시오
9. `test_bad_project_name_fails_ticket_ok` - 이름이 `../etc`, `알파/베타`, `` 인 경우
   `app_ticket_ok` 가 **False** (M11)
10. `test_resolve_returns_none_for_unknown_tag` - `app_ticket_resolve` 가 후보에 없는 태그에 **None**
11. `test_mixed_case_login_resolves_to_the_canonical_subject` - `gh:KiM` 과 `gh:kim` 의 태그가 같다

## 검증 (이대로 돌려 보십시오)

```
python3 -m unittest tests.test_monitor_ticket_regress
```

`Ran N tests` 의 **N 이 11 이상**이고 `OK`, rc 0 이어야 합니다.
