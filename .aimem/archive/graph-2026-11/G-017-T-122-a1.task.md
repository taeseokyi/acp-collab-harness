## 결함 1 (통계) - 추측 분포는 **1번째 줄 승리만** 봅니다

지금 분포 검사는 전부 한 줄에 맞힌 판입니다. **n 번째 줄에서 이기면 n 번째 칸이 느는지**를
가르는 검사가 없어서, 분포가 늘 첫 칸만 올려도 아무도 모릅니다.

→ **새 시나리오**를 더하십시오 (목표 이름 `"통계"`). 이미 있는 도우미를 쓰십시오.

1. `SEED_JS` 로 통계를 심습니다 - **분포를 0으로 비운 채**:
   `{"played": 3, "wins": 2, "streak": 1, "maxStreak": 2, "dist": [0, 0, 0, 0, 0, 0], "lastDay": ""}`
   (`SEED_JS` 가 `lastDay` 를 어제로 채웁니다). 심은 뒤 `page.reload()` + `wait_for_selector`
2. `answer = answer_for_page(page)` 와 `wrong_words(page, answer, 6)` 로 틀린 단어를 받아
   **세 줄을 틀린 뒤 네 번째 줄에서 정답을 맞힙니다**
   (줄마다 `type_guess` → `wait_submit_settled` → **`wait_input_ready`** 로 `busy` 가 풀리길 기다릴 것.
   이 파일에 이미 있는 도우미입니다 - 안 기다리면 입력이 버려집니다)
3. 통계 창이 열리면 **분포 여섯 칸이 `["0", "0", "0", "1", "0", "0"]`** 인지 봅니다
   - **4번째 칸만 1** 인 것이 핵심입니다. 첫 칸이 올라가면 걸립니다
4. 네 값이 **`["4", "3", "2", "2"]`** 인지도 봅니다 (판수 4 · 승률 75 … 는 아닙니다.
   직접 세어 기대값을 정하십시오: 심은 `played 3 / wins 2 / streak 1 / maxStreak 2` 에
   이긴 판 하나를 더한 값입니다. **승률은 `Math.round(wins / played * 100)`** 입니다)
5. **분포 막대에 `hl` 표시**가 이번 판의 줄에만 붙는지도 보십시오
   (`#dist .dist-row .bar.hl` 가 하나이고 그것이 4번째 줄인지)

## 결함 2 (통계) - 네 값의 **이름표**를 아무도 안 읽습니다

숫자 네 개만 읽고 그 아래 이름표(`판수`·`승률 %`·`연승`·`최대 연승`)는 안 봅니다.
이름표만 서로 바뀌어도 못 잡습니다.

→ 이미 있는 통계 시나리오 **한 곳에** 검사를 하나 더하십시오:
   `#stat-row .stat span` 의 글을 순서대로 읽어 **`판수` · `승률` · `연승` · `최대` 가
   그 순서로 들어 있는지** 봅니다 (글자 그대로 같은지가 아니라 순서와 포함 여부를 보십시오 -
   `승률 %` 처럼 단위가 붙어 있습니다). `detail` 에 실제로 읽은 네 글을 찍으십시오.

## 결함 3 (보기 설정) - `r > g > b` 는 **노랑도 통과**합니다

색약 `correct` 가 "주황 계열" 인지를 `r > g > b` 로 보는데, 일반 `present` 노랑
(`#c9b458` = 201, 180, 88) 도 이 조건을 통과합니다. **색약 모드에서 correct 가 노랑으로
칠해지는 결함을 못 잡습니다.**

→ **색상(hue)** 으로 가르십시오. rgb 에서 hue 를 구하는 작은 도우미를 하나 만들고
   (0~360도. 표준 공식입니다. `max`·`min` 과 나눗셈만 있으면 됩니다), 다음을 봅니다:

- **색약 `correct` 는 주황** - hue 가 **0~40도** 안 (실제 `#f5793a` ≈ 20도).
  노랑 `#c9b458` 은 약 48도라 이 조건에서 떨어집니다
- **색약 `present` 는 파랑** - hue 가 **190~250도** 안 (실제 `#85c0f9` ≈ 209도)
- 지금 있는 `r > g > b` · `b > g > r` 검사는 **지우지 말고 그대로 두십시오.** hue 검사를 **더하는** 것입니다
- `detail` 에 `rgb=(…) hue=NN.N도` 를 반드시 찍으십시오

## 결함 4 (보기 설정) - 새로 고친 뒤 **어두운 테마의 칠해진 색**을 다시 안 잽니다

`scenario_settings` 는 새로 고친 뒤 `<html>` 의 `data-theme` 속성과 체크박스만 봅니다.
속성은 남았는데 실제로 안 칠해지는 결함을 못 잡습니다 (R8 에서 꼭 이런 일이 있었습니다 -
`hidden` 속성은 맞는데 CSS 가 이겨서 보였습니다).

→ 새로 고치기 **전**에 `getComputedStyle(document.body).backgroundColor` 를 적어 두고,
   새로 고친 **뒤** 같은 값인지 보는 검사를 하나 더하십시오. `detail` 에 두 값을 모두 찍으십시오.

## 공통으로 지킬 것

- **도구 호출 모양의 글자(`<tool_call>`, `<function=…>`, `<parameter=…>`)를 본문에 쓰지 마십시오.**
  파일을 고칠 때는 실제 편집 도구를 쓰고, 본문에는 사람이 읽을 말만 쓰십시오.
  이번 라운드에 그 글자를 찍고 끝나 아무것도 안 바뀐 시도가 네 번 있었습니다
- 계획을 적는 단계를 건너뛰고 **바로 파일을 열어 고치십시오**
- `sleep` 금지. 기다림은 `wait_for_function` / `wait_for_selector`
- 검사를 조건부로 만들거나 `try/except` 로 삼키지 마십시오
- 기대값을 "실제로 나온 값" 에 맞춰 적어 두지 마십시오
- **검사가 제품(`web/` 아래)의 진짜 결함 때문에 빨개지면 제품도 검사도 고치지 말고**
  첫 줄을 `NEEDS-FIX: <무엇이 어디서>` 로 보고하고 멈추십시오
- 당신의 샌드박스에서는 크로미움이 안 뜹니다(`sandbox_host_linux.cc FATAL`). **그래도 멈추지 말고**
  코드를 정확하게 써 놓고 `python3 -m py_compile` 까지 한 뒤 `PARTIAL` 로 보고하십시오 -
  검증은 엔진이 샌드박스 밖에서 돌립니다. 재시도를 받으면 브리프에 붙은 **검증 출력 꼬리**를 보고 고치십시오
