## 목표

관리자가 방금 고친 두 가지에 **계약 테스트**를 붙인다. 고친 코드는 이미 들어가 있다 -
네 일은 그 계약을 못박고, 되돌아가면 깨지게 만드는 것이다.

## 쓰기 경로

두 파일만 고친다. 둘 다 이미 있는 파일이니 **덧붙여라**(기존 테스트를 지우지 마라):

- `tests/test_aimem_monitor.py` - (A) 요청 본문 절단
- `tests/test_aimem_monitor_auth.py` - (B) 접근 토큰 읽기

다른 파일은 읽기만 하라. 특히 `tools/aimem_monitor/*.py` 를 **고치지 마라** - 테스트가
현재 동작과 어긋나면 그것 자체가 보고감이다(첫 줄 `BLOCKED`).

## 전제

- 표준 라이브러리만. **`pytest` 는 이 환경에 없다.** 두 파일이 이미 `unittest` 로 되어 있으니
  그 파일의 기존 import·헬퍼·네이밍 투를 그대로 따라라. **먼저 파일을 읽어라.**

## (A) `requests[].detail` 절단 - `tests/test_aimem_monitor.py`

**무엇이 바뀌었나.** `tools/aimem_monitor/__init__.py` 에 상수가 하나 생겼다:

```python
REQUEST_DETAIL_MAX = 600
```

그리고 `tools/aimem_monitor/server.py` 에 `_truncate_request_details(requests)` 가 생겨
`scrub_public(state, root)` 안에서 불린다. 하는 일:

- `requests` 가 리스트가 아니면 아무것도 안 한다.
- 각 항목이 dict 가 아니면 건너뛴다.
- `req["detail"]` 이 문자열이 아니면 `detail_truncated = False`, `detail_len = 0`.
- 문자열이면 `detail_len` 에 **원본 글자 수**를 넣고,
  - `len > REQUEST_DETAIL_MAX` 이면 `detail = detail[:REQUEST_DETAIL_MAX] + "…"`,
    `detail_truncated = True`
  - 아니면 `detail` 은 그대로, `detail_truncated = False`

**덮을 것 (각각 독립 테스트):**

1. 긴 `detail`(예: `"가" * 2000`)을 가진 요청이 `scrub_public` 을 지나면
   `len(detail) == REQUEST_DETAIL_MAX + 1` 이고 **마지막 글자가 `"…"`** 이며
   `detail_truncated is True`, `detail_len == 2000` 이다.
2. 짧은 `detail`(`"짧다"`)은 **글자 그대로 남고** `detail_truncated is False`,
   `detail_len == 2` 다.
3. **경계값:** 길이가 정확히 `REQUEST_DETAIL_MAX` 면 자르지 **않는다**
   (`detail_truncated is False`). `REQUEST_DETAIL_MAX + 1` 이면 자른다.
4. `detail` 이 `None` 이거나 숫자이거나 키 자체가 **없으면** 터지지 않고
   `detail_truncated is False`, `detail_len == 0` 이 붙는다.
5. `requests` 가 `None`·`{}`·`"문자열"` 이어도 `scrub_public` 이 터지지 않는다.
6. **`STATE_KEYS` 계약 확인:** `aimem_monitor.STATE_KEYS["requests"]` 문자열에
   `detail_truncated` 와 `detail_len` 이 들어 있다.
7. **원본은 안 잘린다:** 절단은 공개 직전에만 일어난다 -
   `.aimem/requests/<id>.json` 을 읽는 `reader` 경로(또는 `scrub_public` 에 넘기기 전의
   입력 dict)는 전문을 그대로 들고 있다. 같은 state 객체를 두고
   `scrub_public` **전/후**를 비교하는 식으로 못박아라.
   (`scrub_public` 은 입력을 제자리에서 고친다 - 그러니 원본 문자열을 미리 따로 떠 두고 비교하라.)

**기존 테스트가 `scrub_public` 을 부르는 방식을 그대로 따라라.** 서버를 실제로 띄우지 말고
함수를 직접 부르는 쪽이 빠르다. 다만 `scrub_public(state, root)` 는 `state` 에 다른 키가
없어도 돌아야 한다 - 최소 dict 로 불러 보고, 필요하면 기존 픽스처를 재사용하라.

## (B) 접근 토큰 파일 읽기가 심볼릭 링크를 따라가지 않는다 - `tests/test_aimem_monitor_auth.py`

**무엇이 바뀌었나.** `server.load_access_token(root)` 가 `read_text()` 대신
`os.open(path, os.O_RDONLY | os.O_NOFOLLOW)` 로 읽는다.

**왜.** 쓰기(`ensure_access_token`)는 예전부터 `O_NOFOLLOW` 로 심볼릭 링크를 거부했는데
**읽기는 따라갔다.** 토큰 파일 자리를 링크로 바꿔치기하면 쓰기는 막히지만, 서버가 뜰 때
그 링크가 가리키는 **다른 파일**이 접근 토큰으로 읽혔다. 한쪽만 막은 것은 막은 것이 아니다.

**덮을 것 (각각 독립 테스트, 전부 `tempfile.TemporaryDirectory()` 안에서):**

1. **회귀 테스트(핵심):** 임시 root 에 `.aimem/tls/` 를 만들고, **다른 곳**에 64자 hex 를
   담은 파일을 두고, 토큰 파일 자리(`<root>/<TOKEN_FILE>`)를 그 파일을 가리키는
   **심볼릭 링크**로 만든다. `load_access_token(root)` 가 **`None`** 이어야 한다.
   (`TOKEN_FILE` 은 `aimem_monitor` 에서 import 하라 - 경로를 손으로 적지 마라.)
2. **정상 경로는 그대로:** 진짜 파일에 64자 hex 를 쓰면 그 값을 돌려준다
   (앞뒤 공백·줄바꿈은 `strip` 된다).
3. **꼴이 아니면 `None`:** 빈 파일 / `"짧다"` / 65자 hex / 64자인데 hex 가 아닌 문자 포함.
4. **파일이 없으면 `None`** (터지지 않는다).
5. **디렉터리면 `None`** (터지지 않는다).
6. **쓰기 경로는 그대로다:** `ensure_access_token(root, create=True)` 가 없는 자리에
   토큰을 만들면 **권한이 `0o600`** 이고 돌려준 값이 `load_access_token` 으로 다시 읽힌다.
   (`os.stat(...).st_mode & 0o777 == 0o600`)

**심볼릭 링크를 만들 수 없는 환경이면** (`os.symlink` 가 `OSError`)
`self.skipTest(...)` 로 건너뛰어라 - 실패로 만들지 마라.

## 완료 판정

세 명령이 모두 rc 0 이어야 한다.

```
python3 -m unittest tests.test_aimem_monitor -q
python3 -m unittest tests.test_aimem_monitor_auth -q
python3 -m unittest discover -s tests -q
```

마지막은 **기준선이 195건 + 네가 더한 수 + 다른 슬롯이 더한 수** 다. 실패가 **0건**이어야
한다. 네가 더한 테스트 때문에 기존 것이 깨지면 네가 깬 것이다.

## 보고

첫 줄은 `상태: DONE` / `PARTIAL` / `BLOCKED` 중 하나. 이어서
(1) 새로 더한 테스트 메서드 이름을 파일별로,
(2) 위 세 명령의 출력 **꼬리 5줄을 그대로** 붙여라(요약 금지),
(3) 현재 동작과 어긋나 못 덮은 항목이 있으면 번호로 적어라.
