## 무엇이 잘못됐나

앞 라운드(R15 T-203)가 쿠키 의존을 없애려고 티켓 꼴을 `<만료>.<주체>.<mac>` 으로 만들면서
**주소창과 결과물 앱의 `location` 에 `gh:<로그인>` 이 그대로 보이게** 됐습니다.
로그는 `_TICKET_LOG_RE` 가 가리지만 화면은 못 가립니다. 지금 실제로 이렇게 보입니다:

```
/app/~1794481867.gh:kim.ed905261d937de27a4db415e01c98375/%EC%9B%B9%EC%9B%8C%EB%93%A4/js/ui.js
```

## 고칠 것 - 주체 대신 **되돌릴 수 없는 태그**를 싣습니다

회수(목록에서 지우면 즉시 끊김)·남의 티켓 차단·무주체 거절은 **하나도 잃지 않고** 그대로 지킵니다.

### 1. 표준 꼴 하나를 정하십시오

```python
def _app_ticket_canon(subject):
    """`gh:` 주체는 **로그인을 소문자로** 내린 꼴이 표준. 그 밖은 그대로. None/빈값은 `-`."""

def app_ticket_tag(subject, key):
    """URL 에 실을 되돌릴 수 없는 태그. `hmac(key, "app.sub.v1." + 표준꼴).hexdigest()[:12]`."""
```

허용 목록 파일의 로그인은 이미 소문자로 비교되므로, 표준 꼴을 소문자로 두면
`gh:KiM` 쿠키도 그대로 돕니다 (재현기가 봅니다).

### 2. 티켓 꼴을 `<만료>.<태그 12자리 16진>.<mac 32자>` 로

- **서명 payload 는 그대로** `f"app.v1.{exp}.{표준 주체}.{name}"` 입니다 - 주체를 mac 에 묶는 것은
  그대로 두고, **URL 에만** 태그를 싣습니다
- `_app_ticket_parts` 는 가운데 칸을 `[0-9a-f]{12}` 로 **검사**해 `(exp, tag, mac)` 을 돌려주십시오
  (`_SUBJECT_RE` 자리를 대신합니다). 길이 상한 160 과 `_APP_RE` 의 `{1,160}` 은 **그대로 두십시오**
- `app_ticket(name, exp, key, subject)` · `app_ticket_ok(ticket, name, key, subject)` 의
  **인자 꼴은 바꾸지 마십시오.** `app_ticket_ok` 는 받은 주체를 표준화해 태그를 계산하고 티켓의 태그와
  `hmac.compare_digest` 로 맞춰 본 뒤, 지금처럼 mac·만료·`_PROJECT_RE` 를 검사합니다

### 3. 태그에서 주체를 **되찾는 길**을 하나 두십시오

```python
def app_ticket_resolve(ticket, key, candidates):
    """티켓의 태그와 맞는 주체를 후보 가운데서 찾는다. 없으면 None."""
```

`/app/~<티켓>/` 처리에서 후보는 **그 요청 시점에 유효한 주체 전부**입니다:

```
[SESSION_SUBJECT_TOKEN, APP_TICKET_NO_SUBJECT] + ["gh:" + l for l in github_allowed_logins(self.root)]
```

**이것이 회수입니다** - 목록에서 지운 로그인은 후보에서 사라져 태그가 안 풀리고 403 이 됩니다.
목록 파일은 작고 캐시하지 않습니다(지금과 같은 이유).

### 4. 티켓 경로 검사를 이 차례로

1. `_app_ticket_parts` 가 None → 403, `_audit_denied(..., "app-ticket-bad", ..., "형식")`
2. `app_ticket_resolve` 가 None → 403, `app-ticket-bad`, 사유 `주체 못 찾음(회수 또는 위조)`
3. `app_ticket_ok(ticket, app_name, key, 찾은 주체)` False → 403, 사유 `서명·만료`
4. `require_auth` 인데 찾은 주체가 `-` → 403, 사유 `무주체`
5. 쿠키·Bearer 가 **실려 있고** 그 주체의 표준 꼴이 찾은 주체와 다르면 → 403, 사유 `주체 불일치`.
   자격이 **아예 없으면 막지 않습니다** (그게 R15 D1 의 원인이었습니다 - 되살리지 마십시오)

`_audit_denied` 는 앞 태스크(T-206)가 이미 만들어 두었습니다. 그대로 쓰십시오.

### 5. 큐 9번(N5) - 재등록하면 옛 티켓이 되살아나는 것을 **문서화**

위 3번 때문에 **허용 목록에 계정을 다시 넣으면 TTL(12시간) 안의 옛 티켓이 다시 듭니다.**
이것은 **의도한 동작**입니다 - 다시 넣는 행위 자체가 명시적 재허가이고, TTL 이 12시간으로 짧으며,
즉시 끊으려면 접근 토큰을 갈면 모든 티켓이 한 번에 죽습니다(`_app_ticket_key`).
`app_ticket_resolve` 의 독스트링에 이 세 줄을 **그대로 적으십시오.** 코드는 바꾸지 마십시오.
