# T-119 웹워들 목표가 정말 닫혔는지 적대적 검수 + `tests/README.md` 갱신

## 당신이 하는 일

이번 라운드에 작업자들이 **통계 · 보기 설정 · 접근성** 세 목표의 검사 구멍을 메웠다고 말합니다.
당신은 그것을 **믿지 않고 따져 보는** 사람입니다.

- 코드를 새로 만들거나 고치지 마십시오. **`projects/웹워들/tests/README.md` 하나만** 씁니다
- 찾은 결함은 고치지 말고 **보고에 번호를 매겨** 적으십시오

## 이번 라운드에 실제로 일어난 일 (알고 들어가십시오)

- `browser_ui.py` 가 **59검사 → 133검사**로 늘었습니다 (통계 13 · 보기 설정 7 · 접근성 대비 53 ·
  키보드 완주/`aria-live` 9 등). `browser_harness.py` 의 `shot()` 은 이제 **뷰포트**로 찍고
  `full_page=True` 를 주면 전체 쪽으로 찍힙니다
- **`browser_core.py` 는 이번 라운드에 바뀌었을 수도, 안 바뀌었을 수도 있습니다.**
  슬롯 장애로 두 번 실패했다가 다른 슬롯이 다시 맡았습니다. **직접 열어 보고 판단하십시오** -
  "보드" 목표(뒤집기 애니메이션)와 화면 `ENTER`·`⌫` 검사가 실제로 들어갔는지가 관건입니다
- R8 의 교훈: **검사 31개가 전부 초록인데 화면 결함 다섯이 숨어 있었습니다.** 속성(`hidden`,
  `data-state`, class 이름)만 본 검사가 원인이었습니다. 화면은 `is_visible()` ·
  `bounding_box()` · `getComputedStyle()` 로 물어야 증거가 됩니다
- 이번 라운드에 작업자가 **rc 0 으로 끝났는데 파일을 한 줄도 안 바꾼** 일이 네 번 있었습니다.
  "했다" 는 말을 믿지 말고 **파일과 실행 결과로** 확인하십시오

## 1) 돌려 보십시오

```bash
python3 projects/웹워들/tests/browser_core.py;   echo "core rc=$?"
python3 projects/웹워들/tests/browser_layout.py; echo "layout rc=$?"
python3 projects/웹워들/tests/browser_ui.py;     echo "ui rc=$?"
```

세 줄의 `통과 n / 전체 m` 과 rc 를 보고에 그대로 옮기십시오.
(R8 기준선: core 48/48 · layout 18/18 · ui 59/59)

## 2) 네 목표를 하나씩 따지십시오

`projects/웹워들/PROGRESS.md` 의 `## 목표` 에서 아직 `- [ ]` 인 넷입니다. 각각에 대해
**"무엇이 그것을 증명하는가"** 를 `파일:함수` 로 댈 수 있어야 합니다. 못 대면 `아직` 입니다.

- **보드** - `.flip` class 와 **계산된 `animationName`·`animationDuration`** 을 정말 보는지.
  시간 창(약 400ms) 안에 읽어야 통과하는 검사가 **남아 있지 않은지**(느린 기계에서 거짓 실패)
- **통계** - 네 값이 **서로 다른** 시나리오가 있는지(모두 1 이면 자리가 바뀌어도 안 걸립니다).
  **진 판** 뒤 연승 0·최대 연승 유지를 보는지. **끝난 판을 새로 고친 뒤** 판수가 또 늘지 않는지
- **보기 설정** - 색약에서 `present` 가 **파랑**인 것을 단언하는지.
  새로 고친 뒤 **칠해진 색**까지 같은지(속성만 보는 것은 증거가 아닙니다)
- **접근성** - 대비를 **어두움+색약을 겹친 모드**에서도 재는지. 판정 타일 말고
  **화면 키·입력 중 칸·토스트·본문 글자**도 재는지. 화면 `ENTER` 를 **실제로 눌러** 보는지.
  진 판의 `정답: XXXXX` 가 `aria-live` 영역에 실제로 들어가는지

## 3) 빈 검사를 찾으십시오 (핵심)

- 늘 참인 단언(`len(x) >= 0`, `is not None` 만 보는 것), `try/except` 로 삼켜진 검사,
  `if … else pass` / `return` 으로 조용히 건너뛰는 검사
- 기대값을 **실제로 나온 값에 맞춰 적어 둔** 곳 (그러면 틀려도 영원히 초록입니다)
- `sleep` 으로 버티는 곳, 오늘 날짜·정답·포트를 숫자로 박아 둔 곳
- **같은 것을 모드만 바꿔 되풀이하며 수만 불린 곳** - 대비 검사 53개가 정말 서로 다른 것을
  재는지 보십시오
- **대비를 투명한 배경(`rgba(0, 0, 0, 0)`)으로 계산한 곳** - 그러면 숫자가 거짓입니다
