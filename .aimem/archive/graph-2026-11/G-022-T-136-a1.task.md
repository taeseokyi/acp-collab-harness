## 무엇을 검수하는가

지난 라운드(R10)에 모니터 웹에 **프로젝트 결과물 실행**이 들어갔습니다. 모니터가
`projects/<이름>/app.json` 을 읽어 그 폴더를 `/app/<이름>/` 로 내려 주고, 프로젝트 칸의 '실행'
단추가 격리된 iframe 에 띄웁니다. 모니터는 **외부에 공개돼 있고 인증이 걸려 있는데**, 격리된
iframe 의 출처는 `null` 이라 `SameSite=Strict` 세션 쿠키가 실리지 않습니다. 그래서 `/app/` 만
쿠키 대신 **경로 티켓**으로 인가합니다. 이 티켓이 **이번 검수의 과녁**입니다. 새 인가 수단이고,
아직 아무도 때려 본 적이 없습니다.

### 티켓이 어떻게 생겼는가 (`tools/aimem_monitor/server.py`)

- `app_ticket(name, exp, key)` (212행): 티켓 = `"<만료 epoch>.<hmac-sha256 앞 32자>"`,
  서명 대상은 `f"app.v1.{exp}.{name}"`
- `app_ticket_ok(ticket, name, key, now=None)` (220행): 꼴·만료·서명 검사
- `_app_ticket_key(request)` (239행): **서명 키는 접근 토큰 자체**입니다. 토큰이 없으면(인증 끔)
  프로세스마다 새로 만드는 난수 키
- 라우팅 (2519~2545행): `/app/<이름>/...` 에 티켓이 없으면 `302` 로
  `/app/~<티켓>/<이름>/...` 로 보냅니다. 티켓이 있으면 `app_ticket_ok` 로 보고, 통과하면
  `Access-Control-Allow-Origin: null` 과 `app_csp(...)` 를 붙여 파일을 내려 줍니다
- 인증 문(`_auth_gate`, 2394~2404행): **경로가 `/app/~` 로 시작하면 세션 검사를 건너뜁니다.**
  이것이 이 설계에서 가장 위험한 줄입니다
- 경로 정규화는 `_norm_path` (2375행 부근, `posixpath.normpath`, **URL 디코딩 없음**).
  라우팅은 `_APP_RE` 를 **원본 경로**(`raw_path`)에, 인증 문은 **정규화된 경로**에 적용합니다.
  이 둘이 어긋나는 입력이 있는지가 핵심 질문입니다
- TTL 은 `PROJECT_APP_TICKET_TTL_SEC` (12시간)

## 때려 볼 것 (전부 **실제로 돌려** 보고 결과를 표로 적습니다)

### 1. 티켓 인가
1. 만료된 티켓(`exp` 를 과거로) - 거절되는가
2. 위조: 서명 32자 중 한 글자 바꾸기, 길이 늘리기/줄이기, `exp` 만 미래로 바꾸고 서명은 그대로,
   대문자 16진수, 유니코드 숫자(`٣`), 앞에 `+`/공백, `0x` 꼴, 아주 큰 `exp`(10^12 근처)
3. **다른 프로젝트로 재사용**: 프로젝트 A 로 받은 티켓을 B 의 경로에 쓰기. 이름 자리에
   `%EC%9B%B9%EC%9B%8C%EB%93%A4` 처럼 인코딩을 바꿔 쓰거나, 유니코드 정규화(NFC/NFD)가 다른
   같은 글자를 쓰면 서명 검사를 지나는가
4. **접근 토큰을 바꾼 뒤** 옛 티켓이 죽는가 (서버를 새 토큰으로 다시 띄워 확인)
5. 인증을 **끈** 서버에서 티켓 없이 `/app/<이름>/` 이 어떻게 되는가, 그리고 프로세스를 다시
   띄우면 옛 티켓이 죽는가(난수 fallback 키)
6. 타이밍: `hmac.compare_digest` 를 쓰는지 코드로 확인하고, 쓰지 않는 비교가 있으면 적습니다

### 2. 티켓 경로로 `/app/` 밖에 닿기 (가장 중요)
유효한 티켓을 하나 받은 뒤, 그 티켓 경로를 발판으로 다음에 닿는 길이 있는지 봅니다.

- `/app/~<티켓>/<이름>/../../api/state`, `%2e%2e%2f`, `..%252f`(이중 인코딩), `....//`,
  `..;/`, 백슬래시, `%00`, 개행 섞기
- `/app/~<티켓>/../api/state`, `/app/~<티켓>//api/state`, `/api/state/../app/~<티켓>/x`
- 정규화하면 `/app/~...` 로 **보이지만** 원본은 다른 경로인 입력(그 반대도) -
  `_auth_gate` 가 정규화된 경로를, 라우팅이 원본 경로를 본다는 어긋남을 노립니다
- 티켓 경로로 `/static/*`, `/login`, `/api/requests`(POST), 다른 프로젝트 폴더에 닿기
- 요청줄 전체를 절대 URL 로 보내기(`GET http://127.0.0.1:PORT/api/state HTTP/1.1`)
- **판정 기준:** 인증 없는 소켓으로 보낸 요청이 `/app/<그 티켓의 프로젝트>/` 안의 파일 말고
  **무엇이든** 200 으로 돌려받으면 결함입니다

### 3. 티켓이 새는 곳
티켓은 URL 에 들어 있습니다. 한 번 새면 12시간 동안 인증 없이 그 결과물을 읽을 수 있습니다.

- 임시 루트의 `.aimem/access.log` 에 티켓 문자열이 남는가 (`audit()`, server.py 546행)
- 서버 표준오류 로그(`log_message` 를 켜고 띄워 보기)에 남는가
- 404/403 **오류 응답 본문**에 경로가 그대로 실리는가 (실제 바이트에서 티켓 문자열을 찾습니다)
- `Referer`: 결과물 페이지에서 바깥 주소로 나가는 요청에 티켓이 실리는가. 미리보기 iframe 에는
  `referrerpolicy="no-referrer"` 가 붙어 있지만(static/app.js 2708행) **새 탭 링크에는 없습니다**
  (2694~2697행, `rel="noopener noreferrer"` 는 붙어 있음). 결과물 안에서
  `fetch('http://127.0.0.1:<다른 포트>/x')`, `<img src=...>`, 링크 클릭으로 당신이 띄운
  기록용 서버에 실제로 보내 보고, 그 서버가 받은 `Referer` 헤더를 적으십시오
- 브라우저 주소창/히스토리에 남는 것 자체는 결함이 아닙니다(설계상 어쩔 수 없음) - 적어만 둡니다

### 4. 격리 (인증을 **켠** 서버 + 로그인한 브라우저로)
R10 검수는 `allow-popups` 로 연 창을 못 봤습니다. playwright 가 깔려 있습니다
(`from playwright.sync_api import sync_playwright`, `pw.chromium.launch()`).

- 결과물 안에서 `window.open('/app/...')`, `window.open('/api/state')`,
  `window.open('about:blank')` 를 눌러 열고, **그 창의 `window.origin`** 이 `null` 인지,
  그 창에서 `fetch('/api/state', {credentials:'include'})` 가 되는지
- 미리보기 iframe 과 새 탭 **양쪽**에서 `fetch('/api/state')`, `POST /api/requests`,
  `document.cookie`, `localStorage`, `parent.document` 를 시도
- 새 탭은 CSP `sandbox` 지시어로 불투명 출처가 되어야 합니다(R10 결함 2 의 고침). 실제로 그런가
- `allow-popups-to-escape-sandbox` 가 어디에도 없는지 확인

threading.Thread(target=httpd.serve_forever, daemon=True).start()
