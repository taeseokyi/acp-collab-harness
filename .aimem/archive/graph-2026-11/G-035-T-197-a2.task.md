# T-197 `_import_handoff_entries` 가 **REV 를 못 읽은 항목**을 제자리에 넣게 하십시오

고칠 파일은 **`tools/aimem_db.py` 하나**입니다.

## 읽을 것 (이것만)

- `tools/aimem_db.py` 의 `_import_handoff_entries()` (142~158행) 와 `_handoff_rows()` (68~72행)
- `HANDOFF_ENTRY_RE` (34행)

**읽지 마십시오:** `AIMEM.md` 본문, `tools/aimem_monitor/**`, `tests/**`, `projects/**`.

## 결함 (R14 재검수 T-191 에서 '안 닫힘' 으로 남은 결함 10)

DB 를 잃고 `migrate` 로 복구하면 `.aimem/handoff.md` 의 항목을 events 로 되넣습니다. 그때
본문에 `**REV N` 글자가 없는 항목은 `rev` 가 **`None`** 으로 들어갑니다.
`_handoff_rows()` 의 정렬키는 `None` 을 **-1** 로 보므로 그 항목이 **맨 아래로 가라앉고**,
`.aimem/handoff.md` 와 DB 렌더가 서로 달라져 린터의 `HANDOFF_SNAPSHOT_STALE` 이 바로 뜹니다.

## 고칠 것

`_import_handoff_entries` 가 `rev` 를 못 읽으면 **파일 순서에서 이어받게** 하십시오.

- 항목은 `reversed(entries)` 로 **오래된 것부터** 돌고 있습니다. 바로 앞(더 오래된) 항목의 rev 를
  물려받는 것이 기본입니다
- 맨 앞 항목들처럼 앞에 아무것도 없으면, **뒤(더 새것)에서 처음 나오는 rev** 를 쓰십시오.
  그것도 없으면 0 입니다. 두 번 훑어도 됩니다 - 복구 경로라 느려도 괜찮습니다
- `_handoff_rows()` 의 정렬은 **고치지 마십시오.** 옛 항목의 시각이 손으로 적힌 값이라
  REV 가 실제 순서라는 전제가 맞습니다. 고칠 곳은 적재 쪽 하나입니다
- 이미 들어 있는 항목을 건너뛰는 `exists` 질의는 그대로 두십시오
