기존 검사는 지우지 마십시오. 다른 파일은 고치지 마십시오.

## 읽을 것 (이것만)

- `tests/browser_monitor_app.py` **전부** (130줄) - `Checks`·서버 띄우는 틀·`main()` 꼴을 그대로 따릅니다
- `projects/웹워들/docs/preview-storage.md` 의 **2절(48~85행)** - 메시지 세 가지의 꼴

`app.js`·`server.py` 는 읽지 마십시오.

## 배경 한 문단

모니터 쪽 페이지가 `openProjectApp` 으로 띄운 `<iframe sandbox>` 하나에만, 그 프로젝트 몫의
문자열 보관함을 빌려 줍니다. 결과물이 `{aimem:'store.v1',op:'ready'}` 를 보내면 모니터가
`{...,op:'snapshot',items:{...}}` 로 답하고, 결과물의 `{...,op:'put',key,value}` 를 받아
모니터 `localStorage` 의 `aimem.app.v1.<encodeURIComponent(프로젝트이름)>` 한 칸에 모아 둡니다.

## 더할 검사 다섯 개

기존 틀대로 `checks.ok(목표, 조건, 상세)` 를 쓰십시오. **상세에는 실제로 잰 값**을 적습니다.

1. **미리보기에서 한 판 두고 새로 고쳐도 통계가 남는다**
   - 프로젝트 `웹워들` 의 '실행' 을 눌러 미리보기를 엽니다(기존 검사가 하는 방식 그대로)
   - iframe 안에서 물리 키보드로 다섯 글자 + Enter 를 한 번 넣습니다
   - `page.evaluate` 로 모니터 쪽 `localStorage.getItem('aimem.app.v1.' + encodeURIComponent('웹워들'))`
     을 읽어 **`null` 이 아니고** `JSON.parse` 가 되는 객체이며 키가 하나 이상임을 확인합니다
   - 패널을 닫았다 다시 열고, iframe 안에서 `localStorage` 가 아니라 화면에 **앞서 넣은 글자가
     칠해진 채로 보이는지**(`is_visible()` 과 칸의 텍스트)로 확인합니다

2. **보관함이 프로젝트마다 따로다**
   - `page.evaluate` 로 모니터 `localStorage` 에 `aimem.app.v1.%EC%A0%9C2` 같은 **다른 이름의 칸**을
     미리 넣어 둡니다
   - 웹워들 미리보기에서 쓰기가 일어난 뒤에도 그 칸의 **내용이 그대로**임을 확인합니다

3. **딴 창이 보낸 `put` 은 무시된다**
   - 모니터 쪽에서 `window.postMessage({aimem:'store.v1',op:'put',key:'stats',value:'"오염"'}, '*')`
     를 **자기 자신에게** 보냅니다 (`ev.source` 가 iframe 이 아닙니다)
   - 웹워들 칸의 `stats` 값이 바뀌지 않음을 확인합니다

4. **키 꼴·크기 상한이 걸린다**
   - iframe 안에서 `parent.postMessage` 로 `key:'../x'` 하나, `key:'ok'` 에 9,000자 값 하나를 보냅니다
   - 잠깐 기다린 뒤 웹워들 칸에 `../x` 키가 **없고** `ok` 키도 **없음**을 확인합니다
   - iframe 안에서 스크립트를 돌리려면 `page.frames` 에서 `/app/` 프레임을 찾아 `frame.evaluate` 를 쓰십시오

5. **패널을 닫으면 iframe 이 DOM 에서 사라진다**
   - 미리보기를 열었다 닫은 뒤 `page.query_selector('.proj-app-frame')` 가 `None` 임을 확인합니다
   - 닫은 **뒤에** 3번과 같은 가짜 `put` 을 모니터 창에 보내도 칸이 바뀌지 않음을 확인합니다

## 규칙

- **`sleep` 으로 버티지 마십시오.** `page.wait_for_function` / `expect` 꼴로 조건을 기다리십시오.
  꼭 필요하면 `page.wait_for_timeout(300)` 한 번까지만
- 포트·날짜·정답 단어를 숫자로 박지 마십시오
- **검사가 제품 결함을 드러내면 제품을 고치지 말고** 첫 줄을 `NEEDS-FIX: <무엇이 어디서>` 로 보고하십시오
- 파일이 길어지니 **덧붙이는 부분만 150줄 안쪽**으로 쓰십시오. 한 번에 다 못 쓰겠으면
  먼저 뼈대(함수 정의와 `main()` 등록)를 쓰고 이어서 본문을 채우십시오

검사 다섯 개가 무엇을 재는지 한 줄씩과 `통과 n / 전체 m` 줄을 그대로 옮기십시오.
