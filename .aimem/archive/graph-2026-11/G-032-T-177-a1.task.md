(`tests/**` 도 금지 - 검사는 다른 슬롯이 씁니다).

## 지금 무엇이 문제인가

`archive_plan(days)` 는 **태스크·요청·그래프** 세 가지만 셉니다. 그래서 작업이 아카이브로 가도
`.aimem/runs/` 의 실행 기록 파일(지금 953개)과 `events` 표의 그 작업을 가리키는 행은 그대로 남아,
함대 탭 '작업자 실행 상태' 와 보드의 이벤트 목록이 몇 주 전 일로 계속 찹니다.

## 원칙 (태석님 지시)

**날짜만 보고 기록을 따로 자르지 않습니다. 끝난 작업이 아카이브로 가면 그 작업의 기록이 같이 갑니다.**
무엇이 정리되는지는 지금처럼 `plan["tasks"] / ["requests"] / ["graphs"]` 가 정하고, 기록은 그것을 따라갑니다.

## 더할 것 1 - `archive_plan` 에 두 묶음

기존 키(`days`·`cutoff`·`tasks`·`requests`·`graphs`·`total`)의 **뜻과 값은 그대로** 두십시오.
화면과 기존 시험이 그 뜻에 기대고 있습니다. 아래 둘을 **더하기만** 합니다.

```python
plan["runs"]   = [{"id": "T-150-S3-a1-...", "task": "T-150", "when": "2026-11-11T21:01:11",
                   "files": ["T-150-....json", "T-150-....out", ...]}, ...]
plan["events"] = [{"seq": 1, "at": "...", "actor": "...", "kind": "task", "body": "..."}, ...]
plan["total_records"] = len(plan["runs"]) + len(plan["events"])
```

### `runs` 고르는 법

`.aimem/runs/*.json` 을 하나씩 읽습니다(`meta["id"]`, `meta["task"]`, `meta["started"]`).

- **딸린 것**: `meta["task"]` 가 `plan["tasks"]` 의 id 에 있는 실행. 그리고 `plan["graphs"]` 의
  노드가 가리키는 실행 id 와 같은 실행
- **어디에도 안 딸린 것**: `meta["task"]` 가 없거나 DB `tasks` 표에 그 id 가 아예 없는 실행 →
  `meta["started"]` 가 `plan["cutoff"]` **이하**면 함께 (로그와 같은 규칙)
- **절대 빼야 할 것 둘**
  1. **아직 도는 실행** - 같은 이름의 `.rc` 파일이 **없으면** 도는 중으로 보고 건너뜁니다
  2. **열린 태스크의 실행** - `meta["task"]` 가 DB 에 `status != 'DONE'` 으로 남아 있는 태스크를 가리키면 건너뜁니다
- `files` 는 `.aimem/runs/` 에서 `<id>.` 로 시작하는 **모든** 파일 이름입니다
  (`.json` `.brief.md` `.out` `.err` `.rc` `.seen` `.new` 등 - 확장자를 열거하지 말고 접두로 찾으십시오)

### `events` 고르는 법

`SELECT seq, at, actor, kind, body FROM events` 를 돌며 고릅니다.

- **`kind='handoff'` 인 행은 이번 노드에서 건드리지 마십시오** - 다음 노드(T-178)가 따로 다룹니다
- **딸린 것**: `body` 안에 정리되는 태스크·요청·그래프 id 가 **낱말로** 들어 있는 행.
  부분 일치는 안 됩니다 - `T-15` 가 `T-150` 에 걸리면 안 되므로 경계를 확인하십시오:

  ```python
  import re
  def _mentions(body, ident):
      return re.search(r"(?<![0-9A-Za-z-])" + re.escape(ident) + r"(?![0-9A-Za-z-])", body or "") is not None
  ```

- **어디에도 안 가리키는 것**(태스크·요청·그래프 id 를 하나도 담지 않은 행): `at <= plan["cutoff"]` 이면 함께
- **절대 빼야 할 것**: **열려 있는** 것의 id 를 하나라도 가리키는 행.
  열린 태스크(`status != 'DONE'`) · 열린 요청(`.aimem/requests/*.json` 에서 `status` 가 `DONE`/`REJECTED` 가 아님) ·
  도는 그래프(`.aimem/graph/*.json` 에서 노드가 다 `ARCHIVE_TERMINAL_NODE` 가 아님).
  **끝난 것과 열린 것을 함께 가리키는 행은 남깁니다** - 열린 쪽이 이깁니다

## 더할 것 2 - `archive_apply` 가 실제로 옮기기

**지우지 않고 옮깁니다. 아카이브에 먼저 쓰고 확인한 뒤 원본을 내립니다** (지금 태스크 표가 하는 그대로).

- **실행 기록**: `.aimem/runs/<이름>` → `.aimem/archive/runs-<YYYY-MM>/<이름>`.
  `<YYYY-MM>` 은 그 실행 `when` 의 앞 7자이고, 비었으면 `plan["cutoff"][:7]` 입니다.
  `src.replace(dest)` 로 옮기고, 옮긴 뒤 DB 에서도 내립니다: `DELETE FROM runs WHERE id IN (…)`
- **이벤트**: 먼저 `.aimem/archive/events-<YYYY-MM>.md` 에 **덧붙여 쓰고**, 파일을 다시 읽어
  그 `seq` 들이 모두 들어갔는지 확인한 **뒤에만** `DELETE FROM events WHERE seq IN (…)` 합니다.
  `<YYYY-MM>` 은 그 이벤트 `at` 의 앞 7자입니다. 빠진 것이 있으면 지우지 말고 올리십시오:

  ```python
  raise RuntimeError(f"archive: {f.name} 에 {missing} 가 안 들어갔습니다 - DB 에서 내리지 않습니다")
  ```

  한 줄 꼴은 **정확히** 이렇게 (`body` 의 줄바꿈은 한 칸으로 바꿉니다):

  ```
  - `<at>` [#<seq>] <actor> · <kind> · <body>
  ```

  파일이 없으면 머리글 `# 이벤트 아카이브 - <YYYY-MM>\n\n` 을 먼저 씁니다.
  확인은 `f"[#{seq}]" in text` 로 합니다
- `out["runs"] = [옮긴 실행 id, …]`, `out["events"] = [내린 seq, …]` 를 돌려주고
  `out["files"]` 에 옮긴 **파일 수**를 더하십시오
- 맨 끝의 `events(kind='archive')` 기록 줄 본문에 `, 실행 N건, 이벤트 N건` 을 덧붙이십시오.
  **순서가 중요합니다**: 이벤트를 먼저 지우고, 기록 줄은 **그다음에** 넣으십시오
  (반대로 하면 방금 넣은 기록 줄이 바로 지워질 수 있습니다)

## 더할 것 3 - `cmd_archive` 출력

- 끝 줄: `archive: 태스크 N건, 요청 N건, 그래프 N개, 실행 N건, 이벤트 N건 옮김 (파일 N)`
- `--dry-run` 에서도 `archive: 실행 <- N건` / `archive: 이벤트 <- N건` 을 찍습니다

## 절대 하지 말 것

- `.aimem/tls/`, `projects/`, `rounds/`, `AIMEM.md` 은 건드리지 않습니다
- `meta` 표의 `rev` 를 건드리지 마십시오. **REV 번호는 이벤트 수와 무관합니다** - 이벤트를 내려도 그대로여야 합니다
- `VACUUM` 은 넣지 마십시오 (다음 노드가 넣습니다)
- **기존 시험을 고치지 마십시오.** 빨간 것이 나오면 그 시험이 옳습니다 - 코드를 고치십시오
