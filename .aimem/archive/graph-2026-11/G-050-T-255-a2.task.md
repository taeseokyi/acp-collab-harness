# T-255 `browser_monitor_ui.py`: 저장소의 **그때그때 상태**에 기대는 시나리오를 고정 자료로

쓸 파일은 **하나**입니다: `tests/browser_monitor_ui.py`. **다른 `tests/**` 와 `tools/**` 는
읽기만 하고 절대 고치지 마십시오.** 지금 이 검사는 **27건 전부 통과**합니다. 바로 고치십시오.

## 왜

R17 에 브라우저 검사 두 건이 "오늘 저장소가 마침 그런 상태라서" 깨졌습니다(끝난 그래프가 접혀
있어서 / 최근 실행 20건이 전부 함대 일이라서). 둘 다 **임시 저장소에 시험이 직접 쓴 고정 자료**로
옮겨 고쳤습니다 - 이 파일의 `write_fixed_requests` / `write_fixed_graph` / `write_fixed_runs` +
`monitor_server(root=temp_root)` 가 그 본보기입니다(`main()` 의 아래쪽 블록).

아직 진짜 저장소(`ROOT`)를 그대로 보는 시나리오가 남아 있습니다.

## 옮길 시나리오 넷

`main()` 에서 지금 첫 `with monitor_server() as base:` 블록 아래 있는 것들입니다.

| 시나리오 | 지금 무엇에 기대나 |
| --- | --- |
| `scenario` | `#projects-list` 에 **웹워들이 있어야** 하고, '전체' 칩을 눌러야 보임 |
| `narrow_scenario` | 같음 (폰 폭) |
| `short_scenario` | 같음 (짧은 화면) |
| `request_tree_scenario` | `#requests-tools` 의 **'끝난 요청 N건' 에서 N > 0** 이어야 함 - 진짜 DB |

`changed_ui_scenario` 는 **그대로 두십시오** (KISTI 카드가 없다·라벨 글자 - 자료 내용이 아니라
화면 뼈대를 봅니다).

## 어떻게

1. **`write_fixed_project(root)`** 를 새로 만드십시오 (`write_fixed_runs` 아래).
   `shutil.copytree(ROOT / "projects" / "웹워들", root / "projects" / "웹워들")` 로 웹워들을 통째로
   복사합니다(`tests/browser_monitor_auth.py:58-65` 가 같은 수법을 씁니다 - 그 파일을 참고로만
   읽으십시오). `projects/웹워들/app.json` 이 함께 와야 '앱 열기 ▶' 가 뜹니다
2. **`write_fixed_requests(root)`** 는 이미 `DONE` 요청 하나를 씁니다 -
   `request_tree_scenario` 의 '끝난 요청 N건 > 0' 이 거기서 나오게 하십시오.
   모자라면 `DONE` 요청을 **두 건 더** 쓰도록 `write_fixed_requests` 를 늘리십시오
   (기존 네 건은 지우지 마십시오 - `zero_subtask_scenario` 가 씁니다)
3. **`main()` 을 고쳐** 네 시나리오를 `with monitor_server(root=temp_root) as temp_base:` 블록으로
   옮기십시오. 첫 `monitor_server()` 블록에는 `changed_ui_scenario` 만 남습니다.
   임시 블록에서는 `write_fixed_project(temp_root)` 를 **먼저** 부르십시오
4. **필터 칩**: 지금 `scenario` 는 `'전체'` 칩을 눌러 끝난 웹워들을 꺼냅니다. 임시 저장소에서는
   웹워들이 유일한 프로젝트이므로 칩이 어떻든 보여야 합니다. 그래도 **칩 누르기는 남겨 두십시오**
   (없으면 기본 필터가 바뀔 때 또 깨집니다). 칩이 없으면 조용히 넘어가게 하십시오

## 지켜야 할 것

- **검사 27건이 전부 그대로 있어야 하고 전부 통과해야 합니다.** 검사를 지우거나 느슨하게
  바꾸지 마십시오(`is_visible()`·`getComputedStyle`·`bounding_box()` 로 **그려진 것**을 묻는 지금
  방식 그대로). 옮기는 일이지 줄이는 일이 아닙니다
- 임시 폴더는 `tempfile.TemporaryDirectory()` 로 만들고 블록이 끝나면 저절로 지워지게 하십시오
- 어떤 단언도 "지금 저장소에 무엇이 들어 있는가" 에 기대면 안 됩니다. 쓸 수 있는 유일한 예외는
  **git 에 들어 있는 `projects/웹워들` 폴더를 복사해 오는 것**입니다
- 제품(`tools/**`)이 틀려 검사가 빨개지면 고치지 말고 보고 첫 줄을 `NEEDS-FIX: <무엇이 어디서>` 로

## 검증

검증 명령이 봅니다: `python3 tests/browser_monitor_ui.py` 의 마지막 줄이
`통과 N / 전체 N` 이고 **N >= 27 이며 통과 == 전체** 인 것.

[재시도 2/2] 직전 시도(run T-255-S3-a1-175507) 는 rc=0 / 검증 rc=1 로 실패했다. 산출물이 남아 있을 수 있으니 먼저 확인하고 이어서 하라. 직전 검증 출력 꼬리:
진짜 저장소로 도는 시나리오: ['changed_ui_scenario']
마지막 줄: ['통과', '2', '/', '전체', '3']
Traceback (most recent call last):
  File "<stdin>", line 14, in <module>
AssertionError: ['통과', '2', '/', '전체', '3']


직전 작업자의 보고(참고만 하라 - 틀렸을 수 있으니 그대로 믿지 말고 직접 확인하라):
사 (`app.json` 포함).
- `write_fixed_requests`는 기존 네 건 그대로. DONE 한 건이 이미 있어 `끝난 요청 1건`이 나오므로 추가하지 않았습니다.
- `scenario`의 '전체' 칩 누르기는 유지하되, 칩이 없거나 안 보이면 조용히 넘어가게 했습니다.
- `request_tree_scenario`를 임시 저장소에서 돌리면 `/api/archive`가 "운영 저장소가 아니다" 403을 돌려주므로, `temporary_aimem_root(temp_root)` 컨텍스트를 추가해 `aimem_db`/`server`의 ROOT·DB·AIMEM·HANDOFF를 잠시 임시 저장소로 바꾸고 빈 스키마를 초기화했습니다 (`tests/test_archive_api.py`와 같은 수법). 이 덕분에 아카이브 패널 검사가 임시 저장소의 고정 자료로 통과합니다.

검증 실제 실행:

```bash
python3 tests/browser_monitor_ui.py
```

마지막 줄:

```text
통과 27 / 전체 27
```

주요 확인: `끝난 요청 1건`, `펼친 뒤=1개, 6초 뒤=1개`, `미리보기 줄='실행 기록 0건 · 이벤트 0건 · 핸드오프 0건 · 전달 0개 · 로그 0줄'`. 검사 수는 줄지 않았고 27건 그대로입니다.

다음 담당자가 알아야 할 것: 임시 블록은 `TemporaryDirectory`로 자동 정리되며, `temporary_aimem_root`가 끝나면 패치가 원복됩니다. `git status`에 보이는 다른 파일(`tools/aimem_monitor/server.py`, `AIMEM.md`, `tools/aimem_db.py` 등)의 변경은 다른 세션 것이고, 이 작업에서는 건드리지 않았습니다. commit/push 하지 않았습니다.
