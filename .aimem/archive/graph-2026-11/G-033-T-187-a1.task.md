# T-187 정리가 **열려 있는 것의 기록**까지 끌고 가는 결함 넷을 고치십시오

고칠 파일은 **`tools/aimem_db.py` 하나**입니다. 다른 파일은 고치지 마십시오
(`tests/**` 금지 - 검사는 다른 슬롯이 씁니다).

## 읽을 것 (이것만)

- `tools/aimem_db.py` 의 `archive_plan` · `archive_apply` (당신이 바로 앞 라운드 노드에서 쓴 코드입니다)
- 같은 파일의 `CREATE TABLE` 묶음에서 `queue(pos, task, slot_hint, inherited, note)` 와
  `requests(id, …, status, …)` 의 칸 이름

**읽지 마십시오:** `AIMEM.md`, `tools/aimem_monitor/**`, `tests/**`, `projects/**`

## 적대적 검수가 실제로 재현한 결함 넷

### 결함 1 (높음) - 도는 그래프의 실행·태스크·이벤트가 내려간다

`graph_run_ids` 를 **정리되는** 그래프에서만 모으고, **열린 그래프**(노드가 다 끝나지 않은 그래프)의
`attempts[].run_id` 를 지키는 집합이 없습니다. 그래서 도는 그래프라도

- 노드 태스크가 보드에 없으면(`task not in task_status`) 시각 규칙으로 그 실행이 옮겨지고
- 노드 태스크가 보드에서 `DONE` 이면 태스크 연결로 그 실행이 옮겨지고, **그 태스크 행과 그 태스크만
  가리키는 이벤트도 함께** 갑니다

재현(검수 부록 B S1): 열린 `G-1`(노드 `T-2` running)의 끝난 노드 `T-1`(보드 DONE)·`T-3`(보드에 없음)
→ `실행 내림 ['T-1-S1-a1','T-3-S1-a1']`, `태스크 내림 ['T-1']`.

**고칠 것:** `.aimem/graph/*.json` 가운데 **정리되지 않는**(=`plan["graphs"]` 에 없는) 그래프를 모두 돌며

- 그 그래프 id
- 모든 노드의 `id` / `task`
- 모든 노드의 `attempts[].run_id`

를 **보호 집합**에 넣으십시오. 보호 집합에 든 id 를 가리키는 **태스크 행·실행 기록·이벤트**는
`plan` 에 넣지 않습니다. 끝난 것과 보호 대상을 **함께** 가리키면 보호 쪽이 이깁니다.

### 결함 5 (중간) - "열린 것" 집합이 모자란다

열린 요청을 **요청 파일(`.aimem/requests/*.json`)로만** 정합니다. 그래서

- DB `requests` 표에만 있는 열린 요청(파일이 없는 것)이 안 보이고
- **대기 큐**(`queue` 표)의 항목은 **아예 보지 않습니다**

운영 미리보기에서도 큐 2·3번이 가리키는 이벤트(#534, #535)와 `T-157` 이벤트가 정리 대상으로 걸립니다.

**고칠 것:** 보호 집합에

- `SELECT id FROM requests WHERE upper(COALESCE(status,'')) NOT IN ('DONE','REJECTED')` 의 id
- `SELECT task FROM queue` 의 글에서 뽑은 식별자 - 큐 본문에 섞여 있으므로
  `re.findall(r"\b(?:T-\d+|Q-\d{6}-[0-9a-f]{4}|G-\d+)\b", 큐글)` 로 긁으십시오

를 더하십시오.

### 결함 6 (중간) - 전달 기록 보호가 정수 일치에만 기댄다

`round` 가 문자열(`"21"`)이거나 `round` 키가 없는 그래프, 아직 그래프가 안 생긴 라운드의
`r<N>.*` 가 열려 있는데도 옮겨집니다(S12: `옮긴 라운드: [20, 21]`).

**고칠 것:**
- 비교를 `str(g.get("round")) == str(N)` 으로 바꾸십시오
- **`round` 키가 없거나 읽을 수 없는 그래프가 하나라도 남아 있으면 전달 기록은 하나도 옮기지 마십시오**
  (어느 라운드 것인지 모르므로)
- **가장 큰 라운드 번호의 전달 기록은 언제나 남기십시오** (지금 도는 라운드)

### 결함 9 (낮음) - 계획과 실행 사이를 다시 확인하지 않는다

`DELETE` 에 계획 때의 조건이 다시 걸려 있지 않아, 계획 뒤 다시 열린 태스크도 지웁니다.

**고칠 것:** 태스크 `DELETE` 에 `AND status='DONE'` 을, 이벤트 `DELETE` 에 `AND kind=?`(계획 때의 kind)를
다시 거십시오. 실제로 지워진 수가 계획과 다르면 그 수를 `out` 에 그대로 싣습니다(조용히 넘어가지 마십시오).
