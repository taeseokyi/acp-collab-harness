## 작업 1 - 밝은 모드를 기본으로 (태석님 지시 2026-11-09 17:22)

지금 `style.css` 의 `:root` 는 어두운 색이다:
```css
:root { --bg:#0b1015; --card:#121920; --card-2:#0e151c; --border:#2b3541;
        --text:#e8eef5; --muted:#9fb0c0; --accent:#7cc4ff; --warn:#ffb04a; --danger:#ff8d8d; }
```

- **`:root` 를 밝은 값으로 바꾼다.** 예: `--bg:#f6f7f9; --card:#ffffff; --card-2:#f0f2f5; --border:#d4d9e0; --text:#16202b; --muted:#5a6b7c; --accent:#1763b8; --warn:#9a5b00; --danger:#b3261e;` (정확한 값은 대비 요건을 만족하면 네가 정해도 된다)
- **어두운 모드는 선택으로만 남긴다.** `html[data-theme="dark"] { ... }` 블록에 기존 어두운 값을 그대로 옮긴다.
- 색은 **전부 `:root` 토큰으로만** 쓴다. 규칙 본문에 하드코딩된 hex 가 남아 있으면 토큰으로 바꾼다(배지 색 포함 - 배지도 `--badge-*` 토큰을 만들어라).
- `index.html` 의 `.controls` 안에 **`id="theme-toggle"`** 버튼을 추가한다(라벨 `어두운 모드` / `밝은 모드` 토글). `app.js` 가 `localStorage` 에 `aimem-theme` 로 저장하고 다음 방문에 복원한다. **저장값이 없으면 밝은 모드다**(OS 설정을 따라가지 않는다 - 태석님이 기본을 밝게 지정했다).
- **대비 요건: 본문 텍스트 4.5:1 이상, 배지 텍스트도 4.5:1 이상.** 밝은 배경에 옅은 회색 글씨를 쓰지 마라. 배지는 `배경 옅은 색 + 글자 진한 같은 계열` 로 한다.

## 작업 2 - 가독성·정렬 (요청 `20261109-171508-ce9f`, 태석님 17:25)

1. **표 열 정렬:** 숫자·시간(경과, rc, 순서, 진행율)은 `text-align:right` + `font-variant-numeric: tabular-nums`. 텍스트는 왼쪽. 상태 배지 열은 가운데. **열 너비를 고정한다** (`table-layout: fixed` + `<colgroup>` 또는 `th` 에 `width`) - 행마다 열이 흔들리지 않아야 한다.
2. **글자 크기·행간:** 본문 14~15px, 보조/주석 12px 이상, `line-height` 1.5 이상.
3. **카드 위계:** `.card` 간격을 하나의 값으로 통일, `h2`/`h3` 크기·굵기·여백을 통일.
4. **긴 텍스트는 줄바꿈 대신 말줄임 + 툴팁:** 로그 본문, 큐 비고, 보고 머리말(`report_head`), 요청 본문은 `overflow:hidden; text-overflow:ellipsis; white-space:nowrap` 로 한 줄에 맞추고 `title` 속성에 전문을 넣는다. **표 셀이 넘쳐 가로 스크롤이 생기지 않아야 한다.**
5. **요청 트리:** 서브태스크 들여쓰기를 일정하게 하고 `상태 / 슬롯 / 경과` 열을 세로로 맞춘다.

## 작업 3 - KISTI LLM 서버 상태 카드 (태석님 지시, 이번 라운드 핵심)

`GET /api/state` 에 **`kisti`** 키가 새로 생겼다. 서버가 10초 캐시로 외부에서 읽어 넣는다. 모양은 정확히 이렇다:

```json
"kisti": {
  "ok": true,
  "url": "https://aida.kisti.re.kr:10430/status",
  "fetched": "2026-11-09T17:20:31",
  "age_sec": 3,
  "error": null,
  "busy": false, "queued": 0, "phase": "reading the prompt",
  "prompt_tokens": 197084, "generated": 0, "max_tokens": 8192,
  "reasoning_recoveries": 0, "thinking_budget": 6144
}
```

실패하면 `{"ok": false, "url": ..., "fetched": ..., "age_sec": N, "error": "..."}` 만 오고 `busy` 등은 **없을 수 있다** - 반드시 없을 때를 처리해라.

- `index.html` 의 `fleet-section` **바로 아래**에 `<section class="card" id="kisti-section">` 을 넣고 그 안에 `id="kisti-card"` 컨테이너를 둔다. 제목은 `KISTI LLM 서버 (S2·S3 작업자)`.
- 카드는 **작게** 한 줄 요약 + 수치 몇 개다: 상태 배지(`busy` 면 `바쁨` 경고색 / 아니면 `대기` 정상색), `대기열 N`, `단계: <phase>`, `프롬프트 <prompt_tokens> 토큰`, `생성 <generated>/<max_tokens>`, 그리고 작게 `N초 전 읽음`.
- **`ok:false` 면 카드에 오류 문자열을 보여준다**(빨간 배지 + `error` 텍스트). 화면 전체가 깨지면 안 된다.
- **중요: 이 카드는 "지금 kistillm 작업자를 하나 더 띄워도 되는가" 를 보는 창이다.** `busy` 이거나 `queued > 0` 이면 카드 아래에 한 줄로 `지금 kistillm 슬롯을 추가로 띄우면 서버 안에서 직렬화됩니다` 라고 경고를 띄워라.
- **API 키를 프런트에서 다루지 마라.** 서버가 환경변수로만 읽고 내보내지 않는다. `app.js` 에 키 비슷한 문자열이 들어가면 안 된다.

## 작업 4 - 태스크 그래프 트리 (`graphs`)

`GET /api/state` 에 **`graphs`** 키도 생겼다. `tools/fleet_graph.py` 가 쓰는 태스크 DAG 요약이다:

```json
"graphs": [ {
  "id": "R-002", "request": "...", "created": "...", "updated": "...",
  "percent": 42.0, "eta_seconds": 610, "eta_at": "2026-11-09T17:55",
  "counts": {"done": 2, "running": 1, "todo": 2},
  "source": "fleet_graph.progress",
  "nodes": [ {"id":"N1","title":"...","slot":"S1","harness":"claude",
              "status":"done","deps":[],"attempts":1,"max_attempts":2,"last_run":"20261109-...-S1"} ]
} ]
```

`percent`/`eta_seconds`/`eta_at` 는 **null 일 수 있다**(`source` 가 `counts-only` 일 때). 반드시 null 을 처리해라.

- `requests-section`(5. 요청별 분담 트리) 안, 요청 목록 **위**에 `id="graphs-list"` 컨테이너를 만들고 그래프마다 블록 하나를 그린다: 제목줄(`<id> · <request> · <percent>% · ETA <eta_seconds>s`), 그 아래 노드 표(열: 노드ID / 제목 / 슬롯 / 하네스 / 상태 / 의존 / 시도 `attempts`/`max_attempts` / run).
- 노드 표도 작업 2 의 정렬 규칙을 따른다. `deps` 는 `N1, N2` 처럼 잇는다.
- `graphs` 가 빈 배열이면 컨테이너를 비우고 `진행 중인 태스크 그래프가 없습니다` 한 줄만 둔다.
