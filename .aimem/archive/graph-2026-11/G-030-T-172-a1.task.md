## 결함 4 - 설계에 있는 "남는 필드는 버림" 이 빠졌습니다

설계 2절 표: "메시지 전체 | 평범한 객체 | **위 필드 밖의 키가 있으면 버림**".
지금은 `{aimem,op,key,value,part,name}` 같은 메시지도 받아들입니다.

→ `m.aimem !== 'store.v1'` 검사 **바로 뒤**에, 허용 키 집합 밖의 키가 하나라도 있으면
`return` 하십시오.

```js
const ALLOWED_MSG_KEYS = { ready: ['aimem', 'op'], put: ['aimem', 'op', 'key', 'value'] };
const allowed = ALLOWED_MSG_KEYS[m.op];
if (!allowed || Object.keys(m).some((k) => !allowed.includes(k))) return;
```

`ALLOWED_MSG_KEYS` 는 `openProjectApp` 밖의 모듈 수준에 두어도 되고 안에 두어도 됩니다.

## 결함 5 - 이미 상한을 넘은 칸이 영영 굳습니다

`loadPart` 가 저장된 칸의 **키 수·직렬화 길이를 재지 않습니다.** 옛 버전이나 다른 코드가 남긴
키 70개짜리 칸을 읽으면, 그 뒤 모든 `put` 이 "넘침" 으로 되돌려집니다 - **지우기(`value:null`)까지**
되돌려져 칸을 줄일 길이 없습니다.

→ `putIfFits` 에서 **칸이 줄어드는 변경은 언제나 받아들이십시오.** 판정을 이렇게 바꾸면 됩니다:
반영해 본 뒤 `size` 와 직렬화 길이를 재서,

- 둘 다 상한 안이면 받아들임 (지금 동작)
- 상한을 넘더라도 **반영 전보다 `size` 가 줄었거나 직렬화 길이가 줄었으면** 받아들임
- 그 밖이면 되돌리고 버림

## 결함 6 - 정리 훅을 건너뛰는 길 둘

(i) `openRequestDetail`·`openDetail`·`openManagerDetail`(815·973·1551행 근처)은 `openPanel` 을
거치지 않고 `detail-body` 를 비웁니다. 앱 패널이 열린 채 이 셋이 불리면 리스너가 남습니다.

→ **세 함수의 첫 줄**에 `runPanelCleanups();` 를 넣으십시오. (`openPanel`·`closeDetail` 에는 이미 있습니다.)

(ii) 모니터 탭을 닫거나 새로 고치면 250ms 묶음에 남은 쓰기가 사라집니다.

→ 모듈 수준에 한 줄 더하십시오.

```js
window.addEventListener('pagehide', runPanelCleanups);
```

`runPanelCleanups` 가 정의된 **뒤**에 두십시오.
