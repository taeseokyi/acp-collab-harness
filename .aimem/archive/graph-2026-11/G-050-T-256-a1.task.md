# T-256 `browser_monitor_tabs.py`: 탭 검사도 고정 자료 저장소에서

쓸 파일은 **하나**입니다: `tests/browser_monitor_tabs.py`. **다른 `tests/**` 와 `tools/**` 는
읽기만 하고 절대 고치지 마십시오.** 지금 이 검사는 **10건 전부 통과**합니다. 바로 고치십시오.

## 왜

이 파일의 `monitor_server(root=None)` 은 `root` 를 안 주면 **진짜 저장소**를 띄웁니다.
`main()` 이 그렇게 띄워서 `tabs_scenario` 와 `project_picker_scenario` 가 **오늘 저장소에
프로젝트가 몇 개 있는지**에 기댑니다. 특히 `tabs_scenario` 의
`"프로젝트 탭을 누르면 보인다"` 는 `#projects-list .proj-item` 이 **적어도 하나** 있어야 하고,
`project_picker_scenario` 는 고르개에 뜨는 프로젝트 목록에 기댑니다. 프로젝트가 하나도 없거나
반대로 아주 많아지면 그날로 깨집니다(R17 에 같은 이유로 두 건이 깨졌습니다).

## 어떻게

1. **`write_fixed_repo(root)`** 를 새로 만드십시오. 임시 저장소에 **고정 프로젝트 둘**이 생기게
   합니다 - `projects/<이름>/` 과 그 안의 `PROGRESS.md` 한 줄이면 충분한지, 아니면 요청 파일
   (`.aimem/requests/*.json` 의 `project` 칸)도 있어야 하는지 **직접 띄워 확인하십시오**.
   같은 파일의 `monitor_server(root=...)` 로 띄워 `/api/state` 를 받아 보면 가장 빠릅니다
   - 프로젝트 하나는 **진행 중**, 하나는 **끝남**으로 두십시오 (기본 필터가 '진행 중' 이라
     둘 다 끝나 있으면 목록이 빕니다)
   - `tests/browser_monitor_ui.py` 의 `write_fixed_requests` / `write_fixed_runs` 가 임시 저장소에
     자료를 꾸미는 본보기입니다. **그 파일을 고치지는 마십시오 - 읽기만.** 필요한 모양은
     이 파일 안에 따로 쓰십시오
2. **`main()`** 을 `tempfile.TemporaryDirectory()` + `write_fixed_repo(temp_root)` +
   `with monitor_server(root=temp_root) as base:` 로 바꾸고 두 시나리오를 거기서 돌리십시오
3. `tabs_scenario` 의 다른 검사들(탭 넷·보이는 패널 하나·주소로 열기·전역 정리 단추)은
   저장소 상태와 상관없습니다 - **글자 하나 바꾸지 말고** 그대로 두십시오

## 지켜야 할 것

- **검사 10건이 전부 그대로 있어야 하고 전부 통과해야 합니다.** 지우거나 느슨하게 바꾸지 마십시오
- 어떤 단언도 "지금 저장소에 무엇이 들어 있는가" 에 기대면 안 됩니다
- 제품(`tools/**`)이 틀려 검사가 빨개지면 고치지 말고 보고 첫 줄을 `NEEDS-FIX: <무엇이 어디서>` 로

## 검증

검증 명령이 봅니다: `python3 tests/browser_monitor_tabs.py` 의 마지막 줄이
`통과 N / 전체 N` 이고 **N >= 10 이며 통과 == 전체** 인 것.
