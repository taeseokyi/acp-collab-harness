## [REV 107 / 2026-11-09 내림] 8.0 네이티브 상주 슬롯 + 8.0-1~8.0-3 (원문)

사유: 태석님 지시(2026-11-09)로 함대를 claude/codex/opencode **ACP 일회성 자식**으로 되돌렸다. 2026-11-06 에 `agents.entries.<id>.runtime.type="acp"` 를 등록해 `Unknown agent id` 가 해소됐고 스모크 3/3 이 통과했다. `sessions_send` 왕복·`timeoutSeconds: 0` 병렬·`nested:` 레인·300k 교체 규칙은 상주 세션 전용이라 함께 내린다. 새 `8.0` 은 본문에 있다.

### 8.0 최상위 규칙 - 네이티브 상주 슬롯 (태석님 확정 2026-09-28)

**이 절의 나머지보다 우선합니다.** 어긋나면 이 규칙을 따릅니다.

**ACP 런타임은 현재 세션을 만들지 못합니다** (`dispatch_failed / Unknown agent id`).
**원인은 acpx 플러그인이 아닙니다** - 런타임이 요청 `agentId` 를 `agents.entries` 키에
대해 검사하는데 ACP 자식 세션키는 하네스 id 자리를 쓰고 그 값이 설계상 거기 없습니다
(REV 103 실측 확정. 그전 서술은 틀렸습니다). 우회책은
`agents.entries.<id>.runtime.type="acp"` 등록이고 **적용하지 않았습니다** - 못 고치는 게
아니라 지금 고칠 값어치가 없어서입니다. "ACP 불가"로 읽고 틀린 전제에서 출발하지 마십시오.

- **슬롯은 네이티브 서브에이전트 상주 세션입니다.** 관리자가 다음으로 엽니다:

  ```
  sessions_spawn(context: "isolated", cwd: "/home/tsyi/work/opencode",
                 visible: true, label: "S1 린터/보드 CLI", taskName: "s1",
                 group: "AIMEM 함대", task: "<개시 브리프 전문>")
  ```

  `runtime` / `agentId` / `streamTo` / `thread` 를 주지 않습니다. 세션키는
  `agent:coding:dashboard:<uuid>` 로 나고 2절 명부에 박습니다
- **지시와 보고는 `sessions_send(sessionKey, message)` 이고 답이 동기로 돌아옵니다.**
  `sessions_yield` 로 기다리지 마십시오 - **`visible:true` 자식은 완료를 통보하지
  않습니다**(실측). 기록은 세션에 누적되고 `sessions_history` 로 읽습니다
- **작업자는 아웃박스에 쓰지 않습니다.** 보고는 응답 본문입니다
- 브리프에 **슬롯 ID · 확인토큰 · REV · 쓰기 범위 · 배경 · 요구사항 · 검증 방법**을
  전부 싣습니다. 상주라도 최초 컨텍스트는 비어 있습니다. 불일치 시 작업자가 멈추고
  되묻는 것이 **정상 동작**입니다
- 슬롯이 죽거나 컨텍스트가 오염되면 **같은 슬롯 ID 로 새 세션을 열고 명부의 세션키만
  교체합니다.** 토큰은 그대로 씁니다
- **교체·리셋 전에 두 가지를 정리합니다:** 진행 중 태스크의 보드 상태를 `TODO` 로
  되돌리고(`IN-PROGRESS` 인 채로 갈아타면 다음 작업자가 **없는 선행 결과를 찾습니다**),
  미커밋을 정리합니다(작업자의 git 앵커는 HEAD 가 최신일 때만 쓸모가 있습니다)

#### 8.0-1 슬롯은 좁게, 전체 그림은 관리자만 (태석님 지시 2026-09-28)

**작업자에게 종합적인 업무를 주지 않습니다.** 폴더 전체를 판단하는 자리는 관리자 하나입니다.

- **한 슬롯에 한 번에 하나의 국소 태스크.** "이 파일의 이 함수를 이렇게 고치고 이 명령으로
  검증하라" 수준으로 좁힙니다. 범위가 넓어지면 관리자가 먼저 쪼갭니다
- **브리프는 자족적이어야 합니다.** 작업자는 이 파일을 통째로 읽지 않습니다(`0.1`).
  파일 경로·현재 동작·기대 동작·검증 명령을 관리자가 적어 줍니다.
  **"AIMEM 을 읽고 알아서 판단하라" 는 지시는 이 규칙 위반입니다** - 필요한 대목이 길면
  브리프에 인용해 넣습니다. 작업자가 맥락을 찾아 파일을 뒤지면 판단이 관리자와 갈립니다
- **만든 슬롯이 아닌 슬롯이 검증합니다** (구 `1.5` 에서 흡수, REV 104).
  자기 채점은 자기 사각지대를 영원히 못 봅니다
- **매 라운드 `sessions_list` 로 `totalTokens` 를 보고 300k 를 넘으면 교체합니다.**
  바닥값 75k, 국소 태스크는 턴당 2~12k. 요약이 조용히 일어나 작업자가 **접힌 기억을
  근거로 자신 있게 답하는 것**이 진짜 위험입니다(`0.4`). 교체가 싼 이유는 연속성의
  정본이 세션이 아니라 이 파일이기 때문입니다

#### 8.0-2 의사결정과 실행의 분리 (태석님 지시 2026-09-28)

- **아이디어·계획·구조 설계·진행 관리**는 관리자가 **옥티(`review`)·구름(`main`)과
  상의해** 정합니다. `sessions_send(agentId=...)` 로 직접 닿습니다 - 태석님을 중계자로
  쓰지 않습니다
- **범위가 확정된 실행**만 슬롯이 맡습니다. 슬롯에 도달하는 시점에는 "무엇을 왜"가
  끝나 있어야 하고 남은 것은 "어떻게"뿐입니다
- 슬롯이 설계 판단을 요구받으면 **브리프 결함**입니다. `BLOCKED` 가 정상입니다(`0.3`)

#### 8.0-3 병렬 투입 (실측 2026-09-28)

병렬 가능한 태스크는 세 슬롯에 **동시에** 넣습니다.

- **`sessions_send` 에 `timeoutSeconds: 0` 을 줍니다.** 즉시
  `accepted / targetDisposition: "queued"` 로 돌아오고 답을 기다리지 않습니다.
  세 호출을 한 번에 내보내면 세 슬롯이 같이 돕니다
- **기본 타임아웃으로 부르면 직렬이 됩니다.** 답을 기다리느라 한 번에 하나씩
  돕니다. 순서가 중요한 의존 태스크에는 이쪽이 맞습니다
- **레인:** 슬롯은 `nested:<세션키>` **전용 레인**이라 `main`(구름·옥티)과 경합하지
  않습니다. **슬롯 안은 직렬, 슬롯끼리는 병렬**입니다. 합계 상한이 없어 슬롯을 늘려도
  큐가 막지 않습니다 - 실질 상한은 관리자 컨텍스트뿐입니다
- **가장 오래 쓸 교훈: 낙관적 오류는 측정이 잡지만 비관적 오류는 코드를 읽어야만
  잡힙니다.** 병렬 실측이 이미 반증이었는데 *"비경합 구간 값"* 이라는 변명이 그것을
  흡수해 틀린 서술이 살아남았습니다. **느리다는 서술은 측정 말고 코드를 읽으십시오**
- **주의:** 2초보다 짧은 태스크는 투입 지연 때문에 겹치지 않아 직렬처럼 보입니다.
  타임스탬프로만 판정하십시오
