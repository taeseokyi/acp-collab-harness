### 8.0 최상위 규칙 - 네이티브 상주 슬롯 (태석님 확정 2026-09-28)

**이 절의 나머지보다 우선합니다.** 어긋나면 이 규칙을 따릅니다.

**ACP 런타임은 현재 세션을 만들지 못합니다** (`dispatch_failed / Unknown agent id`).
**원인은 acpx 플러그인이 아닙니다** - 런타임이 요청 `agentId` 를 `agents.entries` 키에
대해 검사하는데 ACP 자식 세션키는 하네스 id 자리를 쓰고 그 값이 설계상 거기 없습니다
(REV 103 실측 확정. 그전 서술은 틀렸습니다). 우회책은
`agents.entries.<id>.runtime.type="acp"` 등록이고 **적용하지 않았습니다** - 못 고치는 게
아니라 지금 고칠 값어치가 없어서입니다. "ACP 불가"로 읽고 틀린 전제에서 출발하지 마십시오.

- **슬롯은 네이티브 서브에이전트 상주 세션입니다.** 관리자가 다음으로 엽니다:

  ```
  sessions_spawn(context: "isolated", cwd: "/home/tsyi/work/opencode",
                 visible: true, label: "S1 린터/보드 CLI", taskName: "s1",
                 group: "AIMEM 함대", task: "<개시 브리프 전문>")
  ```

  `runtime` / `agentId` / `streamTo` / `thread` 를 주지 않습니다. 세션키는
  `agent:coding:dashboard:<uuid>` 로 나고 2절 명부에 박습니다
- **지시와 보고는 `sessions_send(sessionKey, message)` 이고 답이 동기로 돌아옵니다.**
  `sessions_yield` 로 기다리지 마십시오 - **`visible:true` 자식은 완료를 통보하지
  않습니다**(실측). 기록은 세션에 누적되고 `sessions_history` 로 읽습니다
- **작업자는 아웃박스에 쓰지 않습니다.** 보고는 응답 본문입니다
- 브리프에 **슬롯 ID · 확인토큰 · REV · 쓰기 범위 · 배경 · 요구사항 · 검증 방법**을
  전부 싣습니다. 상주라도 최초 컨텍스트는 비어 있습니다. 불일치 시 작업자가 멈추고
  되묻는 것이 **정상 동작**입니다
- 슬롯이 죽거나 컨텍스트가 오염되면 **같은 슬롯 ID 로 새 세션을 열고 명부의 세션키만
  교체합니다.** 토큰은 그대로 씁니다
- **교체·리셋 전에 두 가지를 정리합니다:** 진행 중 태스크의 보드 상태를 `TODO` 로
  되돌리고(`IN-PROGRESS` 인 채로 갈아타면 다음 작업자가 **없는 선행 결과를 찾습니다**),
  미커밋을 정리합니다(작업자의 git 앵커는 HEAD 가 최신일 때만 쓸모가 있습니다)

#### 8.0-1 슬롯은 좁게, 전체 그림은 관리자만 (태석님 지시 2026-09-28)

**작업자에게 종합적인 업무를 주지 않습니다.** 폴더 전체를 판단하는 자리는 관리자 하나입니다.

- **한 슬롯에 한 번에 하나의 국소 태스크.** "이 파일의 이 함수를 이렇게 고치고 이 명령으로
  검증하라" 수준으로 좁힙니다. 범위가 넓어지면 관리자가 먼저 쪼갭니다
- **브리프는 자족적이어야 합니다.** 작업자는 이 파일을 통째로 읽지 않습니다(`0.1`).
  파일 경로·현재 동작·기대 동작·검증 명령을 관리자가 적어 줍니다.
  **"AIMEM 을 읽고 알아서 판단하라" 는 지시는 이 규칙 위반입니다** - 필요한 대목이 길면
  브리프에 인용해 넣습니다. 작업자가 맥락을 찾아 파일을 뒤지면 판단이 관리자와 갈립니다
- **만든 슬롯이 아닌 슬롯이 검증합니다** (구 `1.5` 에서 흡수, REV 104).
  자기 채점은 자기 사각지대를 영원히 못 봅니다
- **매 라운드 `sessions_list` 로 `totalTokens` 를 보고 300k 를 넘으면 교체합니다.**
  바닥값 75k, 국소 태스크는 턴당 2~12k. 요약이 조용히 일어나 작업자가 **접힌 기억을
  근거로 자신 있게 답하는 것**이 진짜 위험입니다(`0.4`). 교체가 싼 이유는 연속성의
  정본이 세션이 아니라 이 파일이기 때문입니다

#### 8.0-2 의사결정과 실행의 분리 (태석님 지시 2026-09-28)

- **아이디어·계획·구조 설계·진행 관리**는 관리자가 **옥티(`review`)·구름(`main`)과
  상의해** 정합니다. `sessions_send(agentId=...)` 로 직접 닿습니다 - 태석님을 중계자로
  쓰지 않습니다
- **범위가 확정된 실행**만 슬롯이 맡습니다. 슬롯에 도달하는 시점에는 "무엇을 왜"가
  끝나 있어야 하고 남은 것은 "어떻게"뿐입니다
- 슬롯이 설계 판단을 요구받으면 **브리프 결함**입니다. `BLOCKED` 가 정상입니다(`0.3`)

#### 8.0-3 병렬 투입 (실측 2026-09-28)

병렬 가능한 태스크는 세 슬롯에 **동시에** 넣습니다.

- **`sessions_send` 에 `timeoutSeconds: 0` 을 줍니다.** 즉시
  `accepted / targetDisposition: "queued"` 로 돌아오고 답을 기다리지 않습니다.
  세 호출을 한 번에 내보내면 세 슬롯이 같이 돕니다
- **기본 타임아웃으로 부르면 직렬이 됩니다.** 답을 기다리느라 한 번에 하나씩
  돕니다. 순서가 중요한 의존 태스크에는 이쪽이 맞습니다
- **레인:** 슬롯은 `nested:<세션키>` **전용 레인**이라 `main`(구름·옥티)과 경합하지
  않습니다. **슬롯 안은 직렬, 슬롯끼리는 병렬**입니다. 합계 상한이 없어 슬롯을 늘려도
  큐가 막지 않습니다 - 실질 상한은 관리자 컨텍스트뿐입니다
- **가장 오래 쓸 교훈: 낙관적 오류는 측정이 잡지만 비관적 오류는 코드를 읽어야만
  잡힙니다.** 병렬 실측이 이미 반증이었는데 *"비경합 구간 값"* 이라는 변명이 그것을
  흡수해 틀린 서술이 살아남았습니다. **느리다는 서술은 측정 말고 코드를 읽으십시오**
- **주의:** 2초보다 짧은 태스크는 투입 지연 때문에 겹치지 않아 직렬처럼 보입니다.
  타임스탬프로만 판정하십시오

(실측값·레인 근거는 `.aimem/archive/retired-sections-2026-09.md`)

### 8.0 최상위 규칙 - ACP 일회성 자식 (태석님 지시 2026-11-09)

**이 절의 나머지보다 우선합니다.** 어긋나면 이 규칙을 따릅니다.
(구 `8.0` "네이티브 상주 슬롯" 원문은 `.aimem/archive/retired-sections-2026-11.md`)

**ACP 런타임은 다시 세션을 만듭니다.** 2026-11-06 에 `agents.entries.claude|codex|opencode` 를
`runtime.type="acp"` 로 등록해 `Unknown agent id` 가 사라졌고(스모크 PONG 3/3), 세 항목의
`workspace` 가 `/home/tsyi/work/opencode` 라 `cwd` 인자 없이 이 폴더에서 뜹니다
(`runtime.acp.cwd` 는 스폰에 적용되지 않습니다 - 실측). 업스트림 #138580 은 그대로이고
이 등록이 우회책입니다.

- **슬롯은 ACP 일회성 자식입니다.** 태스크마다 관리자가 새로 엽니다:

  ```
  sessions_spawn(runtime: "acp", agentId: "claude" | "codex" | "opencode",
                 mode: "run", context: "isolated",
                 label: "S1 린터/보드 CLI", task: "<브리프 전문>")
  ```

  `agentId` 는 `2절` 명부의 하네스 칸입니다. `cwd` / `thread` / `streamTo` 는 주지 않습니다.
  세션키는 `agent:<하네스>:acp:<uuid>` 로 나며 **명부에 적지 않습니다**. 턴이 끝나면 세션은
  `done` 으로 남고 재사용하지 않습니다(11-09 실측). `python3 tools/fleet.py close` 가 남은 것을
  짚어 주면 `sessions.delete` 로 거둡니다
- **지시는 스폰의 `task` 한 번, 보고는 자식의 완료 응답 본문입니다.** `sessions_send` 는 쓰지
  않습니다(일회성 자식은 한 턴으로 끝납니다). 보고는 완료 통보로 올라옵니다. 통보 본문이
  잘렸으면 거두기 전에 `sessions_history(sessionKey)` 로 읽습니다(11-09 실측: 전문이 남아 있음)
- **모델:** claude 는 `anthropic/claude-sonnet-5`(항목 고정), codex·opencode 는 `kisti/kistillm`.
  판단이 갈릴 수 있는 태스크는 claude 슬롯(S1)에, 범위가 좁은 실행은 codex·opencode(S2·S3)에
  줍니다. 스폰 `model` 인자로 바꿀 수 있습니다
- **실행 모델의 정본은 하네스 설정입니다** - claude 는 `agents.entries.claude.model`, codex 는
  `~/.codex/config.toml`, opencode 는 `~/.config/opencode/opencode.jsonc`. **`sessions_list` 의
  `model` 은 읽지 마십시오** - OpenClaw 기본 모델(`kisti/kistillm`)이 찍히는 표기라 ACP 자식의
  실행 모델이 아닙니다(11-09 실측: sonnet-5 로 돈 claude 자식도 `kistillm` 으로 표시). CLI
  `openclaw sessions` 의 `claude-acp` 류는 하네스 이름입니다. 자식 조회는
  `python3 tools/fleet.py children` 으로 합니다 - 하네스 설정에서 모델을 읽어 같이 보여 줍니다
- **점검(하이파이브) 브리프의 보고 한 줄 형식:**
  `하이파이브 S<n> OK | REV <N> | 토큰 <t> | 시각 <KST HH:MM> | cwd <pwd> | 모델 <자기 모델 또는 unknown>`.
  claude 는 자기 모델을 압니다. codex·opencode 는 모르면 `unknown` 으로 적고, 관리자가
  `fleet.py children` 출력과 대조합니다. 이 한 줄 **앞뒤에 다른 문장을 붙이지 않습니다**
- **브리프에 슬롯 ID · 확인토큰 · REV · 쓰기 범위 · 배경 · 요구사항 · 검증 방법을 전부
  싣습니다.** 자식은 매번 빈 컨텍스트로 시작합니다. 불일치 시 작업자가 멈추고 되묻는 것이
  **정상 동작**입니다. `python3 tools/fleet.py brief --slot S1 --write <경로>` 가 머리말을 만듭니다
- **이어하기는 새 스폰입니다.** 직전 결과(산출물 유무, 남은 일)를 브리프에 적어 다시 엽니다.
  재배정 전에 보드 상태를 `TODO` 로 되돌리고 미커밋을 정리합니다(`8.1`)
- **위임 파일:** 작업자는 자기 하네스의 사용자 전역 지침 파일에서 위임을 확인합니다(`0절`).
  `~/.codex/AGENTS.md` 와 `~/.config/opencode/AGENTS.md` 는 2026-11-09 에 만들었습니다.
  없으면 작업자가 쓰기를 거절하는 것이 맞습니다
- **상주 세션이 꼭 필요하면**(여러 턴 대화가 필요한 예외) `mode: "session"` + `thread: true`
  로 `#sss-fleet` 채널 세션에서 열고 `sessions_send` 로 지시합니다. 디스코드 자식 스레드가
  생깁니다(`session.threadBindings.spawnSessions` 기본 참). **10.3 에서 미실측** - 첫 사용 전
  프로브 1회를 거칩니다

## [REV 126 내림] 8.0-5 의 REV 111 결함 서술 (고친 3건 + 남은 3건)

> 남은 3건(단일 실행자 잠금·모양 검증·노드별 타임아웃)은 R6(REV 115)에서 해소됐고, `run` 중 `step`·JSON 수정 금지 제약은 잠금으로 풀렸다. 역사로만 남긴다. 2026-11-10 클로드 코드.

**REV 111 에서 고친 결함 3건 (S4 적대적 검수, 관리자가 직접 수정·재현 확인):**

1. **슬롯 바쁨 검사**(`_busy_slots()`). `step()` 이 전체 `running` 개수만 보고 슬롯은 보지
   않아, **관리자가 손으로 띄운 작업자가 살아 있는 슬롯에 그래프가 또 띄웠습니다.** 실측에서
   S1 노드 3개가 한 틱에 모두 배정됐습니다. 이제 `.aimem/runs` 를 정본으로 보아 **그래프 밖
   실행까지** 세고, 바쁘면 건너뛰고 로그를 남깁니다
2. **고아 스폰**(스폰 직후 `_save`). 한 틱의 끝에서 한 번만 저장해, 뒤 노드가 `SystemExit`
   (명부에 없는 슬롯 등)로 죽으면 **앞에서 띄운 작업자가 그래프에 기록되지 않고 고아로
   남았습니다.** 다음 틱이 같은 노드를 다시 띄웠습니다. 이제 노드마다 저장하고 `SystemExit`
   를 잡아 `failed` 로 기록합니다
3. **원자적 저장**(tmp + `os.replace`). `write_text` 직접 쓰기라 쓰다 죽으면 파일이 잘렸고
   (실측 215B -> 107B) 그 뒤 모든 하위명령이 `JSONDecodeError` 로 죽었습니다 - **스폰된 run id
   목록이 같이 사라져 복구 수단이 없었습니다.** 덤으로 `_ready()` 가 **모르는 의존 id 를
   "충족됨" 으로 보던 것**도 막았습니다(오타 난 dep 하나가 노드를 곧바로 띄웠습니다)

**남은 결함 3건은 `4.5` 큐에 있습니다**(단일 실행자 잠금 / 모양 검증 재사용 / 노드별 타임아웃).
**그때까지의 운용 제약: `run` 이 도는 동안 `step` 을 따로 치지 마십시오.** 잠금이 없어 같은
노드를 두 번 띄웁니다(실측: `[('A','S1','fake-1'), …, ('A','S1','fake-3'), …]`). 같은 이유로
**`run` 이 도는 동안 그래프 JSON 을 손으로 고치지 마십시오** - 러너가 메모리 사본으로 덮습니다.
