14. **용어 정리를 `8.0-5` 로 적으십시오**(태석님 질문 18:10 "노드·태스크·라운드가 섞여 있다"): 다섯 층 - **요청**(태석님이 원하는 것, 웹 요청 id/브리프, NEW→PLANNED→IN-PROGRESS→DONE) → **태스크**(보드 3절 한 행 `T-0xx`, 요청을 쪼갠 단위) → **그래프**(태스크들의 DAG, 한 번에 스케줄하는 묶음) → **실행**(작업자 프로세스 한 번, 재시도마다 새 run id) / **라운드**(관리자 세션 한 턴, REV·4절 기록 단위이지 일의 단위가 아님). **식별자 체계(태석님 18:15 확정, fleet.py 에 반영됨):**
   | 층 | 형식 | 예 | 비고 |
   | --- | --- | --- | --- |
   | 요청 | `Q-<YYMMDD>-<4자>` | `Q-261109-8d8d` | server.py 가 만든다(관리자). 지금의 `20261109-173900-8d8d` 를 이 형식으로 |
   | 태스크 | `T-0xx` | `T-050` | 보드 3절 그대로 |
   | 그래프 | `G-00x` | `G-003` | `R-00x` 는 라운드와 헷갈려 폐기 |
   | 실행 | `<태스크>-<슬롯>-a<시도>-<HHMMSS>` | `T-050-S1-a2-174829` | **`fleet.py spawn --task-id T-050 --attempt 2` 가 만든다(반영됨)**. 태스크 없으면 `ADHOC-S1-a1-…` |
   | 라운드 | `R<n>` | `R3` | 관리자 세션 라벨과 4절에만. 실행 라벨에 넣지 않는다 |
   그래프 노드 id 는 `T-0xx` 그대로 쓰고, `fleet_graph.py _spawn_node` 가 `--task-id <노드id> --attempt <n>` 을 넘기게 고치십시오(관리자 소유 파일이라 클로드 코드는 손대지 않음). 기존 `R-002`/`N1~N6`/옛 run id 는 이력이라 두고 다음부터 적용. 웹 UI 의 실행 표는 run id 를 태스크·슬롯·시도로 쪼개 열로 보여 주면 식별이 쉽다.
15. 매 라운드와 같이 REV 증가, 린터·테스트 통과, **커밋·푸시 금지**(이번 대화에서 허용되지 않음), 대기 시간 수치(`fleet.py runs` 경과 vs 당신 턴)를 `4절` 에 한 줄.
