## 과제 (태석님 요구사항 원문 반영)
**AIMEM 함대 운영을 모니터링하고 작업을 요청할 수 있는 웹 UI** 를 이 저장소 안에 만드십시오.
- 모니터링: AIMEM.md 의 REV·명부·`3절` 보드·`4.5` 큐·`4절` 로그, `.aimem/runs/*.json|rc|out` 의 작업자 실행 상태(running/done/lost, 경과 시간), 하네스별 모델.
- 작업 요청: 웹에서 사람이 태스크를 적어 넣으면 `4.5 대기 큐`(또는 별도 요청 파일 `.aimem/requests/*.json`) 에 쌓이고, 관리자가 그것을 분담한다.
- 분담 가시화: 요청한 작업이 어떤 서브태스크로 쪼개져 어느 슬롯(하네스)에 배정됐고 각 상태가 무엇인지 트리/표로 보여 준다.
- **진행율(%)** 과 **완료 예정 시간(ETA)** 을 요청 단위·서브태스크 단위로 표시한다. ETA 는 `.aimem/runs` 의 과거 실행 시간(하네스별 중앙값)으로 추정하고 근거를 함께 보여 준다.
- 기술 제약: 표준 라이브러리 파이썬(`http.server` 등)만. 의존성 설치 금지. 포트는 18799. 정적 HTML+JS 한 벌 + JSON API. 데이터는 파일(AIMEM.md, .aimem/) 에서 읽기만 하고, 쓰기는 요청 파일 생성 하나뿐.

## 진행 방식 (8.0-1 ~ 8.0-4 그대로)
- 요구사항을 도출해 **국소 태스크로 쪼개고** 보드(`3절`)와 큐(`4.5`)에 적은 뒤, 의존 없는 것은 **한 턴에 병렬로 spawn** 하십시오. 서버/API 는 S1(claude), 테스트는 S2(codex), 프런트 정적 파일·검수는 S3(opencode) 처럼 역할을 나누되 판단은 당신이 합니다.
- 새 경로 소유권: 태석님이 이 과제 범위에서 `tools/aimem_monitor/**` 와 `tests/test_aimem_monitor*.py`, `.aimem/requests/**` 를 슬롯에 배정하는 것을 **승인**했습니다. `6절` 에 등재한 뒤 spawn 하십시오(`6.1` 기록 포함).
- 작업자 보고는 믿지 말고 **검증을 재현**하십시오(서버 기동, curl, 테스트 실행). 자기 채점 금지 - 만든 슬롯이 아닌 슬롯이 검수합니다.
- 매 라운드 REV 를 올리고 `python3 tools/aimem_lint.py AIMEM.md` 와 `python3 -m unittest discover -s tests` 를 통과시키십시오. **git commit / push 는 하지 마십시오** - 이번 대화에서 태석님이 허용하지 않았습니다. 작업 트리는 태석님이 검토합니다.
- 대기 시간을 재십시오: 각 spawn 의 `runs` 경과와 당신의 턴 시간을 `4절` 로그에 한 줄로 남기십시오.
