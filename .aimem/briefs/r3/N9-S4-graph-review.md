# T-052 `tools/fleet_graph.py` 적대적 검수 - **읽기 전용. 저장소 파일을 고치지 마라.**

태석님이 이 도구를 함대 규약(`8.0-5`)으로 채택할지 결정해야 한다. 관리자가 판정을 쓰는데,
**판정의 근거가 필요하다.** 네 일은 "쓸 만한가" 가 아니라 **"어디서 깨지는가"** 를 재현해 보이는 것이다.

실험은 `/tmp` 의 임시 디렉터리 + 가짜 그래프 JSON 으로 해라. 저장소의 `.aimem/graph/` 를 쓰지 마라
(**지금 실제 그래프 `R-002` 가 돌고 있다 - 건드리면 진행 중인 작업이 깨진다**).
`fleet_graph.py` 를 import 해서 함수 단위로 부르는 것은 좋다. `run`/`step` 을 실제 스폰까지 가게 하지 마라
(`_spawn_node` 를 monkeypatch 해서 가짜 run id 를 돌려주게 해라).

## 반드시 확인할 것 (각 항목: 재현 방법 + 실제 출력 + 판정 OK/결함)
1. **이중 스폰.** `run` 이 두 번 떠 있으면 같은 노드를 두 번 스폰하는가?
   상태 파일에 잠금(lock/pid)이 있는가? 없으면 어떤 손해가 나는가?
2. **슬롯 충돌.** `step()` 은 전체 `running` 수만 세고 **같은 슬롯이 이미 바쁜지 보지 않는 것으로 보인다.**
   한 슬롯에 두 노드가 동시에 배정되면 어떻게 되는지 재현하라. (관리자가 지금 수동으로 S1/S2 를
   따로 띄워 둔 상태라 실제로 겹칠 수 있다 - 이게 실제 위험인지 판정하라.)
3. **상태 파일 원자성.** 쓰다 죽으면 그래프 JSON 이 깨지는가? 임시파일+rename 인가?
   깨진 상태 파일로 `status`/`run` 을 부르면 어떻게 되는가?
4. **재시도 한정.** 최대 시도 횟수가 실제로 걸리는가? 무한 재시도로 가는 경로가 있는가?
   실패한 노드의 의존 노드는 영원히 `todo` 로 남는가 (교착)?
5. **ETA 계산.** `progress()` 의 `percent` / `eta_seconds` 가 말이 되는가?
   - 표본이 0개인 하네스, 노드 1개짜리 그래프, 순환 의존(`N1->N2->N1`), 빈 `nodes`
   - `running` 노드가 중앙값을 넘겼을 때 `percent` 가 100 을 넘거나 역행하는가?
   - 임계 경로 계산이 순환에서 무한루프에 빠지는가? (**타임아웃을 걸고 실험하라**)
6. **`progress()` 의 부수효과.** 웹 서버가 매 폴링마다 부른다. 쓰기·`subprocess`·`sys.path` 오염이 있는가?
7. **노드 모양 방어.** `nodes` 가 리스트가 아닐 때, 노드가 문자열일 때, `deps` 에 없는 id 가 있을 때,
   `slot` 이 2절 명부에 없을 때 각각 어떻게 되는가?
8. **타임아웃.** `run --timeout` 이 실제로 끊는가? 끊긴 뒤 노드 상태는 무엇으로 남는가
   (`running` 으로 남아 영원히 바쁜 것으로 보이는가)?
