## 결함 1 - `eta_over` 가 같은 run 을 서브태스크 수만큼 중복으로 싣는다
한 요청에 서브태스크 둘을 걸고 둘 다 같은 `run_id` 를 가리키게 했더니
`초과 중: …` 문장이 **똑같이 두 번** 나왔다. 화면에 같은 줄이 두 번 보인다.
`run_id` 기준으로 중복을 제거하라. 어느 함수가 이걸 만드는지는 `_estimate` 를 읽어서 확인하라.

## 결함 2 - 스모크 실행이 하네스 중앙값을 끌어내린다
`median_durations()` 가 `.aimem/runs` 전체를 표본으로 쓴다. 그런데 15~83초짜리 **스모크 실행**
(라벨에 `스모크` 가 들어간 것)이 섞여 opencode 중앙값이 **501초 -> 83초**로 떨어졌고,
그만큼 ETA 가 낙관적이 됐다. 실제 실작업은 850~983초다.

고치는 방향 두 가지 중 **네가 판단해서 하나를 고르고 이유를 보고에 적어라**:
- (a) 라벨에 `스모크` 가 들어간 실행을 표본에서 뺀다 - 간단하지만 라벨 문자열에 의존한다
- (b) **쓰기 경로가 있는 실행만** 표본으로 쓴다 - 태스크 크기와 상관이 더 높지만 메타에 그 정보가 있는지 확인해야 한다

표본이 **2개 미만으로 줄어드는 하네스**가 생기면 기존 대체 규칙(다른 하네스 전체 표본 ->
없으면 기본값)이 그대로 돌아가는지 확인하라. **표본을 걸러서 ETA 가 더 나빠지면 안 된다.**

## 반드시
- `collect()` 의 **반환 스키마를 바꾸지 마라.** 키를 더하지도 빼지도 마라
  (테스트 116건과 프런트가 이 스키마에 묶여 있다). 값만 고쳐진다.
- `run_detail()`(같은 파일 끝에 있다)은 건드리지 마라. 방금 다른 작업에서 추가된 것이다.
- `.aimem/runs/` 는 읽기 전용이다.

## 검증 (출력을 보고에 붙여라)
```
python3 -m unittest discover -s tests 2>&1 | tail -3
python3 -c "
import sys; sys.path.insert(0,'tools')
from aimem_monitor import reader
st = reader.collect()
print('하네스 중앙값:', st['eta'])
for r in st['requests']:
    print(r['id'], r.get('progress_pct'), (r.get('eta_basis') or '')[:160])
"
```
**고치기 전 숫자와 고친 뒤 숫자를 나란히 보고에 적어라.** 중앙값이 어떻게 움직였고
그게 실작업 경과(claude 15~224s / codex 57~983s / opencode 83~948s)와 더 맞는지 말로 설명하라.
중복 제거는 **같은 run 을 가리키는 서브태스크 둘** 을 만들어 직접 재현해 보이고 고친 뒤 다시 보여라.
