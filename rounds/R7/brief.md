## 1-1. 결과물은 프로젝트 폴더에, 라운드 폴더에는 기록만
**프로젝트**는 여러 라운드를 묶는 단위입니다. 결과물은 라운드마다 흩어지지 않고 **`projects/<프로젝트>/` 한 곳에 여러 라운드에 걸쳐 쌓입니다.** 요청마다 프로젝트가 붙어 옵니다(`aimem_db.py request list` 의 `[이름]`, 요청 파일의 `project`).
- **시작할 때** 그 프로젝트의 `projects/<프로젝트>/PROGRESS.md` 를 먼저 읽습니다 - 앞선 라운드가 무엇을 만들었고 무엇이 남았는지가 거기 있습니다(당신은 기억이 없습니다). 폴더가 없으면 새 프로젝트이니 만들고 `README.md`(무엇을 만드는 프로젝트인지, 폴더 구조)를 씁니다.
- **목표를 적습니다.** `PROGRESS.md` 맨 위(제목 바로 아래)에 `## 목표` 절을 두고, 이 프로젝트가 "다 됐다" 고 하려면 있어야 할 것을 체크리스트로 적습니다(`- [ ] 로그인 화면`, 끝난 것은 `- [x]`). 새 프로젝트면 요청과 README 를 보고 **끝까지 가는 데 필요한 목표를 예측해서** 5~15개로 씁니다 - 이번 라운드에 할 것만 적지 않습니다. 이어받은 프로젝트면 끝난 것을 체크하고, 새로 드러난 목표는 덧붙이고, 필요 없어진 것은 지우고 그 사실을 라운드 항목에 한 줄 적습니다. 웹의 프로젝트 진행률이 이 체크리스트의 "끝난 수 / 전체" 입니다. 검증까지 끝난 것만 체크합니다.
- **만들 때** 이미 있는 결과물을 이어서 고칩니다. 라운드 번호가 붙은 사본(`v2`, `R7-…`)을 옆에 만들지 않습니다 - 이력은 git 에 있습니다.
- 작업자에게 쓰게 하려면 먼저 `python3 tools/aimem_db.py ownership set --path "projects/<프로젝트>/<하위 경로>/**" --owner S<n> --note "R7"` 로 배정합니다. 같은 파일을 두 슬롯에 주지 않습니다.
- **끝날 때** `## 목표` 의 체크를 실제 상태에 맞추고, 그 절 **바로 아래**에 이번 라운드 항목을 덧붙입니다(라운드 항목끼리는 최신이 위): `## R7 (날짜)` - 한 일, 바뀐 파일, 검증한 방법, **남은 일**. 다음 라운드의 관리자가 이것만 읽고 이어받을 수 있어야 합니다.
- **구분이 화면에 보이게:** 태스크를 만들 때 `aimem_db.py task set --id T-xxx --request <요청 id> …` 로 요청을 꼭 잇고, 그래프 노드에는 `"project": "<프로젝트>"` 를 적습니다(함대 자체 일이면 생략). 식별자(T-/G-)에는 프로젝트·라운드를 붙이지 않습니다 - 실행 기록에 따로 남아 화면이 프로젝트별로 보여 줍니다.
- 요청을 직접 만들 때(작업 중 생긴 후속 일)는 `aimem_db.py request set --id <id> --title … --project <프로젝트>` 로 프로젝트를 붙입니다. 노드의 `"project"` 는 폴더 이름 하나여야 하며 아니면 `fleet_graph new` 가 거절합니다.
- **프로젝트가 비어 있는 요청**은 함대 자체의 일입니다(`tools/`, `tests/`, `AIMEM.md`). 그 파일을 제자리에서 고칩니다.
- **`rounds/R7/` 는 이 라운드의 기록 폴더**입니다: `brief.md`(이 브리프, 고치지 않음)와 `REPORT.md`(종료 보고 `8.0-8` 종료 3번 전문 - 응답 본문에도 쓰고 여기에도 씀. 프로젝트별로 무엇이 어디에 쌓였는지 경로를 적습니다). 결과물은 여기 두지 않습니다. 다른 라운드의 폴더는 건드리지 않습니다.

## 2. 턴 규칙
- 기다릴 때는 `fleet_graph.py run` 을 **포그라운드로 블로킹**합니다. 백그라운드 감시 + "알림 오면 잇겠다" 로 턴을 끝내지 않습니다. 보고를 본문에 다 쓰기 전에는 턴이 끝나지 않습니다.
- 프로세스는 **pid 로만** 죽입니다(`pkill -f` 금지).
- **커밋·푸시 금지.** 커밋은 라운드가 끝난 뒤 클로드 코드가 합니다.
- **큰 출력은 직접 읽지 않습니다.** 작업자 보고는 첫 줄(`DONE|PARTIAL|BLOCKED|NEEDS-*`)과 요약만, 테스트·린터는 `| tail -20` 또는 실패 줄만, diff 는 `git diff --stat` 뒤 해당 hunk 만.
- **유료 모델 대체 금지.** kistillm(S2)·EXAONE(S3) 장애 시 S1/S4 claude 로 옮기지 않고 그 태스크를 BLOCKED 로 두고 보고합니다.
- **함대 모드.** `fleet_graph run` 출력에 `함대 모드: paused|stopped|ready` 가 찍히거나 rc 3 이면 사람이 멈춘 것입니다. 우회하지 말고(`AIMEM_FLEET_FORCE` 금지) 체크포인트를 남긴 뒤 `상태: PARTIAL` 로 보고하고 끝내십시오.
- **모니터는 HTTPS + 인증**입니다. 작업자에게 운영 서버를 `curl` 로 부르게 하지 말고(401), 토큰을 브리프에 넣지 마십시오. 서버 동작은 테스트가 임시 포트에 띄우는 서버로 확인합니다. 서버 코드를 바꿨으면 `tools/aimem_monitor/monitorctl.sh restart`.

## 3. 그래프 짜기
- **라운드 = 그래프 하나(원칙).** 과제 전체를 의존관계(`deps`) 포함 한 그래프로 짭니다. 둘 이상은 앞 그래프 결과로 계획이 바뀌어야 할 때만.
- **검수는 그래프 안의 노드로**(`verify` 는 그 노드 범위). 관리자는 그래프가 끝난 뒤 한 번만 확인합니다.
- **무료 슬롯 우선.** 테스트·검수·단순 수정·문서 정합은 S2(kistillm)·S3(EXAONE, 동시 1개)에 먼저, S1·S4(유료)는 판단·설계·적대적 검수에만. S3 브리프는 읽을 파일·줄 범위를 못박고 "읽지 말 것"도 적습니다.
- 막힌 노드는 원인을 확인한 뒤 `fleet_graph.py unblock <그래프> <노드>` 로 다시 굴립니다(작업자가 살아 있으면 거절됩니다).
- 핸드오프는 `8.0-8` 종료 1번대로 `handoff add --bump --expect-rev N`.
