# R58 재검수 2 (S4, T-526) - R58-N1·N2 고침

## 판정: 통과

N1·N2 모두 원문 권고대로 고쳐졌고, 되돌리면 새 검사(87·95)가 실패한다. 새 지적은 하 2건.

## 원문 권고 대조
- **R58-N1** (`app.js` `applyRecUploadStatus`): 줄이 `failed` 가 아니고 `shownFailed` 면 '… · 다시 올리는 중입니다.' 로 바꾸고 `shownFailed=false`. 권고대로. 다시 실패(4xx)하면 `failed` 가지가 `shownFailed=false` 를 보고 실패 글을 새로 쓴다(87(b) 가 두 번째 실패를 본다). 87(a) 는 POST 를 붙잡아 '다시 올리는 중' 을 본다.
- **R58-N2** (`browser_voxlog.py` 검사 95): 토큰 서버·틀린 토큰으로 목록 401 → '인증 필요' → 연결 확인의 `api/answers` 를 붙잡아 `api/health` 성공이 마지막 성공이 되게 한 뒤에도 '인증 필요' 인지 본다. 설정 쪽 stt-options 401 이 뒤늦게 덮어 쓰는 오탐도 미리 막아 뒀다. 권고대로.

## 부작용 점검 (코드 읽기)
- 새 녹음 시작(`state.recUpload=null`)·파일 올리기가 추적을 갈아끼우므로 이전 녹음의 `shownFailed` 가 새 녹음 글에 새지 않는다.
- 여러 녹음: 추적은 마지막 녹음 하나의 clientId 뿐이라 다른 줄의 실패·재시도는 글에 안 닿는다.
- 지우기: 추적 중인 clientId 를 지울 때만 추적·글을 비운다(변경 없음).
- 오프라인(`waiting`+lastError)은 `failed` 가 아니므로 처음 시도 때는 글이 안 바뀐다. 실패 → 다시 올리기 → 오프라인이면 '다시 올리는 중' 이 남는다(R58-N8).
- 같은 실패 글을 폴링마다 다시 쓰지 않는다(`shownFailed` 가드 유지).

## 새 지적
### R58-N8 (하) 다시 올리기 뒤 오프라인이면 '다시 올리는 중' 이 계속 남는다
`failed` → 다시 올리기 → 줄이 `waiting`(+lastError)으로 가면 글은 '다시 올리는 중입니다' 인 채 연결이 돌아올 때까지 바뀌지 않는다. 같은 줄이 '올리지 못한 녹음' 칸에도 보이고 연결 표시는 '연결 안 됨' 이라 헷갈릴 정도는 아니다. 고치려면 `waiting`+lastError 에서 '연결되면 다시 올립니다' 류를 쓰면 되나, 처음 시도의 오프라인 글과 함께 정할 일이라 기록만. 검사는 없음.

### R58-N9 (하) 87(a) 는 '다시 올리는 중' 의 재실패 중간 상태를 안 본다
다시 올리는 중 → 또 `failed`(87(b))는 보지만 `shownFailed` 를 내리는 줄(`t.shownFailed = false`)만 지운 되돌림(M3: 글은 쓰되 플래그 유지)이면 재실패 글이 새로 안 써지는지는 (b) 가 잡을 것으로 보인다. 직접 되돌려 확인하지는 않았다. 기록만.
