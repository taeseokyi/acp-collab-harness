## (3) 검수가 찾은 것과 고친 것

S1 적대적 검수(T-133)가 **경로 탈출 61가지를 전부 돌려 보고 유출 0건**을 확인한 뒤,
**정작 이번 라운드의 핵심 기능이 동작하지 않는다**는 것을 잡아냈습니다.

1. **(높음) 미리보기가 실제로는 안 떴다.** `sandbox` iframe 은 출처가 불투명(`null`)이고
   `<script type="module">` 은 언제나 CORS 로 받으므로 `ui.js` 가 막혔습니다. 거기 더해
   **인증을 켜면** 불투명 출처의 하위 요청에 `SameSite=Strict` 쿠키가 실리지 않아 `css/style.css`
   까지 `302 /login` 으로 튕겼습니다 - **CORS 헤더만으로는 운영에서 안 고쳐집니다.**
   → **고침:** `/app/` 아래만 쿠키 대신 **경로 티켓**(`/app/~<만료>.<hmac32>/<이름>/…`)으로 인가합니다.
   티켓이 경로 앞에 있어 상대 경로가 그대로 물고 갑니다. 응답에 `Access-Control-Allow-Origin: null`
   (`Allow-Credentials` 없음). 키는 접근 토큰 - **토큰을 갈아 끼우면 티켓도 전부 무효**입니다.
2. **(보통) `새 탭에서 열기` 가 결과물 코드에 사람의 세션을 넘겼다.** 같은 출처라 결과물 JS 가
   로그인한 사람 권한으로 `/api/state` 를 읽고 `/api/requests`·`/api/archive` 를 부를 수 있었습니다
   (검수 실측). 결과물은 작업자 AI 가 쓴 코드입니다.
   → **고침:** `/app/` 응답 CSP 맨 앞에 `sandbox allow-scripts allow-popups allow-modals` 지시어.
   새 탭도 불투명 출처가 됩니다. 티켓 덕에 쿠키 없이도 파일은 내려옵니다.
   **대가:** 새 탭에서도 `localStorage` 가 막힙니다 - 안내 문구를 그에 맞게 고쳤습니다.
3. **(낮음) 미리보기가 패널 밖으로 34px 잘렸다** → `.detail-body.detail-app` 를 flex 열로, iframe 을 `flex:1`
4. **(낮음) 좁은 화면 높이 규칙이 캐스케이드로 죽어 있었다** → 미디어 쿼리를 기본 규칙 뒤로

**변이 시험** - 검수가 저장소 사본에서 제품을 일부러 깨 각 검사가 진짜 빨개지는지 확인했습니다
(`REVIEW.md` 의 표 13줄). 작업 트리는 `md5sum` 으로 건드리지 않았음을 확인했습니다.
그 과정에서 **`.proj-app-frame { height: 0 }` 으로는 검사가 안 빨개진다**(`min-height: 420px` 이 받쳐 줌)는
것까지 드러났습니다 - 거짓 초록이 아니라 제품이 버틴 경우입니다.
