### 찾아 고친 검사 결함 아홉 — **제품 결함은 하나도 없었습니다**

새 검사가 빨개질 때마다 원인을 끝까지 따졌고 **전부 검사 쪽 잘못**이었습니다. 큰 둘:

   `busy` 해제는 950ms — **300ms 빈틈**이 있습니다. 그런데 `wait_submit_settled` 는
   **이미 색이 칠해진 글자뿐인 추측**(`ababa`)에서는 키 조건이 처음부터 참이라 그 전에 돌아옵니다.
   그래서 다섯 글자가 통째로 버려지고 빈 줄이 제출됐습니다. `wait_input_ready` 를 만들어

나머지 일곱: `animationstart` 가 `pop` 까지 셈 / `animationName`·`animationDuration` 은

**이번 라운드에서 실제로 일어난 일:** G-014 의 네 노드가 전부 `done`, rc 0 으로 끝났는데
**셋이 파일을 한 줄도 안 바꿨습니다.** 그래프는 100% 로 찍혔고 저는 하마터면 그대로 보고할 뻔했습니다.

원인은 제 `verify` 였습니다. R8 교훈(`검사를 만드는 노드의 verify 는 "검사가 돌았다" 여야 한다`)에
따라 `스크립트가 끝까지 돌고 요약 줄을 찍는다` 로 걸었는데, **아무것도 안 바뀐 스크립트도
요약 줄은 똑같이 찍습니다.** "제품이 통과했다" 를 피하려다 **"아무 일도 안 일어났다" 까지 통과**시킨 것입니다.

고친 방법과 효과:

```
python3 … | tail -1 | python3 -c "… sys.exit(0 if … int(p[4]) >= 65 else 1)"
```

**요약 줄이 찍히고 + 검사 수가 늘었을 것.** 둘 다 제품 결과와 무관하고,
아무것도 안 한 시도는 **절대 통과할 수 없습니다.** 바꾸자마자 T-118 의 빈손 시도 두 번을
그 자리에서 잡아냈습니다(`['통과','48','/','전체','48']` → vrc 1 → 재시도).

**`8.0` 에 올릴 규칙:**

> **검사·테스트를 만드는 노드의 `verify` 는 두 가지를 함께 건다** — ① 스크립트가 끝까지 돌고
> 요약 줄을 찍는다 ② **그 수가 지금보다 크다.** ①만 걸면 아무것도 안 한 시도가 통과한다
