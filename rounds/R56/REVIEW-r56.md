대상: `projects/VoxLog/tests/browser_voxlog.py`(고르기·`NEEDS`·끝줄), 새 `tests/test_browser_select.py`, `README.md` 검사 절.

## (1) 기대 관계를 끊으며 약해진 검사 - 없음

- diff 에서 `need(`·`wait_for` 가 들어 있는 줄은 하나도 바뀌지 않았다(`git diff -U0 | grep -E '^[-+].*(need\(|wait_for)'` 출력 없음).
  검사 본문(t1~t78)은 한 줄도 안 건드렸다. 기대는 관계를 **끊지 않고 `NEEDS` 로 함께 돌리는 쪽**을 택했으므로 전체 실행이 확인하던 내용은 그대로다.
- 바뀐 것은 `check()` 의 건너뛰기, `main()` 의 고르기·끝줄뿐이다. 인자 없으면 `SELECTION is None` 이라 `check()` 는 예전과 같다(끝줄은 `N/M 통과` 그대로).
- `NEEDS` 의 5개는 코드와 맞다: t3=t2 가 만든 목록 1개·완료 대기, t4=t3 이 기다린 받아쓰기, t5=t2 의 목록 1개 위에 2개, t6=t2·t5 의 서버 2건, t7=묻기가 받아 적은 글을 요구(t3 이 완료를 기다림). 전이로 `--only 4`→2·3·4, `--only 7`→2·3·7 이 돈다.
- 정적 확인: t9 이후 검사는 공유 `page`/`ctx`(t8 뒤 `ctx.close()`)를 쓰지 않는다. t9·t10 은 공유 서버 `base` 를 가짜 라우트/빈 목록으로만 쓰고, t11 이후는 모두 `new_server`/`new_ctx`/자체 `tmp` 폴더다. 닫힌 변수(`nonlocal`)나 앞 검사가 남긴 모듈 상태도 없다(`global` 은 새 `SELECTION`·`SKIPPED` 뿐).

## (3) 일부 실행이 전체 통과로 읽힐 길

| 입력 | 결과 |
|---|---|
| `--only 999` / `--only 41`(41번은 없음) / `--match zzz` | `고른 검사가 없습니다` + `부분 실행: 0/77 돌림 · 77 건너뜀 · 0/0 통과 (전체 통과 아님)`, rc **1** |
| `--only 7-` / `--only x` | argparse 오류, rc 2 |
| `--onyl 8` (오타) | `unrecognized arguments`, rc 2 (조용히 전체로 돌지 않음) |

| `--only 8 --match 어두운` | 합집합 8·10 |
| 부분 실행 끝줄 | 항상 `… (전체 통과 아님)` 으로 끝나 `\d+/\d+ 통과$` 에 안 걸림. 엔진·도구 쪽에 이 끝줄을 읽는 코드는 없음(`tools`·`fleet_rt` grep) |

## 지적

### R56-N1 (중) 새 단위 검사가 고르기의 핵심 줄을 하나도 지키지 않는다
`test_browser_select.py` 는 `parse_selection`·`test_number`·`expand_needs`(주입한 dict)·`summary_line` 같은 순수 함수만 부른다. 이 함수들을 **쓰는 자리**(`check()` 의 건너뛰기, `main()` 의 `resolve_selection` 호출, rc 규칙, `resolve_selection`/`_known_names` 자체, 실제 `NEEDS` 값)는 호출하지 않는다. `test_real_needs_numbers_sane` 은 번호가 1~78 이고 자기 자신이 아닌지만 본다.
실패 시나리오: 누군가 `check()` 의 건너뛰기 3줄을 지우거나 `main()` 에서 `SELECTION = None` 으로 바꿔도(= `--only` 가 다시 전체를 돈다) 단위 검사 16개가 모두 통과한다. 위 표 A~D. 요청의 목적(고른 것만 돈다, 고른 게 0개면 실패)을 지키는 검사가 브라우저 없이는 없다.
손볼 방향(고치지 않음): 브라우저를 안 쓰는 `check()` 를 직접 불러 `SELECTION={2}` 에서 `SKIPPED` 가 늘고 `RESULTS` 가 안 느는지, `resolve_selection(None, [])` 가 `None`·`resolve_selection({7}, [])=={2,3,7}`·`--match "기본값 읽기"` 가 67 을 고르는지, `_known_names()` 가 77개를 모으는지를 단위 검사에 넣고, `main()` 의 rc 규칙은 `ran`/`bad` 를 받는 작은 함수로 빼서 검사한다.

### R56-N2 (하) 없는 번호·빈 선택이 조용하다
`--only 8,999` 는 999 가 없다는 말 없이 8 만 돌고 rc 0 이다(없는 번호는 41 도 해당). 전부 없을 때만 `고른 검사가 없습니다`/rc 1 이 나오는데 그것도 서버·크롬을 띄운 뒤다. 오타로 고른 번호가 빠져도 "통과" 로 읽힌다.
손볼 방향: 고른 번호 중 `_known_names()` 에 없는 것을 시작 전에 stderr 로 알리고(또는 rc 2), 고른 게 0개면 서버를 띄우기 전에 끝낸다.

### R56-N3 (하) 부분 실행 끝줄의 `3/3 통과` 와 rc 0
부분 실행 끝줄은 `… · 3/3 통과 (전체 통과 아님)` 이고 통과면 rc 0 이다. 끝줄 정규식 `\d+/\d+ 통과$` 에는 안 걸리지만 `grep "통과"`/`grep -c "N/N 통과"` 식 확인이나 rc 만 보는 연결(`&& echo 전체통과`)에는 전체 통과와 구분되지 않는다. 지금 읽는 코드는 없고 엔진 verify 는 인자 없는 전체를 돈다. README 에는 "전체 통과는 인자 없이 돌려 `77/77 통과` 가 나올 때뿐" 이라고 이미 적혀 있어 문서로는 충분하다. 굳이 막으려면 부분 실행 때는 `통과` 대신 `성공 3/3` 처럼 다른 낱말로 적거나 rc 를 구분한다(선택).

### R56-N4 (하) `--match` 가 소스 정규식에 기댄다
`_known_names()` 가 이 파일을 읽어 `check("N 이름"` 줄에서 이름을 모은다. 지금은 77개 모두 잡힌다(41 만 없음 - 확인함). 나중에 `check(f"…")`, 작은따옴표, 이름 안의 `"` 를 쓰면 그 검사는 `--match` 에서만 조용히 빠지고 `--only` 로는 돌아 두 길이 어긋난다. 이를 지키는 검사도 없다(R56-N1 의 `_known_names()==77` 검사로 함께 막힘).
