## 지적

### R54-N1 (상) context 에서 남기기로 한 태그 글자(U+E0020~E007F)가 실제로는 지워진다 - 거르기 범위가 틀린 글자로 적혀 있다
`voxlog/stt_options.py` 의 `"0" <= ch <= "f"`. 파이썬 `\u` 는 16진수 **정확히 4자리**라
`"0"` 은 `U+E002` + `"0"` 두 글자 문자열이다(`len("0") == 2` 로 확인). 한 글자 `ch` 와 이 두 글자 문자열을 비교하니
범위가 사실상 `U+E003 ~ U+E007`(사설 영역, 어차피 Cc/Cf 가 아니라 통과)이 되고, 진짜 태그 글자(분류 Cf)는 범위 밖이라 **그대로 지워진다**.
- 재현: `"A" + U+1F3F4 + (U+E0067 U+E0062 U+E0065 U+E006E U+E0067 U+E007F)` 를 normalize 하면 결과 코드포인트가 `['0x41', '0x1f3f4']` -
  잉글랜드 깃발 이모지(🏴 + 태그열)가 검은 깃발 하나로 줄고 `A` 만 남는다. R53 이 고치려던 바로 그 증상이다(ZWJ 는 `family` 로 통과 확인, 태그만 실패).
- 부수: 같은 범위 오류로 `U+E003~E007` 사설 영역 글자는 통과(무해), 태그 영역 밖 `U+E002`·`U+E008` 도 Co 라 통과 - 의도한 범위가 아니다.
- 고칠 방향: `"\U000e0020" <= ch <= "\U000e007f"`(대문자 U, 8자리) 또는 `0xE0020 <= ord(ch) <= 0xE007F`.
- 4000자 상한·서버로 가는 값에 미치는 것: 지금은 태그가 지워져 영향이 없다. 고치면 깃발 하나가 7 코드포인트라 상한에 7로 센다
  (서버·JS `maxLength` 계산 단위가 다르다 - JS 는 UTF-16 단위라 14로 세어 클라이언트가 더 엄격. 문제는 아니지만 안내 문구 '최대 4000자' 와는 조금 어긋남).

### R54-N2 (상) 새 검사가 N1 의 결함을 잡지 못하고, 깃발 시험 값 자체가 같은 실수를 담고 있다
`tests/test_stt_options.py::test_context_keeps_hangul_and_emoji_sequences_and_newlines` 의
`flag = "\U0001f3f4725e7f"` 에서 `"7"` 도 `U+E006` + `"7"` 두 글자다(같은 4자리 규칙).
시험 문자열이 진짜 태그가 아니라 '사설 영역 글자+숫자·글자' 라서 현재 (틀린) 거르기를 통과하고, 거르기가 맞게 고쳐진 뒤에도
`"2"`→`U+E006`+`2` 는 사설 영역이라 계속 통과 - **태그를 지우는 회귀가 들어와도 이 검사는 계속 통과한다.** (316개 OK 가 이를 증명: N1 의 버그가 있는데 전부 통과.)
- 재현(검사의 값 그대로 normalize 하면 입력과 같음 = 통과, 진짜 태그 입력은 지워짐: N1).
- 고칠 방향: 시험 값을 `"\U000e0067"` 꼴로 쓰고, 결과 코드포인트 중 `0xE0020~0xE007F` 가 남았는지도 직접 단언.

### R54-N3 (하) context 의 외톨이 서로게이트가 거르기를 통과해 받아쓰기 서버 요청 본문 만들기에서 터진다
`json.loads('"\\ud800"')` 로 들어온 외톨이 서로게이트(분류 Cs)는 `("Cf","Cc")` 에 없어 `normalize` 가 남긴다
(`normalize({"context":"a\ud800b"})` → `['0x61','0xd800','0x62']`). `form_fields(...)["context"].encode("utf-8")` 가
`UnicodeEncodeError: surrogates not allowed` - `stt.py` multipart 만들기(`.encode("utf-8")`)에서 같은 예외가 난다. 사람이 입력창에서 만들기는 어렵고 이전에도 있던 틈이나,
'받아쓰기 서버로 가는 값을 거른다'는 N2 의 목적과 맞닿는다. 저장된 옵션이면 그 녹음의 재시도가 계속 실패한다.
고칠 방향: 거르기 조건에 `Cs` 를 더하거나 `value.encode("utf-8")` 실패 시 400.

### R54-N4 (하) N12 가드 - 같은 녹음에서 칸을 닫았다 다시 연 사이 성공하면 사람이 다시 연 칸이 닫힌다
`retryWithOptions` 성공 처리기는 `state.detailId === id` 만 보고 `#detail-stt` 를 닫는다(상태 글만 칸 번호까지 비교). 요청 중 같은 녹음에서
옵션 단추를 닫았다 다시 열면(칸 번호 증가) 응답이 와서 새로 연 칸을 닫는다. 읽기 쉬운 동작 흐름이라 거의 문제는 아니다(재시도가 성공했으니 닫는 쪽이 자연스럽다).
같은 녹음의 성공·실패 일반 흐름(칸 닫기·`loadDetail`·실패 토스트·상태 글 지움)은 `state.detailId === id && seq` 가 같을 때 그대로 동작함을 코드로 확인했다 -
**N12 가드가 같은 녹음의 성공 뒤 칸 닫기·실패 토스트를 막지 않는다.** 가드는 상태 글 지움에만 걸려 있고 토스트·`onApiError` 는 조건 없이 나간다.

### R54-N5 (하) N12 시험은 '다른 녹음으로 옮긴 경우'만 막고, 같은 녹음 성공·실패 쪽 반대 방향 시험은 이번 묶음에 없다
`t70` 은 가드를 지우면(무조건 `st.textContent=''`) 실패한다(B 의 '불러오는 중…' 이 지워짐) - 고침을 되돌리면 실패하는 시험이라 합격.
다만 같은 녹음 성공 뒤 칸 닫기는 `t50` 이, 실패 토스트는 400 경로 시험이 이미 덮고 있어 가드가 과하게 막는 회귀(예: `seq` 비교가 영원히 거짓)를 이번 묶음 시험만으로는 못 잡는다.
t50 이 같은 흐름을 덮는지는 코드로 읽었고, 브라우저 검사는 50 을 포함해 모두 통과했다.

## 확인한 것 (문제 없음)
- **N4 (`with_prev=False`)**: `_rec_retry` 의 첫 확인·잠금 안 확인은 `with_prev=False`, 응답은 `store.get(rid)`(전체)라 재시도 응답에 `prev_transcripts` 가 빠지지 않는다
  (`test_retry_reads_no_previous_transcript`: 호출 순서 `[False, False, True]`). `meta.get("stt_options")` 는 `with_prev` 와 무관하게 남아 `prev_opts` 되돌림이 정상(`test_retry_resubmit_false_restores_old_options`).
  `_rec_get` 은 `?prev=0` 일 때만 지난 글을 뺀다. 웹은 키가 없으면 `renderPrev` 를 건너뛰어 목록이 지워지지 않는다.
- **retry_lock**: 본문 읽기는 잠금 밖, 확인·저장·재제출만 안. `test_retry_lock_keeps_first_job_when_two_retries_overlap` 은 잠금을 빼면 `stt_job` 이 None 이 되어 실패하는 구조(읽어서 판정; 0.2초 겹침 여유는 빠듯하지만 현재 316개에서 통과). 서버 전체 잠금이라 다른 녹음의 재시도도 순서대로 지나가나 각 구간이 짧아 무해.
- **N2 줄바꿈**: `\r\n`·`\r`·U+2028/2029 → `\n`. 저장 값도 읽을 때마다 `normalize` 를 다시 거치므로(`store.py` 626행) 옛 저장 값과 어긋남 없이 읽힘. 옵션이 '바뀌었는지' 를 비교하는 곳은 없어 `\r\n` 저장 값에 대한 부작용 없음. ZWJ 는 통과(`family` 시험 값은 `\u` 4자리가 맞음), `​`·`­`·`﻿`·NUL·U+000B·000C·0085 는 제거. 부수로 ZWNJ(U+200C)·방향 표식(U+200E/F)도 Cf 라 지워진다 - 한국어 문맥엔 영향 없으나 페르시아어·히브리어 낱말은 모양이 바뀐다(참고).
- **검사 50·66 결정성**: 50 은 `wait_for_timeout(100)` 대신 기본값 GET 을 `STT_OPTIONS_HOLD_JS` 로 쥐었다 놓는 방식(쥠→잠금 단언→놓음→풀림 대기)이고 66 도 같은 방식 + `stt_fields_ready` 대기라 시간 의존이 사라졌다.
  `t71`(설정 닫은 사이 응답)·`t70`(N12)도 쥠/놓음으로 결정적이다. 남은 `wait_for_timeout(200)` 은 '아무 일도 안 일어남' 을 보는 음성 확인이라 허용.
