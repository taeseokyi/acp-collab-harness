## 고친 것 확인

**갈래 1 - 인증 우회: 막혔다.** 무인증 원시 소켓으로 브리프가 적은 변형을 모두 다시 돌렸습니다. 대상: `…/../~x/`, `…/x/../../~x`,
`…/../~`, `…/./../~/`, 꼬리 `/` 없음, HEAD, 절대 URI 요청줄(같은 호스트와 `http://evil/`), 없는 이름 `abc`,
`%2e%2e`, `..%2f`, `%252e`, `//../`, `..//`, 앞 `//`, `?`·`#`·`;p` 꼬리, `;` 가운데 조각, `..;/`. 거기에 새 변형도 더했습니다:
질의 속 `?/../~x/`, `%7e`, 백슬래시, 인코딩 없는 UTF-8 이름, `~x/./이름`, `//~x`, 꼬리 `..`, `~1/../이름`, `~/이름`, Host 없는 HTTP/1.0,
POST, 다른 앱, 틀린 Bearer, 위조 쿠키, `X-Original-URL`, `...`, 탭, 대문자 `/APP`, `%2F` 로 붙인 이름, 티켓 꼴 `~1.000…/이름/../../다른앱`.
**41가지 모두 발급 0건, 결과물 본문 0건**이었습니다. 원본에 `.`·`..`·빈 조각이 있으면 404, 정규화 경로가 `/app/~` 로
시작하지 않으면 세션 검사(302 `/login`·401)로 갑니다. 게이트가 세션 검사를 건너뛰는 경우는 원본이 깨끗한 티켓 꼴일 때뿐이고,
그 경우 라우팅은 같은 원본을 같은 정규식으로 읽어 반드시 `app_ticket_ok` 를 거칩니다. 발급 갈래도 서명 전에 세션을 직접 봅니다.
변이 M1(게이트만 R10 으로 되돌림)에서 발급 갈래 검사가 혼자 우회를 막아 내는 것도 확인했습니다(심층 방어가 실제로 작동). 정상 흐름도 그대로입니다.

**갈래 2 - 로그 가리기: 서버가 받아들이는 꼴에서는 막혔다.** 실제 `log_message` 의 표준오류를 파일로 받았습니다.
보낸 요청: 200·HEAD·404(없는 파일)·404(게이트)·403(다른 앱)·절대 URI·앞 `//`·`HTTP/9.9`(505 오류 경로)·제어문자·POST·
질의 속 `/app/~T/`·exp 앞 `0`·대문자 맥·70000자 줄(414). 이 모두가 `/app/~***` 로 가려졌습니다. Referer·임의 헤더·POST 본문에 넣은
티켓은 `log_message` 가 요청줄만 적으므로 기록되지 않습니다. 가려지지 않은 2줄은 `GET /?ticket=<T>` 와 `GET /app/%7E<T>/…` 입니다.
서버는 둘 다 티켓으로 받지 않고 302 `/login` 으로 돌려보냅니다. 클라이언트가 스스로 그 꼴로 보내야만 생기고, 그런 클라이언트는
결과물을 열지 못해 곧바로 드러납니다. 브라우저는 `~` 를 인코딩하지 않으므로 **결함으로 세지 않습니다**(참고: `_TICKET_LOG_RE` 를
`/app/(?:~|%7[eE])[^/\s]+` 로 넓히면 이 둘 중 뒤쪽도 가려집니다). **이 가리기를 지키는 검사는 하나도 없습니다**(변이 M2 = 구멍).

**갈래 3 - Host 허용 목록: 막혔다(괄호 꼴 1건 남음, 실효 없음).**
- 막힘(`'self'` 만 남음): `evil.com`, `EVIL.COM`, `evil.com.`, `evil.com:18800`, `127.0.0.1.evil.com`, `127.0.0.1.nip.io`,
  `localhost.evil.com`, `[evil.com]`, `[::1`, `[::1]:18800@evil.com`, `1.2.3.4:18800:1`, `2130706433`, `127.1`, `0x7f.0.0.1`,
  `[fe80::1%eth0]`, `a b`, `evil.com"; x`
- 통과(운영 쪽): `127.0.0.1:18800`, `192.168.0.5:18800`, `10.0.0.7`, `[::1]:18800`, `[::1]`, `[::ffff:127.0.0.1]:18800`,
  `localhost:18799`, `LOCALHOST`, `localhost.`, `127.0.0.1.`. TLS 쪽에서는 `https://192.168.0.5:18800` 으로 나옵니다.
  **운영(IP 접속)은 그대로 됩니다.**
- 환경변수: 적은 이름과 그 이름의 대소문자·끝 점·포트 붙은 꼴만 통과합니다. `x.aimem.example.org`·`example.org`·
  `aimem.example.org.evil.com` 은 막힙니다. 값 안의 공백·빈 항목도 견딥니다.
- 통과했지만 의도 밖인 것:
  - `evil.localhost`(`.localhost` 접미 허용). RFC 6761 상 루프백이라 같은 기계를 가리킵니다. 결함 아님.
  - **`[::1]evil.com` / `[::1].evil.com` / `[::1]:80.evil.com`**: 괄호 안만 IP 로 검사하고 `]` 뒤를 보지 않습니다. CSP 문자열에
    `http://[::1].evil.com` 이 들어갑니다. Chromium 실측에서는 잘못된 출처로 버려져 evil.com 스크립트가 0개 실행됐습니다
    → **남은 결함 1(낮음)**.
  - `::1`(괄호 없음), `127.0.0.1:99999`, `127.0.0.1:abc` 도 잘못된 출처 문자열을 만들지만 같은 이유로 무해합니다.

**갈래 4 - 미리보기 최소 높이: 안 고쳐졌다.** `getComputedStyle` 로 보면 `min-height` 는 380px 로 적용됐습니다.
390×500·844×390·320×568 에서 iframe 은 380px(안쪽 `innerHeight` 378)입니다. 그런데 웹워들의 키 높이 식이
`clamp(20px, (100dvh - 330px)/3, 54px)` 라서 (378−330)/3 = 16 → 하한 **20px** 그대로입니다. 검수 B 가 권한 "380px 이상" 이
계산상 모자랐습니다. 32px 가 되려면 안쪽 높이가 426px 이상이어야 하므로(테두리 2px 포함) **`min-height: 428px`** 가 필요합니다.
`!important` 주입으로 실측해 보니 세 짧은 화면 모두 32px 가 됐고, 패널 밖으로 나가지 않았으며 가로 스크롤도 0 이었습니다.
380px 에서도 패널은 `overflow-y: auto` 로 스크롤되고, 끝까지 내리면 iframe 아래끝이 패널 아래끝보다 12~16px 위에 있습니다.
가로 스크롤은 0 입니다. 즉 **삐져나오지는 않지만 목표(32px)를 못 이뤘습니다** → 남은 결함 2. 이 값을 지키는 검사도 없습니다(변이 M4 = 구멍).

   주석의 "380px 이상이어야" 도 함께 고치십시오.

   패널 포함 여부를 보십시오(M4 구멍도 같이 메워짐).
2. **(낮음, 실효 없음 - Chromium 실측) `Host: [::1].evil.com` 꼴이 허용 목록을 지나 CSP 문자열에 `evil.com` 을 넣는다.**
   `tools/aimem_monitor/server.py` `_app_origin`: `host[1:host.find("]")]` 만 검사하고 `]` 뒤를 보지 않습니다. Chromium 은 그 출처를
   무효로 버리므로 실제 허용은 생기지 않았습니다(Firefox/Safari 는 못 봄).
   고치는 법: `]` 뒤가 비었거나 `:\d{1,5}` 일 때만 받기(예: `re.fullmatch(r"\[([0-9A-Fa-f:.]+)\](?::\d{1,5})?", host)`).
   포트 꼴도 `\d{1,5}` 로 묶으면 `127.0.0.1:abc` 같은 잘못된 출처 문자열도 사라집니다.
   검사 제안: `test_csp_origin_rejects_unknown_host_name` 에 `[::1].evil.com`, `[::1]evil.com` 을 더하기.
