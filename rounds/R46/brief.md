## 2. 결과물은 프로젝트 폴더에, 라운드 폴더에는 기록만
요청마다 프로젝트가 붙어 옵니다(`request list` 의 `[이름]`). 결과물은 **`projects/<프로젝트>/` 한 곳에 여러 라운드에 걸쳐 쌓입니다.**
- **시작할 때** `projects/<프로젝트>/PROGRESS.md` 를 먼저 읽습니다. 폴더가 없으면 새 프로젝트이니 만들고 `README.md`(무엇을 만드는지, 폴더 구조)를 씁니다.
- **목표.** `PROGRESS.md` 맨 위(제목 바로 아래)에 `## 목표` 체크리스트(`- [ ]` / `- [x]`)를 둡니다. 새 프로젝트면 요청과 README 를 보고 **끝까지 가는 데 필요한 목표를 예측해** 5~15개로 씁니다(이번 라운드 몫만이 아님). 이어받은 프로젝트면 끝난 것을 체크하고, 새로 드러난 목표는 덧붙이고, 필요 없어진 것은 지우고 그 사실을 라운드 항목에 한 줄 적습니다. 검증까지 끝난 것만 체크합니다.
- **만들 때** 이미 있는 결과물을 이어서 고칩니다. 라운드 번호가 붙은 사본(`v2`, `R46-…`)을 만들지 않습니다.
- 작업자에게 쓰게 하려면 먼저 `python3 tools/aimem_db.py ownership set --path "projects/<프로젝트>/<하위 경로>/**" --owner S<n> --note "R46"`. 같은 파일을 두 슬롯에 주지 않습니다.
- **끝날 때** `## 목표` 의 체크를 실제 상태에 맞추고, 그 절 바로 아래에 `## R46 (날짜)` - 한 일, 바뀐 파일, 검증한 방법, **남은 일** - 을 덧붙입니다(최신이 위). 다음 관리자가 이것만 읽고 이어받을 수 있어야 합니다.
- 보드(작업 표)의 줄은 **엔진이 그래프에서 만듭니다**(번호·요청·제목·슬롯·상태) - 따로 등록하지 않습니다. 관리자는 끝난 태스크의 확정(`aimem_db.py task set --id T-xxx --status DONE` 또는 `BLOCKED`)과 산출물(`--artifacts`)만 적습니다. 그래프 노드에는 `"project": "<프로젝트>"`(폴더 이름 하나)를 적습니다(함대 자체 일이면 생략). 작업 중 생긴 요청은 `aimem_db.py request set --id <id> --title … --project <프로젝트>`.
- **프로젝트가 비어 있는 요청**은 함대 자체의 일입니다(`tools/`, `tests/`, `AIMEM.md`) - 제자리에서 고칩니다. 그때는 `.aimem/briefs/fleet-self.md` 를 먼저 읽습니다.
- 종료 보고 전문은 `rounds/R46/REPORT.md` 에도 씁니다(프로젝트별로 무엇이 어디에 쌓였는지 경로를 적습니다). 결과물은 라운드 폴더에 두지 않습니다.
