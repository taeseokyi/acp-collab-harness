## 남은 결함

### 결함 1 - 대소문자 무시를 지키는 시험이 없음 (중간, 시험)
- **무엇이:** `_subject` 의 `.lower()`(`server.py:2431`)를 빼도 시험이 하나도 빨개지지 않습니다(M1, 0 개).
- **어떻게:** 세션 주체는 GitHub 가 돌려준 표기 그대로입니다(`gh:` + `re.sub(...)` - 소문자로 바꾸지 않음, `:2947`/`:2979`). 누가 이 줄을 "정리" 하면 `TaeSeok` 같은 계정은 로그인은 되는데(`:2941`/`:2974` 는 `login.lower()` 로 비교) **다음 요청부터 바로 쫓겨납니다.** 로그인과 쫓겨남이 반복돼 원인을 찾기 어려운 가용성 결함입니다.
- **근거:** `tests/test_aimem_monitor_app_gate.py` 의 `test_github_allowlist_match_is_case_insensitive` 는 목록에 `TaeSeok`, 쿠키에 `taeseok` 을 넣습니다. 방향이 반대입니다. 복사본에 M1 을 넣고 `gh:TaeSeok` 쿠키 + 목록 `taeseok` 으로 찔러 보니 `302 /login` / `401` 이었고, 수정 그대로일 때는 `302 /app/~…` / `200` 이었습니다.
- **고치는 법(제안만):** 시험에 **쿠키는 대문자, 목록은 소문자** 경우를 더합니다(`github_headers("TaeSeok")` + 목록 `taeseok\n`). 아니면 발급할 때부터 주체를 소문자로 바꿉니다(`:2947`/`:2979`). 그러면 화면 표시(`subject_label`)가 소문자로 바뀝니다.

### 결함 2 - 지우기 전에 받은 실행 티켓이 12시간 동안 계속 들음 (낮음~중간)
- **무엇이:** 허용 목록에서 지운 사람이 미리 받아 둔 `/app/~<티켓>/<이름>/` 는 `PROJECT_APP_TICKET_TTL_SEC`(12h) 동안 계속 들습니다.
- **어떻게:** 티켓 MAC 은 `app.v1.{exp}.{name}` 이고 주체를 담지 않습니다(`:217-221`, `:224-245`). 그래서 이 수정이 가져온 "지우면 즉시 끊김" 이 티켓에는 미치지 않습니다. 티켓은 URL 에 실려 있어 브라우저 기록에도 남습니다.
- **근거:** 실측(P2): 지운 뒤 같은 티켓이 200(쿠키 없이도, 지운 쿠키를 붙여도). `/api/state` 는 401.
- **받아들일 만한가:** 닿는 범위는 그 프로젝트의 **정적 앱 파일**뿐이고 `/api`·쓰기·다른 프로젝트로는 못 갑니다. 지금 거둬들이는 길은 접근 토큰을 바꾸고 다시 띄우는 것(모두가 다시 로그인)뿐입니다. 앱이 공개돼도 괜찮은 내용이면 받아들일 만합니다. 그렇지 않으면 구멍입니다. **관리자가 판단할 일**로 남기고, "회수 즉시" 라고 문서에 적는다면 티켓은 예외라고 함께 적어야 합니다.
- **고치는 법(제안만):** (a) 티켓에 주체를 넣습니다: `exp.<subject>.mac`, MAC 입력 `app.v2.{exp}.{subject}.{name}`. 확인할 때 `gh:` 주체면 `github_allowed_logins` 를 다시 봅니다. 불투명 출처라 쿠키가 안 실리므로 주체는 **티켓 안에** 있어야 합니다. 티켓 길이 상한(`len(ticket) > 80`, `:228`)과 `_APP_RE`·`_TICKET_LOG_RE` 를 함께 고쳐야 합니다. (b) 아니면 TTL 을 크게 줄입니다(예: 15분 + 앱 안에서 다시 발급받기).

### 결함 3 - 목록 때문에 끊긴 요청이 감사 로그에 안 남음 (낮음, 운영)
- **무엇이 / 어떻게:** `_subject` 가 목록 때문에 `None` 을 돌려줘도 `audit` 가 없습니다. 목록 파일을 못 읽어 **모두**가 끊길 때(5번)도 흔적이 없습니다.
- **근거:** `server.py:2429-2433`. 실측(P4): 감사 파일이 생기지 않았고 접근 로그에는 `401` 만 있었습니다.
- **고치는 법(제안만):** 끊는 자리에서 `audit(self.root, "session-revoked", self._client_ip(), None, subject)` 를 **직접** 부릅니다. `self._audit` 는 안쪽에서 `_subject` 를 다시 불러 같은 판정을 되풀이하므로 쓰지 않습니다. 한 요청에서 2~3번 불릴 수 있으니(6번) 요청당 한 번만 남기거나 같은 주체는 일정 간격으로 묶습니다. `github_allowed_logins` 가 예외를 삼킬 때도 `log_message`/`audit` 로 "목록을 못 읽음" 을 한 줄 남깁니다.

### 결함 4 - 지우는 건 '정지' 이지 '회수' 가 아님 (참고)
- 목록에서 지웠다가 TTL 안에 다시 넣으면 **옛 쿠키가 되살아납니다**(실측 P5: 다시 넣은 뒤 옛 쿠키로 `/api/state` 200). 의도된 동작이라면 문서에만 적으면 됩니다. 진짜로 거둬들이려면 계정별 "이 시각 이전 발급분 무효" 기록이 필요합니다(제안만).
