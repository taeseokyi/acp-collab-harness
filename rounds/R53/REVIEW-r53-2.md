# R53 재검수 - N1 고침(불러오는 동안 칸 잠금)과 고치며 생긴 새 문제 (S4, 부작용 중심)

대상: `git diff -- projects/VoxLog/web/app.js`(`setSttFieldsBusy`·`loadSttSettings`·`openSttPanel`·`retryWithOptions`)와
`tests/browser_voxlog.py` 의 검사 50·62·65·66, `slow_stt_options`·`stt_fields_ready`. 약속 `rounds/R53/spec.md`. 코드는 고치지 않았다.
첫 검수 N2~N5 는 다시 적지 않는다.

## 돌린 검사

- 단위 `python3 -m unittest discover -s tests` (projects/VoxLog): `Ran 314 tests in 87.002s` · `OK`
- 브라우저 `python3 tests/browser_voxlog.py` **세 번**, 셋 다 `65/65 통과` (50·62·65·66 모두 통과). 첫 검수 때 2회 중 1회 흔들리던 50 이 3회 연속 통과.
- 변이(고침 되돌리기): 사본 복사·파일 쓰기가 이 세션에서 승인이 필요해 **돌리지 못했다.** 시험 코드를 읽어 판정했다(아래).

## N1 고침이 맞는가

맞다. 응답을 기다리는 동안 다섯 칸과 실행·저장 단추가 `disabled` 라 사람이 고를 수 없고, 응답 뒤에 풀리므로 "응답이 사람 값을 덮는" 경로가 없다.
성공·실패 두 갈래 모두 먼저 `setSttFieldsBusy(false)` 를 부르고 그 뒤에 채우므로 채우다 예외가 나도 잠금은 풀린다.
녹음에 옵션이 있으면(`hasSttOptions`) 읽기 없이 바로 채워 잠그지 않는다 - 맞다(캐시를 비우기만 하고 안 읽음 → 하, N9).
설정 칸을 닫았다 다시 열어도 `sttDefaultsReq` 가 하나라 두 처리기가 같은 응답에 풀리고, 풀리는 쪽이 먼저·나중이어도 서로 잠그지 않는다.
검사 50 은 이제 사람이 값을 고르기 **전에** `stt_fields_ready`(칸·단추가 모두 풀림)를 기다리므로 경합이 결정적으로 사라졌다(고르는 시점이 응답 뒤로 고정).

## 지적

### R53-N6 (중) 잠금이 녹음 이동·응답 지연에서 설명 없이 남는다 - 해제가 "그 요청의 응답"에만 매여 있고 시간 제한이 없다

`setSttFieldsBusy(els, true…)` 는 상세 묶음(`state.sttFields.detail`, 한 벌)을 모든 녹음이 같이 쓴다. 풀리는 곳은 `sttDefaults()` 응답 처리기 하나뿐이다.
`openDetail`(app.js 약 1235~1251행)은 다른 녹음으로 옮길 때 `detail-stt` 를 숨기고 `detail-stt-state` 를 비우고 `fillSttFields(detail, {})` 만 하며 **잠금을 풀지 않는다.**

- 재현 A: 옵션 없는 녹음 A 에서 `옵션 바꿔 다시 받아쓰기` 를 연다(칸 잠김·`불러오는 중…`) → 응답 전에 옵션이 있는 녹음 B 로 옮겨 같은 단추를 연다.
  B 는 읽기를 안 하고 바로 채우므로 칸은 값이 보이는데 **전부 `disabled`, 실행 단추도 `disabled`, 상태 글은 빈 칸**(openDetail 이 비움)이다. A 의 응답이 올 때까지 이유 없이 잠긴다.
- 재현 B: `api.js` 의 `fetch` 에 시간 제한·`AbortController` 가 없다(`grep` 확인: `web/api.js` 에 timeout·signal 없음). 폰 회선이 끊긴 채 걸린 요청은 브라우저가 스스로 에러를 낼 때까지(분 단위) 칸이 잠긴 채다.
  설정 칸은 닫았다 다시 열어도 같은 걸린 요청에 묶여 풀리지 않는다.
- 첫 검수가 물은 "응답이 실패·아주 늦음일 때 잠긴 채 남는 길": 실패는 풀린다(에러 갈래가 푼다). **응답이 아예 안 오는 경우와 녹음 이동이 남는 길**이다.
- 고치는 방향(구현은 안 함): `openDetail` 이 옮길 때(그리고 `closeDetail`) 상세 묶음을 풀고 상태 글을 비운다 / 잠금을 "이 요청이 아직 이 녹음의 열린 칸을 위한 것일 때만"으로 하거나 열 때마다 열쇠(번호)를 두어 낡은 처리기가 풀고 새 처리기만 잠그게 한다 / 읽기에 시간 제한을 두어 풀린 뒤 에러를 알린다.
  시험: `slow_stt_options` 로 A 의 읽기를 늦추고 B(옵션 있음)로 옮겨 칸이 풀려 있는지 보는 한 건.

### R53-N7 (하) 저장은 잠그지 않아 "저장 중" 과 "불러오는 중" 이 서로 덮는다

`saveSttDefaults` 는 칸·단추를 잠그지 않는다. (a) 저장 응답을 기다리는 사이 사람이 칸을 바꾸면 응답이 `fillSttFields` 로 되돌려 쓴다(N1 과 같은 꼴이지만 저장 전부터 있던 일, 저장한 값과 같은 값이라 영향은 작음).
(b) 저장 중에 설정 칸을 닫았다 열면 `loadSttSettings` 가 상태 글을 `불러오는 중…` 으로 바꾸고, 저장 응답이 그 글을 `''` 로 지우거나(칸은 아직 잠김인데 글이 없음) 불러오기 응답이 `저장 중…` 을 지운다. 불러오기가 끝나면 저장 단추가 **저장 요청이 아직 안 끝났는데도** 풀려 한 번 더 누를 수 있다(같은 값을 PUT 하므로 무해).
(c) 새로 읽는 GET 이 PUT 보다 서버에서 먼저 처리되면 늦게 온 옛 값이 `state.sttDefaults` 를 덮고 열린 설정 칸을 옛 값으로 채운다(토스트는 "저장했습니다"). 저장 지연 안에 닫았다 열어야 해서 드물다.
조치 불필요에 가깝다. 고치려면 저장 중에도 같은 잠금을 쓰면 (a)(b) 가 함께 닫힌다.

### R53-N8 (하) 새 시험의 빈틈 - 잠금의 "남는 길"과 순간 확인의 틈

- 50·66 은 클릭 직후 `evaluate` 로 잠김을 **한 번** 읽는다. `slow_stt_options` 의 핸들러는 동기 Playwright 의 이벤트 처리 안에서 `time.sleep(1.5)` 로 막아 두므로, 클릭이 끝나기 전에 경로 처리기가 돌면 그 사이 처리 스레드가 멈추고 `route.continue_()` 직후 바로 `evaluate` 가 나간다. 응답이 `evaluate` 보다 먼저 도착해 풀려 있을 틈이 ms 단위로 이론상 있다(세 번 모두 통과 - 관측한 흔들림은 없음). 늦춤을 핸들러가 `time.sleep` 하는 대신 응답을 쥐고 있다가 시험이 확인한 뒤 놓는 방식(이벤트·`threading.Event`)이면 결정적이다.
- 시험이 안 보는 갈래: 읽기 **실패** 때 풀림(에러 갈래 두 곳)·닫았다 다시 열기·녹음 이동(N6)·설정 칸을 닫은 사이 응답이 오면 채우지 않는 가드·`retryWithOptions` 의 `detailId === id` 가드 중 설정/상세 읽기 가드. 62 는 `stt_fields_ready` 가 잠금 없이도 참이라 되돌려도 통과한다(62 의 몫은 새 값 반영이므로 맞음).

### R53-N9 (하) 열 때마다 캐시를 비우는 줄이 읽지 않는 길에서도 돈다

`openSttPanel` 은 `state.sttDefaults = null` 을 옵션 있는 녹음에서도 한다(그 녹음은 읽지 않으므로 캐시만 버리는 셈, 다음 곳이 어차피 새로 읽음 → 무해).
또 이미 걸려 있는 읽기(`sttDefaultsReq`)가 있으면 "새로 읽기" 가 그 **열기 전에 시작한** 응답을 재사용한다(R51-N6 "열 때마다 새로" 와 미세하게 다름, 다른 기기 변경이 그 ms 창에 낄 때만). 기록만.

## 키보드 초점

잠기는 순간 초점이 잠긴 칸에 있을 수 있는 길을 찾았으나 **없다**: 열기는 `#settings-btn`·`#detail-retry-opts` 단추를 눌러서만 일어나 초점이 그 단추에 있고, 잠긴 칸은 Tab 이 건너뛴다.
풀릴 때 초점을 옮기거나 되돌리지 않아도 놓치는 곳이 없다. 단, 사람이 단추 대신 칸으로 곧장 들어가는 길(예: 스크린 리더의 가상 커서)은 읽지 않은 칸이 `disabled` 라 안내되고 `role=status` 글 `불러오는 중…` 이 알려준다(상세 묶음은 N6 의 경우에 이 글이 비어 있음). 하에 못 미침.
