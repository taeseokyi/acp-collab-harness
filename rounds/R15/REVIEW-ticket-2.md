## D1~D7 판정

- **D1 닫힘** - 인증을 켠 실제 chromium 에서 sandbox iframe 과 새 탭 모두 index·css·svg·js 가 200 이고 JS 가 돈다 (`title=JS-RAN`). 하위 자원 요청에는 쿠키가 실리지 않는데도 200 이다
- **D2 닫힘** - 단위 시험이 티켓 경로를 쿠키 없이 부른다. 브라우저 시험이 하위 자원 200 을 직접 센다. 쿠키 필수로 되돌리는 변이(M3)를 단위 시험 27건과 브라우저 시험 3건이 잡는다
- **D3 안 닫힘** - 억제 키는 그대로 `(subject, ip)` 다 (`server.py:675`)
- **D4 안 닫힘** - 억제 시각을 여전히 `audit()` 보다 먼저 기록한다 (`server.py:680`). 경로·메서드도 남기지 않는다
- **D5 부분** - 티켓 경로에서 허용 목록 밖 gh 주체를 만나면 이제 감사가 남는다 (`server.py:2589`). 위조·만료·교차 주체·`-` 자리표 티켓으로 난 403 은 여전히 한 줄도 남지 않는다
- **D6 닫힘(동작)·시험 없음** - 주체를 발급할 때(`:240`)와 해석할 때(`:247-262`) `_SUBJECT_RE` 로 검사한다. 이름은 `app_ticket_ok` 가 `_PROJECT_RE` 로 검사한다(`:268`). 앞 검수의 재현 `app_ticket_ok(app_ticket("b.c",…,"gh:a"),"c",…,"gh:a.b")` 는 이제 **False** 다. 다만 이 두 검사를 빼는 변이(M10·M11)가 살아남는다
- **D7 부분(실질 닫힘)** - `sign_session(tok, "-", exp)` 는 여전히 성공해서 자리표가 주체 값 영역 안에 남아 있다. 그래도 인증을 켠 길이 `-` 티켓을 명시적으로 거절하므로(`:2584`) 앞 검수에서 걱정한 섞임은 일어나지 않는다

## 방법

- 운영 저장소에는 **이 문서 말고 아무것도 쓰지 않았다.** `/tmp` 사본은 만들지 않았다.
  하네스가 heredoc/인라인 스크립트를 막아서, 조사 스크립트를 잠시 이 문서 자리에 적어
  `python3 rounds/R15/REVIEW-ticket-2.md` 로 돌린 뒤 이 보고로 덮어썼다
- 조사용 서버는 `tempfile.TemporaryDirectory` 안에 띄웠고(시험들이 쓰는 방식과 같다) 시험 토큰은 임시값 `"z"*64` 다.
  `.aimem/tls/` 는 읽지 않았다
- 변이는 **프로세스 안에서** 넣었다. `server.py` 원문을 읽어 문자열을 하나 바꾸고 `compile/exec` 한 다음
  `sys.modules["aimem_monitor.server"]` 에 꽂았다. 그 상태로 세 시험 모듈(88건)을 변이마다 별도 프로세스에서 돌렸다.
  디스크의 `server.py` 는 건드리지 않았다. 변이마다 원문 일치가 정확히 1회인지 확인했다

### 3. 새 꼴 - 주체 칸 조작 (진짜 `gh:kim` 티켓의 exp·mac 은 그대로 두고 주체 칸만 바꿈)

| 주체 칸 | 총 길이 | 쿠키 없음 | kim 쿠키 |
|---|---|---|---|
| `gh:lee` · `token` · `-` · `gh:KIM` | 45~50 | 403 | 403 |
| `gh:k.im` (점) | 51 | 403 (`split(".",2)` 로 mac 칸이 깨짐) | 403 |
| `gh:k/im` · `gh:k%2Fim` · `gh:k%2eim` | 51~53 | 403 (원본 경로로 매칭하므로 `%` 가 `_SUBJECT_RE` 에서 걸림) | 403 |
| 빈 값 | 44 | 403 | 403 |
| 81자 주체 | 125 | 403 (`_SUBJECT_RE` 상한 80) | 403 |
| 120자 주체 | 164 | **404** (`_APP_RE` 의 `{1,160}` 가 먼저 자름. 인증 켬/끔 둘 다 404) | 404 |

- 서명으로 만들 수 있는 가장 긴 주체는 `gh:`+77자 = 80자이고, 그때 티켓 길이는 124 다(< 160). `gh:`+78자는 `app_ticket` 이 `ValueError` 를 낸다
- 남의 주체의 티켓에 자기 쿠키를 붙이면 403 이다(`gh:kim` 티켓 + `lee` 쿠키, + 유효한 Bearer). **쿠키를 빼거나 틀린 Bearer 를 붙이면 200** 이다. 정보 N4 에 적었다
- 경로 조작: `/app/~<t>/알파/../알파/` 는 404(게이트), `/app/~<t>/%2e%2e/알파/` 는 403

### 4. `-` 자리표

| 경우 | 결과 |
|---|---|
| 인증을 켠 키로 서명한 `-` 티켓 → 켠 서버 (쿠키 없음 / kim 쿠키) | 403 / 403 |
| 끈 서버가 발급한 `-` 티켓 → 켠 서버 | 403 |
| 끈 서버가 발급한 `-` 티켓 → 끈 서버 | 200 |
| 켠 서버의 `gh:kim` 티켓 → 끈 서버 | 403 (끈 서버는 프로세스 임의 키 `_APP_TICKET_FALLBACK_KEY` 를 쓰므로 키가 다름) |

켠 길과 끈 길은 키도 다르고, 켠 길은 `-` 를 명시적으로 거절한다. 두 길이 섞이는 경로는 찾지 못했다.

## 다음 라운드로 넘길 것

1. **N1 (중간)** - 주체 칸 바꿔치기 시험을 넣는다. 함수 수준에서는 `app_ticket(…, "gh:kim")` 의 주체 칸을
   `token`/`gh:lee`/`-` 로 바꾸고 exp·mac 은 그대로 둔 채 `app_ticket_ok(바꾼티켓, 이름, 키, 바꾼주체)` 가 False 인지 본다.
   라우팅 수준에서는 같은 바꾼 티켓이 쿠키 없이 403 인지 본다. 이것이 M5 를 죽인다
2. **N3** - 브라우저 회수 검사를 **iframe 안에서** 재게 한다. 지운 뒤 `fr.src = <옛 티켓 URL>` 로 다시 넣고 그 응답이 403 인지
   보거나, 쿠키 없는 새 문맥에서 옛 티켓 URL 을 연다. 지금의 `지운 뒤 새로 고치면` 은 발급 경로 검사로 이름을 바꾸거나 둘로 나눈다
3. **N2** - `gh:`+39자 로그인으로 라우팅 `/app/~…/` 이 200 인지 보는 시험(M8)
4. **N6·D5** - 티켓 경로 회수가 `access.log` 에 한 줄 남는지 보는 시험(M9). 위조·만료·교차 주체·`-` 403 감사는 앞 검수 4번 그대로 넘긴다
5. **D3·D4** - 앞 검수 3·4·5번 그대로 (억제 키, 억제 시각을 기록 뒤로 옮김, 경로·메서드 기록, LRU 시험)
6. **D6·D7 (정보)** - M10·M11 을 죽이는 단위 시험. `sign_session` 이 `-` 를 거부하게 해 자리표를 주체 값 영역 밖으로 뺀다
7. **N4·N5 (정보)** - 교차 주체 검사가 bearer 티켓에서 권고일 뿐이라는 점과 재허용 시 되살아남을 의도로 볼지 문서에 적는다.
   URL 에 로그인이 보이는 것이 싫으면 주체 칸을 불투명 식별자(예: 주체의 HMAC 앞 8자)로 바꾸는 방법이 있다.
   그러면 회수 검사를 하려면 역조회가 필요해진다
