## 결론 요약

**T-157 결함 2(회수)는 원시 HTTP 기준으로는 닫혔지만, 그 방식이 실제 브라우저에서 앱을 깨뜨린다.**
티켓 경로가 이제 매 요청마다 세션 쿠키를 요구하는데, `/app/` 응답의 CSP `sandbox`(allow-same-origin 없음)
때문에 앱 문서가 불투명 출처가 되어 **하위 자원 요청에는 SameSite 쿠키가 실리지 않는다.** 그래서 인증을 켠
운영 모드에서는 iframe 안의 js·css·이미지가 전부 403 이다. 서버 코드 자체도 `server.py:2396-2397` 주석에서
이 사실("불투명 출처는 SameSite=Strict 쿠키를 싣지 못하므로")을 전제로 하고 있다. 시험은 쿠키를 손으로
붙여 보내기 때문에 이 모순을 보지 못한다.

T-157 결함 3(거절 감사)은 동작은 하지만, 억제 키 구성과 상한을 지키는 시험이 없다(변이 3개가 살아남음).

## 다음 라운드로 넘길 것

1. **D1 (높음) - 티켓이 쿠키 없이 주체를 실어 나르게 바꾼다.** 제안하는 모양은 이렇다. 티켓을
   `<exp>.<주체>.<mac>` 처럼 주체를 담는 꼴로 바꾸고(주체는 `_SUBJECT_RE` 로 검사하므로 `.` 이 없다),
   검증할 때는 **티켓 안의 주체**로 서명을 확인한다. 그다음 `gh:` 주체면 허용 목록을 다시 본다.
   이렇게 하면 쿠키가 필요 없으니 불투명 출처에서도 동작하고, 회수는 그대로 즉시 걸린다. `token` 주체의
   회수 수단은 지금처럼 토큰 교체다. 티켓 경로의 `self._subject()` 필수 조건(`:2546-2548`)은 빼고,
   회수 감사도 이 경로에서 같은 `_audit_revoked` 를 부른다. 티켓 길이 상한 80자(`_APP_RE`,
   `app_ticket_ok`)는 `gh:` 와 로그인 60자가 들어가도록 다시 잡아야 한다
2. **D2 - 브라우저 회귀 시험을 넣는다.** playwright 는 이미 쓰고 있다(`projects/웹워들/tests/browser_harness`).
   `require_auth=True` 서버에서 sandbox iframe 의 하위 자원이 200 이고 JS 가 도는지, 그리고 허용 목록에서
   지운 뒤에는 403 인지 본다. 단위 시험도 "티켓 경로 요청에 쿠키를 싣지 않는다"를 기본으로 바꾼다
   (`test_aimem_monitor_app.py:454-468` 은 회수 **전** 요청을 쿠키 없이 보내야 한다)
3. **M6·M7·M10 을 죽이는 시험.** 같은 주체를 다른 ip 에서 보내면 두 줄, 다른 주체를 같은 ip 에서 보내면
   두 줄이 남는지 본다. 257번째 키가 들어오면 가장 오래된 키가 빠지는지 본다
4. **D4·D5 - 감사를 보강한다.** 억제 시각은 `audit()` 이 성공한 뒤에 기록한다. 억제된 건수를 세어 두었다가
   다음 줄의 detail 에 `억제 n건` 으로 붙여, 첫 줄 뒤에 일어난 일도 흔적이 남게 한다. 줄에 메서드와
   경로(티켓은 가림)를 넣는다. 티켓 403 과 서명 불일치 쿠키도 같은 억제기(키는 ip)로 기록한다
5. **D3 - 로그 불리기를 막는다.** 억제 키를 주체 하나로 묶고 ip 는 detail 에 적는 방법, 또는 주체별로
   ip 를 n개까지만 따로 세는 방법 중 하나를 고른다. 어느 쪽이든 3번 시험과 함께 고친다
6. **D6·D7 (정보) - 심층 방어.** `app_ticket`·`app_ticket_ok` 가 주체를 `_SUBJECT_RE` 로, 이름을
   `_PROJECT_RE` 로 직접 검사하게 하거나 payload 를 길이 접두나 JSON 으로 인코딩한다. 자리표는 `_SUBJECT_RE`
   영역 밖의 값(예: `~none`)으로 바꾸거나 `sign_session` 에서 `-` 를 거부한다
