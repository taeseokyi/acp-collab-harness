## 새 결함

### N9 · 중간(시험) · N1 수정을 되돌려도 시험이 모두 초록입니다
**재현**: 사본의 `server.py` 에서 `authenticated = authenticated or event == "github-revoked"` 를 `authenticated = True` 로 바꿉니다(M1). 아니면 `elif has_subject:` 의 키에 `safe_path` 를 다시 넣습니다(M2). 그다음 `python3 -m unittest tests.test_monitor_ticket_regress` 를 돌리면 **OK** 입니다. 같은 사본에서 가상 30분을 돌리면 park 는 **0줄**로 앞 검수와 똑같습니다.
**원인**: `test_ticket_subject_cannot_grow_the_audit_keys` 가 태그 `aaaaaaaaaaaa` 인 **가짜** 티켓을 씁니다. 그러면 주체가 None 으로 풀려 `"-"` 키를 탑니다. 진짜 태그(주체가 풀리는 티켓)로 경로를 바꾸는 시험이 없습니다. M11(`주체 불일치` 의 `authenticated=True` 를 지움)도 초록입니다.
**등급**: 이번 라운드에서 가장 무거운 수정(앞 등급 중간)이 회귀해도 알아챌 수 없습니다.
**고칠 방향**: `mint_ticket()` 으로 진짜 티켓을 받습니다. 쿠키 없이 `/app/~T/베타/z{i}` 를 i=0..299 보내 줄 수가 상수 이하인지 봅니다. 이어서 회수된 계정으로 1회 시도해 그 줄이 남는지 봅니다. `주체 불일치` 쪽에는 키에 경로가 들어 있음을 못박는 시험을 둡니다.

### N5 · 낮음 · 인증된 주체가 경로를 바꿔 전역 상한을 채우면 다른 회수 계정이 0줄입니다
**재현** (진짜 저장소에서 읽기 전용, 쓰기는 임시 폴더):
```bash
PYTHONPATH=tools python3 - <<'EOF'
import tempfile, pathlib
from unittest import mock
from aimem_monitor import server as s
with tempfile.TemporaryDirectory() as d:
    root = pathlib.Path(d); t = [1.8e9]
    with mock.patch.object(s.time, "time", lambda: t[0]):
        for m in range(30):
            b = t[0]
            for i in range(300):
                s._audit_denied(root, "github-revoked", "6.6.6.6", "gh:evil", f"/api/x{m}-{i}", "GET", "허용 목록 밖", authenticated=True)
            for k in range(6):
                t[0] = b + 1 + 10 * k
                s._audit_denied(root, "github-revoked", "9.9.9.9", "gh:park", "/api/state", "GET", "허용 목록 밖", authenticated=True)
            t[0] = b + 60
    L = (root / s.AUDIT_LOG).read_text(encoding="utf-8").splitlines()
    print("park 줄", sum("gh:park" in l for l in L), "/ 전체", len(L))   # 실측: park 줄 0 / 전체 1829
EOF
```
**무엇이 잘못됐나**: `github-revoked` 와 `주체 불일치` 의 키에는 아직 경로가 들어 있습니다. 그래서 그 주체 하나가 키를 무제한으로 늘려 분당 60줄 상한을 혼자 다 씁니다. 그동안 다른 회수 계정(park)의 시도는 `audit-dropped` 의 숫자로만 남고, 주체·IP 는 사라집니다.
**등급(낮음)**: 서명된 세션 쿠키가 필요합니다. 회수됐지만 TTL 이 남은 계정이거나, 허용된 내부자여야 합니다. 가리는 쪽 자신은 분당 60줄로 이름이 남습니다. 쿠키 없는 공격자에게는 열려 있지 않습니다.
**고칠 방향**: 상한을 몫별로 나눕니다(무인증·티켓 몫 / 인증 주체별 몫). 아니면 "이번 창에서 처음 보는 `(event, subject)` 는 상한과 무관하게 1줄" 을 보장합니다.

### N6 · 낮음 · 억제 표(256)에서 밀려난 키의 `생략 N건` 이 사라집니다
**재현**: 위 조각과 같은 꼴입니다. kim 티켓 키로 101번(1줄 + 생략 100) → 61초마다 evil 이 새 경로 60개씩 5번 → 61초 뒤 kim 1번. 결과는 **요청 402 / 줄 302 / kim 의 두 번째 줄에 생략 표기 없음 / 메모리 0**. 100건이 어디에도 남지 않습니다.

### N7 · 정보 · 조용해지면 남은 수가 기록되지 않습니다 (물음 4)
상한 생략 수는 **새 키를 쓰려는 시도**가 다음 창에 올 때만 `audit-dropped` 로 나갑니다. 키별 생략 수는 **그 키**가 60초 뒤에 다시 올 때만 나갑니다. 실측 예: evil 200 + 티켓 50 → 1시간 동안 새 거절 없음 → 디스크에는 60줄뿐이고 상한 생략 190건은 메모리에만 있습니다. 소켓 실측에서는 키별 생략 1,197건이 메모리에만 있습니다. 재시작하면 둘 다 사라집니다. 메모리까지 합치면 등식은 늘 맞습니다. 고칠 방향은 종료할 때(`server_close`) 털어 내거나, `audit()` 을 부를 때마다 창 만료를 확인하는 것입니다.

### N8 · 정보 · 쿠키 없는 요청자도 서로 다른 주체의 티켓이 26개 이상이면 상한이 찹니다
