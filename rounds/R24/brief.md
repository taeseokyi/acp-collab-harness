## 1-1. 결과물은 프로젝트 폴더에, 라운드 폴더에는 기록만
**프로젝트**는 여러 라운드를 묶는 단위입니다. 결과물은 라운드마다 흩어지지 않고 **`projects/<프로젝트>/` 한 곳에 여러 라운드에 걸쳐 쌓입니다.** 요청마다 프로젝트가 붙어 옵니다(`aimem_db.py request list` 의 `[이름]`, 요청 파일의 `project`).
- **시작할 때** 그 프로젝트의 `projects/<프로젝트>/PROGRESS.md` 를 먼저 읽습니다 - 앞선 라운드가 무엇을 만들었고 무엇이 남았는지가 거기 있습니다(당신은 기억이 없습니다). 폴더가 없으면 새 프로젝트이니 만들고 `README.md`(무엇을 만드는 프로젝트인지, 폴더 구조)를 씁니다.
- **목표를 적습니다.** `PROGRESS.md` 맨 위(제목 바로 아래)에 `## 목표` 절을 두고, 이 프로젝트가 "다 됐다" 고 하려면 있어야 할 것을 체크리스트로 적습니다(`- [ ] 로그인 화면`, 끝난 것은 `- [x]`). 새 프로젝트면 요청과 README 를 보고 **끝까지 가는 데 필요한 목표를 예측해서** 5~15개로 씁니다 - 이번 라운드에 할 것만 적지 않습니다. 이어받은 프로젝트면 끝난 것을 체크하고, 새로 드러난 목표는 덧붙이고, 필요 없어진 것은 지우고 그 사실을 라운드 항목에 한 줄 적습니다. 웹의 프로젝트 진행률이 이 체크리스트의 "끝난 수 / 전체" 입니다. 검증까지 끝난 것만 체크합니다.
- **만들 때** 이미 있는 결과물을 이어서 고칩니다. 라운드 번호가 붙은 사본(`v2`, `R24-…`)을 옆에 만들지 않습니다 - 이력은 git 에 있습니다.
- 작업자에게 쓰게 하려면 먼저 `python3 tools/aimem_db.py ownership set --path "projects/<프로젝트>/<하위 경로>/**" --owner S<n> --note "R24"` 로 배정합니다. 같은 파일을 두 슬롯에 주지 않습니다.

## 2. 턴 규칙
- **사람이 남긴 말** `rounds/R24/INBOX.md`(`fleet_ctl.py tell`)는 시작할 때, 그래프를 만들기 전, 체크포인트마다 읽습니다. `fleet_graph run` 이 **rc 4** 로 돌아오면 새 말이 온 것이니 읽고 판단한 뒤 다시 `run` 합니다. 같은 요청 안에서는 이 말이 요청 본문보다 앞섭니다.
- 기다릴 때는 `fleet_graph.py run` 을 **포그라운드로 블로킹**합니다. 백그라운드 감시 + "알림 오면 잇겠다" 로 턴을 끝내지 않습니다. 보고를 본문에 다 쓰기 전에는 턴이 끝나지 않습니다.
- **프로세스를 직접 죽이지 않습니다**(`kill`·`pkill` 은 허용 도구에 없습니다). 멈춘 작업자는 엔진이 끊습니다 - 노드 한도(`timeout_sec`)와 침묵 감지. 그래도 남으면 보고에 실행 id 를 적으십시오.
- **커밋·푸시 금지.** 커밋은 라운드가 끝난 뒤 클로드 코드가 합니다.
- **큰 출력은 직접 읽지 않습니다.** 작업자 보고는 첫 줄(`DONE|PARTIAL|BLOCKED|NEEDS-*`)과 요약만, 테스트·린터는 `| tail -20` 또는 실패 줄만, diff 는 `git diff --stat` 뒤 해당 hunk 만.
- **유료 모델 대체 금지.** 무료 슬롯(S2·S3, 둘 다 kistillm) 장애 시 S1/S4 claude 로 옮기지 않고 그 태스크를 BLOCKED 로 두고 보고합니다.
- **함대 모드.** `fleet_graph run` 출력에 `함대 모드: paused|stopped|ready` 가 찍히거나 rc 3 이면 사람이 멈춘 것입니다. 우회하지 말고(`AIMEM_FLEET_FORCE` 금지) 체크포인트를 남긴 뒤 `상태: PARTIAL` 로 보고하고 끝내십시오.
- **모니터는 HTTPS + 인증**입니다. 작업자에게 운영 서버를 `curl` 로 부르게 하지 말고(401), 토큰을 브리프에 넣지 마십시오. 서버 동작은 테스트가 임시 포트에 띄우는 서버로 확인합니다. 서버 코드를 바꿨으면 **직접 재시작하지 말고** 보고에 '모니터 재시작 필요' 를 적으십시오(검수 전의 인가 코드가 운영에 올라가지 않게).

## 3. 그래프 짜기 (정본은 `8.0-8` 의 Graph and verify rules - 아래는 그 요약입니다)
- **라운드 = 그래프 하나(원칙).** 과제 전체를 의존관계(`deps`) 포함 한 그래프로 짭니다. 둘 이상은 앞 그래프 결과로 계획이 바뀌어야 할 때만. 검수는 그래프 안의 노드로 두고, 관리자는 그래프가 끝난 뒤 한 번 확인합니다.
- **만들기·고치기는 무료 슬롯.** 새 코드·결함 수정·테스트·문서는 S2(codex)·S3(opencode)에 줍니다 - 모델은 `slot list` 대로입니다(둘의 공급자가 다르면 동시에 돕니다). S1·S4(유료)는 **판단·설계·적대적 검수에만** - "빨라서" 는 이유가 아닙니다. 검수가 찾은 결함도 무료 슬롯이 고칩니다. 유료 슬롯에 만들기·고치기를 줬다면 보고 (6)에 태스크별 이유를 적습니다. 같은 파일을 두 슬롯에 주지 않습니다.
- **병렬로 짭니다.** 노드는 정말 앞 노드의 결과물을 읽을 때만 `deps` 를 겁니다. 먼저 인터페이스(파일·함수 이름과 입출력 꼴)를 정해 각 브리프에 적어 두면 로직·화면·스타일·검사를 같은 단계에 나란히 둘 수 있습니다 - 검사는 구현이 아니라 그 약속을 보고 씁니다. 같은 단계의 노드는 슬롯을 나눠(공급자가 다른 슬롯이면 더 좋음) 동시에 돌게 하고, 검수만 끝에 둡니다. `fleet_graph.py new` 가 찍는 '모양:' 줄과 참고를 보고 일렬이면 다시 나눕니다.
- **노드는 작게.** 한 노드의 산출물은 새 파일 하나 · 200줄 안쪽 · 검사 10개 안쪽. 더 크면 노드를 나누고, 같은 파일을 둘이 쓰게 되면 파일을 나눕니다. 읽을 파일을 못박고 "읽지 말 것" 도 적습니다.
- **작업자가 할 수 있는 것.** 무료 슬롯은 브라우저와 로컬 TCP 서버를 직접 돌릴 수 있고, 쓰기는 작업 폴더와 `/tmp` 뿐입니다. 브리프에 "먼저 계획을 세워라" 를 넣지 마십시오 - 바로 파일을 고치게 합니다.
- **`verify` 는 "작업자가 일을 했는가" 를 종료 코드로 묻습니다.** `python3 -m unittest … > /tmp/x.txt 2>&1 && …` 처럼 파일로 받아 `&&` 로 잇고, `| tail | grep` 으로 거르지 않습니다. 걸기 전에 **지금 트리에서 그 검사를 한 번 돌려 봅니다** - 관리자 허용 도구로는 `python3 -m unittest …` 와 `python3 tests/<파일>.py` 꼴만 돌릴 수 있으니(`python3 -c`·`node`·`/tmp` 리다이렉트는 막힙니다) 검사 본체만 돌려 종료 코드를 확인하면 됩니다. 엔진은 `verify` 를 울타리 안에서 돌립니다 - 쓰기는 저장소와 `/tmp` 만, `.env`·`.aimem/tls`·API 키 환경변수는 안 보이고 네트워크는 됩니다. 그래서 `$HOME` 에 쓰거나 키를 읽는 검사는 미리 돌렸을 때 통과해도 엔진에서는 실패합니다.
- **검사를 만드는 노드의 `verify` = "돌았다 + 검사 수가 늘었다"** 이지 "제품이 통과했다" 가 아닙니다(예: `… | tail -1 | python3 -c "import sys; p=sys.stdin.read().split(); sys.exit(0 if len(p)==5 and int(p[4])>=65 else 1)"`). 검사가 제품 결함을 찾으면 작업자는 제품도 검사도 고치지 않고 첫 줄을 `NEEDS-FIX: <무엇이 어디서>` 로 보고합니다(엔진이 재시도 없이 막힘으로 둡니다). 그 결함은 뒤의 수정 노드가 고치고, 수정 노드와 재검증 노드에 `통과 수 == 전체 수` 를 겁니다.
- **엔진이 빈손 시도를 실패로 봅니다** - 보고가 도구 호출 글자로 끝난 시도(`aborted`), `write` 경로를 하나도 안 고친 첫 시도(`no-op`). 재시도 브리프에는 직전 verify 출력 꼬리 600자와 직전 보고가 참고로 갑니다. 스크립트는 마지막 줄들에 실패 원인이 찍히게 짜게 합니다.
- **화면 검사는 실제로 그려진 것을 묻습니다.** `hidden`/`display` → `is_visible()`, 색 → `getComputedStyle`, 자리·겹침·잘림 → `bounding_box()`. 화면이 있는 프로젝트는 "요소끼리 겹치지 않는다"·"입력한 뒤에도 화면 밖으로 안 나간다" 를 처음부터 넣고, 로그인 뒤의 화면은 **인증을 켠 검사**도 한 벌 둡니다(`tests/browser_monitor_auth.py` 가 본보기). 화면 태스크 브리프에 이 규칙을 옮겨 적습니다.
- **저장소 사본을 만드는 검수(변이 시험)**는 `.aimem/tls/` 를 빼고 복사해 임시 토큰을 쓰고, 끝나면 그 `/tmp` 폴더를 `rm -rf` 합니다(자기가 만든 `/tmp` 폴더 삭제는 금지 대상이 아닙니다). 검수 브리프에 그렇게 적습니다.
- 막힌 노드는 원인을 확인한 뒤 `fleet_graph.py unblock <그래프> <노드>` 로 다시 굴립니다(작업자가 살아 있으면 거절됩니다). 작업자가 일을 다 했는데 `verify` 가 틀려 실패한 노드는 직접 재현 확인한 뒤 사유를 `events` 에 남기고 닫습니다.
- 핸드오프는 `8.0-8` 종료 1번대로 `handoff add --bump --expect-rev N`.
