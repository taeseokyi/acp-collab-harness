작업 보드

대기 큐 후속 일 · 요청을 처리하다 생긴 다음 할 일(검수 지적 등)

관리자가 라운드마다 새 작업 요청을 먼저 하고 그다음 여기서 위부터 가져갑니다. 요청과 이것이 모두 비면 이어 달리기가 멈춥니다. 순서 번호는 처리된 항목이 빠지면 다시 매겨집니다.

R17-N5
R17 라운드 검수 보고서(rounds/R17/REVIEW-….md)의 5번 항목. 번호는 보고서마다 1부터 다시 세므로 라운드를 꼭 붙입니다
N
결함·발견 - 검수자가 찾은 문제. 등급은 높음 · 중간 · 낮음 · 정보(고치지 않아도 되지만 알아 둘 것)
M
변이 시험 - 코드를 일부러 망가뜨려 테스트가 잡는지 본 것. "살아남음" 이면 테스트 구멍입니다
D
넘어온 결함 - 앞 라운드에서 다 못 닫고 이어받은 문제

라운드 핸드오프 로그 인수인계 기록 · 최신이 위 · 행을 누르면 전문

라운드(또는 클로드 코드 작업)가 끝날 때 다음 관리자에게 남기는 요약입니다 - 한 일, 바뀐 것, 남은 일. 관리자는 라운드마다 기억 없이 새로 뜨므로 시작할 때 최근 두 건부터 읽고 이어받습니다. 항목마다 대개 REV 가 하나 오릅니다(커밋의 REV 번호). 본문의 N·M·D 번호는 그 라운드 검수 보고서의 결함·변이 시험·넘어온 결함입니다(읽는 법은 위 '대기 큐').

태스크 그래프 끝난 그래프는 접혀 있습니다

요청별 분담 트리 끝난 요청은 접혀 있습니다

작업 요청 다음 라운드가 할 일

여기 적어 보낸 요청이 NEW 로 쌓이고, 함대 탭의 라운드 실행을 누르면 관리자가 전부 읽어 나눠 처리합니다. 결과물은 라운드가 아니라 프로젝트 폴더 projects/<프로젝트>/ 한 곳에 여러 라운드에 걸쳐 쌓입니다.
